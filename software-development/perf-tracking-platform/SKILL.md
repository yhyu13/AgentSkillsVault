# 性能跟踪分析平台（Performance Tracking Platform）

## 平台概览

XD 游戏引擎侧搭建的性能监测与分析平台，分线下、线上两条线，目标是实现跨赛季性能劣化预警与性能问题快速定位。

- **O1 线下平台**：基于「标准化测试场景」的线下性能监测和分析平台，实现版本性能问题的快速定位。
  - **KR1**：落地自动测试收集分析全流程，做到跨赛季性能劣化预警。
  - **KR2**：提高性能问题分析速度。
- **O2 线上平台**：线上性能监测和分析平台，实现线上性能问题的快速定位。
  - **KR1**：线上性能埋点新口径代码发版。
  - **KR2**：线上性能看板落地。

看板服务（线下/线上共用）：`http://172.26.229.66:5177/#/producer`（内部地址，需内网访问）。

## 性能指标口径（回答问题时的权威依据）

- **帧时间 P95 / P99**：每赛季上线前 1-2 周，在固化环境（BD、场景、怪物固定）输出帧时间 P95/P99。
- **卡顿率**：帧时间 > 2×中位数的帧占比。
- **长卡顿次数**：>30ms 的卡顿各持续多少秒。
- **统计指标偏好**：当前埋点方式下 P50 参考价值不高，已改为「低于 54fps 的战斗场数对比」这类可直读的模式，不用 P50。
- **发烫测试（手机）**：连续跑 45 分钟帧率曲线，关注平均帧率及其中 <50 帧的时长。
- **loading 监控**：首次 loading 时间、切换进入副本 loading 时间、返回主城时间。
- **输出维度**：分 PC / 安卓 / iOS / 总计，覆盖 CPU、GPU、内存；目标是「一句话能看明白这些指标有没有明显变好或变差」。
- **线上报告**：每赛季输出线上玩家真实帧率（能有内存更好），并观察有无明显问题；更高优先级数据（优先级 4）用于观察某特效（皮肤）、场景是否有明显帧率异常。

## 瓶颈判定规则

- **瓶颈判定**：`GPU busy%` + Game thread / Render thread / GPU 三个耗时，取最大者为瓶颈。
- **CPU 侧拆分**：按模块拆——逻辑 · 动画 · UI · 物理 · 网络。
- **GPU 侧拆分**：按 pass 拆——阴影 · 不透明 · 半透明 · 后处理 · UI，并统计 DrawCall 数。
- 分析目标示例：如 CPU 某帧 14ms，要能拆出各模块各占多少时间，明确大头消耗在哪里。
