# 原始需求背景（验收口径）

> 摘自《性能跟踪分析平台进度》文档「附背景」章节，是平台建设的原始需求，可作为验收口径与背景依据。

## 赛季前（测试环境）

每赛季有一份性能报告（当前赛季的现在就可以准备），分 PC、安卓、IOS、总。

- 建立一个稳定的测试环境，BD、场景、怪物等固化，每个赛季上线前 1-2 周，输出该环境的测试数据：
  - 帧时间 P95 / P99
  - 卡顿率（帧时间 > 2×中位数的帧占比）
  - 长卡顿次数（>30ms 各多少秒）
  - 包括 CPU、GPU、内存
- 希望是一句话，能看明白这些指标有没有明显变好或变差。
- 手机上为了测发烫，连续跑 45 分钟的帧率曲线，关注平均帧率及其中 <50 帧的时长。
- 性能上能明确分析出 CPU、GPU 哪一款是瓶颈，其中的大头主要消耗在哪里。比如 CPU 如果 14ms，分几个模块各占了多少时间。

## 赛季后（线上）

- 上线后每赛季输出报告，分 PC、安卓、IOS、总，线上玩家的真实帧率（能有内存更好），CPU/GPU 哪项是瓶颈更好，会观察有无明显问题。
- 上线后输出报告，有更多的数据（优先级 4 排在其它后面），能看出某特效（皮肤）、场景上是否有明显帧率异常情况。

## 补充监控项

- 加入首次 loading 时间、切换进入副本 loading 时间、返回主城时间也加入监控。

## 瓶颈判定口径

- 瓶颈判定：GPU busy% + Game thread / Render thread / GPU 三个耗时取最大者为瓶颈。
- CPU 侧拆模块（逻辑·动画·UI·物理·网络），GPU 侧拆 pass（阴影·不透明·半透明·后处理·UI）+ DrawCall 数。
