# 俞军 · 产品价值公式+需求三角

> 产品价值=新体验-旧体验-迁移成本；没有场景就没有需求，理解用户不等于满足用户

## 核心理念

俞军产品方法论解决的核心问题是：**如何用可量化的框架判断产品价值，如何用结构化的方法识别真实需求？**

2019年，俞军在《产品方法论》中给出了回答：产品价值可以用公式计算——用户体验=新体验-旧体验-迁移成本；真实需求可以用三角识别——用户+场景+需求，三者缺一不可。这个命题有三个支撑判断：第一，迁移成本是产品价值的关键变量——很多产品失败不是因为新体验不够好，而是因为迁移成本太高；第二，没有场景就没有需求——脱离场景的需求是伪需求，场景定义了需求的真实性和紧迫性；第三，产品经理的底层能力是同理心——不是逻辑，不是执行力，而是真正站在用户角度理解用户。

俞军对中国产品方法论的贡献是**把产品决策从"经验直觉"升级为"框架判断"**——产品价值公式让"做不做这个功能"从拍脑袋变为算账；需求三角让"这是不是真需求"从感觉变为结构化判断；三个底层能力让"什么样的人能做好产品经理"从玄学变为可评估的维度。

核心公式：**产品价值 = 新体验 - 旧体验 - 迁移成本**

## 关键模块

### 模块1：产品价值公式

- 定义：产品价值=新体验-旧体验-迁移成本——这个公式将产品价值量化为三个变量的差值，让"产品值不值得做"从定性判断变为定量计算
- 输入：新产品的体验值 + 现有替代品的体验值 + 用户的迁移成本
- 输出：产品价值的量化判断
- 关键动作：
  - **新体验**：新产品/新功能给用户带来的体验价值——包括功能体验（更快/更好/更方便）、情感体验（更安心/更愉悦/更有掌控感）、社会体验（更有面子/更有归属感）；关键判断：新体验不是"产品有多好"，而是"用户感知到多好"——产品好但用户感知不到，新体验=0
  - **旧体验**：用户当前使用的替代品带来的体验值——旧体验是"基准线"，新体验必须显著超过旧体验才能创造价值；关键判断：旧体验不是"竞品有多差"，而是"用户当前的解决方案有多好"——用户可能用非常原始的方式解决问题，但那个方式对他来说"够用了"
  - **迁移成本**：用户从旧方案切换到新方案需要付出的代价——包括学习成本（重新学习操作）、数据成本（迁移数据/重建关系）、习惯成本（改变使用习惯）、机会成本（放弃旧方案的积累）、心理成本（对未知的恐惧）；关键判断：迁移成本是产品价值公式中最容易被忽视但最关键的变量——很多产品失败不是因为新体验不够好，而是因为迁移成本太高
  - **为什么迁移成本是关键**：迁移成本决定了"好产品"能否变成"被采用的产品"——新体验-旧体验的差值再大，如果迁移成本更大，产品价值仍然为负；案例：Google+ vs Facebook——Google+的体验可能不差，但用户的社交关系全在Facebook上，迁移成本极高，产品价值为负；关键判断：降低迁移成本比提升新体验更有效——与其把新体验从80分做到90分，不如把迁移成本从60分降到30分
  - **为什么百度贴吧能赢**：百度贴吧是俞军产品价值公式的经典案例——贴吧的新体验：基于搜索关键词自动创建社区（用户不需要手动找社区）；贴吧的旧体验：传统BBS需要手动创建版块/手动找版块；贴吧的迁移成本：几乎为零（百度搜索用户直接进入贴吧）；产品价值=高新体验-低旧体验-零迁移成本=巨大正值；关键判断：贴吧的成功不是因为它比BBS"更好"，而是因为迁移成本几乎为零——百度搜索的流量入口让用户"不知不觉"就用了贴吧
- 常见误区：只关注新体验忽视迁移成本——新体验再好，迁移成本太高用户也不会切换；把旧体验等同于竞品体验——旧体验是用户当前的解决方案，不一定是竞品；认为产品价值公式可以精确计算——公式提供的是思维框架，不是精确计算工具

### 模块2：需求三角

- 定义：真实需求由三个要素构成——用户+场景+需求，三者缺一不可；缺少任何一个要素，需求就不成立
- 输入：用户描述 + 场景描述 + 需求描述
- 输出：需求是否真实的判断
- 关键动作：
  - **用户**：谁有这个需求？——不是"所有人"，而是具体的、可描述的用户群体；用户定义的关键：①用户是具体的——"25-35岁的一线城市白领"而非"年轻人"；②用户是有差异的——同一产品对不同用户的价值不同，需要分别分析；③用户是动态的——用户的需求随时间变化，需要持续跟踪
  - **场景**：用户在什么情境下产生需求？——场景定义了需求的发生条件；场景的关键：①场景是具体的——"在地铁上用手机看新闻"而非"看新闻"；②场景包含时间/地点/状态——什么时间、什么地点、什么心理状态；③场景决定了需求的紧迫性——同一需求在不同场景下的紧迫性完全不同
  - **需求**：用户要完成什么？——不是"功能需求"，而是"用户要取得的进步"；需求的关键：①需求是用户视角的——"我想在通勤时不无聊"而非"需要新闻推送功能"；②需求有层次——功能需求/情感需求/社会需求；③需求是可验证的——可以通过用户行为验证需求是否真实
  - **为什么没有场景就没有需求**：场景是需求的"触发器"——没有场景，需求只是"潜在需求"而非"活跃需求"；案例："我想学英语"是潜在需求，"我要出国旅游前学几句英语"是有场景的活跃需求——后者才会驱动付费行为；关键判断：大多数伪需求的本质是"有需求但没场景"——用户确实有这个需求，但没有具体的场景触发它，所以不会产生行为
  - **为什么伪需求=缺场景**：伪需求不是"假的需求"，而是"没有场景的需求"——用户嘴上说需要，但没有具体场景触发行为；识别伪需求的方法：①问"你上次遇到这个需求是什么时候"——如果答不上来→缺场景→伪需求；②问"如果没有这个功能你会怎么办"——如果用户有简单的替代方案→需求不紧迫→伪需求；③观察行为而非言语——用户说的和做的经常不一致，行为比言语更真实；关键判断：伪需求不是"用户不需要"，而是"用户需要但不紧迫"——紧迫性由场景决定
- 常见误区：把需求三角当作三个独立要素——三者是相互定义的，用户定义场景，场景定义需求；只关注需求忽视场景——没有场景的需求是伪需求；把用户需求等同于产品功能——需求是用户视角的，功能是产品视角的

### 模块3：产品经理3个底层能力

- 定义：产品经理的底层能力有三个——同理心/逻辑/自我否定，其中同理心排第一
- 输入：产品经理的日常工作
- 输出：产品经理能力的评估和发展方向
- 关键动作：
  - **同理心**：真正站在用户角度理解用户——不是"我觉得用户需要"，而是"用户真的需要"；同理心的关键：①同理心≠同情——同情是"我为你难过"，同理心是"我理解你的处境"；②同理心需要"放下自我"——产品经理最大的敌人是"我以为"，需要不断提醒自己"我不是用户"；③同理心可以通过训练提升——多和用户交流、多观察用户行为、多体验用户场景；关键判断：为什么同理心排第一——因为产品经理的所有决策都基于"理解用户"，没有同理心，逻辑再强也是"在错误的方向上精确推理"
  - **逻辑**：将复杂问题拆解为可操作的步骤——不是"想清楚"，而是"想清楚并说清楚"；逻辑的关键：①逻辑是结构化思维——MECE（互斥且穷尽）是基本要求；②逻辑是因果推理——区分相关性和因果性，避免"因为A和B同时发生所以A导致B"的谬误；③逻辑是可验证的——每个推理步骤都可以用数据或实验验证；关键判断：逻辑是产品经理的"工具"，同理心是产品经理的"方向"——没有方向的工具是盲目的，没有工具的方向是空谈
  - **自我否定**：敢于推翻自己的判断——不是"认错"，而是"基于新证据修正判断"；自我否定的关键：①自我否定≠自我怀疑——自我怀疑是"我不确定"，自我否定是"我确定我错了"；②自我否定需要"心理安全"——如果组织惩罚错误，产品经理不会自我否定；③自我否定是学习的起点——只有否定旧认知，才能接受新认知；关键判断：为什么自我否定排第三——因为同理心和逻辑是"输入"，自我否定是"纠偏"——没有纠偏，输入可能持续失真
- 常见误区：认为逻辑比同理心重要——逻辑是工具，同理心是方向，方向比工具更重要；把同理心等同于"讨好用户"——同理心是理解用户，不是满足用户所有要求；认为自我否定是软弱——自我否定是理性，坚持错误是固执

### 模块4：产品决策框架

- 定义：产品决策的核心框架是ROI思维——不是"能不能做"，而是"值不值得做"
- 输入：产品需求列表 + 资源约束
- 输出：产品决策的优先级排序
- 关键动作：
  - **ROI思维**：每个产品决策都是投资决策——投入什么资源，获得什么回报；ROI思维的关键：①ROI=回报/投入——不是"回报越大越好"，而是"回报/投入比越大越好"；②回报不只是短期收入——还包括用户价值、战略价值、学习价值；③投入不只是开发资源——还包括机会成本、维护成本、迁移成本；关键判断：ROI思维让产品决策从"感觉驱动"升级为"投资驱动"
  - **为什么做减法>做加法**：做减法比做加法更难但更有价值——每增加一个功能，就增加一份维护成本、一份认知负担、一份用户困惑；做减法的逻辑：①功能越多≠产品越好——功能越多，用户越难找到核心功能，产品越臃肿；②做减法是"选择不做什么"——选择不做什么比选择做什么更需要判断力；③做减法是"聚焦核心价值"——砍掉非核心功能，让核心功能更突出；关键判断：俞军说"一个好的产品经理，最重要的判断是'这个功能可以不做'"
  - **为什么大多数功能是浪费**：产品中的大多数功能使用率极低——俞军引用数据：大多数产品中80%的功能只被20%的用户使用，其中一半功能的使用率低于5%；浪费的原因：①功能是"供给驱动"而非"需求驱动"——产品经理觉得"应该有"就做了，而非用户真的需要；②功能是"竞品驱动"而非"价值驱动"——竞品有所以我也得有，而非这个功能真的创造价值；③功能是"短期驱动"而非"长期驱动"——短期看起来有用，长期增加维护成本和认知负担；关键判断：每增加一个功能前，先问"如果不做这个功能会怎样"——如果答案是不会怎样，就不做
- 常见误区：把ROI等同于短期收入——ROI包括用户价值、战略价值、学习价值；认为做减法就是砍功能——做减法是"聚焦核心价值"，不是简单砍功能；认为"大多数功能是浪费"意味着不需要创新——创新需要做加法，但做加法前需要验证ROI

### 模块5：俞军vs硅谷产品方法论

- 定义：俞军的产品方法论与硅谷产品方法论有根本差异——这种差异来自中国市场的独特特征
- 输入：中国产品实践 vs 硅谷产品实践
- 输出：对中国产品方法论独特性的理解
- 关键动作：
  - **为什么中国产品方法论不同**：中国市场的3个独特特征决定了产品方法论的差异——①用户规模巨大：中国有14亿人口，互联网用户超10亿，用户规模让"小概率需求"也有足够大的市场；②用户分层显著：一线城市和五线城市的用户需求差异巨大，同一产品需要服务不同层次的用户；③竞争极度激烈：中国互联网竞争远比硅谷激烈，产品迭代速度更快，"快"比"好"更重要
  - **中国市场的3个独特特征**：①增量市场vs存量市场：中国市场长期处于增量阶段（新用户不断涌入），产品策略是"快速获客"；硅谷市场更早进入存量阶段，产品策略是"深度留存"；②平台生态vs独立产品：中国市场是"超级App"生态（微信/支付宝/淘宝），产品需要在平台生态中生存；硅谷市场更偏向独立产品，产品可以独立获客；③运营驱动vs产品驱动：中国互联网更偏"运营驱动"——通过活动/补贴/内容运营驱动增长；硅谷更偏"产品驱动"——通过产品体验驱动增长
  - **为什么理解用户≠满足用户**：俞军的核心区分——理解用户是"知道用户要什么"，满足用户是"给用户要什么"；产品经理应该理解用户，但不应该盲目满足用户——原因：①用户说的和想要的不一样——用户说"我要更快的马车"，其实想要的是"更快的交通"；②满足所有用户=没有重点——不同用户的需求可能矛盾，满足所有人=满足没有人；③短期满足可能损害长期价值——用户要"更多功能"，但更多功能可能让产品变臃肿；关键判断：产品经理的职责是"理解用户需求，设计最优解"，不是"用户要什么就给什么"
- 常见误区：认为俞军方法论只适用于中国——产品价值公式和需求三角是通用框架，中国市场特征是应用条件；认为中国产品方法论"低级"——中国产品方法论在用户规模和竞争强度上面临更复杂的挑战；认为"理解用户≠满足用户"意味着不需要用户研究——理解用户是前提，满足用户需要判断力

## 决策启发式

| 场景 | 判断规则 | 来源 |
|------|---------|------|
| 判断产品是否值得做 | 如果新体验-旧体验-迁移成本≤0→不值得做；如果>0→值得做 | 产品价值公式 |
| 判断迁移成本是否太高 | 如果用户需要重新学习/迁移数据/改变习惯→迁移成本高，需要降低迁移成本 | 迁移成本 |
| 判断需求是否真实 | 如果需求三角缺任何一角→伪需求；如果三角完整→真需求 | 需求三角 |
| 判断是否缺场景 | 如果用户说"需要"但答不出"上次遇到是什么时候"→缺场景→伪需求 | 需求三角 |
| 判断产品经理能力 | 如果同理心弱→方向可能错；如果逻辑弱→执行可能乱；如果自我否定弱→纠偏可能慢 | 3个底层能力 |
| 判断是否应该做功能 | 如果不做这个功能"不会怎样"→不做；如果做了ROI不高→不做 | ROI思维 |
| 判断做加法还是减法 | 如果核心价值不清晰→做减法聚焦；如果核心价值清晰但覆盖不足→做加法扩展 | 做减法>做加法 |
| 判断功能是否浪费 | 如果功能使用率<5%→浪费；如果功能是竞品驱动而非需求驱动→浪费 | 大多数功能是浪费 |
| 判断中国vs硅谷方法论 | 如果在增量市场+平台生态+运营驱动→中国方法论更适用；如果在存量市场+独立产品+产品驱动→硅谷方法论更适用 | 俞军vs硅谷 |
| 判断是否应该满足用户 | 如果用户需求与产品核心价值一致→满足；如果不一致→理解但不满足 | 理解用户≠满足用户 |

## 适用场景

### 最适合

- 产品功能决策——用ROI思维判断做不做
- 需求真实性判断——用需求三角识别伪需求
- 竞品分析——用产品价值公式分析竞品优势
- 产品经理能力评估——用3个底层能力评估
- 中国市场产品策略——理解中国市场独特特征

### 不适合

- 技术驱动的产品决策——技术突破的价值难以用公式量化
- B2B复杂采购决策——多方参与、长周期的决策不适用简单的价值公式
- 品牌和情感类产品——情感价值难以量化
- 0到1的探索性创新——没有旧体验和迁移成本的参照
- 高度管控行业——合规要求可能优先于产品价值

## 实施检查清单

- [ ] 是否用产品价值公式评估了每个产品决策——新体验-旧体验-迁移成本
- [ ] 是否重点分析了迁移成本——迁移成本是最容易被忽视的关键变量
- [ ] 是否用需求三角验证了每个需求——用户+场景+需求缺一不可
- [ ] 是否识别了伪需求——缺场景的需求是伪需求
- [ ] 产品经理是否具备3个底层能力——同理心/逻辑/自我否定
- [ ] 是否用ROI思维做产品决策——不是"能不能做"，而是"值不值得做"
- [ ] 是否在做加法前先考虑做减法——做减法>做加法
- [ ] 是否评估了功能的使用率——使用率<5%的功能可能是浪费
- [ ] 是否区分了"理解用户"和"满足用户"——理解≠满足
- [ ] 是否考虑了中国市场的独特特征——增量市场/平台生态/运营驱动

## 诚实边界

1. **产品价值公式的量化困境**：公式看起来可以量化，但"新体验""旧体验""迁移成本"都是主观判断——如何给"体验"打分？不同用户对同一产品的体验评分可能完全不同。公式提供的是思维框架，不是精确计算工具，但使用者可能误以为可以精确计算。

2. **需求三角的"场景"定义模糊**：需求三角强调"没有场景就没有需求"，但"场景"的定义边界模糊——"在地铁上"是场景，"在上班路上"也是场景，"在无聊的时候"算不算场景？场景的粒度没有标准，导致需求三角的判断仍然依赖主观经验。

3. **"做减法>做加法"的适用边界**：做减法在产品成熟期有效，但在产品探索期可能过早——探索期需要做加法来发现核心价值，成熟期需要做减法来聚焦核心价值。俞军的建议更适用于成熟产品，对早期产品的指导力有限。

4. **"大多数功能是浪费"的幸存者偏差**：俞军观察到"大多数功能使用率低"，但这可能是结果而非原因——成功的产品砍掉了低使用率功能，失败的产品可能恰恰是因为缺少某个"低使用率但关键"的功能。使用率低≠功能无用，某些低频功能可能是产品的"安全网"。

5. **中国vs硅谷方法论的二元对立**：俞军对中国和硅谷方法论的区分有一定道理，但过度简化了——中国也有产品驱动的成功案例（如微信），硅谷也有运营驱动的成功案例（如Amazon）。二元对立可能掩盖了更复杂的现实。

6. **同理心的可训练性假设**：俞军认为同理心可以通过训练提升，但同理心的天赋差异可能比训练效果更大——有些人天然更善于理解他人，有些人无论怎么训练都难以真正站在用户角度。同理心作为"第一能力"的门槛可能比俞军承认的更高。

7. **公开资料与原始思想的差异**：《产品方法论》是俞军多年产品经验的总结，但书中部分内容来自俞军在百度的特定经验，可能受百度搜索业务特性的影响。俞军离开百度后的产品实践有限，方法论在非搜索领域的适用性需要更多验证。
