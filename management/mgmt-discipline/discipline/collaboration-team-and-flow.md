# 协作 · 团队与信息流

> 协作的核心张力：安全vs坦诚、透明vs隐私、集中vs分布、同步vs异步——决定团队效能的不是成员"是谁"，而是成员"如何协作"。

## 关键模块

### 模块1：心理安全——协作的地基

- 定义：团队成员确信自己可以承担人际风险——提问、承认错误、提出异议、表达不确定——而不会遭到惩罚或边缘化
- 输入：团队互动中的脆弱性表达
- 输出：信息完整流动 + 错误被及时暴露 + 创新想法被提出
- 关键动作：
  - 区分心理安全与降低标准——心理安全不是"大家和和气气不批评"，而是"可以安全地批评和被批评"；没有心理安全的批评是攻击，有心理安全的批评是反馈
  - 领导者率先展示脆弱性——承认"我不知道"、公开自己的错误、邀请反对意见
  - 建立等发言时间（conversational turn-taking）——高心理安全团队的特征是发言时间相对均衡，而非一两个人主导
  - 对"人际风险行为"给予正向反馈——当有人提问或提出异议时，回应"好问题"而非"这也要问？"
  - 五要素依赖关系：心理安全（地基）→可靠性→结构与清晰度→意义→影响力；心理安全缺失则全部失效
- 常见误区：把心理安全等同于"不批评"——恰恰相反，心理安全让批评变得更安全更有效；认为和谐但产出平庸的团队有心理安全——和谐来自"不争论"而非"争论后达成共识"是心理安全假象

### 模块2：信息循环——协作的血液

- 定义：信息从创造到沉淀的完整闭环——创造（文档/多维表格）→分享（字节圈/群聊/OKR全员可见）→共识（评论/投票/对齐）→沉淀（搜索/知识库/归档）
- 输入：员工日常工作产生的文档、讨论、数据、决策记录
- 输出：组织级共识 + 可检索的知识资产 + 减少重复犯错
- 关键动作：
  - 信息默认公开，需要保密才设权限——反转传统"默认保密"逻辑
  - 鼓励群聊而非单聊——群聊是信息广播，单聊是信息黑洞
  - OKR全员透明——任何人可查看CEO的目标和完成进度，CEO每双月公开给自己OKR逐项打分
  - 文档权限默认"组织内可阅读"——减少信息获取的摩擦
  - 知识库/搜索机制让历史决策可追溯——新人搜索历史文档+OKR记录而非"问人"
- 常见误区：把飞书当"加强版微信"——只用了沟通功能而忽略了信息沉淀；只开放信息而不提升人才密度——没有"善意能人"，"自由信息"只会制造噪音

### 模块3：分布式决策——协作的产出

- 定义：让每个人都能像创始人一样决策——通过信息透明+自主决策替代流程+审批
- 输入：战略层上下文（方向+为什么）+ 业务层上下文（数据+竞品+用户反馈）+ 意义层上下文（价值观+使命）
- 输出：每个节点都能基于完整上下文做出与组织目标一致的决策
- 关键动作：
  - Context not Control：给情景不管控——给足信息让人自己决策，而非告诉人怎么做；CnC的前提是信息透明和人才密度
  - 飞书作为分布式决策基础设施：业务数据通过飞书看板实时共享，减少"汇报-等待"的信息延迟；飞书留存全纪录，弱化层级感——任何人可以追溯到任何决策的原始讨论
  - 善意能人×自由信息：高人才密度下可被信任的自主决策者 × 默认公开的组织信息 = 自主聚合的决策社群——不需要上级指派，员工基于信息自主组队解决问题
  - 异步优先：能文档解决的不开会，只有需要实时对齐时才开会——保护专注时间
- 常见误区：把飞书当成"监控工具"——透明是为了赋能不是为了监视；认为CnC=不管——CnC是给情景不是放任，情景包含方向、数据和价值观

### 模块4：团队效能诊断

- 定义：用五要素框架诊断团队效能低下的根因——心理安全→可靠性→结构与清晰度→意义→影响力
- 输入：团队效能表现 + 成员互动模式
- 输出：效能低下的根因诊断和改善方向
- 关键动作：
  - 效能低下先检查心理安全——如果成员不敢提问和承认错误，其他要素无法生效
  - 团队和谐但产出平庸——检查是否和谐来自"不争论"而非"争论后达成共识"→心理安全假象
  - 某成员沉默寡言——检查是否发言时间极度不均→等发言时间是心理安全的关键指标
  - 成员频繁请示——如果因为不确定角色边界→结构与清晰度不足；如果因为怕犯错→心理安全不足
  - 成员只做最低限度工作——检查意义和影响力：如果成员看不到工作的意义和影响，投入度必然下降
  - 新团队组建——先建立心理安全，再逐步构建其他四要素，顺序不可逆
- 常见误区：认为效能低下是成员能力问题——协作方式比成员构成更重要；把"冲突多"等同于"效能低"——冲突聚焦于事而非人是正常的

### 模块5：坦诚与反馈系统

- 定义：坦诚是协作的润滑剂——但坦诚需要心理安全做前提，没有心理安全的坦诚只会制造恐惧
- 输入：团队成员之间的反馈需求 + 心理安全水平
- 输出：有效的反馈文化
- 关键动作：
  - 坦诚清晰（字节）：说真话说清楚，信息不经过滤直接传递；但字节模式在人才密度高时有效（成员心理韧性足够），在人才密度不足时可能适得其反
  - 心理安全是坦诚的前提（Google发现）：没有心理安全的坦诚只会制造恐惧；Netflix通过Sunshining（领导者公开错误）和向上反馈先行来建立心理安全，然后才要求全员极致坦诚
  - 反馈的4A原则（Netflix）：Aim to assist（旨在帮助）、Actionable（可行动）、Appreciated（感激接受）、Accept or discard（接受或丢弃）
  - 区分对事vs对人：冲突聚焦于事而非人是健康协作的标志；人际攻击必须被即时制止
- 常见误区：认为坦诚=粗暴——坦诚是内容真实+形式尊重；把心理安全当作坦诚的替代——心理安全和坦诚是互补不是替代；认为反馈越多越好——反馈的质量比数量更重要

## 适用场景

### 最适合

- 知识密集型团队——产出依赖信息共享和集体智慧
- 跨职能协作团队——成员背景多元，需要频繁对齐和碰撞
- 创新导向团队——需要试错、需要承认"我不知道"、需要提出疯狂想法
- 千人以上多业务线科技公司——信息不对称是主要效率瓶颈
- 高不确定性环境——没有人掌握全部答案，团队必须共同探索

### 不适合

- 高度标准化的流水线作业——产出依赖流程而非协作
- 危机响应的短期编组——团队存续时间太短，来不及建立心理安全
- 强层级军事化组织——心理安全需要平等互动，与命令-服从模式根本冲突
- 人才密度低的组织——信息透明只会加速内耗和混乱
- 信息安全合规要求极高的行业——默认公开逻辑与合规冲突

## 检查清单

- [ ] 团队中是否存在等发言时间——是否有人主导对话、有人从不发言
- [ ] 领导者是否率先展示脆弱性——承认不知道、公开错误、邀请反对意见
- [ ] 成员提问和承认错误时是否得到正向回应——而非被忽视或嘲笑
- [ ] 冲突是否聚焦于事而非人——人际攻击是否被即时制止
- [ ] 信息是否默认公开——文档权限是否反转（默认组织内可读）
- [ ] OKR是否全员可见——包括CEO的目标和红标项
- [ ] 是否有知识库/搜索机制让历史决策可追溯
- [ ] 人才密度是否达到"善意能人"阈值——否则先解决人的问题
- [ ] 是否建立了异步优先的会议文化——能文档解决的不开会
- [ ] 坦诚是否有心理安全做前提——没有心理安全的坦诚只会制造恐惧

## 诚实边界

1. **相关不等于因果**：Project Aristotle发现心理安全与团队效能强相关，但相关不等于因果。可能是高效能团队自然发展出心理安全，也可能是心理安全导致了高效能。

2. **Google语境的局限性**：研究基于Google内部的180个团队——Google员工本身就是高学历、高自驱的群体。在人才密度较低的组织中，心理安全是否仍然是第一要素，缺乏同等规模的实证数据。

3. **人才密度是硬前提**：飞书模式的核心假设是"员工拿到信息后会做出对组织有利的决策"。如果人才密度不够，信息透明只会加速内耗和混乱。字节自己也是先有高人才密度，才敢做信息默认公开。

4. **文化不可复制**：飞书可以买，但"默认公开"的文化买不来。很多公司部署了飞书，但文档权限依然默认私密、OKR依然只对上级可见——工具变了，行为没变。

5. **信息过载风险**：大规模组织中"自由信息"的副作用是注意力碎片化。字节通过算法推荐字节圈内容来缓解，但这又引入了"谁控制推荐算法"的新问题。

6. **心理安全的度**：心理安全不等于无限包容。过度追求"安全感"可能让团队退化为互相安慰的舒适圈。Edmondson后来明确区分了"心理安全"和"舒适区"——前者是敢于冒险，后者是拒绝挑战。

7. **横切汇总的信息损失**：3个纵切文件横切为1个文件，且无直接collaboration标签的个人蒸馏文件。协作学科的横切深度受限于来源文件数量，需要后续补充。
