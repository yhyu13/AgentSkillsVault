# 华为 · LTC 从线索到回款

> 销售不是英雄的个人表演，而是铁三角协同、流程驱动、数据支撑的系统作战——从线索到现金，每一环都可追踪、可决策、可优化。

## 核心理念

LTC解决的核心问题是：B2B销售中"人治"带来的不可控。传统销售依赖个人能力和关系，业绩波动大、过程不透明、交付常失控。LTC将销售全流程结构化——用铁三角团队替代单打独斗，用决策门控替代拍脑袋，用数据驱动替代经验判断。

三大核心原则：
1. **让听得见炮声的人呼唤炮火**——一线团队有授权、有资源、能决策
2. **赢盈并重**——签单不是终点，盈利和回款才是闭环
3. **不可过度承诺**——交付能力是销售的边界，承诺超出能力=埋雷

## 框架结构

```
LTC三大阶段：

ML(管理线索)          MO(管理机会点)          MCE(管理合同执行)
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│ 收集→验证     │    │ 验证→标前引导  │    │ 交付→变更     │
│  →培育→转化   │ →  │ →投标谈判     │ →  │ →验收→回款     │
│              │    │ →合同签订     │    │ →关闭         │
│ 线索→机会点   │    │ 机会点→合同   │    │ 合同→现金     │
└──────────────┘    └──────────────┘    └──────────────┘
      ATI决策点           ATB决策点           ATC决策点
```

```
四个子流程（更细粒度拆解）：

LTO(线索→机会) ──→ OTO(机会→订单) ──→ OTD(订单→交付) ──→ DTC(交付→现金)
     ML阶段            MO阶段              MCE阶段           MCE阶段
```

```
铁三角作战单元：

         AR（客户经理/指挥官）
         ┌─────────────┐
         │ 客户关系+商务  │
         │ 主导销售节奏   │
         └──────┬──────┘
                │
    ┌───────────┼───────────┐
    │                       │
SR（解决方案经理/智囊）   FR（交付经理/保障官）
┌───────────────┐       ┌───────────────┐
│ 技术方案+竞争   │       │ 交付可行性+成本 │
│ 回答"怎么解决"  │       │ 回答"能不能交付" │
└───────────────┘       └───────────────┘

共同KPI：收入+利润+回款+客户满意度
```

## 关键模块

### 模块1：ML 管理线索

- 定义：将散落的线索收集、筛选、培育，转化为可跟进的机会点
- 输入：MTL产出的高质量线索+销售自拓线索+渠道线索
- 输出：验证通过的机会点（进入MO阶段）
- 关键动作：
  - 线索收集：多渠道汇聚（MTL/展会/客户拜访/老客户引荐）
  - 线索验证：客户有预算+有需求+有决策权+有时间表（BANT框架）
  - 线索培育：对不成熟线索持续触达，等待时机成熟
  - 线索转化：验证通过的线索升级为机会点
- 常见误区：把所有线索都当机会点——未经验证的线索进入MO阶段，浪费投标资源

### 模块2：MO 管理机会点

- 定义：从机会点验证到合同签订的全过程，是LTC中竞争最激烈的阶段
- 输入：验证通过的机会点
- 输出：签订的合同
- 关键动作：
  - 机会点验证：确认竞争态势、我方定位、赢率评估
  - 标前引导：影响客户采购标准，将竞争门槛向我方优势倾斜
  - 投标谈判：铁三角协同——AR管客户关系+SR管技术方案+FR管交付承诺
  - 合同签订：确保合同条款可执行、可盈利、可交付
- 常见误区：为了签单过度承诺——SR写进方案但FR无法交付，埋下交付失败的地雷

### 模块3：MCE 管理合同执行

- 定义：从合同签订到回款关闭的全过程，确保"签得来、交得出、收得回"
- 输入：签订的合同
- 输出：回款完成+项目关闭
- 关键动作：
  - 交付执行：按合同范围、质量、时间交付
  - 变更管理：控制范围蔓延，变更必须走审批+追加预算
  - 验收确认：客户签字确认交付成果
  - 回款管理：按合同条款催收，回款是LTC的终点
  - 项目关闭：复盘总结，沉淀经验教训
- 常见误区：签单后销售撒手不管——AR在交付阶段缺位，客户关系断裂导致回款困难

### 模块4：铁三角

- 定义：AR/SR/FR三人组成的作战单元，三人共同对项目全生命周期负责
- 输入：项目立项指令
- 输出：项目经营结果（收入+利润+回款+客户满意度）
- 关键动作：
  - AR（客户经理）：客户关系维护、商务谈判、销售节奏把控，是项目指挥官
  - SR（解决方案经理）：技术方案设计、竞争策略制定、客户技术交流，是项目智囊
  - FR（交付经理）：交付可行性评估、成本测算、交付资源调度，是项目保障官
  - 三人共享KPI，项目奖金包分配而非个人提成
- 常见误区：铁三角变成"铁一角"——AR独大，SR和FR沦为配角，方案和交付质量失控

### 模块5：关键决策点

- 定义：LTC流程中的门控机制，确保关键节点有决策、有记录、有责任
- 输入：阶段交付件+风险评估
- 输出：继续/终止/调整决策
- 关键动作：
  - ATI（Approve to Invest）：立项决策——这个机会点值不值得投入资源跟进？
  - ATB（Approve to Bid）：投标决策——要不要投这个标？赢率是否足够？
  - ATC（Approve to Contract）：签约决策——合同条款是否可接受？是否盈利？
- 常见误区：决策点变成签字仪式——没有真正的风险评估和商业论证，只是走流程

### 模块6：数字化平台 iSales

- 定义：支撑LTC流程的数字化系统，实现全流程数据化、可追踪、可分析
- 输入：全流程业务数据
- 输出：商机评分+流程效率分析+风险预警
- 关键动作：
  - 全流程数据录入（线索/机会/投标/合同/交付/回款）
  - 商机评分模型：基于历史数据预测赢率，准确率85%
  - 流程效率分析：各阶段停留时长、转化率、瓶颈识别
  - 风险预警：超期未回款、交付偏差、合同风险自动提醒
- 常见误区：系统变成负担——一线觉得录入数据是额外工作，数据质量差导致分析失真

## 决策启发式

| 场景 | 判断规则 | 来源 |
|------|---------|------|
| 线索验证 | 如果线索不满足BANT（预算/权限/需求/时间）中任意两项，则归入培育池而非直接进入MO | ML阶段实践 |
| 投标决策 | 如果赢率评估<30%且无战略价值，则ATB应否决投标，避免资源浪费 | ATB决策原则 |
| 合同条款 | 如果合同利润率低于公司红线且无战略理由，则ATC应否决签约 | 赢盈并重原则 |
| 过度承诺 | 如果SR方案中的承诺超出FR交付能力评估，则以FR评估为准 | 铁三角制衡 |
| 交付变更 | 如果客户变更请求影响合同范围>10%，则必须走变更审批+追加预算 | MCE变更管理 |
| 回款催收 | 如果回款逾期>30天，则升级至AR+FR联合催收，而非仅财务催收 | 回款管理实践 |

## 与其他方法论的关系

| 关联方法论 | 关系 | 接口 |
|-----------|------|------|
| MTL | 上游 | MTL产出高质量线索→LTC的ML阶段接收并跟进 |
| IPD | 上游 | IPD产出可销售的产品包→LTC在MO阶段基于产品包制定解决方案 |
| ITR | 下游 | LTC交付后客户问题→ITR接管售后服务 |
| ISC | 并行 | LTC签单后→ISC执行供应链交付（OTD子流程） |
| BLM/DSTE | 上游 | 战略规划确定销售目标→LTC在战略框架内执行销售 |

## 适用场景

### 最适合

- B2B大客户销售（客单价高、决策链长、交付复杂）
- 销售过程需要技术方案和交付承诺的复杂项目
- 销售团队规模大、需要标准化管理的组织
- 跨区域/跨产品线协同作战的企业

### 不适合

- C端零售/电商（消费者决策链短，LTC过重）
- 标准化产品的简单交易（不需要铁三角和复杂流程）
- 小型销售团队（<10人，流程成本高于收益）
- 纯渠道销售（厂商不直接面对终端客户）

## 实施检查清单

- [ ] 铁三角是否真正三人协同（而非AR独大）？
- [ ] 三人是否共享KPI（收入+利润+回款+客户满意度）？
- [ ] ATI/ATB/ATC是否有真实的否决记录（有没有项目被叫停过）？
- [ ] ML阶段的线索是否有BANT验证（而非所有线索直接进入MO）？
- [ ] MO阶段是否有赢率评估机制（而非每个机会都投）？
- [ ] MCE阶段AR是否持续参与（而非签单后撒手）？
- [ ] 变更管理是否有审批+追加预算机制（而非免费加需求）？
- [ ] iSales系统数据质量是否可靠（一线是否认真录入）？
- [ ] 代表处是否有授权范围内的自主决策权（而非事事上报）？

## 诚实边界

1. **组织前提**：铁三角有效运作的前提是三人能力对等、权力制衡。如果AR独大或FR话语权弱，铁三角就退化为"AR+两个助手"。
2. **授权边界**："让听得见炮声的人呼唤炮火"需要真实的授权。华为代表处有合同金额30%以内的自主决策权，很多企业学铁三角但不给授权，一线仍然事事请示。
3. **数据基础**：iSales系统依赖高质量数据。2800万条流程数据是华为多年积累的结果，新系统数据冷启动阶段分析能力有限。
4. **知识盲区**：本文件基于公开资料整理，不包含华为LTC的授权矩阵细节、iSales系统架构和行业适配方案。
5. **变革周期**：华为2008年启动LTC变革，联合埃森哲，历经近十年打磨。这不是一个可以速成的项目。
