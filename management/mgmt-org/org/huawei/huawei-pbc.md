# 华为 · PBC个人绩效承诺

> 用承诺而非指标驱动个体与战略对齐的全周期绩效管理方法

## 核心理念

PBC解决的核心问题：如何让每个人的工作目标与组织战略保持动态一致？

传统绩效管理的痛点是"定指标→年底打分"的割裂模式——年初定完就束之高阁，年底打分全凭印象。PBC的解法是把绩效从"结果考核"变成"承诺管理"：员工不是被动接受指标，而是主动承诺要达成什么成果、用什么路径、带什么团队。承诺一旦做出，全周期跟踪、季度回顾、动态调整，直到年底闭环。

核心思想可以概括为三点：
1. **承诺型而非标准型**：目标不是从岗位说明书里抄出来的标准答案，而是基于战略解码后个人主动承诺的挑战性目标
2. **三维一体**：业务成果、执行过程、团队能力三者缺一不可，避免"只看结果不看过程"或"只看个人不看团队"
3. **强关联薪酬**：绩效结果直接挂钩奖金和晋升，不是参考意见而是决定性输入

## 关键模块

### 模块1：Win——业务目标承诺

- 定义：个人对业务成果的承诺，是PBC的权重主体（60-80%）
- 输入：BEM战略解码→部门KPI→个人承接的关键任务
- 输出：3-5条可衡量的业务承诺，每条含目标值、完成标准、时间节点
- 关键动作：
  - 从部门KPI中识别个人可影响的指标
  - 区分"承诺型目标"（必须达成）和"挑战型目标"（争取达成）
  - 每条承诺必须有量化衡量标准
- 常见误区：把Win写成岗位职责描述而非承诺；目标过于保守或过于激进

### 模块2：Execute——执行路径与管理协作

- 定义：达成Win承诺所需的执行方式、管理动作和跨部门协作承诺
- 输入：Win承诺拆解后的关键路径、跨部门依赖关系
- 输出：流程改进承诺、协作承诺、管理改进承诺
- 关键动作：
  - 识别Win达成过程中的关键障碍和依赖
  - 明确需要哪些跨部门协作及协作方式
  - 管理者需承诺团队管理改进动作
- 常见误区：Execute写成日常事务清单；与Win缺乏因果逻辑

### 模块3：Team——能力发展与团队建设

- 定义：支撑Win和Execute持续达成的能力建设承诺
- 输入：岗位能力模型、团队短板分析
- 输出：个人学习承诺、团队培养承诺、知识沉淀承诺
- 关键动作：
  - 识别Win达成所需但当前缺失的能力
  - 制定具体的学习/培养计划（非泛泛的"加强学习"）
  - 管理者需承诺下属培养和梯队建设
- 常见误区：Team写成"读书计划"；与业务目标脱节

### 模块4：六大制定原则

- 定义：PBC制定时必须遵守的约束条件
- 六条原则及其含义：

| 原则 | 含义 | 反模式 |
|------|------|--------|
| 双向沟通 | 上下级共同讨论确定，非单向下达 | 上级直接发目标邮件 |
| 挑战性 | 目标需跳一跳够得着 | 目标=去年实际×1.05 |
| 对齐性 | 个人→部门→公司战略逐级对齐 | 各自为战，目标打架 |
| 可衡量 | 每条承诺有明确的完成标准 | "提升团队能力" |
| 责任唯一 | 每条承诺有且仅有一个责任人 | "共同负责" |
| 动态调整 | 环境变化可申请调整，但需走流程 | 年初定完不改，年底硬评 |

### 模块5：全周期管理

- 定义：PBC不是年初定年底评，而是贯穿全年的动态管理过程
- 输入：季度经营数据、项目进展、外部环境变化
- 输出：季度回顾结论、PBC调整建议、年度绩效等级
- 关键动作：
  - 季度回顾：上级与下属面对面复盘Win/Execute/Team进展
  - 中期调整：环境重大变化时允许修改PBC，但需重新沟通确认
  - 年度评估：基于承诺完成度打分，而非绝对业绩水平
- 常见误区：季度回顾流于形式；中期不敢调整PBC导致年底"背锅"

### 模块6：强制分布与结果应用

- 定义：绩效结果按比例强制分布，直接挂钩薪酬和职业发展
- 输入：年度PBC评估得分
- 输出：绩效等级（A/B/C/D/E）及对应奖金额度、晋升资格
- 关键动作：
  - A级≤20%，给予超额奖金和优先晋升
  - E级约5%，进入绩效改进计划或末位淘汰
  - 绩效结果直接决定奖金包分配，不是参考意见
- 常见误区：主管搞平均主义给全员B+；末位淘汰执行不坚决

## 决策启发式

| 场景 | 判断规则 | 来源 |
|------|---------|------|
| 目标设定时 | 如果目标不需要跳一跳就能达成，则目标太低，需上调 | PBC挑战性原则 |
| Win权重分配 | 如果管理者岗位，Win占60%；如果专家岗位，Win可到80% | 华为实践 |
| 季度回顾发现目标偏离 | 如果偏离因外部环境变化，则启动PBC调整；如果因执行不力，则不调整目标而加强执行 | PBC动态调整原则 |
| 团队绩效整体偏低 | 如果全员都未达成Win，先检查目标设定是否合理，再检查执行 | 华为绩效校准机制 |
| 末位淘汰对象选择 | 如果连续两次E级，则进入淘汰流程；如果首次E级但有改进意愿，则给PIP机会 | 华为末位淘汰实践 |
| PBC与OKR选择 | 如果需要强薪酬关联+承诺型目标，选PBC；如果需要鼓励冒险+挑战型目标，选OKR | PBC/OKR对比 |
| 个人与团队目标冲突 | 如果个人Win达成但Team承诺未完成，则绩效不超过B | PBC三维一体原则 |

## 与其他方法论的关系

| 关联方法论 | 关系 | 接口 |
|-----------|------|------|
| BEM | 上游 | BEM第六步输出PBC，BEM解码的KPI→PBC的Win承诺 |
| DSTE | 上游 | DSTE年度BP阶段→BEM解码→PBC制定 |
| KPI | 对比参照 | KPI是标准型指标考核，PBC是承诺型全周期管理；KPI关注"考什么"，PBC关注"承诺什么+怎么达成" |
| OKR | 对比参照 | OKR是挑战型+弱薪酬关联，PBC是承诺型+强薪酬关联；OKR鼓励冒险，PBC强调兑现 |
| BLM | 间接上游 | BLM输出战略→DSTE→BEM→PBC |
| 干部管理 | 下游 | PBC绩效结果是干部选拔/淘汰的输入 |
| 科学分钱 | 下游 | PBC绩效等级决定奖金分配比例 |

## 适用场景

### 最适合

- 中大型企业（100人以上），战略解码链条清晰
- 业务目标可量化、可分解的行业（制造、通信、互联网）
- 需要强执行力+强薪酬驱动的组织文化
- 管理者有意愿和能力做季度回顾的组织
- 已有BLM/BEM等战略解码体系的企业

### 不适合

- 10人以下初创团队（沟通成本高于管理收益）
- 创意型/探索型工作占主导的团队（更适合OKR）
- 管理者不愿做绩效沟通的组织（PBC会沦为形式）
- 没有战略解码体系直接上PBC（Win承诺缺乏上游输入）

## 实施检查清单

- [ ] 是否已建立战略解码体系（BEM或等效），PBC的Win有上游输入
- [ ] 是否定义了三维结构的权重比例（Win/Execute/Team）
- [ ] 是否建立了双向沟通机制（PBC制定必须上下级面谈）
- [ ] 是否建立了季度回顾制度（非年底一次性打分）
- [ ] 是否建立了PBC动态调整流程（什么情况可以改、怎么改）
- [ ] 是否定义了强制分布比例和结果应用规则
- [ ] 是否建立了绩效校准机制（跨部门拉齐标准）
- [ ] 是否培训了管理者PBC制定和回顾的面谈技能
- [ ] 是否建立了末位淘汰的配套机制（PIP、转岗、补偿）

## 诚实边界

1. **PBC不是万能的**：如果组织没有清晰的战略方向，PBC的Win承诺就成了无源之水
2. **强制分布有代价**：末位淘汰在人才市场紧俏时可能造成优秀人才流失（怕被误判而主动离开）
3. **承诺型目标的局限**：承诺型目标天然偏保守（承诺了就要兑现），不适合需要大量试错的创新业务
4. **沟通成本高**：双向沟通+季度回顾+动态调整，对管理者时间投入要求很高
5. **文化前提**：PBC有效运行需要"以奋斗者为本"的文化土壤，在"以和谐为本"的组织中会变形
6. **公开资料局限**：华为PBC的完整操作细则（如校准会议流程、PIP具体方案）未公开，本文基于公开资料推断
