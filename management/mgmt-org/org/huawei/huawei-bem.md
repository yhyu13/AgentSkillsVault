# 华为 · BEM 业务执行力模型

> 将战略意图逐层解码为可衡量、可追踪、可考核的执行闭环，终结"战略空转"。

## 核心理念

BEM要解决的根本问题是：战略规划与个人行动之间的断层。BLM解决了"想明白"，但"做到位"需要另一套机制——将抽象的战略意图逐层翻译为具体的KPI、重点工作和个人承诺。BEM的核心主张是：战略必须经过结构化解码，否则就是口号。

BEM从三星引进后融入六西格玛的CTQ（Critical to Quality）分解逻辑，使得战略解码不是简单的目标拆分，而是基于关键成功因素的系统性展开。其独特价值在于"三次解码"机制：SP阶段解码→BP阶段解码→部门PBC解码，确保战略从公司层到个人层的逐层穿透。

## 关键模块

### 模块1：明确战略方向

- 定义：将BLM输出的业务设计转化为可操作的战略方向描述
- 输入：BLM业务设计蓝图 + SP报告
- 输出：3-5条战略方向陈述（每条可衡量、可追踪）
- 关键动作：战略方向必须满足SMART原则；一条战略方向对应一个战略主题
- 常见误区：战略方向仍然是愿景式描述（如"成为行业领先"），而非可操作的方向（如"在X细分市场实现Y%份额"）

### 模块2：导出CSF（关键成功因素）

- 定义：识别实现战略方向必须具备的少数关键成功因素
- 输入：战略方向陈述
- 输出：每个战略方向对应的2-4个CSF
- 关键动作：CSF是"如果这个因素不具备，战略方向就无法实现"的必要条件；用鱼骨图或逻辑树从战略方向向下推导
- 常见误区：CSF太多（超过4个说明没有抓住关键）；CSF描述是活动而非因素

### 模块3：导出战略KPI

- 定义：将CSF转化为可量化的绩效指标
- 输入：CSF清单
- 输出：战略KPI集（每个CSF对应1-3个KPI）
- 关键动作：KPI必须可衡量、可追踪、有基准值和目标值；区分领先指标（预测性）和滞后指标（结果性），两者都要有
- 常见误区：只有滞后指标没有领先指标；KPI与CSF的因果关系不明确

### 模块4：CTQ分解（关键质量特性分解）

- 定义：运用六西格玛的CTQ方法，将战略KPI逐层分解为可操作的子指标
- 输入：战略KPI集
- 输出：CTQ树（KPI→子指标→可操作要素）
- 关键动作：每一层分解都要验证因果关系——"如果子指标达成，上层指标是否必然改善？"；分解到可直接行动的颗粒度
- 常见误区：分解层级过深（超过4层失去可操作性）或过浅（停留在KPI层面无法行动）；分解时丢失因果关系

### 模块5：重点工作

- 定义：将CTQ分解结果转化为年度重点工作和项目
- 输入：CTQ树
- 输出：年度重点工作清单 + 责任人 + 里程碑 + 资源需求
- 关键动作：重点工作必须对应CTQ中的可操作要素；每项工作有唯一责任人；跨部门工作需要明确主责和协责
- 常见误区：重点工作与CTQ脱节（变成日常工作清单）；责任人模糊（多个部门"共同负责"等于无人负责）

### 模块6：PBC（个人绩效承诺）

- 定义：将重点工作落实到个人的绩效承诺
- 输入：年度重点工作清单 + 部门KPI
- 输出：个人PBC（Win + Execute + Team 三部分）
- 关键动作：
  - Win（成果目标，60-80%权重）：直接承接战略KPI和重点工作
  - Execute（执行路径，10-20%权重）：关键行动举措和里程碑
  - Team（协作机制，10-20%权重）：跨部门协作承诺和能力发展
- 常见误区：PBC的Win部分与战略KPI无关联；Team部分变成空洞的"加强沟通"

### 模块7：三次战略解码

- 定义：BEM不是一次性动作，而是在DSTE流程中分三次逐层解码
- 输入：SP报告 → BP要求 → 部门目标
- 输出：三次解码的穿透链路
- 关键动作：
  - 第一次解码（SP阶段）：公司战略→业务单元战略方向+CSF，解决"方向对齐"
  - 第二次解码（BP阶段）：业务单元CSF→部门KPI+重点工作，解决"目标量化"
  - 第三次解码（部门PBC）：部门KPI→个人PBC，解决"责任到人"
- 常见误区：三次解码变成一次分解（直接从公司目标跳到个人KPI）；中间层解码缺失导致上下脱节

### 模块8：经营分析会（执行闭环的核心机制）

- 定义：月度经营分析会是BEM解码结果的跟踪和纠偏机制
- 输入：KPI达成数据 + 重点工作进展 + 问题清单
- 输出：纠偏措施 + 问题闭环跟踪
- 关键动作：
  - 三层结构：经营结果分析（KPI达成率）→ 重点任务进展（里程碑完成度）→ 问题闭环跟踪（上次问题的解决状态）
  - 核心原则：不打招呼、不搞形式、直击问题、闭环管理
- 常见误区：经营分析会变成汇报会（只报好消息）；问题提了但无闭环跟踪；只看结果不看过程

### 模块9：四大分解原则

- 定义：BEM战略解码必须遵循的四个原则
- 输入：战略KPI和重点工作
- 输出：符合原则的分解方案
- 关键动作：
  - 垂直分解：从公司→业务单元→部门→个人，上下贯通，每层可追溯
  - 横向协同：跨部门KPI和重点工作必须对齐，避免部门墙
  - 均衡考虑：财务指标与非财务指标、短期与长期、领先与滞后指标均衡配置
  - 责任分解矩阵：每项重点工作用RACI矩阵明确主责(R)/协责(A)/咨询(C)/知会(I)
- 常见误区：只做垂直分解忽略横向协同；财务指标一统天下；RACI矩阵流于形式

## 决策启发式

| 场景 | 判断规则 | 来源 |
|------|---------|------|
| 导出CSF时 | 如果CSF超过4个/战略方向，说明没有区分"必要"和"重要" | BEM操作规范 |
| 设定KPI时 | 如果KPI只有滞后指标（如收入、利润），必须补充领先指标（如客户满意度、管线数量） | 六西格玛CTQ逻辑 |
| CTQ分解时 | 如果分解超过4层仍无法行动，回到上层重新定义CTQ | 六西格玛实践 |
| 确定重点工作时 | 如果重点工作与CTQ无法建立因果关系，说明这不是战略重点工作而是日常工作 | BEM框架逻辑 |
| 落实PBC时 | 如果Win部分权重低于60%，说明个人承诺被管理事务稀释 | 华为PBC实践 |
| 三次解码时 | 如果第二次解码（BP阶段）跳过CSF直接分KPI，解码质量会显著下降 | 华为实践 |
| 横向协同时 | 如果两个部门的KPI存在冲突（如销售要增速、风控要控险），必须在BP阶段显式对齐 | BEM四大原则 |
| 经营分析会时 | 如果会议超过2小时，说明准备不足或议题发散 | 华为实践 |
| 问题闭环时 | 如果同一问题连续3次出现在经营分析会上，说明闭环机制失效，需要升级处理 | 华为实践 |
| 责任分解时 | 如果一项重点工作有2个以上R（主责），等于没有主责 | RACI原则 |

## 与其他方法论的关系

| 关联方法论 | 关系 | 接口 |
|-----------|------|------|
| BLM | 上游 | BLM输出业务设计蓝图和战略意图，BEM接收后进行战略解码；BLM管"想明白"，BEM管"做到位" |
| DSTE | 母框架 | BEM是DSTE中BP制定阶段的核心工具；BEM输出BP+KPI+PBC，DSTE管理全流程闭环 |
| PBC | 直接下游 | BEM第六步输出PBC，PBC是BEM解码的最终落地载体 |
| 六西格玛 | 方法来源 | BEM的CTQ分解方法来自六西格玛；CTQ树是六西格玛中从Y（结果）到X（因素）的分解工具 |
| BSC | 互补 | BSC提供战略地图的因果链可视化，BEM提供更结构化的解码和闭环机制；BSC偏展示，BEM偏执行 |
| OKR | 替代/互补 | OKR适合创新业务的挑战性目标管理，BEM/PBC适合成熟业务的承诺性目标管理；两者可并行使用 |
| IPD | 并行 | BEM解码出的产品方向KPI→IPD的Charter开发；BEM确定"做什么"，IPD解决"怎么做" |
| 经营分析会 | 执行机制 | 经营分析会是BEM解码结果的月度跟踪和纠偏机制，属于DSTE执行监控阶段 |

## 适用场景

### 最适合

- 中大型企业将年度战略规划（BP）解码为可执行的KPI和重点工作
- 战略规划与个人绩效脱节，需要"力出一孔"的组织
- 跨部门协同要求高的复杂业务（如多产品线、多区域）
- 需要月度跟踪和纠偏的持续经营场景

### 不适合

- 初创企业（战略方向尚未稳定，不适合做结构化解码）
- 单一业务线的小团队（解码成本高于收益）
- 纯探索性/创新性业务（BEM的承诺型机制与探索的不确定性冲突，OKR更合适）
- 临时性项目（用项目管理工具更直接）

## 实施检查清单

- [ ] 战略方向已从BLM业务设计中导出，每条可衡量
- [ ] 每个战略方向已识别2-4个CSF，且满足"必要条件"标准
- [ ] 每个CSF已设定1-3个战略KPI，包含领先指标和滞后指标
- [ ] CTQ分解已完成，因果关系已验证，分解深度不超过4层
- [ ] 年度重点工作已从CTQ导出，每项有唯一主责人
- [ ] 个人PBC已制定，Win部分权重≥60%，且与战略KPI直接关联
- [ ] 三次解码已完成：SP→BP→PBC逐层穿透，无跳层
- [ ] 垂直分解已验证：个人PBC可追溯到公司战略方向
- [ ] 横向协同已对齐：跨部门KPI冲突已显式解决
- [ ] RACI矩阵已完成：每项重点工作有且仅有一个R
- [ ] 经营分析会机制已建立：月度召开，三层结构，问题闭环
- [ ] 均衡性已检查：财务/非财务、短期/长期、领先/滞后指标均衡配置

## 诚实边界

1. **解码质量取决于战略质量**：BEM是解码工具，不是战略工具。如果BLM输出的战略方向本身有问题，BEM只会高效地执行一个错误的方向。
2. **六西格玛假设的局限**：CTQ分解假设因果关系可被结构化识别，但在高度不确定的创新业务中，因果关系往往是模糊的，CTQ分解可能产生虚假的精确感。
3. **承诺型机制的刚性**：PBC是承诺型机制，一旦承诺就很难调整。在快速变化的环境中，这种刚性可能成为障碍。华为通过经营分析会的纠偏机制部分缓解了这个问题，但根本矛盾仍在。
4. **组织成熟度要求高**：BEM的有效运转需要组织具备数据基础（KPI可衡量）、管理基础（经营分析会可执行）、文化基础（承诺必须兑现）。缺乏这些基础的组织，BEM容易沦为形式主义。
5. **PBC与创新的张力**：PBC的承诺型机制天然倾向于保守——人们会承诺"大概率能做到的事"而非"需要冒险才能做到的事"。在需要突破性创新的场景中，OKR的挑战性目标机制可能更合适。
6. **时间与资源成本**：一次完整的BEM解码周期（BP制定）通常需要2-3个月，加上每月经营分析会的持续投入，对中小组织是显著的管理成本。
