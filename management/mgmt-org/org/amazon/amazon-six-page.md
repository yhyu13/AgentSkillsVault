# Amazon · 6页纸备忘录

> 用叙述体长文替代PPT，强制作者把逻辑写透，让读者在安静中完成深度思考，再进入讨论。

## 核心理念

6页纸备忘录要解决的根本问题是：**会议中的浅层思考与信息失真。**

PPT天然鼓励碎片化表达——要点罗列、关键词堆砌、逻辑跳跃靠演讲者口头补全。这导致三个后果：信息密度低（一页PPT能承载的实质内容极少）、依赖演讲技巧（同一个PPT，口才好的人讲和口才差的人讲效果天差地别）、逻辑不连贯（幻灯片之间的因果链靠听众脑补）。贝索斯在2004年做出一个激进决定：高管会议全面禁止PPT，改用6页叙述体备忘录。

这个决定的底层逻辑是：**写作是思考的强制函数。** 你无法用模糊的措辞糊弄一篇连贯的叙述文——要么逻辑通了，要么写不下去。PPT允许你用bullet point掩盖思维的漏洞，但备忘录不允许。Edward Tufte的信息设计思想对贝索斯有直接影响——Tufte长期批评PPT降低信息分辨率，主张用高密度叙述体传递复杂信息。

6页纸的核心主张：一份好的备忘录应该可以独立阅读、独立成立，读者不需要作者在场讲解也能完整理解论证。这意味着作者必须在文档内部完成所有逻辑闭环，不能依赖"我到时候再解释"。

## 框架结构

```
6页纸备忘录 = 深度思考的强制函数
│
├── 前提：禁止PPT（2004年贝索斯禁令）
│   ├── PPT局限1：信息密度低 → 关键词≠论证
│   ├── PPT局限2：依赖演讲技巧 → 好口才≠好逻辑
│   └── PPT局限3：逻辑不连贯 → 幻灯片间因果链断裂
│
├── 备忘录要求
│   ├── 叙述体：完整句子、完整段落、完整论证
│   ├── 完整逻辑链：前提→推理→结论，每一步可见
│   ├── 数据支撑：观点必须附数据，不接受"我认为"
│   └── 可独立阅读：读者不需要作者在场
│
├── 会议流程（逆向设计）
│   ├── 前30分钟：全员安静阅读备忘录
│   ├── 阅读后：自由讨论与质疑
│   └── 作者：回答问题，接受挑战
│
├── 写作成本
│   └── 写好一份备忘录需要1-2周
│
└── 思想来源
    └── Edward Tufte：信息设计，反PPT，高密度叙述体
```

## 关键模块

### 模块1：叙述体写作

- 定义：用完整的句子和段落构建论证，而非bullet point罗列
- 输入：待决策的问题+相关数据+论证逻辑
- 输出：一篇6页左右的连贯叙述文
- 关键动作：
  - 每个观点必须用完整句子表达，不能用短语代替论证
  - 段落之间有明确的逻辑过渡，读者不需要猜测上下文关系
  - 结论必须从前提推导而出，不能跳跃
- 常见误区：把叙述体写成"加长版PPT"——每段一个要点，段落间无因果链，本质上还是bullet point思维

### 模块2：数据支撑

- 定义：每个关键论断必须附带可验证的数据，不接受无依据的判断
- 输入：业务数据、市场研究、用户反馈、财务模型
- 输出：每个论断都有数据锚点的论证文档
- 关键动作：
  - 区分"事实"和"推断"——事实附数据源，推断附推理过程
  - 关键数字必须可追溯，标注数据来源和口径
  - 用数据回答"为什么"而非仅回答"是什么"
- 常见误区：堆砌数据不做解读——数据本身不是论证，数据+解读才是论证

### 模块3：安静阅读机制

- 定义：会议前30分钟全员安静阅读备忘录，不讨论、不讲解
- 输入：6页纸备忘录
- 输出：所有参会者对同一份文档的独立理解
- 关键动作：
  - 阅读期间禁止交谈，确保每个人独立消化内容
  - 参会者可以在文档上标注问题和批注
  - 30分钟后进入讨论，基于各自的阅读理解展开
- 常见误区：跳过安静阅读直接讨论——这会让会议退化为"作者讲PPT"的模式

### 模块4：作者责任制

- 定义：备忘录的作者是讨论的核心责任人，必须回答所有质疑
- 输入：参会者的提问和挑战
- 输出：当场回应或承诺后续补充
- 关键动作：
  - 作者必须在场接受挑战，不能"写完就跑"
  - 面对无法当场回答的问题，必须承诺跟进时间和方式
  - 作者的回应质量直接反映备忘录的思考深度
- 常见误区：作者把备忘录当"交作业"——写完就不再关心后续讨论

### 模块5：1-2周写作周期

- 定义：一份高质量的6页纸备忘录通常需要1-2周完成
- 输入：问题定义+数据收集+多轮修改
- 输出：经过反复打磨的论证文档
- 关键动作：
  - 第一稿完成后必须放一放，隔天再读，发现逻辑漏洞
  - 找同事做"友好读者"提前审阅，指出不清晰之处
  - 数据核实和口径统一往往占写作时间的40%以上
- 常见误区：把备忘录当"6页的周报"来写——1-2天赶出来的备忘录和1-2周打磨出来的备忘录，质量差距是数量级的

## 决策启发式

| 场景 | 判断规则 | 来源 |
|------|---------|------|
| 选择会议文档形式 | 如果决策涉及复杂因果链→用备忘录；如果只是信息同步→PPT或口头即可 | Amazon实践 |
| 评估备忘录质量 | 如果读者不需要作者在场也能完整理解论证→合格；否则→不合格 | 6页纸核心要求 |
| 判断写作是否完成 | 如果还有"到时候再解释"的念头→说明逻辑还没写透 | 叙述体写作原则 |
| 会议时间分配 | 如果讨论时间<阅读时间→说明阅读不充分或问题太浅 | Amazon会议流程 |
| 面对质疑时 | 如果无法当场回答→承诺跟进，不要现场编造 | 作者责任制 |
| 写作周期规划 | 如果决策重要性高→预留2周；一般决策→至少1周 | Amazon实践 |

## 与其他方法论的关系

| 关联方法论 | 关系 | 接口 |
|-----------|------|------|
| 华为"胶片文化" | 对比 | 华为PPT偏汇报型（向上汇报、信息同步），Amazon备忘录偏思考型（向下深挖、逻辑论证）；华为胶片服务于层级沟通，Amazon备忘录服务于集体决策 |
| 字节"飞书文档" | 对比 | 字节偏实时协同编辑（多人同时在线修改），Amazon偏深度个人写作（一人主笔、反复打磨）；飞书文档追求速度和共识，6页纸追求深度和严谨 |
| Working Backwards PR/FAQ | 上游 | PR/FAQ是产品决策的6页纸变体，6页纸是通用决策的叙述体格式 |
| Edward Tufte信息设计 | 思想来源 | Tufte批评PPT降低信息分辨率，主张高密度叙述体；贝索斯受此影响推行6页纸 |
| Amazon Leadership Principles | 文化底座 | "Dive Deep"和"Have Backbone"是6页纸的文化前提——没有深度思考的习惯和敢于挑战的氛围，备忘录会退化为形式 |

## 适用场景

### 最适合

- 高管层面对重大决策的深度讨论（战略方向、大额投资、组织调整）
- 需要多方对齐复杂逻辑的跨团队决策
- 论证链条长、数据支撑要求高的技术/商业决策
- 组织文化鼓励挑战和质疑，而非层级服从

### 不适合

- 快速信息同步（周报、站会、进度更新）——用PPT或口头更高效
- 紧急决策（来不及写1-2周备忘录的场景）
- 执行层面的操作性问题（不需要深度论证，需要快速行动）
- 文化不匹配的组织——如果下属不敢质疑上级，6页纸讨论会退化为"领导定调、大家附和"

## 实施检查清单

- [ ] 备忘录是否用叙述体写成（完整句子、完整段落、完整论证）
- [ ] 每个关键论断是否有数据支撑
- [ ] 读者是否可以不依赖作者讲解独立理解全文
- [ ] 是否预留了1-2周的写作周期
- [ ] 会议是否安排了前30分钟安静阅读时间
- [ ] 参会者是否在阅读后才有充分讨论
- [ ] 作者是否在场接受挑战并回答质疑
- [ ] 是否区分了事实（附数据源）和推断（附推理过程）
- [ ] 是否有同事提前审阅过初稿
- [ ] 文档长度是否控制在6页左右（过长说明聚焦不够，过短说明深度不够）

## 诚实边界

1. **写作成本高**：1-2周的写作周期意味着6页纸不适合高频决策场景。如果每个决策都要写6页纸，组织会陷入"写作瘫痪"。Amazon能推行是因为它只用于S-Team等高层决策场景，不是所有会议都要求6页纸。

2. **对写作能力的强依赖**：6页纸的有效性高度依赖作者的写作能力和逻辑思维。写作能力弱的人写出的备忘录，可能比PPT更难理解——冗长的叙述比清晰的bullet point更让人迷失。

3. **安静阅读的文化前提**：30分钟安静阅读要求参会者有足够的专注力和阅读能力。在注意力碎片化的环境中，这个前提越来越难满足。

4. **与华为胶片文化的对比局限**：华为PPT偏汇报型、Amazon备忘录偏思考型，这个对比成立的前提是"典型场景"。实际上华为也有深度分析文档，Amazon也有简短同步——两种形式在不同场景下各有价值，不是非此即彼。

5. **与飞书文档的协同差异**：字节飞书文档的实时协同编辑适合快速迭代和集体共识构建，Amazon备忘录的深度个人写作适合严谨论证和独立思考。两种模式解决的是不同问题，不能简单说谁优谁劣。

6. **Edward Tufte影响的边界**：Tufte对PPT的批评主要针对低信息密度的问题，但PPT本身不是问题根源——浅层思考才是。6页纸是治标（强制深度思考），但如果没有"Dive Deep"的文化底座，6页纸也会退化为形式主义的"6页废话"。
