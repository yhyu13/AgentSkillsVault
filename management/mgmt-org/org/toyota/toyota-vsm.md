# 丰田 · 价值流图VSM

> 看见全貌——从原材料到交付，识别每一处浪费

## 核心理念

VSM解决的问题是：为什么局部优化往往导致全局劣化？答案——因为你只看到了流程的一个片段，没有看到全貌。VSM（Value Stream Mapping，价值流图）让你画出从原材料到产品交付给客户的完整流程，然后在图上标注每一个步骤是增值的还是非增值的。结果往往令人震惊：一个需要30天交付的产品，真正增值的时间可能只有2小时，其余全是等待、搬运、检查。VSM不是画图，是看见——看见浪费在哪里，看见改善的杠杆点在哪里。

## 框架结构

```
VSM三步法
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  第一步       │     │  第二步       │     │  第三步       │
│  绘制现状图   │ ──→ │  设计未来图   │ ──→ │  实施改善     │
│              │     │              │     │              │
│  · 走完全流程 │     │  · 消除浪费   │     │  · 制定计划   │
│  · 记录每个   │     │  · 建立连续流 │     │  · 逐步实施   │
│    步骤的数据 │     │  · 实施拉动   │     │  · 验证效果   │
│  · 标注增值/  │     │  · 设定目标   │     │  · 绘制下一轮 │
│    非增值     │     │              │     │    未来图     │
└──────────────┘     └──────────────┘     └──────────────┘

VSM图上的关键数据：
每个工序：C/T（周期时间）| C/O（换模时间）| 可用时间 | 正品率
工序间：库存量 | 等待时间
信息流：订单下达方式 | 生产计划方式
```

## 关键模块

### 模块1：绘制现状图

- 定义：画出当前流程的真实状态，基于现场观察而非想象
- 输入：现场走查、数据收集
- 输出：现状价值流图（包含所有步骤、数据、信息流）
- 关键动作：从客户端开始逆流而上画；亲临现场收集数据（不用旧数据）；记录每个工序的周期时间、换模时间、库存量、等待时间；画出信息流（订单如何传递）
- 常见误区：坐在办公室凭记忆画图；只画物料流不画信息流；用理想数据而非真实数据

### 模块2：识别增值与非增值

- 定义：判断每个步骤是否创造客户愿意付费的价值
- 输入：现状图上的每个步骤
- 输出：增值/非增值分类+浪费清单
- 关键动作：三个标准——客户是否愿意付费？步骤是否物理改变产品？是否第一次就做对了？计算增值时间占比（增值时间/总交付周期）；识别七大浪费在图上的位置
- 常见误区：把"必要的非增值"（如合规检查）当作增值；只关注增值时间，忽视必要的非增值时间

### 模块3：设计未来图

- 定义：在现状图基础上设计消除浪费后的未来流程
- 输入：现状图+浪费清单
- 输出：未来价值流图（1-3年目标状态）
- 关键动作：消除不增值的步骤；建立连续流（消除工序间等待）；实施拉动式生产（看板）；均衡化排程；设定改善目标（如交付周期从30天缩短到5天）
- 常见误区：一次设计太多改变，不切实际；未来图没有具体数据支撑

### 模块4：实施改善

- 定义：从现状到未来的实施路径
- 输入：未来图+改善优先级
- 输出：改善实施计划+验证结果
- 关键动作：按优先级排序改善项目；每个改善项目用A3格式管理；实施后验证效果；绘制新一轮现状图，进入下一个循环
- 常见误区：画完图就结束，不执行改善；改善没有优先级，眉毛胡子一把抓

## 决策启发式

| 场景 | 判断规则 | 来源 |
|------|---------|------|
| 局部优化但全局未改善 | 画VSM看全貌，找到真正的瓶颈 | VSM核心逻辑 |
| 不确定改善优先级 | 先消除瓶颈工序前的库存和等待 | TOC+VSM |
| 增值时间占比极低 | 正常——大多数时间是非增值的，逐个消除 | VSM实践 |
| 想直接画未来图 | 必须先画现状图，否则不知道从哪里改善 | VSM三步法 |
| 现状图太复杂 | 从一个产品族开始，不要试图一次画全厂 | VSM范围原则 |
| 改善后效果不明显 | 重新画现状图，检查改善是否真正落地 | VSM循环 |

| 关联方法论 | 关系 | 接口 |

| TPS精益生产 | 分析工具 | VSM是TPS现状诊断和未来设计的方法 |

| TOC约束理论 | 互补 | TOC找瓶颈，VSM画全貌，两者结合更有效 |

## 适用场景

### 最适合

- 从原材料到交付有明确物理流程的制造场景
- 交付周期长但增值时间短的流程
- 局部优化但全局未改善的组织
- 精益转型的起点——先画图再行动

### 不适合

- 纯知识工作流程（VSM需要适配，信息流比物流更抽象）
- 流程极短、步骤极少的场景（VSM价值有限）
- 高度定制化的一次性项目（无重复流程可画）
- 尚未定义产品族的复杂工厂（需要先做产品族分析）

## 实施检查清单

- [ ] 是否从客户端开始逆流而上画现状图
- [ ] 是否亲临现场收集数据（非凭记忆）
- [ ] 是否同时画了物料流和信息流
- [ ] 是否计算了增值时间占比
- [ ] 是否识别了七大浪费在图上的位置
- [ ] 是否基于现状图设计了未来图
- [ ] 未来图是否有具体数据目标
- [ ] 是否制定了从现状到未来的实施计划
- [ ] 实施后是否重新画现状图验证

## 诚实边界

1. VSM是诊断工具不是治疗工具——画完图不等于问题解决了
2. 现状图的准确性取决于现场观察的深度——走马观花的VSM不如不画
3. VSM主要针对物理流程，知识工作需要大幅适配
4. 未来图容易画得过于理想，实施时需要务实分期
5. VSM是一次性快照，流程在持续变化，需要定期重画
6. 选择哪个产品族画VSM是关键决策——选错了产品族，改善方向就偏了
