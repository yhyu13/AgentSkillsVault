# 字节跳动 · 内部赛马+动态韧性

> 赛马不是内斗，是用竞争替代审批——让数据当裁判，让市场选赢家。动态韧性不是口号，是一套制度化反熵增的组织工程。

## 核心理念

内部赛马+动态韧性解决的核心问题是：**如何在组织规模扩张后，依然保持创业公司的创新速度和活力？**

大多数组织的命运是：规模带来效率，效率带来利润，利润带来舒适，舒适带来僵化，僵化带来衰亡——这就是组织熵增。字节跳动的回答是：用制度化的竞争和流动对抗熵增。

赛马机制的本质是"用竞争替代审批"——不需要上级判断哪个方向对，让多个团队并行探索，由数据决定胜负。动态韧性的本质是"把公司当产品来迭代"——CEO是公司这个产品的产品经理，组织架构本身就是持续A/B测试的对象。

## 框架结构

```
内部赛马 + 动态韧性 = 反熵增组织系统
│
├── 赛马引擎（创新压强）
│   ├── 并行竞争：多个团队同时开发同类产品，数据决定胜负
│   ├── 资源分配：胜者获得资源倾斜，败者快速转向或合并
│   └── 决策权下放：创业单元拥有人事/预算/合规三权
│
├── 流动系统（人才循环）
│   ├── 35%内外部流动率：制造创新压强+打破部门墙
│   ├── 2.9年中位在职时长：沉淀知识资产+形成复利效应
│   └── 60%校招生2年内晋升：年轻人快速承担核心职责
│
├── 韧性架构（组织形态）
│   ├── 217个创业单元：每单元<150人（邓巴数约束）
│   ├── 蜂窝中台：能力模块化+可插拔+支撑轻量化
│   └── 三次组织升维：极简→蜂窝→分布式网络
│
└── 反馈闭环（数据驱动）
    ├── 试错周期3个月：快速验证/快速转向
    ├── 项目存活率>45%：高于行业平均
    └── 跨区协作指标>60%：打破信息孤岛
```

## 关键模块

### 模块1：并行竞争机制

- 定义：多个团队同时开发同类产品或探索同一方向，由数据而非上级判断决定胜负
- 输入：战略方向+可用资源+多个候选方案
- 输出：经过市场验证的最优方案+快速淘汰劣质方案
- 关键动作：
  - 抖音早期多个团队并行开发短视频产品，最终由用户数据选出胜者
  - 胜者获得资源倾斜，败者团队快速拆解并入胜者或转向新方向
  - 不预设"正确答案"，让实验结果说话
- 常见误区：把赛马等同于内耗——赛马的关键是"数据裁判"而非"政治博弈"；没有数据标准的赛马会退化为派系斗争

### 模块2：人才流动系统

- 定义：通过高流动率制造创新压强，同时沉淀知识资产形成复利效应
- 输入：35%内外部流动率+2.9年中位在职时长
- 输出：持续注入新视角+打破部门墙+知识资产沉淀
- 关键动作：
  - 内部活水：员工可跨部门转岗，无需当前主管批准
  - 外部流动：高淘汰率保持人才密度，淘汰标准与绩效强关联
  - 2.9年中位时长看似短暂，但字节认为：在高速迭代环境中，2.9年足以让一个人经历多个完整项目周期，沉淀的方法论比工龄更有价值
- 常见误区：只看到流动率而忽略知识沉淀——没有飞书文档留存和知识库，高流动率只会导致组织失忆

### 模块3：分布式创业网络

- 定义：将大组织拆解为小单元，每个单元拥有独立决策权，通过中台共享能力
- 输入：业务需求+人才储备+中台能力模块
- 输出：217个<150人的创业单元，每个拥有人事/预算/合规三权
- 关键动作：
  - 邓巴数约束：每个单元<150人，符合人类社交认知上限，确保沟通效率
  - 三权下放：人事权（自己招人）、预算权（自己花钱）、合规权（自己审批），减少对总部的依赖
  - 蜂窝中台提供可插拔的能力模块（推荐/审核/增长），新业务像搭积木般快速组合
- 常见误区：只拆分不赋能——没有强中台支撑的小团队只会各自为战、重复造轮子

### 模块4：反熵增制度

- 定义：一套制度化手段，持续对抗组织规模带来的惯性、舒适和僵化
- 输入：组织熵增信号（决策变慢/创新减少/人才流失/部门墙加厚）
- 输出：持续的组织活力+创新速度+人才吸引力
- 关键动作：
  - A/B测试组织架构：把公司当产品来迭代，组织形态本身就是实验对象
  - 小团队拆分：团队超过150人就拆分，保持敏捷
  - 制度极简：30项管理制度压缩为1项，减少合规负担
  - 始终创业作为核心价值观：文化层面持续提醒
- 常见误区：把反熵增等同于频繁重组——重组是手段不是目的，过度重组会破坏组织记忆

## 决策启发式

| 场景 | 判断规则 | 来源 |
|------|---------|------|
| 是否启动赛马 | 如果方向确定但路径不确定→启动赛马；如果连方向都不确定→先做探索性研究 | 抖音早期实践 |
| 赛马何时收束 | 如果数据出现显著分化（一个方案明显优于其他）→收束资源到胜者；如果差异不显著→延长赛马周期 | 数据驱动原则 |
| 团队是否该拆分 | 如果团队>150人→拆分；如果沟通需要3层以上传递→拆分 | 邓巴数理论 |
| 人才流动是否健康 | 如果流动率<15%→组织可能僵化；如果>50%→组织可能失稳；35%左右为健康区间 | 字节实践数据 |
| 试错项目是否继续 | 如果3个月内无显著正向信号→转向或终止；存活率>45%说明筛选标准合理 | 试错周期3个月 |

## 适用场景

### 最适合

- 高度不确定的市场环境，需要快速试错和转向
- 人才密度高、员工自驱力强的组织
- 多业务线并行、需要内部竞争保持活力的集团
- 从创业期向成熟期过渡、面临"大公司病"的组织

### 不适合

- 强监管行业（金融/医疗/航空）——试错成本过高，赛马不可接受
- 资源极度匮乏的早期创业公司——没有余力支持多个并行团队
- 人才密度低的组织——赛马会退化为内耗，流动率会变成流失率
- 需要深度积累的行业（基础研究/芯片设计）——2.9年中位时长不足以积累专业深度

## 实施检查清单

- [ ] 是否有明确的赛马数据标准——否则赛马会退化为政治博弈
- [ ] 赛马收束机制是否明确——何时合并、何时终止、资源如何再分配
- [ ] 团队规模是否受邓巴数约束（<150人）
- [ ] 创业单元是否拥有三权（人事/预算/合规）
- [ ] 是否有强中台提供可插拔能力模块——否则小团队会各自造轮子
- [ ] 人才流动是否有制度保障（内部活水、转岗机制）
- [ ] 知识沉淀是否有飞书/文档系统支撑——否则高流动率=组织失忆
- [ ] 试错周期是否明确（3个月为参考）
- [ ] 是否有反熵增的定期检查机制

## 诚实边界

1. **赛马的成本极高**：多个团队并行开发同一方向，意味着大量资源的重复投入。字节能承受是因为其利润率和融资能力支撑了这种"冗余创新"。对大多数公司来说，赛马的ROI可能远低于集中力量办大事。

2. **2.9年中位时长的双面性**：字节将其解读为"知识资产沉淀+复利效应"，但客观上，2.9年意味着大量组织记忆随人员离开而消失。飞书文档留存部分缓解了这个问题，但隐性知识（经验、直觉、人脉）无法文档化。

3. **35%流动率的副作用**：高流动率制造了创新压强，但也制造了团队不稳定、项目连续性差、培训成本高等问题。字节用高薪+期权对冲，但这不是所有组织都能复制的。

4. **赛马的心理成本**：并行竞争意味着有人会"输"。如何处理败者团队的情绪、如何避免"赢者通吃"导致的协作意愿下降，是赛马机制必须面对的治理问题。

5. **邓巴数的理想与现实**：<150人的创业单元在理论上很美，但实际业务中，跨单元协作的协调成本可能比层级管理更高。跨区协作指标>60%说明协作确实在发生，但也说明大量时间花在了跨团队对齐上。
