# Netflix · 知情船长决策模型

> 用Informed Captain+Farming for Dissent+Disagree then Commit实现快速决策+全员执行

## 核心理念

知情船长决策模型解决的核心问题是：**取消审批后，谁来拍板？怎么拍板才能既快又对？**

Netflix用F&R飞轮取消了层层审批，但审批消失不等于决策消失。如果没人拍板，取消审批只会制造决策真空——要么没人敢做决定（决策瘫痪），要么人人都做决定（决策冲突）。知情船长模型就是Netflix给出的答案：每个关键决策指定一个"船长"，船长负责收集信息并做最终决定。但船长不是独裁者——在决定前必须主动收割反对意见，在决定后所有人必须全力执行。

三个组件构成一个完整的决策闭环：Informed Captain解决"谁决定"，Farming for Dissent解决"怎么决定得更好"，Disagree then Commit解决"决定后怎么办"。三者缺一——没有船长则决策无主，没有反对意见则决策盲区，没有执行承诺则决策空转。

核心命题：**决策速度是核心价值——宁可快速决策偶尔犯错，也不要缓慢共识追求完美。**

## 框架结构

```
知情船长决策模型
│
├── 谁决定：Informed Captain（知情船长）
│   ├── 定义：每个关键决策指定一个船长
│   ├── 船长≠最高职级的人——是最了解情况的人

│
├── 怎么决定：Farming for Dissent（收割反对意见）
│   ├── 船长主动找不同意见——欢迎反对声音
│   ├── 跨部门、跨层级征求意见
│   └── 反对意见是决策的输入，不是决策的否决
│
├── 决定后：Disagree then Commit（不同意但执行）
│   ├── 可以不同意，但决定后必须全力执行
│   ├── 同意≠一致同意——不需要所有人点头
│   └── 决定后不再质疑——如果还在质疑，说明决策过程有问题
│
└── 底层价值：决策速度
    ├── 宁可快决策偶尔犯错，不要慢共识追求完美
    └── 错误决策可修正，决策瘫痪不可修正
```

## 关键模块

### 模块1：Informed Captain——知情船长

- 定义：每个关键决策指定一个"船长"，船长是该决策的最终决策者和责任人
- 输入：决策议题 + 相关信息
- 输出：最终决策 + 执行指令
- 关键动作：
  - 船长是最了解情况的人，不是职级最高的人——一个对技术细节了如指掌的工程师可以是技术决策的船长，即使他的上级在场
  - 船长对决策结果负责——如果决策错误，船长承担后果，而不是推给"集体决策"
  - 船长必须"知情"——在做决定前必须充分收集信息，不能凭直觉拍脑袋
  - 一个决策只有一个船长——多人负责等于无人负责
  - 船长身份随决策议题变化——同一个人在不同议题上可能是船长也可能是执行者
- 常见误区：把船长等同于管理者——船长由"谁最了解情况"决定，不是由组织架构决定；以为船长可以独断——船长必须先Farming for Dissent再拍板，跳过这一步就是独裁

### 模块2：Farming for Dissent——收割反对意见

- 定义：船长在做决定前，主动、系统地收集不同意见，尤其是反对意见
- 输入：船长的初步判断 + 相关方的观点
- 输出：经过反对意见检验的决策
- 关键动作：
  - "Farming"是主动行为——船长不是被动等待反对意见出现，而是主动去"收割"：找不同部门的人、不同层级的人、不同专业背景的人征求意见
  - 跨部门征求意见——避免本位主义盲区，市场部门的技术决策需要听工程部门的意见，反之亦然
  - 跨层级征求意见——一线员工的视角往往比管理者更接近真实情况，船长不能只问同级和上级
  - 反对意见是决策的输入，不是决策的否决——船长听完所有反对意见后仍然可以做出与多数人不同的判断，但必须是在充分了解反对理由之后
  - 欢迎反对声音≠无限讨论——收集意见有截止时间，到时间就拍板
- 常见误区：以为Farming for Dissent等于民主投票——船长听取意见但不一定采纳多数意见；只找认同自己的人征求意见——这不是Farming for Dissent，这是自我确认

### 模块3：Disagree then Commit——不同意但执行

- 定义：决策过程中可以不同意，但决定做出后必须全力执行
- 输入：船长做出的最终决定
- 输出：全员全力执行
- 关键动作：
  - "同意"和"一致同意"是两回事——Netflix不追求一致同意（consensus），一致同意是决策速度的敌人
  - 不同意的人有权表达反对——但表达时机是决定前，不是决定后
  - 决定后不再质疑——如果决定后你还在质疑，说明Farming for Dissent阶段你没有充分表达，或者决策过程本身有问题
  - "全力执行"不是消极服从——即使你不同意，执行时也要全力以赴，而不是等着看决策失败来证明自己当初是对的
  - Commit是组织纪律——没有Commit，船长模型就退化为"各干各的"
- 常见误区：把Disagree then Commit等同于"闭嘴照做"——Commit的前提是Dissent阶段被认真对待，如果反对意见只是走过场，Commit就是被迫服从；以为Commit意味着不能复盘——复盘是事后学习，质疑是事中阻挠，两者不同

### 模块4：决策速度——核心价值

- 定义：在知情船长模型中，决策速度是被优先保障的价值，准确率是次要追求
- 输入：决策议题的紧迫性和可逆性
- 输出：决策节奏——快决策+快修正
- 关键动作：
  - Netflix的信念：大多数决策是可逆的——做错了可以改，但决策瘫痪的代价是时间窗口的永久丧失
  - 快速决策偶尔犯错 > 缓慢共识追求完美——这是Netflix与追求零失误的组织在底层假设上的根本分歧
  - 船长模型的每个环节都在加速：指定船长消除"谁来决定"的等待，Farming for Dissent有截止时间避免无限讨论，Disagree then Commit消除执行阶段的犹豫
  - 决策速度不是鲁莽——速度快的前提是船长"知情"和Dissent充分，跳过这两步的快不是速度而是冒进
- 常见误区：把决策速度等同于不思考——速度快的前提是信息充分收集（Informed）和反对意见充分听取（Dissent）；以为快速决策就不需要复盘——恰恰相反，快速决策更需要快速复盘和修正

### 模块5：船长≠最高职级——知情原则

- 定义：船长的指定依据是"谁最了解情况"，而非"谁职级最高"
- 输入：决策议题的专业领域 + 相关人员的知识深度
- 输出：船长人选
- 关键动作：
  - 知情原则是对层级决策的根本颠覆——传统组织中"谁官大谁拍板"，Netflix中"谁最懂谁拍板"
  - 管理者在船长模型中的角色转变：从"拍板者"变为"信息供给者"——管理者提供战略背景和约束条件，但不替最了解情况的人做决定
  - 船长可能是一线员工——如果一个客户服务问题最了解情况的是客服代表，那她就是船长
  - 知情原则与Context, not Control一脉相承——管理者提供Context（情景），船长基于Context做决策
- 常见误区：管理者无法接受下属做船长——这是从Control到Context转型中最常见的心理障碍；以为"最了解情况"等于"最有经验"——一线的实时信息有时比多年经验更有决策价值

## 决策启发式

| 场景 | 判断规则 | 来源 |
|------|---------|------|
| 谁应该是船长 | 如果某人最了解该决策涉及的情况→指定为船长；如果职级最高但不是最了解的→让位 | 知情原则 |
| 是否需要更多反对意见 | 如果所有意见都一致→警惕群体思维，主动找不同视角；如果已有充分反对→可以拍板 | Farming for Dissent |
| 决定后有人继续质疑 | 如果质疑在决定前未被表达→说明Farming for Dissent失败，需修复流程；如果已表达但被否决→提醒Disagree then Commit | DtC |
| 决策速度vs决策质量 | 如果决策可逆→优先速度；如果决策不可逆→允许更长的Dissent周期 | 决策速度原则 |
| 船长是否可以独断 | 不可以——跳过Farming for Dissent的船长是独裁者，不是知情船长 | Informed Captain定义 |
| 反对意见是否需要全部采纳 | 不需要——反对意见是输入不是否决，船长综合判断后做最终决定 | Farming for Dissent |
| 多人争当船长 | 看谁最了解情况——如果多人同等了解，由上级指定一人，但必须给出理由 | 知情原则 |
| 执行中遇到新信息 | 如果是重大新信息→船长有权重新决策；如果是边际信息→继续执行，事后复盘 | 决策速度原则 |

## 适用场景

### 最适合

- 高不确定性、高速度要求的市场环境——决策窗口短，共识来不及形成
- 人才密度高、专业分工细的团队——不同领域的决策需要不同领域的专家做船长
- 取消审批后需要替代性决策机制的组织——知情船长填补审批流程留下的真空
- 创意/内容/技术类业务——最佳方案无法通过集体投票产生
- 跨部门协作频繁的组织——Farming for Dissent天然打破部门墙

### 不适合

- 安全敏感行业——航空/医疗/核能，错误代价不可逆，需要集体决策和多重审批兜底
- 人才密度低的组织——"知情船长"可能只是"最不差的选项"，个人决策质量无法保障
- 强层级文化的传统企业——"下属做船长"与"领导拍板"的文化冲突无法调和
- 合规要求极高的行业——金融/制药，监管要求必须保留集体决策和审批流程
- 决策不可逆且代价巨大的场景——如重大并购、战略转型，需要更审慎的集体决策

## 实施检查清单

- [ ] 每个关键决策是否指定了唯一的船长
- [ ] 船长是否是最了解情况的人而非职级最高的人
- [ ] 船长在做决定前是否主动进行了Farming for Dissent
- [ ] Farming for Dissent是否覆盖了跨部门、跨层级的不同视角
- [ ] 反对意见是否被认真对待而非走过场
- [ ] 决定后是否全员执行Disagree then Commit
- [ ] 决定后是否还有人持续质疑——如果有，检查Farming for Dissent是否充分
- [ ] 管理者是否能接受下属做船长——这是从Control到Context的关键心理转变
- [ ] 决策速度是否被优先保障——是否存在为了追求共识而拖延决策的情况
- [ ] 是否有决策复盘机制——快速决策需要快速复盘和修正

## 诚实边界

1. **知情原则的判断难题**："谁最了解情况"本身就是一个需要判断的问题。在专业交叉的决策中，不同人可能都认为自己最了解情况，此时指定船长可能变成新的权力博弈。

2. **Farming for Dissent的文化前提**：收割反对意见的前提是组织有坦诚表达的文化。如果员工习惯于"老板说什么就什么"，Farming for Dissent只会收到礼貌的附和，而不是真正的反对意见。

3. **Disagree then Commit的权力不对称**：理论上"可以不同意但必须执行"，但如果船长是上级，下属的"不同意"需要极大的心理安全。如果船长是下属，上级的"Commit"可能暗含"我等着看你失败"的消极态度。

4. **与亚马逊Disagree and Commit的差异被简化**：亚马逊版本中，"Disagree and Commit"更多是贝索斯作为CEO的个人管理风格——"我不同意但我会全力支持你去做"。Netflix将其系统化为组织模型，但系统化后的执行难度远高于个人原则。

5. **决策速度的代价**：快速决策偶尔犯错是Netflix的预期，但"偶尔犯错"的频率和代价在公开资料中没有被充分讨论。在错误代价高的场景中，决策速度优先的假设可能不成立。

6. **与华为BEM的对比简化了双方**：华为的ATI/ATB/ATC+IPMT不是纯粹的"集体决策"，IPMT中有明确的决策权归属；Netflix的Informed Captain也不是纯粹的"个人决策"，Farming for Dissent本身就是一种集体智慧输入。两者的差异是程度和侧重点，不是二元对立。
