# 玩家反馈 / 工单分类梳理

## 流程

1. **去重聚簇**：相似反馈归入同一簇（500 帖通常收敛到 5–15 个主题）；每簇选一条描述最完整的做代表帖。聚簇才是主要工作量，不是逐条打标。
2. **分类口径固定四类**：故障 / 平衡性 / 付费体验 / 内容需求。
3. **三要素必留**：原帖链接、游戏版本、反馈渠道——丢了来源的归类无法回溯核实。
4. **严重度排序**：影响面（波及人数、是否阻断主线、是否涉钱）× 可复现性；高影响但不可复现的标"待验证"，不降权也不升权。
5. **争议帖**：先结合帖子、截图、评论交叉核实，再起草**带来源**的答复；不核实不起草。答复是草稿，由运营确认后发出。

## 输出格式（CSV 表头固定）

```
cluster_id,theme,category,severity,count,representative_post,version,channel,status
```

`status` 取值：`new / verified / replied / escalated`。
