# 音频方向到实现交接工作流

将本文件用于需要跨阶段推进的音频任务。仅执行用户当前所需环节，不把整理规格当成制作或验证音频。
以下流程、字段与检查项是对角色职业方法的规范化展开，不是来源原文中的完整 SOP。
原始依据与证据边界见 [source-map.md](source-map.md)，填写骨架见 [deliverables.md](deliverables.md)。

## 1. 接收与澄清

- 确认阶段、范围、交付对象、输出路径与许可；没有明确路径先询问。
- 从已提供的材料识别平台、引擎、中间件、版本及当前开发状态。
- 区分新建方向、补齐事件、优化实现、VO 规划与已有规格评审。
- 列出已知、未知、阻塞、不适用四类信息，避免把空白当作默认同意。
- 向策划职责索取缺失交互、叙事节点、情绪意图与台本；先确认再扩展事件清单。
- 向工程职责核对能力与预算测量口径，不把平台标签当成音频能力保证。
- 向美术职责获取视觉情绪，不接管美术资产制作或美术圣经编写。

## 2. 输入清单

| 输入 | 最少要获得的信息 | 不足时的处理 |
|---|---|---|
| 游戏概念 | 核心体验、玩法支柱、情绪目标 | 请用户或策划职责确认，不自定题材 |
| 系统设计 | 交互、状态变化、反馈、失败与取消 | 阻塞相关事件规格 |
| 叙事文档 | 场景、节点、角色意图、关键转折 | 请策划职责补齐，不杜撰情节 |
| 美术圣经 | 情绪、材质、空间与视觉节奏 | 标注未对齐，不自行制作视觉资产 |
| 技术约定 | 平台、引擎/中间件版本、能力限制 | 请工程职责确认，不编造 API |
| 音频资产 | 文件/事件/版本/引用/许可/加载组 | 区分缺失与未检查，不声称可用 |
| VO 材料 | 台本 ID、角色、语言、版本、授权 | 交策划/本地化职责核对 |
| 预算与验证 | 场景、设备、口径、上限、日志 | 保留待确认/待测，不填固定阈值 |

来源中 `design/gdd/`、`design/art/`、`assets/audio/` 与 `CLAUDE.md` 是建议读取位置。
实际项目可以换路径；只读取用户提供或授权范围内的现有文件。
仅做技能整理时，不因为这份清单而去读取游戏项目或音频资产。

## 3. 方向决策

1. 将已确认的玩法与叙事目标整理为情绪锚点。
2. 根据情绪锚点提出音乐基调、声音材质和动态层级候选。
3. 对每个候选说明听觉收益、反馈清晰度、内容量、实现成本与潜在风险。
4. 请用户选择，不在未批准时将候选写成项目既定方向。
5. 以统一声音调色板约束后续事件，并记录有意例外及理由。
6. 分别定义菜单、探索、战斗、高潮的进入、持续、退出与恢复。
7. 将层级切换绑定到策划已确认的状态，不擅自新增玩法状态。
8. 标明参考音频是否真实存在及是否已获播放权限，不凭链接标题作听感判断。

## 4. 从交互到事件

- 为每条交互保留上游来源，建立交互与事件的映射，不用音频事件名替代玩法定义。
- 区分反馈、状态提示、环境持续声、叙事提示与 VO，检查是否重复播放同一信息。
- 明确“开始、保持、结束、取消、失败、恢复”等实际需要覆盖的情况。
- 为每个事件定义触发前置条件、作用域、触发频率、重入与停止/重置。
- 用变体减少重复感；用分层表达强度或材质，避免无目的地叠加层数。
- 将优先级解释为资源竞争时的听觉意图，由工程核对抢占、限流或虚拟声部支持。
- 为距离衰减标明声源坐标/跟随、单位、近远范围、曲线、遮挡与混响需求。
- 将二维 UI 与三维声音分开，不默认 UI 也应用空间衰减。
- 为事件标明总线、资源组、加载方式与并发口径。
- 对未提供的素材写“待制作/待提供”，不得将事件行视为资产已经存在。

### 命名核对

可采用 `audio.<domain>.<subject>.<action>` 作为讨论模板，先核对项目现有命名并统一批准。
例如 `audio.sfx.<subject>.impact` 只说明字段位置，不是可播放事件或实际中间件路径。
将变体、语言与分层信息优先放在事件元数据；若项目需要命名编码，另订统一规则。
检查大小写、分隔符、唯一性与稳定性；避免重命名使现有引用失效。
不要照搬某个中间件的专用对象名称或宣称跨中间件无需迁移。

## 5. 混音与实现评审

1. 用总线树核对路由、用户音量控制、空间处理与效果发送。
2. 说明动态控制何时开始、何时退出、暂停/切场景如何处理及恢复条件。
3. 将关键提示、VO、音乐与环境的优先级转为可评审的让位规则，不仅写响度数值。
4. 对每个控制参数记录单位、默认值来源、调整范围和批准状态；无来源留空说明。
5. 比较已有方案、引擎原生方案与候选中间件，记录适配、维护、授权与工具链约束。
6. 把事件契约、实例/池化、资源生命周期与空间参数交工程实现。
7. 检查循环停止、实例归属、池化复用重置、场景卸载和流式读取的边界。
8. 将能力不确定项列为阻塞或待验证，不用伪代码冒充实现。

## 6. 预算与验证计划

- 把预算按平台、场景、统计口径和测量方法分别记录。
- 明确同发语音指音频通道/实例；VO 角色配音不是该单位的同义词。
- 不把各事件上限之和直接当成实际峰值；请工程测量共同出现和生命周期重叠。
- 不将压缩文件大小直接当成运行时内存；解码数据、缓冲、效果与对象开销需核对。
- 为短音效、长音乐、环境与 VO 分别说明加载/流式/卸载候选，不预定统一方案。
- 列出高密度触发、多声源重叠、快速切场景、暂停恢复、长时运行等适用场景。
- 记录设备/构建/中间件版本、采样/编码条件、场景、预期与实测；没有实测保留空白。
- 让质量保障职责或工程职责提供真实日志、播放检查及限制；本技能不代替执行。
- 超限后先说明原因证据与候选取舍，再安排复测；没有数据不宣布优化成功。

## 7. VO 与本地化流程

1. 与策划职责锁定角色、台本意图和文本版本。
2. 提出声线与表演范围选项，记录情绪强度、清晰度和发音要求。
3. 将录制技术规格列为项目决策，确认采样率、位深、声道、格式、响度与噪声控制。
4. 约定台本行 ID、角色、语种、版本和文件名，保持文本与音频关联稳定。
5. 与本地化职责确认配音覆盖策略、文本冻结点、缺失回退和不同语言时长处理。
6. 将授权、录制、剪辑、审听、接入与语言覆盖分开标状态。
7. 不将配音方向完成等同于演员已录制、授权已取得或语言版本已验收。

## 8. 收尾与交接

- 将“方向已批准”“规格已交付”“资产已制作”“工程已接入”“实际验证已完成”分开记录。
- 在交付中列出未覆盖交互、孤立引用、缺失资产、未定参数、未批准方向和验证缺口。
- 向统筹职责提交实际路径、关键决策、事件清单状态、风险、审批项与下一步。
- 将策划、工程、美术、本地化的待办按职责交接，不依赖固定个人花名或专用调度函数。
- 在收到新证据后更新对应行，不将旧版本结论泛化到新平台或新语言。
