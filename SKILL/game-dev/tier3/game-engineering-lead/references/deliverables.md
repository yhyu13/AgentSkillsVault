# 工程交付模板

按需复制以下片段到用户授权的产物中。将占位符替换为实际内容；未执行项保留“未运行/待确认”，不要写成通过。
本次制作只提供模板，不表示已为任何游戏实现这些产物。

## 1. 输入与缺口清单

| 字段 | 填写内容 |
|---|---|
| 任务/阶段/范围 | `<任务 ID、阶段、范围与非目标>` |
| Story/Output Path | `<实际路径或待确认>` |
| GDD/系统索引 | `<真实文件路径、需求 ID、版本>` |
| 架构/ADR/控制清单 | `<已有文件或缺失项>` |
| 引擎/版本/平台 | `<引擎、小版本、包/插件版本、目标设备>` |
| 联网形态/运行环境 | `<单机或联网、权威部署、可用工具>` |
| 授权与阻塞 | `<允许写入的动作、缺口、确认负责人>` |

## 2. 主架构与需求矩阵

对每个模块记录责任、依赖方向和边界，不为没有依据的模块预先写实现。

| GDD 需求 ID | 来源位置/版本 | 层级 | 模块/路径 | 输入/输出/权威 | 依赖 | ADR ID | Story ID |
|---|---|---|---|---|---|---|---|
| `<策划提供的 ID>` | `<路径/行号>` | `<基础/核心/玩法>` | `<模块>` | `<契约>` | `<前置>` | `<ID/待决>` | `<ID/待拆>` |

在矩阵后列出未承接需求、冲突、版本假设和待确认项；不要为了闭环擅自改写设计需求。

## 3. ADR 模板

```text
ADR ID：<编号>
标题：<一个明确决定>
状态：<提议/待确认/已接受/被替代>
层级：<基础/核心/玩法>
关联：<GDD 需求 ID、模块、Story>
适用版本：<引擎、小版本、平台、包/插件>

上下文：
  <问题、约束、来源与需要作出的选择>
备选方案：
  A：<方案、收益、成本、风险>
  B：<方案、收益、成本、风险>
决定：
  <选择、理由、适用边界>
后果：
  <正面收益、代价、残余风险、依赖与后续工作>
验证：
  <验证问题、方法、环境、真实证据路径；未执行时标未运行>
回退/重审：<触发条件、替代 ADR 或待确认项>
批准：<负责人、决定与时间；没有批准时写待审批>
```

至少为三个不同的基础层关键决策分别建立记录。
可从引擎与平台、资源生命周期、数据与存档基础中选题；用实际 GDD 上下文决定，不复制三个同义标题。

## 4. 一页控制清单

将范围限定到当前任务；保持简短、可执行，并把例外与 ADR 关联。

```text
适用项目/版本/任务：<填写>
允许变更路径：<填写>
依赖方向：<允许与禁止的依赖>
gameplay：<数据驱动的参数来源和配置变更入口>
core：<热路径范围、零分配检查方法及证据>
ai：<可调试的状态/原因记录与脱敏要求>
network：<权威归属、输入校验；不适用时说明原因>
ui：<权威状态来源、展示缓存边界、回写接口>
性能门槛：<帧率、CPU/GPU、内存、适用带宽与测量环境>
技术验证入口：<项目真实命令/步骤与证据位置>
QA 验收入口：<计划、执行责任方、结论位置>
禁止事项：<越范围修改、未核实 API、伪证据、未授权发布等>
例外：<理由、影响、批准人、关联 ADR>
```

先确认目录语义再应用这些项目基线；不要将规则写成无条件适用所有引擎的定律。

## 6. 技术证据与状态表

只记录真实执行结果；命令和日志需与构建版本及环境对应。

| 证据 ID | 需求/Story/AC | 环境/构建标识 | 命令或步骤 | 预期 | 实际结果 | 证据路径 | 状态/责任方 |
|---|---|---|---|---|---|---|---|
| `<ID>` | `<关联>` | `<版本/设备>` | `<实际命令或步骤>` | `<预期>` | `<输出或未运行原因>` | `<路径/待生成>` | `<未运行/失败/技术通过/QA待验/已验>` |

- 将“已写用例”“已运行”“技术通过”“QA 已验”区分记录。
- 将编译或静态检查结果只用于支持对应技术检查，不代替行为验收。
- 不把拟定的日志路径当作已经存在的文件；交付时核对证据是否存在。
- 将缺少环境、输入、权限或 QA 结论的条目保留为待处理，不伪造签字。

## 8. 安全、CI 与遥测片段

安全项按“资产/信任边界 → 威胁 → 控制措施 → 残余风险 → 证据/负责人”记录。

CI 项按“触发 → 版本化环境 → 技术检查 → 构建/约定测试 → 产物归档 → 失败处理”记录，使用项目真实入口。

| 事件/实验 | 业务问题/假设 | 触发或分组 | 必要字段/指标 | 观察窗口/停止条件 | 权限与脱敏 | 验证状态 |
|---|---|---|---|---|---|---|
| `<名称>` | `<目的>` | `<条件>` | `<字段或指标>` | `<规则>` | `<保留与访问>` | `<未实施>` |

将遥测事件和 A/B 实验分开建模；不要将未实施的字段写成已上线埋点。
