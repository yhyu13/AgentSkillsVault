# 交接与门控汇总模板

本模板为本次规范化产物，便于统筹收集专业交接；不是原文规定的数据格式。
先确认项目输出路径与写入许可，再填写。保留方括号占位符，不用虚构内容补齐。

## A. 专业任务分派

```text
Task ID：[项目内唯一编号]
角色/能力域：[承接专业职责]
优先级：[项目约定]
当前阶段：[Phase 编号与名称]
上下文：[目标、已确认决策、范围限制]
依赖：[前置 Task ID、输入路径、已确认版本]
Deliverables：[专业产物、判断和证据要求]
Output Path：[已获许可的项目输出路径]
Handoff：[回传统筹职责；列明实际路径、完成内容、未决项与验证状态]
```

## B. 专业交接回收

```text
Task ID：[对应任务编号]
专业职责：[实际承接职责]
执行状态：[已分派 / 执行中 / 已交付 / 已评审 / 阻塞 / 未验证]
实际产物：[路径、版本或标识]
专业结论：[保留对应职责的判断与归属]
实际执行：[实际完成的工作；没有执行则写未执行]
验证证据：[测试、评审、Playtest 或其他证据路径；无则写未验证]
依赖核对：[采用的输入版本、仍未满足的依赖]
未决事项：[阻塞、影响、下一步承接]
```

- “已分派”不等于“已交付”，“已交付”不等于“已评审”。
- 不把计划中的并行、测试或 Playtest 写成已经执行。
- 缺失专业承接时记录阻塞，不代填专业判断。

## C. 阶段门控汇总

```text
门控：[设计评审 / 架构评审 / 烟雾测试 / 发布检查等]
当前阶段 → 拟进入阶段：[原 Phase 编号]
评审职责：[提供专业结论的能力域]
评审强度：[full / lean / solo；具体规则待项目约定或引用已确认约定]
判定：[PASS / CONCERNS / FAIL]
具体阻塞项：[问题、对应产物、承接职责；无则写无]
支撑证据：[真实路径、版本、环境与适用范围]
整改与再确认：[需补充的专业工作]
用户豁免：[无 / 明确决定、适用范围与记录]
人工放行签字：[不适用 / 待用户或经授权发布负责人决定并签字；记录签字依据]
高影响动作审批：[未请求 / 待确认 / 已确认的动作与范围]
结论：[推进 / 先解决或取得明确豁免后再推进；发布另核对人工签字与审批]
```

- 不发明三态的数值阈值或严重度分级。
- 保留原判定；用户豁免不等于测试通过或技术风险消失。
- 没有评审证据时，不填 PASS。
- QA 结论属于建议性质量门（advisory），不自动授权发布；发布前另核对人工放行签字和明确审批。

## D. 汇编交付摘要

```text
本次阶段：[当前阶段与交付范围]
进入位置依据：[已有产物与用户确认]
已确认约束：[引擎、目标平台、评审强度]
本阶段产物：[实际路径及专业归属]
质量门：[判定、证据、未决项或豁免]
跨专业一致性：[已核对项、冲突及处理]
已知风险与缓解：
  - [风险、对应缓解、承接职责、仍待补的证据]
未验证 / 缺失：[不得包装为完成的内容]
下一步：[等待用户决定或已确认的后续任务]
```

模板依据：原规范 L23、L71、L76-L80、L104-L107、L113。
字段细分、执行状态与证据记录属于本次规范化，来源区别见 [来源映射](source-map.md)。
