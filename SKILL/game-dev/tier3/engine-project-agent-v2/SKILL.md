# engine-project-agent-v2 · 现有引擎工程开发闭环（可执行版）

纪律不变：先读懂、小步改、改完用运行证据验证、交付留痕。相对原版的差异：新增复现优先、Unity/UE 各自的读工程路线图、VCS 纪律、四级验证阶梯和固定格式的改动日志。

## 闭环（每轮）

1. **复现优先**：改 bug 前先拿到可复现（操作步骤 / 存档 / 版本号 / 日志）。复现不出来走 §复现不出来，不许跳过直接改。
2. **30 分钟读图**（原版缺失）：
   - Unity：`Assets/Scripts` 分层 → asmdef 依赖图 → `ProjectSettings/` → 出问题场景/预制体的引用链
   - UE：`Source/` 模块与 Build.cs 依赖 → `Config/Default*.ini` → `.uproject` 插件清单 → 相关 DataAsset/蓝图
   - 跨模块问题（动作错位、剧情未触发）先写调用链：输入 → 动作绑定 → 物理/状态机 → 表现与剧情衔接，在链上标出疑似断点再动手
3. **最小改动**：只动必须动的位置；顺手重构、顺手优化在正式工程里都是风险。
4. **验证阶梯（四级，说明停在哪级）**：
   ① 编译通过 → ② 复现场景通过 → ③ 日志/运行数据确认 → ④ 相关功能回归清单通过。
   只停在①不算验证；视觉/手感类问题以录屏与运行画面为证据。
5. **记录**：每轮按下方改动日志格式落一条。

## VCS 纪律（原版缺失）

- 开工确认工作区干净、在专用分支；每轮改动独立提交，提交信息附验证结论
- 不碰生成目录：`Library/` `Intermediate/` `Binaries/` `Saved/` `DerivedDataCache/`
- 覆盖场景、改共享配置、动 `.meta` / `.uproject` 前必须人确认

## 复现不出来（原版缺失）

1. 在可疑路径加日志插桩，跑一遍拿真实数据
2. 二分最近变更（代码版本 / 资产 / 配置）定位引入点
3. 向需求方要：存档、录像、平台与设备、精确版本号
4. 仍无复现 → 交付"已排除项 + 插桩日志 + 下一步建议"，不盲写补丁

## 长程任务

可以连续多轮，但安全性来自**每轮都有验证记录**，不是"跑得久"；每轮结束在改动日志落一条 checkpoint，人随时能接管。

## 交付物

- diff（可审阅的改动，不是整个工程）
- 改动日志，固定格式：`轮次 | 现象 | 定位 | 改动 | 验证停在哪级 | 剩余风险`
- 需要人决策的点单列（如影响存档兼容、涉及付费逻辑）

## 边界

没有工程访问权：先要权限或最小复现，不臆测结构、不盲写"应该能用"。从零验证新玩法不在正式工程做，走 game-proto-validation-v2。性能与兼容性结论必须有运行数据，"应该没问题"不算数。

## 相对原版（engine-project-agent）的改进

闭环第一步从"梳理结构"前移为"复现优先"，并补复现失败的四步路径；新增 Unity/UE 各自 30 分钟读图路线；新增 VCS 纪律与生成目录黑名单；"改完必验证"细化为四级阶梯；交付物定义固定格式改动日志；删掉"20 小时无人工干预"这类不可验证案例，替换为可执行的安全条件。
