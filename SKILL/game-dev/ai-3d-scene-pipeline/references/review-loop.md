# 多机位盲审循环：可执行判据

## 为什么单独抽出来

场景"像不像"是**视觉**问题，不是文字描述能判定的。所以流程必须是：

```
实现 → 固定机位截图 → 独立审查 Agent 对照参考图 → 差异清单 → 修 → 再截图 → 再审
```

关键在两点：
1. **固定机位**：每次截图相机参数一致，否则没法逐轮对比。
2. **独立审查方**：审查 Agent 不参与实现，避免"我做的当然没问题"。

## 机位表（照抄即可开工）

| 编号 | 机位 | 用途 |
|---|---|---|
| A | 主视角（与参考图同机位） | 风格 / 配色 / 主体感 |
| B | 俯视 90° | 平面布局 / 物件间距 |
| C | 3/4 侧视 | 高度层次 / 前后关系 |
| D | 局部特写 | 材质 / 小物件 |

## 审查 Agent 的提问清单（逐条打勾，不要笼统"好不好看"）

- 画风与配色是否与参考图一致？
- 物件的位置、朝向、比例是否与参考图一致？（逐个物件列）
- 是否有**缺失**的物件（参考图有、场景里没有）？
- 是否有**多出**的物件？
- 材质 / 贴图是否贴错位置、拉伸、缺失？
- 光照方向与色温是否与参考图一致？
- 轮廓剪影（silhouette）是否与参考图吻合？

## 差异清单格式

```
| 机位 | 差异 | 严重度(阻断/可见/细微) | 处理动作 | 负责人 |
```

只有"阻断"和"可见"两类必须修完再进下一轮；"细微"可以显式接受并记录在案。

## 落地提醒

- 截图脚本用 Blender 无头渲染（`blender -b -P shot.py -- --cam A`）或引擎内相机，二选一但固定。
- 别用"AI 看一眼描述"替代截图——必须落成图片。
- 每轮迭代把机位参数写进版本控制，否则第 5 轮和第 1 轮不在同一基准上。
