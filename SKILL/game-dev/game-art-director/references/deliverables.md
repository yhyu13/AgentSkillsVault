# 交付骨架

以下均为待项目填写的骨架，不是已经完成的美术、资产清单或实测报告。来源明确要求九节美术圣经、逐资产规格与 AI 提示词、技术美术和可访问性矩阵；具体表格列与证据状态是本次规范化。来源依据见 [source-map.md](source-map.md)。

填写时保留“待确认/证据不足”而不是猜数值；未生成文件不填真实素材路径；未实际执行检查不填“已验证”或“通过”。

## A. 九节美术圣经

建议路径：项目授权的 `design/art/art-bible.md`。按任务范围引用，不要求无依据时虚构完整项目。

先记录：概念/GDD 来源、平台/管线、已有美术圣经、用户确认的方向、尚未决定项。

| 节次与标题 | 至少记录的内容 | 依据与输出关联 |
|---|---|---|
| 1. 视觉锚点与风格参照 | 视觉目标、概念依据、参照需求或实际参照、已确认方向与备选项 | 概念/GDD；影响实体与资产规格 |
| 2. 配色 | 色彩角色、使用约束、项目色值来源、可访问性关联、待确认项 | 视觉方向、UX需求；色值/对比度未测不得填结论 |
| 3. 构图 | 经确认的构图和视觉组织要求、适用场景、例外 | 概念、关卡/角色/UI需求；关联资产 |
| 4. 角色视觉语言 | 角色文档依据、统一视觉要求、实际状态与动画需求、例外 | 角色设计；实体ID/规格ID |
| 5. 环境视觉语言 | 关卡依据、环境视觉约束、复用/差异要求、待确认项 | 关卡设计；实体ID/规格ID |
| 6. UI 视觉语言 | UX 规格位置、视觉约束、可访问性等级和矩阵引用 | UX职责负责人；不替代玩法数值设计 |
| 7. 动画原则 | 项目原则、动画需求、状态或素材对应、参数依据和缺口 | 角色/环境/UI设计；无来源不填时长/曲线/帧率 |
| 8. 资产命名规范 | 项目规则、实际适用范围、例外与审批状态 | 技术偏好；主资产清单 |
| 9. 资产格式、尺寸与预算 | 格式规则、尺寸/单位、预算与测量范围、平台/管线约束 | 技术偏好、工程确认；逐资产规格 |

每节使用以下结构：

```text
输入证据：〔实际文档与段落；缺失则注明〕
约束与选择：〔已确认内容；候选方案另列〕
待确认项：〔决定人、影响范围；无则明确无〕
输出引用：〔相关实体/规格/UX或检查位置〕
```

本次把来源中“角色/环境/UI”一组拆为三节，与其余六类构成九节。不要把这张表说成来源唯一固定标题。

## C. 逐资产规格与 AI 提示词

建议位置：项目授权的 `design/assets/`；具体文件名按项目约定，不强制新增未授权文件。

```text
规格 ID：〔待填〕
实体 ID / 设计来源：〔待填〕
用途与使用场景：〔待填〕
美术圣经引用：〔章节与决策位置〕
风格与构图需求：〔已批准内容；未确认则列候选/缺口〕
角色/环境/UI 约束：〔按实际资产类别填写，不适用写不适用〕
命名 / 计划文件路径：〔项目规则与来源；实际路径待文件产出后填〕
文件格式：〔项目约定与来源，待确认则注明〕
尺寸与单位：〔项目要求/测量依据，禁止默认通用尺寸〕
资源预算与适用范围：〔值、单位、来源；缺依据注明待确认〕
动画需求：〔状态、动作等需求及依据；参数未定则保留缺口〕
目标平台 / 渲染管线：〔工程证据与待确认项〕
AI 生成提示词：〔草稿或已确认，必须保留下面的结构〕
美术圣经偏离：〔无/具体差异与待审批项〕
实际文件 / 主清单引用：〔仅填真实文件，尚未产出写计划项〕
```

AI 提示词骨架：

```text
目的：生成用于〔使用场景〕的〔视觉实体〕资产。
依据：遵循〔美术圣经章节及已确认风格、配色、构图要求〕。
主体：仅描述〔角色/环境/UI文档中的实际需求〕。
动画：满足〔已确认动画需求；静态资产写明不适用〕。
输出限制：按〔项目文件格式、尺寸与单位、管线约束〕组织交付。
待确认：〔未批准的风格、尺寸、格式、动画等；确认前不视为生产就绪〕。
```

只写规格需要的约束，不承诺生成工具一定满足文件格式、动画或引擎导入要求；实际产出后仍需核对。
AI 提示词不是资产，不凭提示词存在就登记素材完成或性能合格。

## F. 可访问性分级与特性矩阵

建议路径：项目授权的 `design/accessibility-requirements.md`。

完整等级：Basic / Standard / Comprehensive / Exemplary。
来源主流程仅明确列出 Basic/Standard/Comprehensive；Exemplary 出现在完整枚举中，但其准入条件、各级特性集合与阈值均未被定义。不要自行补齐为既定分级标准。

先记录：项目选定等级、确认来源、UX 文档位置、各级定义缺口、实现与检查状态。

| 特性 | 等级适用关系 | 需求/项目依据 | UX 引用位置 | 状态 | 验证环境与证据 | 缺口/责任 |
|---|---|---|---|---|---|---|
| 色盲模式 | 〔项目待确认，不预设等级〕 | 〔待填〕 | 〔待填〕 | 待实现 | 〔未检查〕 | 〔待确认需求与实现〕 |
| 重映射 | 〔项目待确认，不预设等级〕 | 〔待填〕 | 〔待填〕 | 待实现 | 〔未检查〕 | 〔待确认需求与实现〕 |
| 字幕 | 〔项目待确认，不预设等级〕 | 〔待填〕 | 〔待填〕 | 待实现 | 〔未检查〕 | 〔需求由策划/音频协作，视觉呈现归本职责〕 |
| 文本缩放 | 〔项目待确认，不预设等级〕 | 〔待填〕 | 〔待填〕 | 待实现 | 〔未检查〕 | 〔待确认需求与实现〕 |
| 输入 | 〔项目待确认，不预设等级〕 | 〔待填〕 | 〔待填〕 | 待实现 | 〔未检查〕 | 〔待确认需求与实现〕 |

状态规则：

- **支持**：存在现有实现证据；注明版本、位置或工程交接，未运行检查时不冒充已验证。
- **待实现**：尚未实现或待确认；在缺口列说明具体情况，不能把待确认当作已实现。
- **已验证**：实际执行相应检查，记录环境/版本、方法、结果与可回查证据；文档审查本身不证明运行时功能可用。

本表是待填写骨架，默认“待实现”只表示尚未据此技能开展实现，不是任何真实项目的现状。
要求 UX 规格引用同一选定等级和矩阵位置；等级或特性调整时同步工程缺口和受影响资产。
