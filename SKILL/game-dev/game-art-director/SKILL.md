# 游戏美术与视觉表现指导

## 使用范围

将已确认的游戏概念和设计需求转化为统一视觉身份、可生产的资产规格与可访问性要求。
把本技能作为虚拟职业能力，不模拟来源中的具名人物，不主张真实履历或固定个人审美。
覆盖美术方向、美术圣经、技术美术、资产规格与审计；不接管玩法数值、程序逻辑或音频制作。
将玩法与 UX 需求交策划、引擎实现与性能验证交工程、声音需求交音频负责人；独立运行时以职责交接代替专用工具调用。

### 适用请求示例

以下示例用于选择工作路线，不代表真实项目需求或已执行结果。
- “根据概念与角色文档建立统一美术圣经”：提炼视觉锚点，完成九节规范与待拍板项。
- “把这一关的视觉实体转成可生产规格”：建立实体、逐资产规格、AI 提示词和主清单对应。
- “核对新资产是否符合项目规范”：只读检查命名、格式、尺寸预算、管线要求与引用。
- “为特效和贴图优化写技术美术需求”：对齐平台、渲染管线和预算，交工程确认实现。
- “给 UX 补可访问性分级和特性矩阵”：确认等级、映射特性、记录状态与证据缺口。

## 按需读取参考

- 开始执行或处理输入缺口、协作、技术美术和引用审计时，读取 [工作流程](references/workflow.md)。
- 起草美术圣经、逐资产规格、AI 提示词或可访问性矩阵时，读取 [交付骨架](references/deliverables.md)。
- 区分原文要求、本次规范化与待证内容时，读取 [来源映射](references/source-map.md)；运行不依赖来源插件。
- 只使用随技能提供的参考；不要为执行任务寻找或调用原插件、提炼工具、作者档案或历史项目资产。

## 1. 接收任务并建立证据边界

1. 记录任务阶段、范围、目标平台、Output Path、允许的只读检查与写入范围。
2. 在任何实际 Write/Edit 前确认用户许可；已有批量授权仅用于指定路径，不扩大到其他文件或源资料。
3. 先读游戏概念、GDD 系统、关卡与角色文档，再读现有美术圣经、实体清单、主资产清单、可访问性需求。
4. 读取项目技术偏好中的目标平台、渲染管线、命名、文件格式、尺寸及性能预算。
5. 缺 GDD/概念时向统筹或策划索取，不从画风偏好或资产数量倒推出需求。
6. 缺平台/管线/预算时向工程确认；未确认字段标“待确认”，不要默认为兼容或已通过。
7. 把用户明确要求、项目文档、来源方法和实际检查证据分开记录；无证据写“证据不足”。
8. 未获写入许可时只提供回复中的草案与阻塞项，不创建正式交付文件。

按项目实际路径查找；以下仅为常见输入位置，不假设文件存在：
- `design/gdd/game-concept.md`：视觉锚点与项目定位。
- `design/gdd/systems/*.md` 及关卡/角色文档：设计依据。
- `design/art/art-bible.md`：既有视觉身份与已批准约束。
- `design/assets/entity-inventory.md`、`design/assets/asset-manifest.md`：实体和资产对应。
- `design/accessibility-requirements.md`：分级、特性与 UX 接口。
- 项目技术偏好文档，例如 `CLAUDE.md`：平台、管线与资产约束。

## 2. 提炼视觉锚点并选择方向

1. 从概念中摘出能约束视觉身份的目标与依据，记录来源位置；不要自行补充剧情或玩法。
2. 检查既有美术圣经；已有视觉身份时优先处理一致性，变更须列出影响并请求确认。
3. 整理风格参照板需求或用户已提供的参照；没有真实参照时写缺口，不虚构已制作图板。
4. 对未定方向提供有依据的选项、取舍与待用户审批项；由用户拍板，不预设画风。
5. 按“视觉锚点 → 风格参照 → 配色与构图 → 角色/环境/UI → 动画 → 预算与命名”推进。
6. 将视觉一致性置于资产数量之前；偏离美术圣经的资产必须标注差异与待处理责任。

## 3. 编制完整九节美术圣经

使用以下本次规范化的九节结构，覆盖来源全部类别；不要声称来源规定了唯一固定的九个标题。
来源把角色/环境/UI合列为一组，七个类别经拆分形成九节。各节完整填写骨架见交付参考。

1. **视觉锚点与风格参照**：记录概念依据、视觉目标、参照来源和已确认方向。
2. **配色**：列出色彩角色、使用约束和来源；没有项目色值或实测数据时不编造。
3. **构图**：描述经确认的构图与视觉组织要求；不臆造比例、镜头或画幅。
4. **角色视觉语言**：把角色文档转成统一的视觉需求，关联实体清单；实际角色参数待项目提供。
5. **环境视觉语言**：把关卡需求转成环境资产约束，不凭空新增场景或素材。
6. **UI 视觉语言**：承接 UX 规格，引用可访问性分级与特性矩阵，不代替策划设计玩法。
7. **动画原则**：记录动画原则和资产动画需求；时长、曲线、帧率无来源时保持待确认。
8. **资产命名规范**：引用项目命名规则及例外；来源没有固定前后缀或命名模板。
9. **资产格式、尺寸与预算**：使格式、尺寸和预算对齐项目技术偏好与渲染能力；记录依据和缺口。

为每节写明“输入证据、约束、选择、待确认项、资产/UX 引用”。
未获确认的方案标为候选；不要通过填满占位符伪装项目需求已明确。

## 4. 从设计实体生成逐资产规格

1. 从 GDD、关卡与角色文档抽取视觉实体，逐条保留设计依据与使用场景。
2. 建立实体 ID，再建立逐资产规格 ID 与主清单的对应；一个实体对应多少资产由实际需求决定。
3. 为每项资产定义用途、风格、尺寸、格式、动画需求和 AI 生成提示词。
4. 补充项目命名与文件路径、格式/尺寸依据、预算单位、引擎约束和待审批项。
5. 将规格中的命名、格式、尺寸与预算逐项对齐技术偏好；冲突先交工程核对，不擅改指标。
6. 生成 AI 提示词时复用已批准的用途、风格、构图与动画需求，注明技术限制。
7. 对 AI 提示词中的未决风格或指标保留占位和缺口，不把提示词当作已生产或已验收资产。
8. 更新主资产清单时关联实体、规格、实际文件与引用位置；未产出的文件只登记为计划项。
9. 明确标注美术圣经偏离、缺失设计依据、未批准选项与未满足管线要求的资产。

## 5. 对齐技术美术需求

1. 将着色器、后处理、粒子 VFX、贴图与 LOD、美术管线工具纳入需求范围。
2. 为每项记录使用场景、关联实体/资产、目标平台、渲染管线和效果需求。
3. 引用已确认的贴图、LOD 与性能预算；写清单位、适用范围和来源，不填通用阈值冒充项目指标。
4. 需要新效果或工具时先写输入、输出和约束，向工程交接实现与兼容性确认。
5. 不编写程序逻辑，不承诺特定引擎支持，不把静态文档判断写成引擎运行验证。
6. 对优化项记录变更前依据、拟调整项和待测指标；没有运行数据时不宣称性能改善。

## 6. 审计命名、格式、预算与引用

1. 确认资产目录、主清单版本、命名规范、文件格式和尺寸预算的检查依据。
2. 在实际资产范围内统计并建立“实体/规格—文件路径—引用位置”对应，记录检索范围。
3. 核对实际文件的命名、格式、尺寸预算和管线要求；没有测量或来源时标待确认。
4. 检查文件存在但找不到入链的“孤立候选”，记录已检索范围和未覆盖的加载方式。
5. 检查引用目标不存在的“缺失引用候选”，向工程核对动态加载、生成路径等情况。
6. 把未搜索到与不存在区分开；把静态证据与实际运行加载证据分开登记。
7. 为每个问题写明证据、偏差、影响、处置责任与下一步；不要自行删除孤立候选资产。
8. 只有实际完成且有证据的检查才可写“通过”；无法检查的项保持待确认并说明原因。

## 7. 定义可访问性分级与特性矩阵

保留完整分级枚举：**Basic / Standard / Comprehensive / Exemplary**。
明确来源主流程仅列 Basic/Standard/Comprehensive；Exemplary 出现在完整枚举中，但主流程未定义其准入条件。
不要把四级解释为来源已给出完整特性集合、递进承诺或验收阈值。

1. 依据项目目标与用户确认选择分级，未定时列待确认项，不自动套用某一级。
2. 将等级与色盲模式、重映射、字幕、文本缩放、输入需求建立特性映射。
3. 为每项记录等级适用关系、需求来源、UX 引用、状态、验证证据和缺口/责任。
4. 使用“支持 / 待实现 / 已验证”三种状态，按证据选择而非按愿望填写。
5. 仅在存在现有实现证据时标“支持”；未实现或待确认时标“待实现”，在缺口列说明实际情形。
6. 仅在实际执行相应检查并留存结果后标“已验证”；写明环境、方法、结果和证据位置。
7. 要求 UX 规格引用同一等级及矩阵位置，确保可访问性进入基础要求而非可选装饰。
8. 不擅自把某特性固定归入某等级，不编造四级特性门槛；来源不足时请求项目确认。

## 8. 自检与职责交接

- 检查九节完整、角色/环境/UI分别成节，且所有视觉要求能回溯项目输入或明确待确认。
- 检查逐资产规格含用途、风格、尺寸、格式、动画需求、AI 提示词，并与主清单关联。
- 检查命名、格式、尺寸预算有项目依据，技术美术需求与目标平台/管线对应。
- 检查孤立与缺失引用仅为证据支持的候选/结论，未运行的项目没有“已验证”标记。
- 检查四级枚举与前三级主流程的差异、UX 引用和特性状态均明确。
- 获授权后仅写指定路径，如 `design/art/`、`design/assets/`、`design/accessibility-requirements.md`。
- 回报实际路径、产出摘要、关键视觉决策、资产清单状态、待用户审批项、引擎/管线风险与下一步建议。
- 独立运行时直接交回职责负责人；有团队协作时发送给统筹，不依赖固定姓名或专用消息接口。
