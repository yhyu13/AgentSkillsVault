# docs/ 目录骨架（模板）

本目录放**可复用的方法文档**与**决策正本**。三条规矩：

1. **一份正本**：同一套内容只在一处是正文，其余地方只放指针（链过去，不复述）。
   复述 = 迟早漂移。仓内 agent 可加载的技能放 `.claude/skills/<name>/SKILL.md`，
   `docs/` 下同名文件只留指针。
2. **版本留档**：改一版另存新号（v1 → v2），旧版原样留着。评审要对比、复盘要追溯、换人接手要看演进。
3. **引用必须可达**：文档里的路径、锚点、行号引用都要能被 `scripts/check-refs.py` 验到。

## 建议布局

```
docs/
├── README.md            ← 本文件：目录说明与索引
├── <domain>/            ← 一个领域一个目录（正本在这里）
│   ├── README.md        ← 领域入口：现状、边界、下一棒任务
│   └── <artifact>.md    ← 具体产物
├── research/            ← 检索与事实层：来源分级、核实状态
└── decisions/           ← 决策记录（口径定稿 / 版本演进 / 被否决的方案）
```

## 目录职责

| 目录 | 放什么 | 不放什么 |
|---|---|---|
| `docs/<domain>/` | 该领域的正本：方案、报告、评审对账 | 一次性中间产物（放 `reports/` 或临时目录） |
| `docs/research/` | 检索结果与事实核实，按来源分级（1~4 级） | 未经核实的结论当事实写 |
| `docs/decisions/` | 决策正本：口径定稿、版本演进、被否决的方案 | 流水账 |
| `docs/pitch/`（若有） | 对外叙事材料：大纲、正文、路演稿 | 内部工作记录 |

## 写文档的硬要求

- **每个事实带来源级别**，未核实的写明状态（`已核实` / `计划` / `待补`），不要混用。
  状态标记能被写成机器可查的反例断言，就写成断言（见 `scripts/check-refs.py` 同级的验收器做法）。
- **交叉引用给具体位置**：`docs/x.md §2.2`、`` `docs/x.md:123` ``，不要只写「见 x」。
  被引文件一旦改动，引用要重新核对——评审回路会追这一条。
- **引用别人的产物前先确认它在仓里**：`docs/…`、`specs/…` 里的路径要真实存在；
  工作树路径（`wt/<slice>/…`）是那时的仓根相对写法，新文档里直接写仓根相对路径。
- **有意缺失的引用要声明**：在文件头写 `<!-- refcheck:skip-file -->` 并说明原因，产物入库后移除声明。

## 索引写法

索引表里每一行都要能回答「去哪看」，且链接必须可达：

| 条目 | 正本在哪 | 何时用 | 何时别用 | 来源 |
|---|---|---|---|---|
| `<name>` | `[正本路径](../正本路径)`（**agent 可加载**）或 `本目录/<file>.md`（人读镜像） | …… | …… | …… |

「正本在哪」这一列不许填「人读镜像」当正本——除非它真是唯一的正本；否则写清哪份是 loadable 的、
哪份是给谁看的。
