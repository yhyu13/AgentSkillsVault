# 文档目录规则与正本纪律

## 一份正本，其余是指针

同一套内容出现两处，就会有两份漂移的副本。规矩：

| 位置 | 是什么 | 谁读 |
|---|---|---|
| `.claude/skills/<name>/SKILL.md` | **agent 可加载正本**（带 `name:` + `description:` 前置元数据） | agent（本仓会话直接加载） |
| `docs/<name>.md` | **人读镜像 / 指针索引** | 人（评审、交接、查证据） |
| 用户级 skill vault | **用户级安装真身**（四个 store 的源） | 本机所有会话 |

规则：

1. 人读镜像**不复述正文**，只留「想看什么 → 去哪」的表。
2. 人读镜像**不带同名 `name:` 前置元数据**——带了会被扫成第二个同名 skill id，
   于是同一套方法出现两个 id、各改各的，两份都不可信。
3. 仓内正本与 vault 正本**逐字节一致**，改动要同步两边（vault 侧跑 manifest → sync → verify 三步）。

## 引用必须可达，且要分级查

文档引用失准分三类，**检查手段不同**：

| 类别 | 例子 | 谁查 | 怎么查 |
|---|---|---|---|
| 可达性 | 指向不存在的文件 / 断链 / `file:line` 越界 / md 锚点不存在 | **机器必查** | `scripts/check-refs.py`（零依赖，只标准库） |
| 内容相符 | 文件存在，但列名/措辞/版本号与被引文件对不上 | **独立 reviewer** | 给可检查的标准，逐条核对 |
| 跨正本口径 | 两份正本对同一件事说法相反 | **独立评审 + 状态标记** | 评审回路；正本单一化 |

机器查不到的两类**不能靠 agent 自觉**——实现者不得给自己的 PR 出评级。

## 写引用时的规矩

- **给具体位置**：`docs/x.md §2.2`、`` `docs/x.md:123` ``，不要只写「见 x」。
- **工作树路径是历史写法**：`wt/<slice>/<rest>` 语义等于「那时的仓根下的 `<rest>`」。
  新文档直接写仓根相对路径；老文档里的这类引用应该改写（`check-refs.py --fix` 能机械替换）。
- **被引文件若本次被改动**，相关引用必须重新核对——这是跨正本口径漂移最常见的触发路径。
- **占位符不是引用**：`{a,b}.png`、`01–04.png`、`NN` 这类写法不该被当成真实路径去验。

## 忽略清单 `.refcheck-ignore`

只登记两类，且每条都要在 PR 正文说明理由：

```
# 外部仓路径（另一个仓里的文件）
scripts/office/validate.py
# 已登记为「待产出」的物料
poster/out/
```

**不得用它掩盖真实漂移。** 新增忽略项 = 承认这条引用不可达，是有记录的判断，不是「修好了」。

## 有意缺失的声明

文档整篇在讲「还缺什么」或指向尚未产出的物料时，在文件头写：

```html
<!-- refcheck:skip-file -->
<!-- 本文是「还缺什么」的清单，所列路径**有意尚不存在**。 -->
```

产物入库后**移除声明**，让检查恢复覆盖。

## 目录职责

见 `templates/docs/README.md`。一句话版本：

- `docs/<domain>/` 该领域的正本（方案、报告、评审对账）
- `docs/research/` 检索与事实层，来源分级 1~4 级，未核实的写明状态
- `docs/decisions/` 决策正本：口径定稿 / 版本演进 / 被否决的方案
- `reports/` 一次性报告与证据（截图、跑批结果）
- `specs/<编号>-<slug>/` 每个目标的 spec / plan / tasks 三件套

## 状态标记

全文只允许三种状态，不许混用：`已核实`（有 2~3 级来源）/ `计划`（方案定了没验证）/ `待补`（依据未定）。

交稿前只改状态、不改措辞。状态标记一旦能写成**反例断言**（把违规措辞当反例喂给验收器，
验收器必须拒绝），就写成断言——人眼盯不住，机器能盯住。
