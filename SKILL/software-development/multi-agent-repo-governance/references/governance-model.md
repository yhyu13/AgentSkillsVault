# 治理模型：五条规则为什么这样定

> 这份文档解释**为什么**，以及在什么条件下可以偏离。规则条文在 `templates/AGENTS.md`。

## 三层门禁

```
H1  冲突与基线     → 能不能合（客观事实：有没有冲突、主线脏不脏、分支含不含最新 main）
H2  所有权与正本   → 该不该合（边界：有没有写别人切片的东西、有没有动治理面）
H3  分级与授权     → 谁来合（绿=agent 自动、黄=要人批、红=只有 admin）
```

三层**不互相豁免**：H1 过了不代表 H2 过了，H2 过了不代表 H3 过了。
每层都要单独出一次结论，并且**结论有保质期**（H1 的 TTL 是 10 分钟）。

## 为什么 H1 要看「主线脏不脏」

冲突试算（`git merge-tree`）只能比较**已提交的树**。如果主线工作树里有未提交改动，
试算出来的「0 处冲突」是假的——因为它假设了主线工作树的内容，而真实合并时那些改动还在。
所以规则把「主线有 ≥1 个脏文件」直接判 `BLOCKED`，并明文禁止「用干净的 merge-tree 结果
去抵消主线脏这一事实」。

这也是为什么 H1 禁止 `git stash` / `git clean` / `checkout --`：它们是「把用户的改动藏起来或删掉」
来让检查通过——检查通过不等于问题消失，只是被藏了。

## 为什么 H1 的结论有 10 分钟 TTL

R1 的结论是对「某一时刻」的快照。10 分钟后，主线可能已经推进、PR 可能已经推了新提交、
工作树可能又脏了。规则把失效事件列死（主线新提交 / 工作树变脏 / PR 新 push / 远端 main 新提交），
并要求**调用方**（不是脚本）按时间戳判定过期。脚本无状态、不缓存、不判定过期——否则脚本会拿着
一份过期结论说「通过」。

这条在多 Agent 并行合并的仓里尤其重要：主线每几分钟就动一次，TTL 不是形式。

## 为什么 H2 的「所有权」必须是登记制

并行切片的根本冲突是**两个 agent 同时写同一个文件**。解决方案不是靠 agent 自觉，
而是靠**可机判的登记**：issue 切片表里用固定格式登记每个切片的独占范围
（`- \`<slice>\` → \`<dir1>\`、\`<dir2>\``），机判逐个文件核对 diff 是否越界。

登记制的好处是**边界变了就是 PR 内容变了**：切片表改了，ownership-check 的判定输入就变了，
必须重新跑一遍。如果靠 agent 自觉，改边界时没人会想起来重跑。

登记格式必须固定成上面那行，是因为机判用 `sed` 按 `- \`<slice>\` → ` 解析——
写成表格，机判读不到，于是「登记了但判定为越界」，是最容易踩又最难查的坑。

## 为什么 H3 要分三档

单看「有没有 CI 绿」不够：文档改动和治理面改动的风险不是一个量级。
三档把「谁来批准」「谁来执行」分开：

| 档 | 谁批准 | 谁执行 merge | 典型场景 |
|---|---|---|---|
| 绿 | reviewer subagent（机判复核） | agent 自动 | 纯内容切片，越界 0，CI 全绿 |
| 黄 | user（人） | user 批准后 user 或 agent 代执行 | 触碰共享正本、reviewer 有非阻塞意见、需人工目验 |
| 红 | admin（主账号） | **仅 admin**；agent 禁止执行 | 改治理面、越界、force-push、删正本、凭据 |

「谁批准」和「谁执行」分开，是为了支持**代执行**：user 批准后，agent 可以代跑合并，
但必须在 PR 评论里留批准引用——这样事后能查清「谁批的」。

**只升不降**是防「agent 自我降级」：红/黄不能被 agent 或 reviewer 降成更低档，
降级唯一路径是 user/admin 在 PR 评论写明原等级、新等级、理由、改判人。

## 为什么独立评审（FR-608）不能省

机判读的是**结构**：提交格式、路径存在性、文件是否越界。它读不出**语义**：
「引用指向的文件存在，但里面的列名和你写的不一样」——机判无能为力；
「两份正本对同一件事说法相反」——机判更无能为力。

所以必须有**独立上下文**的 reviewer：给它可检查的标准（「AC-13 必须是真实表格行」），
而不是「好不好」。实现者不能给自己的 PR 出评级——自己写的东西自己看不出来。

评审的产出是可被脚本解析的 `GRADE=` 块，写进 PR 评论，这样「合不合格」有留痕、可回溯。

## 三条不可协商的底线

1. **不得自行关闭 issue**：关闭是对 user 承诺的终态，只能由 user 授权。
2. **不得用 `--no-verify` / 强推 / 篡改检查记录**：这三样都会让「检查通过」失去意义。
3. **不得把 2 个切片塞进 1 个 PR**：并行切片的边界一乱，越界检查就失去判据。
