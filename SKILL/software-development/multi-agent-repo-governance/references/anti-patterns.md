# 反面清单：真实踩过的坑

每条都是「症状 → 根因 → 对策」。多数不是 agent 笨，是流程缺了一环。

## 1. 同步基线的 merge 提交让门禁永久变红

**症状**：PR 的 commit-lint 一直红，但作者说「我什么都没改错」；分支明明包含了 main 最新提交，
R1 却过不了；改了提交历史也不管用（不能强推）。

**根因**：R1 要求「PR 分支包含 main 最新提交」→ agent 用 `git merge origin/main` 同步 →
默认 message 是 `Merge remote-tracking branch 'origin/main' into feat/x` → 既不合 `type(slice): 主题`，
也没有 `Refs: #N` → commit-lint 红 → 失去绿级 → 要人批 → 而 R1 又禁强推 → **流程自锁**。

**对策**：同步基线时给合规 message：

```bash
git merge origin/main -m "chore(<slice>): 同步 main 基线" -m "Refs: #<issue>"
```

合并提交也是提交，同样受 §4 约束。

## 2. 机判只从正文 grep 结论，等于没查

**症状**：`test_fail` 恒为 0，不管正文里写「失败 12 个」；引用死链一路放行。

**根因**：判定写成 `grep -oE '失败[ ]*[0-9]+[ ]*(项|个)'`——从 PR 正文抽数字，不重跑命令。
正文是人写的，会写错；更糟的是**它压根不检查**。

**对策**：判据必须**真跑命令**。`refs-check` 就是为补这个洞加的第 5 道闸门。
判据抽自正文的地方，只能用于「人已经声明的事实」，不能当机器检查。

## 3. 引用指向不存在的文件，全绿放行

**症状**：CI 全绿，合并后文档里的链接 404。

**根因**：没有引用检查闸门；机判不查路径存在性。

**对策**：`scripts/check-refs.py`。注意它要处理三种「看起来像路径其实不是」的情况：
占位符（`{a,b}.png`、`01–04.png`、`NN`）、外部仓路径、工作树路径。

## 4. 引用指向存在但内容不符（假自证）

**症状**：文档写「对照表列头是形态/代价/判据/用户角色」，被引文件里其实是「维度/我们/他们/判断」。

**根因**：机判只判可达，不判语义；且「引用」被当成了免检区。

**对策**：独立 reviewer 逐条核对**被引文件的实际内容**。给 reviewer 的标准要可检查
（「对照表列头逐字比对」），不要给「好不好」。

## 5. 「实例」指错位置，结论跟着错

**症状**：文档举例「同一份文档 2.2 节 vs 5.1 节自相矛盾」，但 5.1 节里根本没有那句话。

**根因**：真实矛盾其实是**跨文档**（大纲 v5 说「能跑通」、正文 v7 说「还在验证」），
被写成了文内矛盾；位置指错后，结论也错。

**对策**：写「证据」时把**位置和原文**一起钉死，评审按位置去核。这条对 skill 自己也适用。

## 6. 同一套内容两份正本，各改各的

**症状**：仓里同时有 `.claude/skills/x/SKILL.md` 和 `docs/skills/x.md`，
两边内容不一样，agent 加载的和人读的不一样。

**根因**：为了「给人看」在 docs/ 又抄了一份。

**对策**：正本收敛到可加载位置，docs/ 那份只留指针且**去掉 `name:` 前置元数据**。
再加一道检查：扫全仓找同名 skill 出现在两处。

## 7. 全员假红：账单封锁被误判成权限问题

**症状**：所有 workflow 失败，job `steps: []`、2 秒内结束；dev 同步连续失败、落后几十个提交。

**根因**：账号级账单封锁（annotation 原文：*recent account payments have failed or your
spending limit needs to be increased*）。看起来像 token 权限问题，但修法完全不同。

**对策**：先看 check-run 注解原文（`gh api .../check-runs/<id>/annotations`），再分类。
`started_at` 与 `completed_at` 只差 1~2 秒 = 没拿到 runner。

## 8. R1 结论过期了还在合

**症状**：PR 正文贴的 `MAIN_HEAD` 与当前 `git rev-parse main` 对不上；或者贴的时候是绿的、合的时候已经红了。

**根因**：结论是快照，仓在并行合并，主线每几分钟动一次。

**对策**：TTL 10 分钟 + 失效事件清单；**合并动作与最后一次 R1 之间不要插别的事**；
R1.1 明文禁止「先合再补检查」。

## 9. 忽略清单变成垃圾桶

**症状**：`.refcheck-ignore` 越写越长，最后把所有出问题的路径都加了进去。

**根因**：忽略没有成本，于是被当成「消错」手段。

**对策**：忽略只登记两类（外部仓路径、已登记待产出的物料）；每条忽略都要在 PR 正文说明理由；
**把「加了忽略项」当成有记录的判断，而不是「修好了」**。

## 10. 自动修复把引用改错地方

**症状**：形如 `wt/<slice>/index.html` 的引用被自动改成 `index.html`，指向了仓根另一个同名文件。

**根因**：自动替换只认「去掉前缀后路径存在」，没认「语义上是不是同一个文件」。

**对策**：自动替换必须**唯一命中**才动手，否则只给建议不改。
宁可让人多看一眼，也不要让工具批量制造漂移——工具造成的漂移比原本的更难查。
