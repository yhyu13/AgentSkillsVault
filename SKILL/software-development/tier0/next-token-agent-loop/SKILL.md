# 下一块，然后循环

模型补下一块文本。循环把工具结果送回去，才成为智能体。先写账本，再改提示、工具或循环。上下文被压缩或换人时，只读账本，不靠聊天记录回忆。

## 账本

在任务目录建 `agent-loop/`。四个文件就是交接材料：

| 文件 | 记什么 | 完成时能看到 |
|---|---|---|
| `CASE.md` | 失败输出、期望、步数上限、使用的消息格式 | 上限是一个整数，格式是这一次请求实际用的名字 |
| `SOURCES.md` | 每个有问题的事实来自权重、请求，还是历史 | 三列都有原文，缺的那列写“没有” |
| `TRACE.md` | 每一步的请求、停止原因、执行结果、追加进历史的文本 | 最后一步写明返回或到顶 |
| `CHECK.md` | `scripts/check_case.py` 的退出码和输出 | 退出码是 0 |

模板在 `templates/`。`scripts/check_case.py` 检查这四份，不调用模型。

```powershell
python scripts/check_case.py <任务目录>/agent-loop
```

退出码 0 才算这份排查做完。非 0 时，先补它点名的文件，不要改判定。

```text
PASS facts=1 limit=4
FAIL step limit is not a positive integer
FAIL missing TRACE.md
```

第一行是完整账本。空模板先失败在步数上限不是正整数。缺文件时失败行写出文件名。三列都写“没有”也会失败：事实必须至少在权重、请求、历史之一里有一句不少于 8 个字的原文。

## 先标出这块文本从哪来

把有问题的那次输出写进 `SOURCES.md`，每行一个事实，三列都要有原文：

1. **权重里就有的。** 训练数据能支撑的事实。1952 年的总统属于这里。
2. **这次请求带进去的。** 系统消息、工具定义、身份说明、发送前放进提示的 git 状态。
3. **历史里刚刚追加的。** 用户消息，以及上一次工具的输出。

三份里都没有的事实，模型不能可靠答出。今天的日期、仓库里的文件、最近发布的包版本，都要落到第 2 或第 3 份。不要用“换一个更聪明的模型”代替这个缺口。

## 核对模型真正看见的文本

接口侧的 JSON 消息数组，不是模型补全时看见的文本。把实际格式的一个片段写进 `CASE.md`。

- 标出回合边界：system、user、assistant。ChatML 用开始和结束标记；Harmony 是另一套格式。用这次请求实际采用的那一套。
- 用户回合结束后，请求要先打开 assistant 回合。没有这个开头，补全没有规定的下一步。
- 特殊标记是训练时认得的，不是注释。少一个、多一个，都会改变下一块猜什么。

## 看下一块，不看整段

模型不能回头删已写出的 token。`TRACE.md` 记录这次采样里实际出现的前几个候选；没有采样器输出时写“未采样”，不要补一个看起来合理的概率。

这些数只属于 MegaDev 第 1 课那一次演示，不是别的模型的测量值：certainly 约 66%，sure 与三个反引号各约 14%，随机数 8、7、9 约 20%、18%、16%。演示把 `isEven(7)` 写成 true，因为错句已经追加，不能回头删。

- 错句已经进入历史，就只能在后面追加更正。
- 推理模型的思考痕迹是例外：它可以对着自己说“不对”，再换路。正式输出没有这个例外。
- 需要真随机时，用工具取，不用模型抽。

## 工具是一段约好的文本

模型只有在请求里被告知写法时，才会发出工具调用。

1. 系统消息写明：工具存在、语法、能拿到什么。没写时，模型会改口说自己看不见文件系统，即使外层其实能执行。
2. 选定停止序列。演示用 bash 的结束标签。生成到这里必须停，一次接口调用结束。
3. harness 在自己所在的电脑上执行，不在模型里执行。
4. 没有命令，就返回文本。有命令，就执行。失败记成 invalid input，不要省略。超时、权限失败、空输出分开写，不都叫 invalid input。
5. 把输出以 user 角色追加进完整历史。下一次补全必须看见它。

一次回复可以含多个工具块。逐个解析，汇总后再追加。

## 循环的停止条件

一次工具调用后停住、等人再发，那不是智能体。智能体是循环。

- `CASE.md` 写一个整数上限。第 1 课的演示是 40 步；那是那次代码的上限，不是推荐值。讲师原话是步数大概比回合更合适，但在那个例子里差别不大。不要写成普遍规则。
- 每次请求带上：模型、输出上限、系统消息、思考设置、工具、全部消息历史。历史不能省。
- 停止原因不是工具调用，就在 `TRACE.md` 写“返回”。是工具调用，就执行并把结果追加，进入下一步。
- 到了上限仍是工具调用：停止，在 `TRACE.md` 写“到顶”，把最后一条历史路径写出来。不要再发一次请求，也不要把到顶写成成功。

## 算上下文时把沉默的部分算进去

报告 token 时在 `TRACE.md` 分开写：用户原文、系统消息、工具目录、发送前注入、历史里的工具结果。没有计数器输出的那一列写“未计数”。

第 1 课里，工具搜索开着时，一句 hi 约 21,000 token。这是那一次 harness 的计数，不是短消息的通常长度。

## 判定对照

同一份失败输出，只允许一个主缺口。先选表里最靠上的一行，再写账本。不要同时改提示、工具和循环。

| 看见的输出 | 主缺口 | 下一步只改这里 |
|---|---|---|
| 说自己看不见明明能执行的资源 | 请求里没有工具语法 | 系统消息补存在、语法、能拿到什么 |
| 写出了工具文本，但没有执行 | 没有停止序列，或 harness 没接 | 生成到结束标记就停，由 harness 所在的电脑执行 |
| 执行了，下一句仍说不知道 | 结果没有追加 | 把 stdout 或错误以 user 角色写入历史 |
| 事实在训练后才变化 | 只存在于权重的旧副本 | 用工具取当前值，不换一个“更聪明”的模型 |
| 前一句错了，后面照着错的继续 | token 已经追加 | 在后面更正，不指望它删掉前面 |
| 步数用完仍在调用工具 | 到顶 | 停止并记录最后一条历史，不把到顶写成成功 |

六行都对不上，就在 `CASE.md` 写“未归类”，并贴出模型看见的原文。不要为了归类去改写输出。

## 续跑

换人、压缩上下文或换一台机器时，不重读聊天。按这个顺序读 `agent-loop/`：

1. `CASE.md`：失败输出、期望、步数上限、消息格式。
2. `SOURCES.md`：哪个事实还写着“没有”。
3. `TRACE.md`：最后一步是返回、到顶，还是停在半路。
4. 停在半路，就从最后一条已追加的历史继续。不要重跑已经有结果的命令。

一个没有参加前几步的人，只凭这四份文件必须能说出下一步。说不出，就是账本缺行，不是记忆问题。

## 完成标准

`python scripts/check_case.py <任务目录>/agent-loop` 退出码是 0。脚本会核对：

- `SOURCES.md` 每一行都有权重、请求、历史三列，而且不能三列都是“没有”。
- `TRACE.md` 有步数上限、返回或到顶，以及失败工具的错误原文。
- 成功的工具输出出现在下一步的请求里。
- 演示数字没有被写成所有模型或所有 harness 的常数。
