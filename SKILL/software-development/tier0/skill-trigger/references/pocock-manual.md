# Matt Pocock 的缺失手册

来源：BV1opMh6TEgL。英文原片 1242 秒，标题是 *The Missing Manual: How to Write Great Skills*。中文上传标题是「Skill实战：如何构建高质量的Skill」。公开流 480p。中文识别模型把英文听乱，下面只用英文识别稿。

| 规则 | 时间 | 怎么用 |
|---|---|---|
| 先决定用户调用还是模型调用 | 310–315 秒 | 描述不是每份 Skill 的必选项 |
| 模型调用的描述每次请求都占上下文 | 322–347 秒 | 一百条描述就是一百段固定成本 |
| 模型即使描述匹配，也可能不调用 | 395–420 秒 | 这是他选择用户调用的原因，不是禁令 |
| 他不想为“是否按时触发”做评测 | 419–438 秒 | 与 Perplexity 的负例评测相反；两套都保留，按调用方式选 |
| 正文分成步骤和参考 | 450–484 秒 | 可以只有步骤，或只有参考 |
| 每次都用的参考留在主文件 | 约 591–671 秒 | 不是所有资料都外置 |
| 只在一个分支用的资料放到指针后面 | 650–697 秒 | 主文件只留一行指针 |
| 用一个引领词压缩要求 | 742–768 秒 | 例子是 vertical slice；再到推理痕迹里看它有没有出现 |
| 看得见下一步时，当前步会被跳过 | 955–1006 秒 | 把后续阶段拆出去 |
| 删除测试识别空操作 | 1105–1133 秒 | 删掉后行为不变，就不是 Skill 该写的 |
| 多人只加不删会留下沉积 | 1058–1105 秒 | 不承重、过期或不属于这个分支的内容删掉 |

“一百条描述”是他的举例。引领词必须能在这次运行的推理里看见，不能只写进正文就算生效。
