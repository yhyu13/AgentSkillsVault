# Perplexity 六步

来源：BV1rb5y6wEJV，讲者慢学AI，554 秒，精读 Perplexity《Designing, Refining, and Maintaining Agent Skills at Perplexity》第二期。公开流只有 640×480，没有官方字幕。下面是转述，不是原文。

| 步 | 讲者的说法 | 评分时怎么用 |
|---|---|---|
| 0 评测 | 真实请求、已知失败、邻近但不该加载的请求 | 没有负例，不能因为正文完整给高分 |
| 1 描述 | 路由触发器；建议以 load when 开头，控制在约 50 词 | 50 词是讲者转述，不是本库硬上限 |
| 2 正文 | 写判断、坑和负例，不重复模型已会的步骤 | 通用流程算上下文税 |
| 3 目录 | 脚本放确定逻辑，重资料条件加载，模板固定输出 | 文件多不自动加分，位置错要扣 |
| 4 迭代 | 一个分支上跑代表性请求，看有没有误加载和相邻回归 | 描述改词后必须重跑正负例 |
| 5 发布 | 带着行为证据上线 | 结构检查通过不等于可以发布 |

讲者把“乱加载”听成“负力”，把 eval 听成 Evil，把 body 听成“证文”。这些识别错误不进入规则。

下一期才讲上线后的维护。本期没有给出维护步骤，不从标题补。
