# 四个打分维度

一次运行只给同一份会话打一遍标签。每个维度一个标签 + 1–3 句理由。理由里要有可核对的动
作（重跑次数、改错的文件、用户纠正了几回），不要写「整体感觉不错」。

标签与分值固定，不要自创：

| 维度 | 标签 | 分值 |
|---|---|---|
| 效率 `efficiency` | `highly_efficient` / `mostly_efficient` / `mostly_inefficient` / `highly_inefficient` | 1.0 / 0.8 / 0.4 / 0.2 |
| 代码质量 `code_quality` | 同上，另加 `insufficient_evidence` | 同上，`insufficient_evidence` 不计分 |
| 流程遵循 `procedure_compliance` | 同上四档 | 1.0 / 0.8 / 0.4 / 0.2 |
| 简洁 `verbosity` | 同上四档 | 1.0 / 0.8 / 0.4 / 0.2 |

## efficiency：有没有直奔结果

评的是「从提问到可用结果」的总成本，包括返工、用户盯人成本、多余步骤、串行化。

| 标签 | 什么情况 |
|---|---|
| `highly_efficient` | 路径直接：没有重复读或重复跑，独立步骤并行，没有返工 |
| `mostly_efficient` | 滑了一两次（重复读、过早重试、小修正），没有连带成本 |
| `mostly_inefficient` | 反复浪费，或造成一轮返工，而早期检查本可避免 |
| `highly_inefficient` | 浪费主导整场：同一缺陷跨轮重做、反复被用户纠正、长时间打转 |

判据是「同样工具、同样信息下，一个称职工程师需要多少步」，不是「在当时上下文里看着难免」。
看着难免但一条前置检查能避免的，照样扣分，理由里点出那条检查。

## code_quality：改得对不对

只评有代码改动的会话；没有改动记 `insufficient_evidence`，不进均值，也不判失败。

看四件事：改动是否回答了需求；是否引入新的缺陷面（未处理的分支、吞异常、隐式类型）；是否符合
仓库既有约定；有没有跑过能证明它工作的检查。

| 标签 | 什么情况 |
|---|---|
| `highly_efficient` | 改动最小、符合约定、有检查佐证 |
| `mostly_efficient` | 有小瑕疵（命名、注释、少一个边界），不影响正确性 |
| `mostly_inefficient` | 能跑但有遗留问题，需要一轮返工 |
| `highly_inefficient` | 改错方向、破坏既有行为、或明显跑不过却宣称完成 |

## procedure_compliance：按没按说明做

先确定这次会话**适用**哪些说明（仓库 AGENTS.md、被触发的 Skill、用户当场的流程要求），再逐条看
有没有照做。没有适用说明时，记 `mostly_efficient` 并在理由里说明「无适用说明」，不要凭空扣分。

典型扣分：跳过了要求的前置检查；该问的不问自己猜；该停的确认点没停；交付格式不符合约定。

## verbosity：说得多不多

评的是输出里对结果没有贡献的部分：复述用户的话、重复自己、把执行细节当结论、无必要的清单。

| 标签 | 什么情况 |
|---|---|
| `highly_efficient` | 只给结论、证据与下一步 |
| `mostly_efficient` | 有少量铺垫，不影响阅读 |
| `mostly_inefficient` | 一半以上是噪音，关键结论要自己找 |
| `highly_inefficient` | 结论被埋或缺失，篇幅主要在处理过程复述 |

不要因为「写得详细」就扣分：详细但有信息量的解释属于结果的一部分。扣的是重复与空话。

## 理由怎么写

一句话说清**最主要**的浪费 + 一个粗计数 + 可修的原因：

> 同一测试跑了三轮才通过（3 次 `pytest`，两次失败原因相同），缺一条「先本地跑目标测试」的前置检查。

不要写「效率一般」。理由会被拿去当证据，写不出具体动作的评分不能作为修改依据。

## 批量与并行

- 50 个会话以内一批做完；超过 50 个按 20 个一批。
- 允许委托本地子代理并行，条件是：会话内容留在本机；每个子代理只拿到 rubric 与会话本身；回收后由主流程统一校验标签。
- 主流程必须自己读一遍被引用的片段，确认引用真实存在，再写进证据。

## 与总分的关系

原始均值经 `curve(x) = 0.5 + 0.5x` 曲线化后进入总分。曲线化只是把「四档离散标签」拉开一点，
不改变排序，也不用来美化分数。总分公式见 SKILL.md 第 3 步。
