# 旁白与字幕

口播是这门课的第二份讲稿，不是页面文字的朗读。它要有自己的节奏：一句一个动作，
说完就停，让画面接上。

## TTS 契约

| 项 | 值 | 备注 |
|---|---|---|
| 引擎 | `edge-tts`（免 API key，但**要联网**：走微软在线端点） | 音色稳定，时间轴可直接取；断网会直接失败，不会静默降级 |
| 音色 | `zh-CN-YunyangNeural` 男声 / `zh-CN-XiaoxiaoNeural` 女声 | 一门课只用一种，不要中途换 |
| 语速 | 1.0（默认） | 实测 5.08 字/秒；按 5.0 估算，留 2% 余量 |
| 采样 | 24 kHz 单声道 wav | 交给 ffmpeg 前不转 mp3，避免二次压缩 |
| 粒度 | 一句一次请求 | 整段合成无法拿到句级时间戳 |

**时长预算**：目标秒数 × 5.0 = 口播字数。反过来说，写完一集先数字数：
3909 汉字 ÷ 5.0 ≈ 13 分钟纯语音，落在 6 集 17.5 分钟的成片里，说明有 4.5 分钟留白。
留白低于 10% 的集，观众会觉得被追着念。

## 断句

```python
SPLIT = re.compile(r"(?<=[。！？；!?;])")
```

- 按句号、问号、感叹号、分号切。逗号不切——中文逗号两侧语义还连着，切开会得到半句话。
- 切完把短于 8 个字符的碎片并到下一句，否则会出现「但是。」这种一闪而过的字幕。
- 一句对应一条字幕线索。一页可以有 1–4 句，页在整段旁白期间保持不变。
- 单句上限 36 个汉字（两行 × 18 个汉字；标点不计宽度）。超了在语义处拆，不要靠提高语速解决。

## 时间轴

每条字幕需要 `start/end`，页需要 `[in, out]`。做法：

1. 合成时逐句拿到音频时长，累加得到 `start/end`，句间插入 0.3–0.6 秒静音。
2. `timing.json` 里每段带 `slide` 索引（句子 → 页），页面在第一个属于它的句子开始时切。
3. 页切换用 0.25 秒的淡入/位移，不能用硬切——旁白还在念上一句时画面已经换了，观众会晕。
4. `attach_slides.py` 的作用就是校验「段数 == 句子数」，不一致直接报错，不要静默补零。

## SRT 规范

| 项 | 阈值 | 为什么 |
|---|---|---|
| 每行汉字 | ≤ 18 | 1280 宽、36 px 字号下的实测可读上限 |
| 每屏行数 | ≤ 2 | 三行会压住画面底部文案 |
| 单条时长 | ≥ 1.2 秒 | 低于 1.2 秒读不完；宁可合并相邻短句 |
| 相邻条重叠 | 0 | 重叠会让播放器闪烁 |
| 时间戳格式 | `HH:MM:SS,mmm` | 逗号是 SRT 标准；闸也接受点号（部分工具的输出），但那只是兼容，不是标准 |

长句处理顺序：先在标点处拆 → 仍超长再在语义停顿处拆 → 最后才缩字号（且不低于 36 px）。
行末可以留逗号、顿号（断行本来就在这些位置）；不要留句号。

## 响度

链式处理，顺序不能换：

```
acompressor=threshold=-26dB:ratio=3.5:attack=5:release=150
loudnorm=I=-14:TP=-3:LRA=11
volume=1.28
alimiter=limit=0.85:level=disabled
```

- 单遍 `loudnorm` 在 2–3 分钟的短片实测只到 **−15.4 LUFS**，到不了 −14。补 `volume=1.28` 才稳。
- 限幅必须**在最后**，且必须写 `level=disabled`。`alimiter` 默认的自动电平会把峰值
  重新抬到 0 dB：实测旧顺序（限幅 → 增益）交付的 6 集成片真峰值为 −0.6～0 dB，
  全部越界；改成上面的顺序后是 **−1.4 dBTP / −14.9 LUFS**。
- 验收读回 `Input Integrated` 与 `Input True Peak`：−14 ±1 LUFS，TP ≤ −1 dB。
- 旁白是唯一音轨时也要过这条链；有 BGM 时 BGM 压在旁白下 12–18 dB。

## 字幕烧录

- 交付两份：内嵌字幕版（`mov_text`，`language=chi`，默认开启）与 `-clean` 无字幕版。
- 内嵌用软字幕，不要烧进画面——观众要能关。需要烧录时另出一份 `-burn`，不要覆盖原片。
- 字幕底边距画面底部至少 5% 高度。实测发现过字幕压住页面底部说明文字的情况，
  这类问题机器闸看不出来，只能抽帧目视。
