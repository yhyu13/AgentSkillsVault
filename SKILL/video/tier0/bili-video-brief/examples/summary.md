# 示例：一支 9 分钟工具测评的摘要骨架

原片：BV1xz8Y6SEX1《多Agent瓶颈是人类注意力，是时候使用 Herdr 了》· 562 秒 · 中文
这份示例只演示结构与口径写法，完整稿在原项目里。

## 一分钟版

当程序员从开一只 Coding Agent 变成同时开四五只，最先不够用的不是算力，是注意力：切终端、查岗、等授权，思路被打断。
Herdr 保留真实 PTY、窗格、SSH 和持久会话，再给终端补上 agent 状态感知和 CLI 控制。
代价是它只做「容器」：不做文件隔离、没有任务依赖图、状态检测会误判，验收仍然是人。
开了两只以上 agent 并且关心谁在等授权的人该看；只开一个 shell 的人可以跳过。

## 分章要点

### 问题：注意力先爆了（00:02–00:42）

- 开一个 Codex 改页面、再起一个做 review，旁边挂着开发和测试服务；「账面吞吐量确实拉满了，但人的注意力却先爆了显存」。
- 传统终端只会打字符日志，看不懂 agent 状态，于是人变成赛博保安，每隔几分钟手动轮询。
- 代价不是那几秒，而是上下文切换拖慢判断。

### 模型：五个对象（01:31–01:55）

**关键概念表**

| 对象 | 含义 |
|---|---|
| Session | 管整套运行时 |
| Workspace | 对应一个代码仓库 |
| Tab | 项目里的视图 |
| Pane | 真实伪终端 |
| Agent | Pane 里被识别的编码进程 |

测试脚本只算 Pane；Codex 既是 Pane 也是 Agent——前者管字节流，后者管生命周期。

### 状态：注意力跟着事件走（03:05–03:48）

working / blocked / done / idle / unknown，未知不能当成成功或失败。状态向上聚合，后台工作区也能亮红灯。

## 口径表

| 说法 | 来源与强度 | 交付里怎么用 |
|---|---|---|
| 单个 Rust 二进制、无账户、无云面板、无遥测 | 讲者对产品形态的描述 | 写成「讲者描述」，未独立验证 |
| Screen Manifest、`herdr agent explain` | 讲者讲的机制 | 机制描述，命令按听写校正，未实跑 |
| 「瓶颈从生成能力转向调度质量」 | 讲者的判断 | 标为预判，不写成结论 |
| 终端里的 pid / workspace id | 示意值 | 画面与课件里标「示意」 |
