# 摘要契约

摘要不是观后感，也不是替讲者背书。它是一份**可核对**的读稿：每个判断都能回到原片某一秒。

## 五段结构

| 段 | 作用 | 长度 |
|---|---|---|
| 一分钟版 | 读者只读这段也能决定要不要继续 | 4–6 句 |
| 分章要点 | 骨架，带时间戳 | 3–12 章 |
| 关键概念表 | 名词、状态、命令、对象的定义；小节标题里要出现「关键概念表」四个字 | 一张表 |
| 口径表 | 每条重要说法的来源与强度 | 一行一条 |
| 未核验 | 版本、价格、可用性、未对照官方文档的部分 | 列表 |

## 八条硬规则

1. **时间戳是证据，不是装饰。** 每条要点后面写 `（00:42–01:31）`，范围覆盖它所在的那几句，不写「约 1 分钟」。
2. **比喻不当数据。** 「注意力爆了显存」「赛博保安」是讲者的修辞；写成观点引用，不写成结论。
3. **自述不当事实。** 「一个 Rust 二进制」「没有遥测」是讲者对产品的描述，摘要里写「讲者描述」，除非你亲自验证过。
4. **预判写明是预判。** 「瓶颈会从生成能力转向调度质量」是判断，不是测量；写成「讲者预判」，不要出现在本文结论里。
5. **没有数字就不造数字。** 原片没给播放量、用户数、性能数字，摘要里就不能出现。
6. **示意图要标示意。** 终端里的 pid、workspace id、文件数，只要不是原片原话，就在口径表里写「示意值」。
7. **区分机制与实跑。** 「Screen Manifest 匹配 UI 特征」是讲者讲的机制；`herdr agent explain` 是否真能这样用，没跑过就标注未实跑。
8. **一条要点只承担一个判断。** 不要把「它是什么、它不是什么、它适合谁」塞进一段。

## 引语怎么用

- 直接引语只取逐字稿里连续的原文，允许删掉语气词，不允许拼句。
- 中英混排时保留原文写法（`Blocked`、`PTY`），别翻译成「受阻」「伪终端」，否则读者对不上界面。
- 引语超过两行就改成转述，并保留时间戳。

## 常见失真（都要挡住）

| 失真 | 表现 | 改法 |
|---|---|---|
| 比喻升格 | 把「爆了显存」写成「内存不足导致崩溃」 | 还原成比喻，标「讲者比喻」 |
| 立场隐藏 | 讲者是产品使用者，摘要写成中立评测 | 开头一句写明讲者身份 |
| 结论前置 | 把讲者的预判写成文章结论 | 标「讲者预判」，并给出反例条件 |
| 概念漂移 | 全程把 Pane 和 Agent 混用 | 建概念表，全文统一 |
| 数字幻觉 | 自己补一个「大概三成开发者」 | 删掉，或写「原片未给数字」 |
| 时间戳漂移 | 所有要点都写「视频里提到」 | 回到逐字稿找区间 |

## 一分钟版的写法

四句结构最好用：

1. 原片在解决什么问题（一句）。
2. 它的核心主张是什么（一句）。
3. 它付出的代价或边界是什么（一句）。
4. 谁该看、谁可以跳过（一句）。

不要在一分钟版里出现专业名词的解释，那是分章要点的事。

## 口径表的写法

三列：说法 / 来源与强度 / 交付里怎么用。

- 来源与强度：讲者自述、讲者实测口吻、讲者讲的机制、讲者判断、可外部核验的事实。
- 「交付里怎么用」写动作，不写评价：写成「讲者描述」/「只作风险清单」/「不当数据」。

## 自检

- 随机抽三条要点，能否在 30 秒内从逐字稿里定位？定位不到就删或改。
- 把讲者名字遮住，摘要还成立吗？成立说明你没写出立场。
- 一分钟版里有没有一句话是「没有逐字稿就写不出来」的？没有就说明还太泛。
