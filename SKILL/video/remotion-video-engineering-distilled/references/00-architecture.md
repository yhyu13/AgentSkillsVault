## 2. 一条主链路，而不是一串工具名

```text
需求与约束 → 帧级合成 → 素材与特效 → 预览/配置
          → 本地或云端渲染 → 独立验收 → 交付与保留策略
```

- 单领域问题只读取对应分册；只有存在真实依赖时才扩展协作。
- 先确定分辨率、帧率、时长、媒体与运行环境，再决定编码、并发和云部署。
- 预览正常只是中间证据，不能替代真实渲染和平台验收。
- 文档与技能的通过，不等于视频已经渲染成功。

## 3. 原资料的依赖结构

资料记载该归档包含 130 个具有 `package.json` 的包，按生产依赖形成十层单向结构。其架构主线为：

```text
core → renderer / media → bundler / studio-server
     → cli → lambda / cloudrun
```

这用于理解职责边界，不是要求实际项目逐层安装全部包。包数、源码数和行数均是资料归档统计，不能用来承诺当前版本规模或性能。

## 4. 渲染链路的概念定位

原资料将渲染概括为：入口与配置 → 打包 → 服务产物 → 浏览器准备 → 打开页面 → 列举并选择合成 → 逐帧定位与捕获 → 中间帧写盘 → 视频编码 → 音频处理 → 音视频封装与起播优化。

实际路径可能受渲染选项、原生合成器和平台影响，不应把这条概念链当作所有版本都逐步执行的调用栈。具体参数与定位见渲染分册。

## 5. 证据等级

| 等级 | 本包如何使用 |
|---|---|
| 资料记载 | 从本地分册读取的能力、常量与路径；必须注明版本和出处 |
| 专业提炼 | 基于资料整理的操作步骤、诊断方法与检查清单；不是新增 API 事实 |
| 本次文档检查 | 检查结构、来源、链接与打包完整性；不证明外部命令或渲染成功 |
| 项目复验 | 在目标版本、操作系统、浏览器、媒体与云账号上实测 |
| 未能确认 | 缺失签名、冲突参数、现行价格/配额/许可等；保留问题，不猜答案 |
