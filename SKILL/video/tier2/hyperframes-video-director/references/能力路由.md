# 能力路由：先选交付物，再选制作路线

[整理稿入口](README.md) · [总览](总览.md) · [制作方法](制作方法.md) · [验收规则](验收规则.md) · [来源与依赖](来源与依赖.md) · [项目卡模板](项目卡模板.md)

## 1. 路由前先判断请求状态

1. 明确迁移既有 Remotion 源码 → `remotion-to-hyperframes`，不套新建意图访谈。
2. 既有工程明确要求渲染或发布，且已具备相应授权 → 只做导出或发布及必要输出核验，不重做 brief；若只有笼统的“继续”，先确认是否授权渲染/发布。
3. 提问、暂停、讨论方案 → 先回答；不自动改工程。
4. 既有工程的明确操作或局部编辑 → 只做被要求的检查、预览、修改等动作；编辑仅改目标及必要关联，不重新问整片 brief。
5. 有 `BRIEF.md` → 恢复已确认决定；有工程无 brief → 从分镜和现有文件恢复。
6. 真正的新建请求 → 进入意图收集与下表路由。

**主入口的完整需求才收集必要字段。** 已给出的内容不重复问；一次只确认一个会实质改变交付的未决问题。字幕身份、短动效澄清等专项问题交给所属路线。

## 2. 十条领域路线速查

| 要交付的东西 | 路线 | 必要输入 / 关键确认 | 不适用或应转交 |
| --- | --- | --- | --- |
| 现有 Remotion 工程的等价迁移 | `remotion-to-hyperframes` | 明确的迁移请求、可读 React 源码、可运行的原工程 | 随口提到 Remotion；反向迁移；任意源码讲解 |
| 可翻页、分段呈现、分支的演示稿 | `slideshow` | 先确认确实要 HyperFrames 可导航演示稿；大纲或现有页面 | 只说“幻灯片”却想要线性 MP4，先澄清 |
| 讲话视频的逐字字幕、主体遮挡字幕 | `embedded-captions` | 已确认的本地单主体讲话视频；探测后再选字幕身份 | 访谈/多人、硬切、坏转录、复杂手持；信息卡片不是字幕 |
| 讲话/访谈/播客的图文信息包装 | `talking-head-recut` | 本地视频；探测转录后确认画幅、布局、风格、卡片数 | 逐字字幕；按内容删段、换序或重新剪镜头 |
| 节拍决定画面的音乐视频 | `music-to-video` | 音乐文件、视频音轨或明确生成意图；投放位置/画幅；驱动画面的视觉概念 | 音乐只是背景；需要旁白或网站采集；仅因“有歌”就切路线 |
| 短、无旁白、运动本身的表达 | `motion-graphics` | 文字、数字、logo、图形或真实来源；专项最多一个澄清问题 | 长片、旁白解释；未确认平台兼容就承诺本机可用 |
| 真实 PR 的变更说明 | `pr-to-video` | PR 引用、讲解角度、受众；按真实变更量推荐时长 | 无 PR 内容的网站宣传；伪造提交、diff 或效果 |
| 产品宣传、站点展示或导览 | `product-launch-video` | 网站/brief/脚本；先分“营销”还是“如实展示”；脚本是否逐字配音 | 非产品知识解释转 faceless；纯代码变更转 PR 路线 |
| 文章、主题、笔记的无真人解释视频 | `faceless-explainer` | 要表达的主张、讲解角度、时长、位置；已有脚本是否逐字 | 产品推广转 product；现成 footage 的剪辑转 general |
| 自定义创作、素材编辑、自由组合 | `general-video` | 明确的画面目标、素材、格式与约束；也承接 `flow: companion` | 不是绕过专项门槛的万能兜底 |

时长是推荐而非凑时指标：motion 通常低于 10 秒、可到约 30 秒；product、faceless 常见 30–90 秒且硬上限约 3 分钟；PR 按变更量选段，上限约 3 分钟。字幕和 talking-head 路线支持任意长度，但仍要先验证转录与素材条件。

## 3. 容易选错的边界

### 3.1 三种“给讲话视频加东西”

| 需求 | 正确路线 | 对原片的承诺 |
| --- | --- | --- |
| 逐字字幕，强调文字与人物遮挡关系 | `embedded-captions` | Standard/Cinematic 不重调色、不剪原片；Theme 的底板反应是专项许可的例外 |
| 人名条、要点、引语、数据标注、侧栏 | `talking-head-recut` | 内容顺序和讲话时间轴保留；会重编码，画幅/布局可造成可见裁切 |
| 删掉一段、重排镜头、调整节奏或重混素材 | `general-video` | 属于真正素材编辑，须记录原片与输出对应关系 |

不要因为都用了“字幕”一词就选字幕路线，也不要把 talking-head 的“视频不动”理解为字节不变或画面绝不裁切。

### 3.2 产品、文章、PR 是三个来源体系

- **产品视频**：真实 UI/网站展示以 capture 或用户素材为证据；no-capture 只适用于允许的营销创作，不适用于假装如实展示原站。
- **解释视频**：视觉是教学性的设计；可合成文字、token、抽象图形。真实数据必须另有来源，不能把示意值包装成测量结果。
- **PR 视频**：内容来自真实 PR 与 diff；没有读取成功就不编造功能、文件、提交或修复结果。

### 3.3 `slideshow` 不是视频渲染管线

专项交付的是可运行工程、`SlideshowController` 所需的 JSON 数据岛，以及导航/分段呈现/演讲者能力。不能用 `hyperframes render` 把首个 composition 导出后声称整份演示稿已导出。若用户确实需要 MP4，先确认可接受的线性化方式，再另定制作与导出方案。

## 4. 流程方式不改变交付路线

### 4.1 三种模式

| `flow` | `storyboard` | 推导的 `mode` | 审阅方式 |
| --- | --- | --- | --- |
| `automation` | `no` | `autonomous` | brief 确认后按路线推进；最终渲染仍等待批准 |
| `automation` | `yes` | `collaborative` | 计划与静态分镜先审，再制作动态成品 |
| `companion` | `yes` 或 `no` | `collaborative` | 由 `general-video` 承接共创，保留专项输入与约束 |

- `flow` 决定管线归属；`storyboard` 决定审阅强度；`mode` 决定检查点行为。
- `companion` 不意味着可以绕过真实素材、平台或授权条件。
- 专项 route contract 若明确不适用 run-shape（slideshow、字幕、talking-head、motion），不机械套用通用两次询问。
- 修订提案不等于确认提案；“go”默认只批准当前检查点，不擅自改变已记录的 `flow` / `storyboard`。仅当消息明确列出完整 brief、全部默认值和“go”的确认范围时，才按其明确约定确认整份 brief。

### 4.2 哪些现在问，哪些延后

- 新建视频先确认会影响交付的输入、主张、投放位置与格式、受众/时长、角度；已确定的不再问。
- 产品先问“卖产品还是展示站点”；提供脚本时再确认 `VO_MODE` 是逐字还是可重构。
- PR 先读取真实变更量再推荐长度；不能先承诺“大 PR 必做满三分钟”。
- `embedded-captions` 先探测素材，再从自身 35 种身份的 catalog 推荐 2–3 种；不搜索 HyperFrames registry。
- `talking-head-recut` 先探测和转录，视觉四项在 Step 7 确认后，再最终定稿分镜。
- `motion-graphics` 最多一个澄清问题；不能把普通长视频访谈套给它。

## 5. 横向能力的调用时机

| 需要解决的问题 | 调用能力 | 不该误解为 |
| --- | --- | --- |
| 时间窗、源偏移、子合成、变量、媒体 seek | `hyperframes-core` | 只调 CSS 层级或 Studio lane |
| 选择动效语法、复杂场景、转场、runtime | `hyperframes-animation` | 所有片段套相同入场模板 |
| 主体姿态、推进/重取景、遮罩、SVG/3D | `hyperframes-keyframes` | 改动视频源片段的 in/out 或剪掉原片内容 |
| 品牌、构图、叙事、字体与节奏 | `hyperframes-creative` | 只有配色形容词，没有可执行约束 |
| 人声与音乐清晰度、FX、音量自动化 | `hyperframes-audio` | 用生成音乐替代混音；有声音就算完成 |
| 初始化、检查、采样、预览、导出 | `hyperframes-cli` | 命令示例等于实际执行成功 |
| 复用现成 blocks/components | `hyperframes-registry` | 所有路线都要搜 registry，或离线也能 add |
| 可继续编辑的时间轴、轨道、安全区 | `hyperframes-studio` | Studio 的组织规则就是渲染层级规则 |
| 本地素材、转录、复用、生成和处理 | `media-use` | 缺 provider 时仍承诺生成成功 |
| Figma 品牌与资产导入 | `figma` | 视频渲染时在线读取 Figma |

## 6. motion-graphics 的十个类别与门槛

本次文件核对确认以下 `categories/<类别>/module.md` 全部存在；这是入口存在证据，不是类别端到端实测。

| 类别 | 用途 | 制作前必须知道的限制 |
| --- | --- | --- |
| `kinetic-type` | 文字运动、标题节奏 | 字体与可读性先定，不能只靠夸张动作 |
| `stat` | 数字、计数、关键指标 | 没有万能 `stat-motion` block；合适时复用计数组件，否则手写 |
| `charts` | 图表强调 | 饼图/环形图/百分比等存在 registry 缺口，需手写；数值要有来源 |
| `logo-reveal` | 标识揭示 | 需要真实 logo/透明素材；不要手绘冒充官方标识 |
| `lower-thirds` | 人名条、角标、透明包装 | 明确目标 alpha 格式及编码器支持；不能仅改扩展名 |
| `maps` | 地理/位置/路线信息 | helper、浏览器、网络瓦片与地理合规依赖需单独核实 |
| `webpage` | 真实网页重点展示 | 真实 capture 失败不能伪造网页作降级 |
| `news` | 新闻/标题片段 | 真实文本与来源先核实；部分参考样例缺失，可按现有手写流程 |
| `tweet` | 真实社交帖子展示 | 需要真实帖子字段、头像/媒体；provider 未实测 |
| `asset-fusion` | 素材与图形融合 | 需要真实资产、锚点与绑定，不能把占位图当素材完成 |

**平台限制：**该专项声明 macOS Apple Silicon 或 Linux x64。当前 Windows 不在声明支持范围内；本次未运行以判断其必然成功或失败。不要擅自宣称已支持。

**缺文件的边界：**本次未找到 `motion-graphics/phases/source/resolve.mjs`；但 `media-use/scripts/resolve.mjs` 实际存在。不能据此说整个素材解析能力缺失。地图 helper、grounding 文件存在，也仍需依赖和输出验证。

## 7. 无法唯一分流时

只问造成分叉的那个问题，例如：

> 这份演示稿需要保留翻页和演讲者模式，还是导出为自动播放的线性 MP4？

在答复前可记录候选路线与各自影响，不先搭建工程，也不替用户选择交付形式。
