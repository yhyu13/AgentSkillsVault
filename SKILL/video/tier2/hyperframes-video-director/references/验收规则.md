# 验收规则：每一步都有与它匹配的证据

[整理稿入口](README.md) · [总览](总览.md) · [能力路由](能力路由.md) · [制作方法](制作方法.md) · [来源与依赖](来源与依赖.md) · [项目卡模板](项目卡模板.md)

> 本次只验收整理稿本身。下文是未来视频项目的检查清单，所有示例命令均未在本次执行。不能把“检查通过”写成“视觉已确认”，也不能把“已导出”写成“已发布”。

## 1. 状态与证据一一对应

| 状态 | 必要证据 | 不代表什么 |
| --- | --- | --- |
| `planned` | brief、路线、镜头/卡片计划、素材/依赖清单 | 工程已可运行、成片已完成 |
| `checked` | 实际检查命令、退出码、报告、被覆盖的时间点 | 用户看过或批准导出 |
| `previewed` | 实际可访问的预览、目标工程、视觉检查记录 | 视频文件已生成 |
| `rendered` | 真实输出路径、非空文件、渲染日志与规格探测 | 没有黑帧/错字幕/声音问题 |
| `verified` | 对最终输出的播放/采样/规格/同步验证 | 已上传或公开发布 |

只前进有证据的阶段。失败、跳过的检查、未验证的外部服务必须单列。发布、反馈上传、公开 issue 是独立授权动作，不在这条本地制作状态链中自动发生。

## 2. 制作前验收：先确认“能做对什么”

- [ ] 交付格式与路线一致；演示稿、字幕、图文包装、真正剪辑未混淆。
- [ ] 输入文件存在且可读，来源与使用权明确；原文件不会被未经授权覆盖。
- [ ] 输出画幅、fps、时长/时长策略、语言、声音要求已记录。
- [ ] 已确认的决定与模型建议分开；用户指定目标没有扩大。
- [ ] Node.js、FFmpeg/ffprobe、浏览器和实际 CLI/专项脚本的可用性分别记录。
- [ ] 需要登录、网络、模型下载、生成或上传的步骤有授权和缺口说明。
- [ ] 插件安装方式与命令入口已核对；不自动更新原技能，也不默默改用 latest。

`doctor --json` 文档明确**退出码总是 0**，必须检查 JSON 的 `ok` 与具体项目；不能只看命令成功返回就写“环境通过”。

## 3. Composition 静态检查

首轮 HTML 可用 lint 快速排错；最终统一使用 `check`，它内部再次运行 lint。不要在最终 check 前机械追加一次冗余 lint。

重点核对：

- [ ] 独立根与子合成模板形式正确；子合成 `<style>` / `<script>` 不被错误放在会被丢弃的 head 中。
- [ ] composition id、timeline key、挂载路径一致；组装后 id 唯一。
- [ ] 根尺寸、clip 时间窗、源偏移、子合成边界正确；没有超出根时长的无意截断。
- [ ] 不混淆 `data-media-start`（源内偏移）与 `data-start`（合成时间）。
- [ ] 所有 timed video 没有非法 timed 祖先；子合成 host 例外未误报。
- [ ] 音频 id 齐全，本地媒体与字体路径可读；无多余 `crossorigin`。
- [ ] 没有 CSS transform 与 GSAP 同属性冲突；没有对 `.clip` 的生命周期属性做 tween。
- [ ] 没有渲染关键实时钟、未固定随机数、网络、交互或游离 rAF。
- [ ] 静帧作品明确采用静帧策略；不为消除“无动画”警告硬塞漂移动画。

## 4. 浏览器检查：空报告不等于通过

`check` 在同一浏览器/seek 采样中检查运行时、布局、可选 motion 断言和文字对比度。

读取 `check --json` 时至少记录：

```text
ok
browserSkipped
lint / runtime / layout / motion / contrast / hdr / snapshots
```

- `browserSkipped: true` 时，空的 layout/motion/contrast **不是零问题**；先排除 lint 错误、崩溃或浏览器未启动。
- 默认只对错误返回失败；严格交付可加 `--strict`，让警告也阻断。
- 默认采样不能覆盖所有时刻；加入场景关键帧、转场边界和必要的密集采样。
- 检查普通文字对比度至少 4.5:1、大字至少 3:1（按工具规则），但通过比例仍需看真实背景、描边和动态叠加。
- 有意遮挡/溢出只在快照证明合理后标记到**最小具体元素**；不要在整个根节点加忽略标志掩盖其他错误。
- Canvas 内文字和像素不能只凭 DOM bbox 判断；需要看实际画面。

动画项目可增加匹配 HTML basename 的 `*.motion.json`，声明可见时间、前后顺序、在画布内、持续活动等断言。选择器拼错应报错，不可当作通过。sidecar 没有断言就不代表动效已被自动证明。

## 5. 视觉检查：看关键帧，也看运动关系

### 5.1 最少证明点

| 时间点/内容 | 要看到什么 |
| --- | --- |
| 首帧 | 没有意外黑屏、缺字、未加载字体或占位素材 |
| 每个场景中段 | 真实素材、主标题、数据与构图符合计划 |
| 入场/峰值/退场 | 主体动作、遮挡、裁切、重叠与转场符合意图 |
| 字幕/引语出现点 | 文字正确、时间正确、阅读停留足够 |
| 结尾前与最后一帧 | 最终锁定正确，没有无意复位、残影、空尾或黑尾 |
| 含视频的子合成 | 播放的是正确源帧，不是黑面板、静态首帧或错误时间 |

### 5.2 主观反馈翻译成可检查的问题

- “太乱” → 对齐、间距、同屏信息数、主次与运动竞争。
- “看不清” → 实际尺寸、对比度、背景遮挡、停留时间、字体覆盖。
- “不连贯” → 同一主体身份、方向、速度、父子变换与衔接边界。
- “假 3D” → z/相机位移、透视、遮挡与斜角证据，而非只有 scale。
- “像网页” → 视频媒介的尺度、层级、镜头构图和实际叙事密度，不是堆装饰。

`keyframes`/focused `--shot` 证明机制；`snapshot` 证明完整画面。辅助选择器的正确运动不能替代主体或整片的正确。

## 6. 音频验收：结构与听感分开

- [ ] 源文件、音轨角色、音量、FX 和分组明确；音频 id 无遗漏。
- [ ] 词时间、句时间、画面和字幕没有系统性漂移；源时间/速率改动同步到声音。
- [ ] 音乐在人声下已做 carve；处理在 bed 上，人声组不含音乐或音效。
- [ ] 多片段的人声成员变化后重算；clip-local 与 composition-time automation 没混用。
- [ ] FX node id 与自动化目标真实存在；没有把不支持自动化的效果参数写成无效包络。
- [ ] 预览没有因 FX 解析失败而退到干声；最终导出的链解析成功。
- [ ] 首尾与转场无突兀爆音、意外切断；混响/延迟尾巴是否需要延长另行确认。
- [ ] 有真实播放/听音或可用的客观检测记录；不能仅凭波形外观说“听清”。
- [ ] 若明确静音，记录依据；例如 product 路线的 `music: none`、无 `SCRIPT.md`、无音效/宿主音频。不要把遗漏音轨当有意静音。

如果无法直接听音，写明“混音听感未验证”，提供实际测量和需人工确认的项目；不要用文字报告冒充听音。

## 7. 最终预览与渲染授权

共享视频路线的最终门：

1. 组装与技术检查通过。
2. 启动真实 Studio preview，保留审阅期间的服务。
3. 使用实际输出的项目 URL：`http://localhost:<port>/#project/<project-name>`，不能只给 `index.html`。
4. 验证 URL 返回 HTTP 200，并确认打开的是目标工程；HTTP 可达本身不证明画面正确。
5. 给出可审阅的成品状态，询问“现在导出，还是先修改哪些地方？”
6. 只有明确批准后才 render。用户“继续”若只是继续编辑/检查，不自动升级成导出授权。

`draft` 用于迭代，`looks` 用于首次正式编码，`delivery` 用于最终交付。质量档位不是完成证明；最终仍须检查输出。

专项差异：字幕使用真实合成预览及专项 QA；talking-head 的可选 live preview 仅在用户要求且导出后启动；slideshow 用演示导航验收而非 MP4 渲染门。

## 8. 导出后验证：文件存在只是第一步

- [ ] 输出路径、文件名、实际文件大小与本次 run 对应，未误交中间版本。
- [ ] 渲染命令成功，保留关键日志；查看 capture 路径、GPU 和耗时摘要，区分慢路径与内容缺陷。
- [ ] `ffprobe` 读取实际容器/视频/音频流，核对时长、尺寸、fps、编码与目标；时长差按帧率和容器规则判断。
- [ ] 视频含真实画面，不只有容器头；抽查开场、转场、中段、结尾。
- [ ] 检查黑帧、冻结、缺帧、错位、重复尾帧、字体丢失与音画同步；不能只看一帧。
- [ ] 有音轨要求时确认音轨存在且内容正确；静音要求则确认没有意外背景声。
- [ ] 透明输出确认 alpha 信息，并叠到浅色/深色背景查看；普通 MP4 不能当透明 overlay。
- [ ] 迁移项目有基线与目标的比较结果；差异逐项解释，不凭“看起来差不多”完成。
- [ ] 演示稿逐页/分段呈现/分支/演讲者路径可用；不得用第一页 MP4 代替。

可把实际输出的 SHA-256 写入项目卡，确保交付的就是验证过的文件。哈希证明身份，不证明画面正确。

## 9. 路线专用验收表

| 路线 | 不可省略的证据 | 特别容易误报完成的地方 |
| --- | --- | --- |
| `embedded-captions` | 素材准入、完整转录、身份选择、safe zones、真实遮挡合成预览、timing/overflow/occlusion 结果 | 字幕编造、遮挡错误、只抽三帧漏掉烧录字幕；Theme 交错中间文件 |
| `talking-head-recut` | 平铺 word array、文字校正、确认后的卡片策略、卡片时间钳制、最终组装与输出 | JSON 分镜没编译、卡片内脚本/远程素材、视频冻结、无意裁切人物 |
| `music-to-video` | 唯一 audiomap、镜头覆盖全曲、计划校验、锚点对应、音画节奏 | 舒缓音乐硬切虚假节拍、每拍一个文件、总时长不齐 |
| `motion-graphics` | 类别/平台/素材策略、真实资产、开场/标志动作/结尾证据 | 入口存在即报可运行；透明文件没有 alpha；网页失败后伪造原页 |
| `product-launch-video` | sell/show、VO_MODE、可信 capture 或用户真实截图、品牌一致性 | capture 失败仍继续；把 no-capture 当 UI 重画许可 |
| `faceless-explainer` | 主张、教学逻辑、真实/示意数据区分、实际视觉表达 | 按文章段落机械分页、合成数据冒充事实 |
| `pr-to-video` | 真实 PR 元数据/diff、ingest 结果、变更解释与代码一致性 | fetch 失败仍编故事；在调用方仓库随意输出视频 |
| `slideshow` | 数据岛、直接打开、导航、分段呈现、必要分支与演讲者路径 | 单 MP4 只含第一张；脚本/远程依赖导致无法打开 |
| `remotion-to-hyperframes` | 源分析、Remotion 基线、HyperFrames 输出、eval/diff 与限制 | 只翻译外壳；状态/effect/UI 库不等价；未比较即说忠实 |
| `general-video` | 对实际编辑目标、素材、时间轴和输出的验证 | 改一处却重做全片；局部裁切被误当时间剪接 |

## 10. 示例命令与证据记录

**以下仅为命令形态，未在本次执行。** 在真实视频工程中按实际版本和入口调整；插件模式的适配缺口见[来源与依赖](来源与依赖.md)。

```bash
npx hyperframes doctor --json
npx hyperframes check --json --snapshots
npx hyperframes check --strict --at <关键时间点> --at-transitions
npx hyperframes snapshot --at <首帧,各场景,转场,末帧>
npx hyperframes preview --background
# 获得明确导出批准后才执行：
npx hyperframes render --quality delivery --output ./renders/final.mp4
ffprobe -v error -show_format -show_streams -of json ./renders/final.mp4
```

不要把带占位符的示例直接当成可执行命令；不要假定 `render` 或 `preview` 服务模式支持普通 `--json`。

每条证据最少记录：

```text
目标 / 工程版本 / run_id / 命令或检查方法 / 退出码 /
结果路径 / 覆盖时间点 / 发现 / 修复 / 复验 / 未覆盖项
```

## 11. 交付与停止条件

完成说明应包含：**交付格式、实际文件、规格、验证依据、已修复问题、剩余限制、下一步授权**。只交付分镜/制作卡时明确“未渲染”；依赖不足时明确阻塞位置，不把计划写成完成。

遇到真实素材获取失败、授权不足、平台不兼容、关键检查失败或无法可靠转录时，保留现有成果，报告原因与可选补救。不要通过改时长、忽略全局、伪造素材、跳过失败检查或擅改用户目标“凑完成”。
