# AI 视频生产（AI Video Production）

模型写代码、渲染、回头看自己渲出来的帧、再把不对的地方修掉 —— 这是社区总结出的核心工作方式。
本 skill 把它固化成一个可重复的流程。

## 何时调 / 何时不调

| 调 | 不调 |
|----|------|
| 要做一条视频（宣传片/短片/长教程/动效片） | 只做已有素材的剪裁拼接 → 用 `video-use` |
| 要给"一句话生成视频"类模型写提示词 | 只写 Remotion 组件 API → 用 `remotion-*` 系列 skill |
| 要决定用哪条技术路线 | 只做 UI 动效打磨 → 用 `make-interfaces-feel-better` |
| 要审片、抽帧、做对抗评审 | 只写文案 → 用 `content-craft` |

## 一、先定路线（不要默认 Remotion）

| 路线 | 适合 | 关键判据 |
|------|------|---------|
| 纯 HTML + Canvas/WebGL 逐帧渲染 | 概念短片、15s 宣传片、群论式样片 | 不装任何东西；短片一句话就够 |
| Remotion | 长片、分集、要复用组件和时间轴 | React/TS 生态；改一行重渲 |
| HyperFrames | HTML 渲染视频，专为 Agent 设计 | 见 `hyperframes` skill |
| Three.js / `@remotion/three` | 3D 场景、作品墙、镜头推进 | 需要真实 3D |
| Blender（代码驱动） | 要真实材质与物理感 | 几何/材质/相机/声音全部代码生成 |

其它社区路线：`onetake`（一镜到底产品发布片，每一拍从上一拍长出来）、`anidoodle`（手绘风插画+动画+配乐）、
`lemo-opuscar`（39 种纯代码影片风格）、`guizang-product-video-skill`（读代码库做产品更新宣传片）。

## 二、制作流程（长教程 / 产品片）

1. **先喂素材**：官方文档、产品截图、参考视频一股脑丢进去，让模型先整理成资料。
   要求口播里说的每一句都能在资料里找到出处，找不到就不许说（防编造）。
2. **一句一句写脚本**：旁白按句写，每句对应一个画面；先出静帧/小段预览，认可了再全量渲染。
3. **配音与字幕**：每句单独合成并缓存，改哪句只重做哪句；字幕按逐词时间戳切，画面跟着词走。
   免费方案 edge-tts（稳但没感情）；要感情换 Qwen3-TTS / IndexTTS（本地）或云端 TTS。
4. **音乐与音效**：BGM 在有人声时自动压低（ducking），逐集统一响度（LUFS）。
5. **包装脚本化**：进度条、章节时间轴、分 EP、合集、封面、投稿简介，全部从同一份时间轴生成。
6. **主动要求加速渲染**：并发、GPU 渲染、复用浏览器实例、分集缓存、慢图层降采样（进度条只渲 1/3 帧）、审片先降分辨率。
7. **自验收**：帧数、音画对齐、响度、字幕与排版是否挤在一起。**但最后必须自己通看一遍** —— 模型说没问题不代表能发。
8. **写 HANDOFF**：区分"用户点过头的"和"只是试稿"，多会话并行才不会互相踩。

## 三、短片 / 预告：多 agent 流水线

1. 搭工程：素材归档、音乐按需裁段、拼音轨并检查接缝爆音；把复用动效做成组件（遮罩闪、颗粒、网点、贴纸描边、2.5D 镜头、按拍发光）。
2. 按镜头分组并行（横屏/竖屏各分组），每组一个 agent；每个 agent 先渲关键帧，用资深动效设计师标准自审，至少改两轮；**渲染一次只跑一个，避免缓存打架**。
3. 出审片版：完整成片 + 每 10 帧一格的缩略图总览 + 每个重拍/砸点的截帧对照。
4. 对抗审片：开三个审片 agent，各只盯一类问题 —— ①卡点与节奏 ②质感（专找"像 demo"的地方）③文字/署名/安全区/素材合规。
5. 按问题返工出终版，最后查时长、音量、黑帧。

> 对抗审片的思路：把审片拆开，每个 agent 只盯一类问题，比让一个 agent 全量检查更有效。

## 四、收敛流程（比工具更重要）

```
参考片定调 → 分镜 → 每场景静帧 → 确认后动画 → 对抗审片 → 自验收
```

- 一句话够做概念短片；**产品片与长片必须走静帧流程**，能少返工很多次。
- 素材来源优先级：参考片（whatships.com）> 自己描述。没有参考片，模型会退回"居中大字 + 渐变背景"的 AI 模板味。
- 组件库用 21st.dev 等罐头库，别让模型现场手搓产品 UI。

## 五、提示词模板

见 `references/prompts.md`（一句话版 / 产品宣传片 / 换受众 / 当导演 / 改片镜头语言 / App Icon / 自用起手式）。

铁律：
- 素材用**真实截图 / logo / 官网链接 / 文档**，别编界面也别编事实。
- 修改片子要给**具体镜头指令**（"推镜都放慢到 0.7 倍""这里硬切""推近到那个按钮"），"再好看一点"没用。
- 提示词别写太满：说清目标、给谁看、多长、有什么素材，剩下的让模型发挥，做完再像导演一样提意见。

## 六、审片清单

- 抽帧拼联系表（`ffmpeg tile` / `remotion still`），每 10 帧一格
- 帧数与时长、时长是否超限
- 音画对齐（逐词时间戳是否落在对应画面上）
- 响度是否统一（LUFS 一致，无削波）
- 字幕/排版是否挤在一起、是否出安全区
- 黑帧、闪帧、最后一帧是否正常
- 素材授权（尤其中间引用的第三方素材）

## 八、坑（已验证）

- `npx skills add --agent kilo` 会把 skill 落到 `.kilocode/skills`，本 harness 只读 `.kilo/` —— 装完必须挪。
- Remotion 渲染前必须显式指定可用浏览器（`Config.setBrowserExecutable`），否则 `chrome-headless-shell` 下载会长时间挂住。
- `@remotion/non-pure-animation` 会对 `transition: "none"` 误报（那是默认空操作）。
- Remotion 官方字幕路径是 `@remotion/whisper-webgpu`（需 GPU），不是 whisper.cpp；中文必须显式传 `language`（不支持自动语种检测）。
