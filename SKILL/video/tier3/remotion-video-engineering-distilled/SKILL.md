# Remotion 视频工程 · 蒸馏技能

## 适用范围

使用本技能处理 React 编程式视频的方案、实现准备、故障分诊与验收。以本地资料的 Remotion `4.0.532` 为知识基线，不承诺与当前最新版相同。

本技能是方法与参考资料，不包含 Remotion 运行依赖、现成可渲染工程、媒体素材或云凭据，不自动安装、部署、启动服务或产生费用。不要修改原始技能或原项目配置，除非用户另行授权。

## 开始前

1. 确认用户要的是方法说明、实际代码/文件、渲染排障还是成片验收；不要将文档审核当成片成功。
2. 对实现或排障任务收集版本、操作系统、入口、composition ID、尺寸、fps、总帧数、props、素材、目标 codec 与实际错误。
3. 缺少非关键参数时明确假设；涉及成本、部署、覆盖文件或不可确认 API 时先确认。
4. 检查目标项目已有结构与约定，再决定是否改文件。只在用户指定范围内操作。
5. 从以下路由选择一个主领域，按需增加依赖领域；不要一次加载全部资料。

## 按依赖推进

1. **明确合成契约**：固定输入、帧数、时间轴、资源和预期产物。
2. **准备表现层**：选择字体/特效、字幕/音效方案，检查素材授权与就绪。
3. **选择渲染环境**：明确本地或云端、codec、像素格式、并发和平台前置条件。
4. **先小样后全量**：建立可重复基线，再扩大分辨率、时长、分片和并发。
5. **独立验收**：有实际产物才判断成片；没有证据时写“证据不足”。
6. **留证交付**：保留命令、版本、配置、素材标识、日志、输出路径和未确认项。

单一问题可缩短流程；不要为一句命令解释引入完整团队协作或云部署。

## 证据与表述

- “资料记载”：来自 [来源索引](references/11-source-index.md) 的本地分册。
- “工程建议”：基于资料提炼的方法，不新增未经确认的 API 事实。
- “本次检查”：只描述实际完成的读取、结构、引用或打包检查。
- “待项目复验”：在用户目标版本与环境中验证 API、平台行为、参数、性能和费用。
- “未能确认”：资料冲突或缺证；明确缺什么，不编造默认值、完整签名、价格或许可门槛。

上游 `packages/...` 路径只作为来源映射，不是当前工作区的文件，也不是本次已复核的源码。

## 不可跳过的校正

- 时长换算为 `durationInFrames / fps ≈ 秒数`，不是原资料某处写反的公式。
- 插值输入范围严格递增；Sequence 的 `from` 按父时间轴解释，内部使用相对帧，嵌套时累计偏移。
- 不采纳透明视频分册中互相矛盾的 codec/pixelFormat 组合，先核对实际版本并试渲染。
- 不根据 WebM 时间刻度常量的错误文字说明猜测真实单位。
- 像素哈希相同、码流字节相同、整个文件字节相同是不同结论。
- 文档/技能通过不等于真实渲染、跨平台播放或云部署通过。

完整限制见各分册，不要将“待确认”隐藏在脚注中。

## 输出格式

根据任务输出：

```text
问题定性：需要解决什么，哪些不在范围内
版本与前提：资料来源、目标项目版本、运行环境
方案：输入 → 处理 → 输出；仅列必要步骤
关键参数：已知默认 / 项目选择 / 待确认
验证：实际执行的检查，或缺失的证据
交付：文件/命令/结果路径
边界：未确认项与下一步
```

代码片段必须标注“未实跑”或附真实执行结果。不要交付带已知缺陷的完整示例，不用占位参数冒充可运行脚本。
