## 3. 值得保留的六条方法

1. **先判断请求状态，再选择工作流。** 提问、暂停、局部修改、既有工程操作和新建制作不是同一种请求。
2. **按最终交付物分流，不按偶然关键词分流。** 有音乐不一定走音乐驱动；提到 Remotion 不等于迁移；字幕和图文卡片不是一条路线。
3. **把确认过的决定写入项目。** `BRIEF.md` 管意图，`STORYBOARD.md` 管叙事与镜头，设计规范管视觉，composition 管实际实现。
4. **制作是依赖图，不是必须全部执行的编号清单。** 无旁白就跳过配音；单镜头不制造转场；已有项目只修受影响的部分。
5. **技术通过不等于视觉通过，视觉通过不等于获得渲染授权。** 检查、预览、导出、导出后验证、发布分别记录。
6. **真实素材不能靠“降级”变成伪造。** 网站采集失败不能用虚构 UI 冒充原站；缺少依赖时交付制作卡或阻塞说明，而不是虚构完成。

## 4. 最容易误判的交付边界

- **可导航演示稿 ≠ 线性 MP4**：`slideshow` 交付翻页、分段呈现、分支和演讲者模式，不能只渲染第一页当作整份演示稿。
- **字幕层 ≠ 图形包装 ≠ 剪接原片**：分别考虑 `embedded-captions`、`talking-head-recut`、`general-video`。
- **原片内容/时间轴不变 ≠ 文件字节不变**：`talking-head-recut` 会重编码输入以保证 seek；布局也可能改变可见画幅。
- **技能入口存在 ≠ 功能已跑通**：`motion-graphics` 的 10 个类别模块均存在，但平台、外部素材、registry 与手写补缺要求不同。
- **制作卡 ≠ 成片**：依赖不足时可先完成设计、规划和任务交接，不能把它们称为已渲染视频。

## 5. 怎样复用而不丢真

- 实际制作时，以真实工程与当前用户确认优先；不要拿本目录的模板覆盖用户改动。
- 原资料存在冲突时，先看专项 route contract，再看共享流程；无法安全判断则记录阻塞。已识别的差异集中写在[来源与依赖](来源与依赖.md)。
- 示例命令只是后续执行参考。涉及下载、账号、费用、远程上传、发布或覆盖文件时，仍需相应授权。
- 本整理稿属于对来源的中文归纳与改编。再分发须保留相关许可、版权与 NOTICE；尤其不能遗漏 `talking-head-recut` 的 MIT 归属。
