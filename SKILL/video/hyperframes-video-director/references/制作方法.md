# 制作方法：从意图到可验证的工程

[整理稿入口](README.md) · [总览](总览.md) · [能力路由](能力路由.md) · [验收规则](验收规则.md) · [来源与依赖](来源与依赖.md) · [项目卡模板](项目卡模板.md)

> 这是后续制作的参考方法，不是本次已执行的视频任务。共享流程不能覆盖专项路线的真实素材门槛、转录结构、确认点或导出方式。

## 1. 先恢复事实，不从空白模板重来

实际执行前按顺序读：

1. 用户当前请求、指定目标和明确的“不改/暂停”要求。
2. 工程根目录的 `BRIEF.md`、`STORYBOARD.md`、专项 JSON 和最近反馈。
3. `frame.md` → `design.md` → `DESIGN.md`，取第一个存在的设计规范。
4. `hyperframes.json`、当前 composition、媒体清单与已有输出。
5. [项目卡](项目卡模板.md)中记录的确认项、依赖、失败和下一步。

旧项目卡不能覆盖真实文件的新状态。用户改动、已确认分镜、已采用的素材均先保留。只改指定镜头/元素时，从受影响的文件进入，重跑对应验证，不重做全片。

## 2. 把需求收敛成制作简报

### 2.1 最小信息集

| 维度 | 应落到什么决定 |
| --- | --- |
| 交付物 | 演示工程、MP4、透明 overlay、字幕成片，还是仅分镜/规划 |
| 主张 | 一句可验证或被论证的表达，不只是“介绍某产品” |
| 受众与位置 | 影响术语、画幅、字幕密度、停留时间与构图 |
| 输入 | 真实视频、音频、图片、品牌规范、网站、PR 或文章的路径/引用 |
| 声音 | 原声、旁白、音乐、音效，还是明确静音 |
| 约束 | 时长、语言、画幅、fps、品牌、禁用元素、隐私与授权 |
| 审阅 | 是否需要分镜/静态草图、是否共创、哪些决定已确认 |

把用户已给出的答案直接使用。只问未解决且会改变成品的内容；不要把一份问卷全部重问。

### 2.2 `BRIEF.md` 的职责

- `workflow`：实际执行路线；共创 brief 记录为 `general-video`。
- `flow`：`automation` 或 `companion`。
- `storyboard`：`yes` / `no`，表示是否先审计划和草图。
- `message`、`destination`、`aspect`、`language`、`audience`、`length`、`angle` 等：记录本路线确认值，保留用户原话于正文。
- 正文分区：`## Intent`、`## Assets`、`## Customizations`、`## Notes`。

**生命周期：**先确认 brief，再在获准的视频工程中初始化；按原约定在 `init` 后写入 brief，不把说明文件提前塞进待初始化目录。既有工程恢复时不重复初始化。明确变更后写回原 brief；一次检查点的临时模式变化写入分镜的 `mode`，不改原始意图。

不要把某个视频的 message、受众或时长自动变成长期偏好。偏好只按明确同意、允许字段和路线保存。

## 3. 先设计叙事，再设计动画

### 3.1 分镜是可被反驳的提案

每个镜头/段落至少能回答：

- **画面**：具体主体、布局、动作，不写“丰富视觉”。
- **文案**：实际显示的文字、数字、单位、引语；来源不明标为待确认。
- **声音**：旁白原句、原声锚点、音乐/音效提示；无声音则明确为空。
- **主视觉与机制**：谁是 hero，怎样运动，为什么此动作帮助表达。
- **衔接**：与前后镜头保持什么、替换什么、是否真的需要转场。
- **理由**：这一镜头如何证明主张；不能贡献信息就考虑删去。

`STORYBOARD.md` 的常用字段：`format`、`duration`、`message`、`arc`、`audience`、`mode`；逐帧记录 `status`、`src`、`duration`、`scene`、`voiceover`、`poster` 和衔接。状态是：

```text
outline：结构/意图已写，尚未落地布局
built：布局已存在并确认，动态尚未完成
animated：完整动态场景已经落地，待整体验证
```

`animated` 不是“整片已经验收”。专项 `storyboard.json`、`shot-plan.json` 是各路线自己的规划格式，不能假装通用解析器会执行它们。

### 3.2 静态草图与最终预览是两件事

协作且需要分镜时：

1. 先审文字计划；修订只动被指出的镜头。
2. 按批准的计划绘制 `storyboard.html`：真实字体、颜色、标题、关键布局；尚未制作的图表/媒体可用明确占位块。
3. 草图是静态自包含审阅页，无动画、无脚本、无外部素材；此阶段不跑 CLI 或渲染。使用内嵌字体或系统字体回退；若随包字体不能内嵌，不临时联网下载，并记录最终字体替换的复验要求。
4. 用户确认布局后再补素材与动画；保留布局、层级、文案和最终状态。
5. 如果用户只要分镜，确认后的 `storyboard.html` 就可以是最终交付，不必继续制作视频。

最终动态预览则使用真实 Studio 工程。不要拿静态分镜或源码路径冒充最终预览。

## 4. 制作是依赖图，不是必做清单

```text
已确认 brief / 计划 / 局部修改目标
              ├─ 素材准备 ─────────────
              ├─ 可选：旁白与词级时间 ─┼─ 画面制作 ─ 时长对齐 ─ 组装
              └─ 可选：音乐与音效 ─────┘                       │
                                            可选：转场 / 字幕 ─┤
                                                               ↓
                                      检查与声音处理 ─ 最终预览 ─ 批准 ─ 导出
                                                               ↓
                                                          导出后验证
```

| 阶段 | 输入 | 产物与完成条件 | 没有需求时 |
| --- | --- | --- | --- |
| 素材/组件 | 已确认计划、真实素材、组件清单 | 本地素材与来源记录；blocks 接线完成 | 不需要外部素材就跳过解析 |
| 音频 | 可选旁白脚本、音乐意图、用户原声 | 音频文件、词级时间、`audio_meta.json`（该路线使用时） | 无旁白不生成 TTS；明确静音则跳过 |
| 画面 | 设计规范、计划、批准草图 | 每场景 composition；布局/动效按确认落地 | 静帧也是合法交付 |
| 时长对齐 | 真实音频/视频时长与镜头 | 场景时长、转场重叠、媒体边界一致 | 无新时基则保留原值 |
| 组装 | 完成的场景 | 可播放 `index.html`，子合成挂载正确 | 局部编辑只更新相关挂载 |
| 转场/字幕 | 组装结果；字幕另需词时间 | 合理衔接、一条字幕轨 | 单场景不做转场，无字幕需求不新增 |
| 验收与交付 | 实际组装结果 | 检查、视觉证据、预览批准、输出探测 | 未满足则停在当前状态 |

并行制作互不依赖的镜头可以节省时间，但 registry 安装等共享写操作先完成，避免竞争。外部生成只有在能力、费用和上传授权明确时才进行，不把“等待”当作成功。

## 5. Composition 的技术底线

### 5.1 时间、结构与媒体

| 契约 | 做法 |
| --- | --- |
| 根结构 | 独立 `index.html` 不包 `<template>`；子合成用 `<template>`，样式与脚本放 template 内 |
| 画布 | 根用 `data-width` / `data-height`，CSS 宽高用 100%；不要硬编码另一种分辨率 |
| 身份 | 根 `data-composition-id` 与注册的 timeline key 一致；组装后 id 全局唯一 |
| 时间 | `data-start` / `data-duration` 定义半开窗口 `[start, end)`；`data-media-start` 选源内偏移 |
| 源编辑 | 保留不同源片段时，一段一媒体元素；视觉缩放/裁切不等于剪接时间 |
| 轨道 | `data-track-index` 只是 Studio 显示 lane；视觉层级用 CSS |
| 视频嵌套 | timed video 不放进另一个普通 timed ancestor；sub-composition host 是允许的例外 |
| 音频 | 每个 `<audio>` 有 id；不给视频/音频加 `crossorigin` |
| 生命周期 | 不在 `.clip` 上 tween `display` / `visibility` / `autoAlpha`；透明度/子节点动作分开处理 |
| 字体 | 命名 `font-family` 配套本地 `@font-face`；不能依赖在线字体渲染 |

每个使用 GSAP 的 composition 注册**一个暂停的 timeline**，在完成构建后注册：

```js
const tl = gsap.timeline({ paused: true });
// 依据真实构图与时基构建动作，不调用 tl.play()。
window.__timelines["scene-01"] = tl; // 必须匹配根 composition id
```

根 `data-duration` 决定编译时导出长度，不靠脚本临时改时长。timeline 过长会被截断，过短会停住；不能用延长黑尾掩盖缺陷。`class="clip"` 是常用工具/布局约定，不是 runtime 计时的替代物。

### 5.2 动画必须可 seek、可重复

禁止用实时钟、未固定种子的随机数、网络、hover/scroll、计时器或未注册 rAF 驱动渲染关键运动。异步字体/素材准备好后再完成注册；无限循环只有在明确有限的根时长下按专项约束使用，不无条件循环。

- 默认组合 2–4 条适用的原子动效规则，复杂场景再使用 blueprint；规则名字必须来自实际索引。
- 空间运动优先 GSAP `x/y/scale/rotation` 等可合成属性；避免同节点 CSS transform 与 GSAP 同属性打架。
- 不在 tween 时刻临时读取布局尺寸决定运动；根据真实构图先确定几何。
- 关键帧要证明起点、过程、峰值与最终停留；同一主体连续运动，不用换对象交叉淡化冒充连续位移。
- 不把辅助框的运动当作主体动画证据；画布/WebGL/3D 另看真实像素、深度关系和遮挡。
- 可读文案与最终锁定画面要有足够停留；不擅自回弹到初始姿态或以黑帧结束。

### 5.3 Studio 可编辑性

每个有结构的场景独立成子合成；字幕合并在一条专用轨，按 graphics/captions/audio/video 等角色分组。可见内容按 action-safe 90%（四边 5%）规划，字幕和关键内容按 title-safe 80%（四边 10%）规划；平台 UI 另有时服从平台。

标尺、辅助线和调试框不写进交付 composition。专项卡片模板若使用不同安全区，保留其明确规则，不机械套入通用字幕区。

## 6. 素材与品牌必须先冻结成工程输入

1. 先查用户资产和 `.media/manifest.jsonl`，复用已确认且用途一致的文件。
2. 需要新素材时明确类型：`image`、`logo`、`bgm`、`sfx`、`voice`、`icon`、`grade`、`lut` 等。
3. 先核实实际可用的宿主能力、provider、授权和网络；没有可用 provider 就记录阻塞，不假装生成成功。
4. 保存真实本地文件、原始来源、用途、权利状态和证据；记录 `resolved` 与 `processed` 的区别。
5. 官方 logo、真实网页、真实帖子、真实 PR 不从记忆重画。
6. 生成素材与事实证据分开；示意数据不能冒充实测数据。
7. 最终渲染读本地资产，不临时访问生成接口或设计服务。

Figma 导入先处理 tokens，再处理组件/资产。静态资产、token 和组件可由 REST 路径读取；动作/shader 依赖可用连接器或原生导出。缺失的动态信息不能声称已从静态截图恢复。

Registry 搜索使用英文意图，例如 `reveal a headline one line at a time`；先核对结果，再安装和接线。block 通过 `data-composition-src` 挂载；component 合并 HTML/CSS/JS。缓存目录不等于离线安装能力。字幕身份 catalog 和 talking-head 卡片不走这条 registry 流程。

## 7. 声音处理要服务于信息，而非堆音效

- `media-use` 负责素材、转录、生成和预处理；`hyperframes-audio` 负责已放入时间轴的轨道关系。
- 逐字旁白脚本写入专项要求的 `SCRIPT.md`；分镜中的 voiceover guide 不自动等于已锁定配音稿。
- 按真实音频时长同步画面；不要凭估读速度填时长。
- **音乐在人声下时需要 carve**：处理音乐 bed，指向人声/人声组；不能把 carve 放到人声自身，也不只把全曲音量压低就算完成。
- 多个人声片段先分组；人声组不混音乐、bed、音效。新增片段后重算 carve。
- `data-fx-chain` 是效果链；`data-automation` 是时间包络；`data-fx-carve` 保留可重算的避让关系。
- clip automation 使用片段本地时间；bus automation 使用整片时间，搬移包络时不能照搬数字。
- 顶层 composition 根的 FX chain 是 master；子合成根不自动成为父工程 master。
- 自动检查不能证明“好听/听清”。预览效果链失败可能播干声，导出却可能失败；必须核对解析结果并检查最终混音。

## 8. 专项方法保留，不强行共用一套模板

### 8.1 字幕：先排除不适合的素材

先探测本地素材和整段内容，排除多人/硬切、无清晰人物或讲话、过短（少于 3 秒）、已有烧录字幕、快速手持、不可用转录等。硬切素材先拆分再处理；坏转录不能补成编造的逐字稿。

再从 `CATALOG.md` 的 35 种身份推荐，选择一种；默认安静的 rail 承载大部分文字，embed 只突出峰值。Cinematic 是纯 embed。先运行 `prepare.sh`，读取 `safe-zones.json`，按身份生成创意 JSON/编译计划，使用 `preview-frames.cjs` 做真实遮挡合成预览，通过专项 timing/overflow/occlusion 检查后才导出。

Standard/Cinematic 不改动原片；Theme 的底板反应是例外，最终可能是 `final_fx.mp4` 而非中间的 `final.mp4`。不要误把中间文件交付。

### 8.2 Talking-head 图文包装：转录驱动卡片

流程归纳为：

```text
确认本地输入 → 探测时长/尺寸/fps → 提取音频 → 本地 Whisper 转录
→ 校正文字且保留时间 → 暂定卡片规划 → 确认视觉策略
→ 最终分镜 → 逐卡 HTML → 组装与动作编译 → 抽检 → 批准后导出
```

- 原文 Step 6 先写轻量分镜、Step 7 又要求先确认视觉参数。这里将前者视为暂定规划，最终布局在确认后定稿，避免顺序冲突。
- `transcript.json` 是平铺数组：`[{ "text": "实际词", "start": 0.2, "end": 0.5 }]`，不是 `segments` 或 `words` 包装。更正词语不随意改时间；最终词结束超出媒体时须钳制到实际时长。
- `storyboard.json` 是规划产物，没有 CLI 会把它自动变成视频。
- 画幅支持 16:9、9:16、4:5。根据原片推荐，确认布局、风格与卡片数。
- 卡片数量建议公式：`max(5, round(videoSec / (basePace × densityMultiplier)))`。高密度倍率 0.7、中密度 1.0、低密度 1.5；basePace 依时长选择，不为了凑数量切碎完整观点。
- zone 为 `fullscreen`、`whiteboard-area`、`lower-third`、`side-panel`、`video-overlay`；由组装阶段解析为实际像素边界。
- 卡片单根 `.card[data-card-id]`，CSS 带作用域；禁止卡片内 script、外部 URL、inline 事件。动作只声明 `data-anim-*`，在主合成中编译成统一 GSAP timeline；相对时间需加 `startSec`。
- 输入会重编码为便于 seek 的本地 MP4，关键帧间隔按实际 fps 设置。保留内容/时间轴，但不保证字节或可见画幅完全不变。
- 本路线不搜索通用 registry；长内容可分章节子合成。只在用户请求且导出后按需打开其 live preview，不套共享流程的制作中预览时机。

### 8.3 音乐驱动：只相信一份分析结果

用该路线的 `analyze-beatgrid.py` 产生 `audiomap.json`。有明确律动时按真实 beat anchors 切分；舒缓音乐按乐句与能量推进，不硬追虚假的节拍网格。镜头数按不同视觉处理划分，不是每拍一文件；组内可以增加密度。

组装后总时长对齐 `audiomap.audio.duration_sec`；无旁白、无网站采集。需要歌词同步时另取歌词与时间，不能假装音乐分析器已识别全部歌词。

### 8.4 短动效：资产先于设计

形成类别与素材策略 → 获取真实素材（若有）→ 根据可用资产确定布局/动作 → 复用组件或手写缺口 → 检查开场、标志动作、最终停留 → 批准后导出。

十个类别文件存在不代表全部能无依赖执行。Windows 平台声明、registry 缺口、地图/网页/帖子 provider 等限制见[能力路由](能力路由.md)。透明 overlay 要验证 alpha 与实际编码器，而非只把文件命名为 `.webm`。

### 8.5 三种来源型内容

- **PR**：用 `gh`/实际访问能力取得真实 PR，`fetch-pr.mjs` 与 `ingest.mjs` 形成来源和差异；失败就停。默认 `code-editorial`；不要在调用方代码仓库里随手创建视频目录，使用独立视频工程。
- **产品**：先确认 sell/show 和脚本 `VO_MODE`。如实展示必须以 capture 或用户真实截图为源；URL capture 失败是停止条件，no-capture 不授权伪造原站。
- **Faceless**：根据文本叙事设计视觉，不按段落机械分页；不运行网站 capture。可建立该管线要求的合成文本/token 输入，真实用户图像另行记录，不凭空捏造证据图片。

### 8.6 演示稿与迁移

- `slideshow`：保留 `SlideshowController` 数据岛、导航和分段呈现，验证直接打开/演讲者路径。不是单 MP4 导出。
- Remotion：先建立原工程基线，再翻译到可 seek 的 HyperFrames，再运行迁移 eval/视觉比较。`useState`、`useReducer`、有状态 effect、第三方 React UI 等先识别阻塞；不能只把 JSX 改成 HTML 就声称等价。

## 9. 局部编辑的复验路径

| 用户只改什么 | 最少应重做什么 |
| --- | --- |
| 标题/颜色/文案 | 目标样式与文案、字体适配、布局/对比度、相关画面 |
| 主体运动 | 相关 keyframes、focused shot、起止/峰值/结束快照 |
| 一段视频源时间 | 该 clip 及相邻边界、源帧、音画同步、根时长 |
| 旁白或音乐 | 对应转录/时长/分组/carve、受影响画面与字幕、最终混音 |
| 画幅 | 布局与安全区、媒体可见范围、字幕区、目标编码设置 |
| 导出参数 | 不必重写创作；重做导出与输出规格/完整性验证 |
