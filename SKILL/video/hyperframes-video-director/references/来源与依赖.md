### 5.1 字幕路线的具体依赖

- 文档给出的项目内精确依赖例：`sharp@0.35.3`、`puppeteer@25.8.0`、`gsap@3.15.0`。这是随包文档值，不是本次联网确认的最新版或本机安装状态。
- WhisperX 经 `uvx` 驱动；现有合格 word-level `transcript.json` 可按专项规则采用。
- 抠像权重**未随包**：首次 prepare 会下载 `u2net_human_seg`（文档约 168 MB），需要网络和相应运行条件。
- 有 Bash 脚本与 Node/CJS 路径，Windows 上须确认 shell、路径和依赖兼容性；不能因为文件存在就承诺开箱即用。

### 5.2 外部生成与 Figma 的边界

- 宿主若提供已授权的音乐/音效能力，优先使用宿主；不要重复要求安装同一能力的 CLI。
- 宿主媒体接入、CLI 登录、API key 计费是不同路径；以真实环境与用户授权为准，不凭缓存状态声称已登录。
- 不把凭据写入整理稿、项目卡、共享仓库或日志。项目 `.env` 仅在对应真实工具确实需要且获准时处理，不提交版本控制。
- Figma 静态资产/token/组件走 REST；动作与 shader 的权限另行确认。静态截图不能证明完整动画；shader 的连接器导出可能被扁平化，须使用可保留效果的原生导出。
- 渲染阶段只使用已冻结的本地资产。

### 5.3 平台与实现缺口

1. **motion-graphics 的平台声明**是 macOS Apple Silicon / Linux x64；当前 Windows 不在声明范围。本次没有运行复现，不能写成“Windows 已验证支持”或“必然失败”。
2. `motion-graphics/phases/source/resolve.mjs` 未找到，但 `media-use/scripts/resolve.mjs` 存在。不要把单个旧路径缺失泛化为整个 media-use 缺失。
3. charts 的 pie/donut/ring/% 在该模块中标为 registry 缺口；stat 没有通用 `stat-motion` block。需按实际 catalog 结果手写或使用适用组件，不编造可安装名字。
4. maps helper 需要 puppeteer-core、Chrome/浏览器与可冻结的地图素材/瓦片；网络和地理合规要求独立确认。
5. news 有参考 sample 缺失但有手写流程；tweet 依赖真实字段与素材；asset-fusion 需真实资产和锚点绑定。
6. webpage 的真实 capture 不可用时不能套泛化 asset-free fallback。

## 6. 插件命令的静态适配缺口

原插件执行规则要求：

```text
node "<PLUGIN_ROOT>/skills/hyperframes/scripts/plugin-cli.mjs" <command> <args...>
```

并要求：

- 插件目录只读，命令在用户项目运行。
- 由插件管理器管理技能版本，不运行 `hyperframes skills update`、`skills check` 或 `npx skills add`。
- 启动器锁定 manifest 对应 CLI 版本；下载失败不能回退 latest。
- 共享 Node helper 通过 `--script` 传递版本上下文；插件版本并不冻结 provider、registry 或项目全部依赖。

**本地静态发现：**`plugin-cli.mjs` 第 10–16 行只搜索根 `plugin.json`、`.claude-plugin/`、`.codex-plugin/`、`.cursor-plugin/` 和 Gemini manifest；本次仅核对到 `.codebuddy-plugin/plugin.json`。此外第 23–25 行要求 `manifest.name === "hyperframes"`，而本包是 `hyperframes-director`，版本是 `1.0.4`，并非上游 CLI 声明 `0.8.149`。

因此不能保证这个原启动器在当前宿主包结构下锁定到 0.8.149。**这是静态适配缺口，未运行复现。**后续需要核实宿主实际命令入口与版本映射；不改原技能包、不伪造 manifest、不静默改用未固定版本。

其他命令文档仍有 standalone 更新/全局技能提示。应按安装模式解释，不能把复制来的 `npx hyperframes ...` 或 `skills update` 示例直接执行成插件更新。
