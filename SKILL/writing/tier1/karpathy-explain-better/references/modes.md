# 四种输出形式的提示词模板与判断清单

每节包含:**适用场景 / 提示词模板 / 常见错误**。

> 所有模板都默认叠加两条总规:
> ① 禁用 `word-ban.md` 里的中英 AI 词,命中即改成日常话;
> ② 结论必须压成**一个可核对的大数字**(hero 数字),不是形容词。

---

## 1. 简化文字(ASD-STE100 风格)

**适用**

- 默认起点
- 用户说"看不懂""简单点"
- 概念本来不复杂,但被绕来绕去讲乱了

**提示词模板**

```
请用中文解释【主题】,借鉴 ASD-STE100 的清晰表达原则,但不要写成生硬的手册。

要求:
- 使用短句,一句话尽量只讲一个要点
- 同一个概念始终用同一个名称,必要术语首次出现时给出解释
- 先说核心结论,再用一个具体例子说明
- 保留关键前提和适用边界,不要为了简短删掉重要信息
- 禁用「值得注意的是 / 不仅仅是…而是 / 至关重要 / 显著提升 / 赋能 / 底层逻辑」
  这类只加气势不加信息的词(完整表见 word-ban.md)
- 全文 ≤ 250 字;结论里必须有一个数字
```

**判断清单**

- ✅ 一段话能讲清的事,不要拆成五段
- ✅ 同一概念不要换两个名字("算法 A"不要来回切"方法/方案/模型")
- ✅ 删掉所有形容词后,句意不变 → 形容词就该删
- ✅ 跑 `check_explain.py`,禁用词 0 命中
- ❌ 不要为了"简短"删掉关键前提
- ❌ 不要硬塞航空术语风(fuselage / torque 之类)

---

## 2. 结构图

**适用**

- 模块之间谁调用谁、出错回哪里
- 流程有多分支(并行 / 串行 / 条件)
- "上一步的输出"是谁的输入——靠纯文字脑补不出来

**提示词模板**

```
请把下面的内容画成一张结构清晰的图,重点展示各部分之间的关系,而不是把原文塞进方框。

要求:
- 每个节点只保留一个核心概念
- 箭头注明关系或传递的信息(动词短句)
- 区分主流程和分支,标出输入与输出
- 原文没有交代的关系不要自行补全,不确定的地方单独标注
- 最后用三句话说明这张图应该怎么看

输出格式:优先 Mermaid 代码块;兜底 ASCII 图。
```

**判断清单**

- ✅ 节点不超过 12 个,否则再分层或分组
- ✅ 箭头写"做什么"(输入/触发/调用/校验),不写"是什么"
- ✅ 输出形态:主流程 vs 分支 / 实线 vs 虚线
- ❌ 不要把原文逐句塞进方框里
- ❌ 不要补全原文没说清的关系——不确定就标注

## 3. 3 页 Boss 海报(单文件 HTML,默认形态)

**适用**

- 要"一屏看懂",要发群里/投到会议室
- 算法演示、机制可视化、参数影响——都能压成 3 页
- 用户说"做个海报/一页看懂/发我个链接"

**没有真实数据怎么办**:在 canvas 里程序化绘制简化样本(粗笔画数字、简单几何、合成图),用 JS 实时绘制 + `getImageData` 读像素作为输入。

**提示词模板**

```
请把【主题】做成一个 3 页的单文件 HTML 海报,手机能左右滑动,默认自动播放。

要求:
- P1 一句结论 + 一个 hero 数字(字号 ≥ 视口短边 12%,3 米外能读)
- P2 三步机制,每步一个动词,一行讲完
- P3 一个可拖的滑块(现场试)+ 一句"以后遇到什么该想起它"
- 背景必须是动态 canvas(慢浮点阵/噪声呼吸/扫描线),文字可以静止
- 每页 ≤ 45 个汉字;禁用 word-ban.md 里的 AI 词
- CSS/JS 全内联,不引外部资源
- 先给 Mermaid 逻辑链,再排版
```

**判断清单**

- ✅ 3 页 `data-page`,滑动 + 自动播放 + 暂停按钮都在
- ✅ hero 数字可核对(有出处),不是形容词
- ✅ 背景是 canvas 动态层,不是静态图
- ✅ 缩略到 20% 还能读到 hero 数字
- ✅ 单文件,内联 CSS/JS,断网也能看
- ✅ 控件数量 < 4 个(一个滑块 + 翻页 + 暂停)
- ✅ 数值/边界正确——不能"交互酷但结果是错的"
- ✅ **给外部看时验过托管端**:`curl -I` 有 `Accept-Ranges` 与正确的 `Content-Type`、`Range` 返回 206（只看 HTTP 200 不算过）
- ❌ 不要花哨动画盖住内容
- ❌ 不要外链 CDN / 字体 / 图片

## 4. 讲解视频

**适用**

- 抽象概念需要视觉节奏(注意力机制、卷积过程)
- 用户只想听"那 3 分钟",不想从头学一门课
- 围绕**单一具体问题**,不是知识普及

**提示词模板**

```
帮我做一个 40 秒的科普/教学视频,主题是【填写你的主题】。

要求:
- 画面用 HTML + Canvas 画,逐帧截图合成(或 Remotion / HyperFrames)
- 视觉风格为【手绘卡通 / 科技感微距 / 3Blue1Brown 数学动画】
- 背景必须动(慢浮 / 呼吸 / 扫描线),文字只做淡入
- 旁白配音使用【EdgeTTS 或 ElevenLabs】
- 字幕:挂软字幕轨且默认开,另给 srt 和无字幕版
- 音量:loudnorm 到 -14 LUFS,峰值 -1 dBTP
- 先给 Mermaid 逻辑链,再写 STORYBOARD.md 分镜时间轴
- 最后逐帧导出
```

**判断清单**

- ✅ 围绕一个具体问题,不是"从头教 X"
- ✅ 先有 Mermaid 逻辑链,分镜按链条展开(不是按知识点罗列)
- ✅ **字幕能开关**:软字幕轨 + 默认开 + `-clean.mp4` 兜底(见 `video-spec.md`)
- ✅ **音量到平台上限**:实测 `-15…-13 LUFS`,不是 -23 LUFS
- ✅ **背景在动**:逐帧差分 ≥ 0.8(`check_explain.py` 会测)
- ✅ 分镜表先写(几秒 / 画面 / 旁白 / 动效)
- ✅ 旁白与画面同步(节奏不抢戏)
- ✅ **时长以旁白音频的实测长度为准**——分镜里的秒数只是估算;按估算切帧会让后半段音画全错
- ✅ **转场不改变总时长**(淡入淡出作用于片段自身,不做重叠)
- ✅ **推镜逐帧亚像素渲染**——不要用 `zoompan` 的整数裁剪,否则"冻住一帧→跳一格"
- ✅ 交付前跑过**抽帧校验**与**抖动量化**(见 `scripts/verify_video.py`)
- ✅ **发布出来还要能拖能播**:成片 `moov` 在 `mdat` 之前(faststart),提供方支持 Range/206
- ✅ 可疑符号过过"缺字形"判定(`U+E123` 基准比 md5),或走浏览器渲染——两条路径的规则见 `form4-video-delivery.md` §5.1
- ✅ 交付物可播放——不要只交一份"方案"
- ✅ 上一版已归档(成片 + md5 + 症状清单),改之前先存
- ❌ 不要让模型自选 API key / 不要塞入付费资源
- ❌ 不要"看起来完整"——必须真能跑 / 真能播
- ❌ 不要拿体积当质量指标:抖动版的体积反而更小(大量重复帧白拿压缩率)
- ❌ 不要假设 ffprobe 存在(很多 Windows 环境只装了 ffmpeg)

## 选择哪种形式的决策树

```
看不懂 ──┐
         │
         ├─ 是表达不清 / 术语太绕?
         │      → 形式 1:简化文字
         │
         ├─ 是关系多 / 流程杂?
         │      → 形式 2:结构图
         │
         ├─ 是"试一下才知道"?
         │      → 形式 3:3 页 Boss 海报(带一个滑块)
         │
         └─ 是节奏 / 动效才能讲清?
                → 形式 4:讲解视频(字幕可关、背景在动)
```

三种形式共用一个底座:先画 Mermaid 心流链(`flow-first.md`),再按链条分页/分镜。

## 升级信号(从轻到重)

- 文字仍抽象 → 升图
- 图看懂了,但想"试一下" → 升 3 页海报
- 海报的每一步需要"被讲出来" → 升视频

## 降级 / 拒绝信号

- 视频需求其实一句结论就能解决 → 退回文字
- 用户只问"X 怎么用" → 别启动 skill,直接答
- 不确定用户是否愿意看视频 → 先问,不要默默交付
