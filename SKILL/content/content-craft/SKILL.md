# 内容生产总纲

把一份源材料（或一个念头 + 一手经历）写成能直接发的内容。长文、短帖、知乎专栏、去味改写，是同一套手艺在不同长度和平台上的表达，不是四件不同的事。

## 概念 · 是什么 / 不是什么

| | 是什么 | 不是什么 |
|---|---|---|
| 这份 skill | 一套内容生产手艺：准确、有用、易读、像人 | 翻译工具；排版工具；发布机器人；灵感生成器 |
| 好内容 | 读者看完能观察、能判断、能落手，且读起来是具体的人在说话 | 资讯搬运、情绪发泄、AI 式整洁废话、好看的花活 |
| 改写/去味 | 删掉模板感、表演感、语域漂移，同时保住事实和术语 | 敏感词替换；反技术、反抽象、反专业 |
| 发布 | 暂存草稿，交人确认 | 自动点"发布" |

## 三条信条 + 活人感基线

1. **准确**：术语、版本、路径、代码、数据都能对上。核实过才算数。
2. **有用**：读者看完知道怎么观察、怎么判断、怎么落手。
3. **易读**：不是把信息塞满，而是把复杂问题讲顺。

**活人感不靠口语化表演，靠三个东西**：

- **具体**：能看到场景、工具、版本、trace、代码路径、失败分支或读者反馈。
- **取舍**：知道作者为什么这么判断，也知道这个判断在什么条件下成立。
- **不装**：不把普通事实写成时代趋势，不把材料整理写成深刻洞察。

> 判据：如果一段话没有具体对象、具体动作或具体证据，即使语气顺滑，也按 AI 味处理。

## 统一流程（5 步，固定顺序）

```
1. 判形态与读者   → 长文 / 短帖 / 知乎 / 去味改写；写给谁、读者带走什么
2. 源头锚定       → 只搬运源里已有的事实，列出"可用事实"和"不可编造项"
3. 定一个论点     → 全文一条主线，一个角度，一句灵魂话
4. 写 + 去 AI 味  → 边写边按反模式清理（同一遍，不要写完了另起一遍才发现全是模板腔）
5. 双向回读质检   → 保真回读 → 残留回读 → 抽读关键段 → 交付
```

## 铁律一：源头锚定（不编造）

- 只用源里已有的事实、数字、quote、例子、截图。**缺材料就开口要，不许补**。
- 数字必须带参照物：单位、测试条件、对比基线、样本范围、时间跨度。**条件和数字不能拆开**。
- quote 加引号的前提是**逐字出现在源里**；改写出的句子标 `derived`，不加引号。
- 无源引用（`研究表明 / 数据显示 / 专家指出`）按三种模式处理：删（论点能独立成立才留）、审（标"缺来源"，不补虚构出处）、占位（仅在用户要求保留原结构时）。
- 不编造 URL、API、类名、客户证言、mention、生成过的截图。没有 URL 就写 `[LINK — 发布前替换]`。
- 观点要有来源：作者、文档、issue、commit、trace、实验、读者反馈——不借"很多人"撑场。

## 铁律二：一个论点（不堆砌）

- 全文（或单条帖子）只服务**一个论点、一条主线**。不把整篇总结成多个平铺要点。
- 一个角度、一个灵魂 quote、一张图的职责**单一**。不合并多个视觉 job。
- 一段一义：一段只做一件事（下定义 / 解释机制 / 展示证据 / 下判断），不炖成一锅。
- **核心观点全文只出现 2 次**：定义处 + 总结处。中间直接使用，不反复解释。
- 编辑判断自己拍板：**不输出多个版本让用户选**。不满意让用户带着新约束重生成。

## 去 AI 味（总则 + 反模式 + 双向回读）

**总则：先保信息，再谈风格。** 任何改写不能新增事实、删核心事实、改责任主体或改谓词的方向/强度。专业词、系统主语、引用原文、命令、字段、日志默认保留。

### 禁用词（命中即删或换具体）

| 类别 | 例 |
|---|---|
| 清嗓/开场套话 | 值得注意的是、事实上、实际上、说实话、关键是、有趣的是、这让我想到、不得不说 |
| 总结腔 | 综上所述、总而言之、归根结底、总的来说、一言以蔽之、At the end of the day |
| 时代/填充套话 | 在当今社会、随着技术的不断发展、随着 AI 的快速发展、从根本上说 |
| 意义通胀 | 标志着、反映了趋势、奠定了基础、体现了价值、展现了潜力、意义重大、不可或缺 |
| 汇报腔 | 先说判断、直奔主题、值得重点关注、不难看出、众所周知、核心在于 |
| 商业黑话 | 赋能、抓手、闭环、链路、颗粒度、护城河、赛道、打法、方法论输出、形成共识 |
| 网络梗/夸张 | YYDS、绝绝子、破防、拿捏、炸裂、封神、降维打击、赢麻了、核弹级 |
| 冗余确认副词 | 真正、真的、确实、实际上（**无对照对象时删**，有对照对象时留） |
| 元叙述 | 接下来我将、下面我们来看、让我们来探讨、首先…其次…最后 |

### 结构反模式（句式/段落层面，比单词更隐蔽）

1. **二元对比假戏剧** `不是 X，而是 Y`：先立一个读者没有的误解再推翻。整篇 ≤ 2 次，直接说 `Y` 即可。
2. **否定式列举** `不是 A 不是 B，是一种…`：绕一圈，直接说是什么。
3. **三件套列举**：凑三项装完整。按事实数量写，两项就两项。
4. **总结式/正能量收尾**：前面说清楚了就结束，不重复、不上价值、不展望。
5. **加粗滥用 / 分条列点强迫症**：重点靠内容，不靠格式；简单回复不列点。
6. **对称填充** `既…又…，既要…又要…`：没有信息增量的对仗删掉。
7. **同义词躲避**：同一对象别换三种说法（`修表→这门手艺→这项技能`）。关键词该重复就重复。
8. **动词名词化** `进行了优化 / 实现了提升` → `改顺了 / 快了多少`。
9. **翻译腔四件套**（AI 味根子是翻译腔，先在英文句法里想好再逐字翻中文）：
   - 否定-纠正结构（同上 1）
   - 形容词+冒号起手 `逻辑很清晰：…` → 直接讲内容
   - 抽象名词做主语 `X 的 Y 比 Z 更 W` → 换人/动作/具体对象做主语
   - 物理动作动词 `接住/击穿/扛住/立住` → 中性动词（是/做/返回/触发/写入/确认/收到）
10. **假口语化 / 假现场感**：硬塞网络梗、伪造生活细节（`凌晨三点，窗外下着雨`）、戏剧化碎句（`三年。两个人。一个想法。`）——真人用梗是随机的，模型是批量的，更假。
11. **节奏单调**：每句差不多长、差不多落点，同型骨架反复到能预判下一句。长句装信息、短句落锤，交替。
12. **破折号/连词过密**：`——` 一段最多保留一处真正承担插入；连词靠语序和事理相接，不靠 `因为…所以…同时…此外` 堆。

### 处理原则

- **句首引导词后面还跟着实质内容** → 句内洗，删引导词留骨架。
- **整句都是空话**（剥掉引导词就什么都不剩）→ 进"建议删除"清单交用户拍板，不擅自软化成另一种说法。
- **元规则**：去味动作本身别用同义词轮换降密度——那会把密度问题换成"油滑感"。换词躲重复本身就是模型腔。

### 双向回读（交付前必做，两步分开）

- **Pass 1 保真**：protected spans 漂没漂；范围/条件/否定/情态/完成态/方向/强度逐项可追溯；数字与修饰对象、主体与动作的配对关系对得上；语域统一；术语不失真。
- **Pass 2 残留**：开场残留（`结论先说/值得注意的是`）、总结残留（`总的来说`）、narrator 残留（解释"这说明了什么"）、空泛判断残留（`方向是对的/意义重大`）、节奏过匀。只做轻修，不重写全文。

## 形态适配（同一套手艺，四种长度）

### 长文（技术深度 / 方法论 / 复盘）

```
开头(三句内说清：讲什么 / 为什么值得看 / 带走什么)
  → 背景(前置知识 + 为什么现在聊)
  → 主体(3–8 块，一段一义；先全景图再下钻；关键节点给读者引导)
  → 判断(把局部观察提炼成更高一层理解，带依据和边界)
  → 结尾(一句判断收束 / 给下一步 / 延伸阅读，不做空洞升华)
```

- 开头禁区：不从"在这个时代"开讲、不先铺大背景、不端正确废话当帽子。
- 代码块前有"用途句"（这段证明什么、重点看哪几行）、后有"解释句"。省略用注释标明，不用含糊 `...`。
- 列表不能是目录：每项自带信息增量，删掉描述只留名词会丢信息才算合格。
- 图表回答一个明确问题；结论回连数据。

### 短帖（LinkedIn / X / 公众号 / 小红书）

```
Hook(张力 + 好奇 + 短，第一句能让人停下；不制造假悬念)
  → Value(1–3 行还清 hook，一个可用的框架/判断/数据/步骤，带源证据)
  → 互动提示(邀请具体立场/例子/反驳/缺失步骤，不用 "Thoughts?" 这种空问)
  → 软 CTA(把转化轻于价值；"完整报告放第一条评论"要真放)
```

- 一个论点，不是一个摘要。不写 press release，不写博客缩写。
- 灵魂 quote 做脊柱，不做装饰。
- 语言按平台母语重写，不逐字翻译；中文社媒节奏重排句子，不搬英文连词。
- 第一人称经历和判断在源里有就保留。

### 知乎专栏（技术设计稿 / 深度解析）

```
TL;DR(标题下 3–5 条可抄走的判断，扫完能走)
  → 为什么/验证哪条(正文第一块，架构类必写，配图)
  → 错路对照(先画读者会想错的，再画正路)
  → 脉络(需求 → 接缝 → 树根 → 主干 → 切开)
  → 正文(每步：人话 → 是什么/不是什么 → 一张图)
  → 收获和结论(5–7 条能搬走的判断 + 一段把主线落地)
  → PS / PPS / PPPS(三层附言，给读完的人)
```

- 知乎不渲染 mermaid/SVG，图必须 PNG。每个独立论点一张图，标题即论点，红字钉"不是什么"。
- 先比喻后术语；术语第一次出现用大白话落地。
- 收获里不放文件名、函数、路径——那些不是收获。

### 去 AI 味改写（任意文本）

- 判场景（chat / status / docs / public-writing）→ 划 protected spans → 判力度（轻改/中改/重改）→ 双向回读 → 输出。
- 默认输出**单一推荐版本**；用户要"先标问题不改写"时切标注模式（每条：问题族 + 触发点 + 建议动作 + 是否建议改写）。
- 缺材料的文本标 `材料不足`，只说明"删完还剩什么、缺哪类材料"，不替作者用新说法把篇幅填回去。

## 发布红线

- **只暂存草稿，禁止自动点"发布"**，交用户确认。
- 不蹭灾难、危机、丑闻、裁员做注意力，除非源本身就是这个话题且能加有用上下文。
- 不编造数据、quote、URL、截图、mention、客户证言、产品结果。
- 不假装生成过图片；只写了 image prompt 就明说没生成。
- hashtag 0–3 个且具体，不用标签代替观点；不点名无关的人/公司。
- 平台字数、图片尺寸按**当前官方规则**；能联网就先刷新，字符上限会变。

## 质检清单（强制，先出稿 → 立刻扫描 → 硬修 → 抽读 → 交付）

按 skill 写的第一版只是草稿。模型会自然滑回 `不是 X 而是 Y`、`真正/其实/实际上` 这类句式，即使结构内容都对了也要扫一遍：

- [ ] **滑回扫描**：`不是 X 而是 Y` 族 ≤ 2 次；`真正/其实/实际上/确实` 高频压掉（删掉后技术信息量不变 = 填充，删）。
- [ ] **意义通胀扫描**：`标志着 / 反映了 / 奠定了 / 体现了 / 展现了` 后面没有具体影响就删。
- [ ] **源头保真**：每个数字有参照物和条件；每个 claim 能回指源；无 unsupported claim / fake quote。
- [ ] **单一论点**：全文一条主线，没混进第二个论点。
- [ ] **活人感**：随机抽三段，能否看到具体的人、场景、工具、版本、trace、判断？
- [ ] **平台字数**：短帖在官方上限内，长文不过长（知乎 2500–6000 字，超 8000 砍）。
- [ ] **发布前**：正文不留编辑痕迹（`这一版/上一稿/按要求改过`）。

**完成标准**：读起来像一个有经验的人在复盘/分享，而不是一份被整理得很干净的材料。
