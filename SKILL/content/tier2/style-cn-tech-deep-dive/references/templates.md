# 句式库 (Templates)

可直接套用的中文句式。每条 = **使用场景 + 模板 + 注意事项 + 原文示例**。

---

## 一、开场钩子变体(指纹 1)

### 变体 A · "瓜" + 服务承诺
- 模板:`这个瓜,我帮你把 <技术细节 / 后续 / 全貌> 都 <扒清楚 / 理清楚 / 一次讲清楚>。`
- 触发:争议/爆料类
- 示例:`这个瓜,我帮你把技术细节和后续都扒清楚了。`

### 变体 B · "一件事" + 时间锚定
- 模板:`<具体日期>,一个叫 <人名/机构> 的 <角色> 发了 <动作>:... 这件事把 <行业 / 公司> 的 <问题> 顶到了 <谁> 面前。`
- 触发:有具体触发人和日期的事件
- 示例:`9 月 18 日,一个叫 ferstar 的开发者发了一篇排查文:...`

### 变体 C · "我们今天聊" + 反直觉钩子
- 模板:`今天我们聊一件 <反直觉的事>:<简短描述>。`
- 触发:偏正面的 deep-dive / 产品解析
- 示例:`今天我们聊一件国产模型悄悄拿到第一的事:Hunyuan 在某基准上反超了 GPT-5。`

**禁忌**:
- 不要 `在这个 AI 飞速发展的时代...`
- 不要 `今天我们来聊聊...`
- 不要 `作为一名 XX,从我自己的观察来看...`

## 二、第 N 层递进起头(指纹 2)

### 模板
```markdown
**第 N 层,<层面名>。** <核心陈述句>
<细节 1>
- <细节点>
- <细节点>
- <细节点>

<可选第 N+1 层>
**第 N+1 层,<层面名>。** <核心陈述句>
<细节 1>
```

### 层面名常用词
- 第一层:行为本身 / 事件本身 / 公开记录
- 第二层:社区复测 / 独立验证 / 二手信息
- 第三层:官方回应 / 当事方表态 / 对手动作
- 第四层(慎用):行业影响 / 监管跟进

## 三、公平论反转(指纹 3)

### 变体 A · 平心而论 + 收窄
- 模板:`平心而论,"<合理面>"这件事,很多 <同类产品> 都在做,有些是 <明示 / 默认> 的。<主体> 的问题不在 "<动作>" 这个行为本身,而在 <N 个具体条款> — 这 N 点叠加,性质就从 "<原属性>" 变成了 "<新属性>"。`

### 变体 B · 说句公道话 + 收窄
- 模板:`说句公道话,<承认面>。但 <主体> 的麻烦在于 <具体问题>,这就让 <定性>。`

### 变体 C · 不吹不黑 + 双面
- 模板:`不吹不黑地讲,<主体> 一边 <积极面>,一边 <问题面>。但问题是 <核心矛盾>。`

## 四、精确数字表达(指纹 4)

### 数字 + 量级 + 触发条件 + 单位
- 模板:`<数字><单位>,触发条件是 <场景>,<限制条件>。`

### 示例堆(组合用法)
```markdown
- <极端值>,只要 <触发条件> 就中招
- <均值/中位数>,来自 <样本>
- <重试次数> 还在 pending 里等重传
- 单会话最多 <N 次> 捕获
- 删了 <X> 后 <Y 分钟> 内自动重新 <动作>
```

### 数字密度建议
- 每个强主张配 3-5 个数字
- 没有数字的强主张 → 砍掉或改为弱主张
- 加粗 1-2 个最扎心的数字

## 五、N 条死线压缩(指纹 5)

### 模板
```markdown
**N 条"死线"**:
<短句 1>,
<短句 2>,
<短句 3>,
<短句 4>。
```

### 注意事项
- 每条 ≤ 12 字
- 用动词/名词短语,不用长句
- 4-5 条为佳,3 条勉强,6 条以上读起来不像"压缩"
- 每条彼此独立(无重叠无包含)

### 通用化变体
- "N 条红线"
- "N 个判据"
- "N 条判断标准"
- "N 个'别 X' 清单"

## 六、冒号双行小节标题(指纹 6)

### 模板
```
## <主题>:<锐评>
```
- 冒号前 2-6 字
- 冒号后 5-12 字,是一个锐评/定性/亮点

### 锐评句式库
- `:<一个名词短语的定性>` 例:`:一份罕见的透明披露`
- `:<反直觉判断>` 例:`:服务端拿私钥,本地都解不开`
- `:<3-4 个并列关键词>` 例:`:道歉、修复、开源、邀审查`
- `:<具体可记忆结论>` 例:`:选型判断`

### 反例(平铺,不要用)
- ❌ `## 上传行为的技术细节` → 改 `## 上传行为:服务端拿私钥,本地都解不开`
- ❌ `## ZCode 的功能介绍` → 改 `## ZCode 全貌:GLM-5.3 官方 Harness`
- ❌ `## 我们的建议` → 改 `## 该不该用:选型判断`

## 七、立场标(指纹 7)

### 给合理面
- `平心而论,` (开头)
- `说句公道话,` (开头)
- `不吹不黑,` (开头)
- `客观地说,` (开头)

### 给金句/定论
- `说到底,` (开头)
- `其实问题很简单,` (开头)
- `这件事的本质是` (开头/中段)
- `这才是` (句中转折)
- `关键在于,` (开头)

### 给实务建议
- `给几条务实的建议:` (开头,带冒号)
- `具体到行动上,` (开头)
- `落到实操:` (开头,带冒号)
- `如果是我会` (开头)

### 给诚实声明
- `用户自行 X、配置的任意 Y 或另行安装的 Z,可能具有额外的数据发送行为 —`
- `不能仅因... 就推定...`
- `<工具> 能做的 <A>,但 <B> 是用户自己决定的`

## 八、收尾三段(指纹 8)

### 模板
```markdown
<金句段>
说到底,<题材> 给整个 <行业> 上了一课:**<中心论点金句,加粗,含反直觉对比>**。
<1 句支撑论证,用"即便...也远比..."等对比结构>。

<反问段>
<1 句反问读者,具体到场景>。
<可选 1 句互动邀请>。
```

### 金句加粗模板
- `**<X> 的本质不是 <Y>,是 <Z>**`(对比)
- `**<X> 不是 <Y>,是 <Z>**`(否定+重定义)
- `**<X> 靠的不是 <Y>,是 <Z>**`(依赖重写)
- `**为什么 <X> 在 <Y>?因为 <Z>**`(问+答)

### 反问模板
- `你会 <什么场景> <什么选择>?(评论区聊聊你的标准)`
- `如果你正在 <场景>,你会怎么 <动作>?`
- `这件事 <影响谁> ?值得每个人想想。`

## 九、圈层黑话密度参考(指纹 9)

### 推荐密度
- 中文 AI 圈产品/模型/厂商名:全文 5-10 次自然穿插
- 数字单位用圈层常用单位(token、star、fork、PR、benchmark、context window)
- "我们 / 国产 / 中文圈 / 圈内"等圈层标记:1-3 次,放在定位段

### 自然穿插示例
- "和 DeepSeek Harness、Claude Code 这些是同类竞品"
- "在国产 AI 厂商里"
- "GLM 系、DeepSeek 系、Kimi 系"

### 反例(为了显得懂行硬塞)
- ❌ 一段话塞 5 个模型名 + 3 个 benchmark 名
- ❌ 用圈内梗当事实(例:"懂的人都懂 XX")

## 十、信息差诚实声明(指纹 10)

### 模板
```markdown
<用户责任段>
用户自行编写的 <脚本 / 配置 / 扩展>、配置的任意 <地址 / 端点> 或另行安装的
<第三方组件>,可能具有额外的数据发送行为 — "<不能仅因通过 <工具> 启动,
就推定其用途或接收方已经获得官方审核>"。
```

### 触发条件
- 涉及第三方工具链
- 涉及平台/扩展机制(MCP、Plugin、Hook、Command、Skill)
- 涉及用户可自配的端点(API、URL、Webhook)

## 十一、过渡句(节与节之间)

### 顺承过渡
- `随后发生的事是:`(引出官方回应)
- `<前节总结>,<后节引子>。`
- `抛开争议,<后节主题>。`

### 反转过渡
- `但这还没完。`(引出另一面)
- `不过故事到这里只是上半场。`
- `问题是,谁来 <动作>?`

### 衔接模板
- `这件事的本质是 <X>。那 <X> 怎么落地?<引出下一节>`
- `<前节> 讲的是 <Y>。接下来聊 <Z>。`

## 十二、列表项句式

### 三层列表(常见于功能模块拆解)
```markdown
### 1. <模块名>
- <要点 1,2-3 个动作细节>
- <要点 2>
- <要点 3>
```

### 功能对比表(常见于全解析)
```markdown
| 形态 | 入口 | 说明 |
|------|------|------|
| Desktop | <X> | <Y> |
| Web | <X> | <Y> |
| CLI | <X> | <Y> |
```

## 十三、口语化但不滑头的口吻

### 可用
- "扎心"(形容数字很残酷)
- "搭车"(形容意外附带)
- "扒清楚"(形容挖到底)
- "一夜回到解放前"(形容倒退)
- "买账"(形容接受)
- "打住"(形容暂停)

### 慎用(用了就是段子手腔)
- "yyds / 绝绝子 / 破防了 / 芭比 Q 了"
- "咱就是说 / 一整个..."
- emoji 表情

### 不用
- "在这个大模型时代"
- "作为 AI 时代的 XX"
- "让我们一起..."

## 十四、原文金句(可直接迁移的中心论点)

写新文时如果一时想不出金句,可以参考 iTech 的金句结构(对比式金句):

> **Agent 工具的信任,不是靠品牌,是靠可审计性**。

迁移公式:`<X> 的 <核心属性>,不是靠 <直觉依赖>,是靠 <可验证动作>。`

示例衍生:
- 模型的智能,不是靠参数量,是靠泛化测试。
- 开源的安全,不是靠许可证,是靠社区审计。
- API 的可信,不是靠 SLA,是靠可重放日志。
