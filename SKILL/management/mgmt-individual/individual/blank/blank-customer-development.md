# 史蒂夫·布兰克 · 客户开发法(Customer Development)

> 办公室里没有真相；先验证客户再开发产品，4步必须按顺序执行

## 核心理念

布兰克要解决的根本问题是：**为什么大多数创业失败是因为做了一款没人要的产品？为什么"先开发产品再找客户"的顺序是错的？**

布兰克的底层逻辑是顺序反转：传统产品开发流程是"开发产品→推向市场→找客户"，布兰克把它反转为"找客户→验证需求→再开发产品"。这个反转基于一个根本洞察：**办公室里没有真相**——你坐在办公室里想象出来的客户需求，大概率是错的。唯一验证假设的方式是走出办公室，与真实客户对话。

核心公式：**传统流程（产品开发→客户）= 假设驱动 → 布兰克流程（客户→产品开发）= 验证驱动 → 客户开发4步（发现→验证→创造→建设）→ 每一步必须按顺序 → 客户开发与产品开发必须并行 → 布兰克是理论源头，莱斯是实践简化**

布兰克是精益创业运动的理论源头。2005年，布兰克在斯坦福和伯克利教授客户开发课程，埃里克·莱斯是他的学生之一。莱斯把布兰克的客户开发思想操作化为Build-Measure-Learn循环和MVP工具，写成了《精益创业》。布兰克是理论架构师，莱斯是实践工程师。

## 关键模块

### 模块1：客户开发4步

- 定义：客户开发4步是布兰克对创业流程的重新定义——从客户发现到公司建设的4个阶段，每一步必须按顺序执行，不可跳过
- 输入：创业假设（问题假设/客户假设/产品假设/商业模式假设）
- 输出：经验证的商业模型、可规模化的销售模型、可持续的公司组织
- 关键动作：
  - 客户发现(Customer Discovery)——第一步：验证问题是否存在、客户是否真实、解决方案是否被需要；从假设出发，走出办公室，与潜在客户对话，验证或推翻假设；客户发现的目标不是"确认假设是对的"而是"发现假设是否成立"
  - 客户验证(Customer Validation)——第二步：验证是否找到了可重复、可规模化的销售模型；客户验证回答的核心问题是"客户愿意为这个解决方案付费吗？"如果验证失败，回到客户发现重新开始
  - 客户创造(Customer Creation)——第三步：验证成功后，开始大规模获客；客户创造不是"找到第一个客户"而是"创造一个可规模化的获客引擎"；从早期采用者扩展到主流市场
  - 公司建设(Company Building)——第四步：从探索型团队转型为执行型组织；建立正式的部门、流程、管理结构；公司建设必须在客户创造成功后才能开始，否则会过早固化不成熟的组织结构
  - 为什么4步必须按顺序——每一步的输出是下一步的输入：没有发现就没有验证，没有验证就没有创造，没有创造就没有建设；跳过任何一步等于在未验证的假设上建设，结果是浪费资源和时间
- 常见误区：认为4步可以并行——4步必须按顺序，但客户开发与产品开发可以并行；认为客户发现=用户调研——发现是验证假设不是收集意见；认为验证失败=创业失败——验证失败是学习，回到发现重新开始才是正确路径

### 模块2：客户发现

- 定义：客户发现是客户开发4步的第一步——验证问题是否存在、客户是否真实、解决方案是否被需要，核心方法是"走出办公室"
- 输入：问题假设、客户假设、产品假设
- 输出：经验证的问题定义、客户画像、价值主张
- 关键动作：
  - 问题假设→客户假设→走出办公室→验证——第一步：写下你的问题假设——"我们认为X类客户有Y问题"；第二步：定义客户假设——"我们认为Z类人群是我们的目标客户"；第三步：走出办公室——与真实客户对话，不是问"你觉得这个想法怎么样"而是观察他们的行为、理解他们的痛点；第四步：验证或推翻假设——如果假设被推翻，修改假设重新验证
  - 为什么办公室里没有真相——布兰克最著名的论断：你坐在办公室里想象出来的客户需求，大概率是错的；原因：①确认偏差——你倾向于寻找支持你假设的证据；②幸存者偏差——你只看到使用类似产品的客户，看不到不使用的；③投影偏差——你假设客户和你想的一样；唯一对抗这些偏差的方法是走出办公室与真实客户对话
  - 客户发现的2个阶段——第一阶段：验证问题——客户真的有这个问题吗？问题有多痛？客户现在如何解决？第二阶段：验证解决方案——客户认为你的解决方案有价值吗？他们愿意付费吗？他们愿意切换吗？
  - 客户发现的访谈技巧——不要问"你喜欢这个产品吗"（所有人都会说喜欢），而要问"你上次遇到这个问题是什么时候？你怎么解决的？花了多少钱？"——行为数据比态度数据更有价值
- 常见误区：把客户发现当作"推销想法"——发现的目的是倾听不是说服；只访谈"友好"的客户——友好客户的反馈不可靠，需要访谈真实目标客户；用问卷替代访谈——问卷只能收集预设答案，访谈才能发现未知问题

### 模块3：客户验证

- 定义：客户验证是客户开发4步的第二步——验证是否找到了可重复、可规模化的销售模型，是客户发现和客户创造之间的关键门槛
- 输入：客户发现的输出（经验证的问题定义/客户画像/价值主张）
- 输出：可重复可规模化的销售模型，或回到客户发现的决策
- 关键动作：
  - 是否找到可重复可规模化的销售模型——可重复：同样的销售流程可以反复使用获客；可规模化：增加销售资源可以线性增加获客量；如果销售模型不可重复（每个客户都需要定制化方案）或不可规模化（获客成本随规模指数增长），验证就未通过
  - 为什么验证≠发现——发现回答"问题是否存在"，验证回答"客户是否愿意付费"；发现是定性的（访谈/观察），验证是定量的（付费/订单/合同）；发现告诉你"方向对不对"，验证告诉你"能不能赚钱"
  - 失败→回到发现——验证失败不是创业失败，而是学习信号：说明你的客户发现不够深入，或者你的销售模型不对；布兰克说"验证失败是客户开发最有价值的时刻——它告诉你之前的假设有问题，现在你有机会修正"
  - 验证的关键指标——付费转化率、获客成本(CAC)、客户生命周期价值(LTV)、销售周期长度；这些指标必须可重复——不是一次性的运气而是系统性的结果
- 常见误区：把一次成功当作验证通过——一次成功可能是运气，验证需要可重复性；认为验证=签合同——验证是验证销售模型不是签一个合同；验证失败后不愿回到发现——沉没成本偏见让人不愿承认假设错误

### 模块4：客户开发vs产品开发

- 定义：客户开发与产品开发是两条必须并行的线——客户开发验证假设，产品开发构建产品，两条线相互驱动而非先后顺序
- 输入：客户假设、产品需求、技术约束
- 输出：客户开发与产品开发的并行节奏
- 关键动作：
  - 为什么两条线必须并行——传统流程是"先开发产品再找客户"——产品开发先行，客户开发后行；布兰克认为这是错的：没有客户验证的产品开发是在黑暗中射击；正确的做法是两条线并行——客户发现驱动产品方向，产品原型驱动客户反馈
  - 为什么产品开发先于客户开发是错的——产品开发先行的问题：①你不知道为谁开发——没有客户画像的产品是"为所有人开发=为没有人开发"；②你不知道开发什么——没有问题验证的功能是"猜测功能"；③你不知道何时完成——没有验证标准的开发是"永远做不完"
  - 并行的节奏——客户发现阶段：客户开发先行，产品开发做最小原型；客户验证阶段：产品开发加速，客户开发验证销售模型；客户创造阶段：产品开发完善，客户开发大规模获客；公司建设阶段：两条线融合为正式组织
  - 两条线的冲突管理——客户开发说"客户要A"，产品开发说"技术只能做B"——这种冲突是健康的，解决冲突的过程就是产品市场匹配的过程；避免任何一条线主导另一条线
- 常见误区：认为客户开发=不做产品——客户开发是验证方向，产品开发是构建产品，两者缺一不可；认为并行=同时做所有事——并行是节奏协调不是同时做所有事；让产品开发主导客户开发——产品开发容易陷入"功能陷阱"，必须让客户开发保持方向

### 模块5：布兰克vs莱斯

- 定义：布兰克与莱斯的关系是"理论源头vs实践简化"——布兰克提供了客户开发的理论架构，莱斯把理论操作化为精益创业的工具集
- 输入：布兰克客户开发4步、莱斯精益创业Build-Measure-Learn
- 输出：两者的互补使用框架
- 关键动作：
  - 布兰克是理论源头——布兰克在2003年出版《Four Steps to the Epiphany》，首次系统提出客户开发法；布兰克的理论更完整、更结构化——4步法覆盖从发现到建设的完整流程；布兰克的理论也更复杂——4步法有大量子步骤和检查点
  - 莱斯是实践简化——莱斯在2011年出版《精益创业》，把布兰克的思想操作化为Build-Measure-Learn循环和MVP工具；莱斯的框架更简单、更易执行——3步循环比4步法更容易理解和实践；莱斯的框架也更聚焦——主要解决"如何验证假设"而非"如何建设公司"
  - 为什么两者互补——布兰克提供"为什么"和"全局"——为什么需要客户开发？4步法的完整逻辑是什么？莱斯提供"怎么做"和"工具"——怎么做MVP？怎么测量？怎么转型？用布兰克理解全局，用莱斯执行细节
  - 两者的差异——布兰克更关注B2B和复杂销售模型，莱斯更关注互联网和快速迭代；布兰克的4步法更适合需要深度客户关系的业务，莱斯的Build-Measure-Learn更适合可以快速实验的业务
- 常见误区：认为莱斯完全替代布兰克——莱斯简化了布兰克但没有替代，布兰克的全局视角仍然不可替代；认为布兰克过时了——布兰克的理论是精益创业的基础，没有布兰克就没有莱斯；只学莱斯不学布兰克——缺少布兰克的全局视角，莱斯的工具容易变成"为实验而实验"

| 关联方法论 | 关系 | 接口 |

| 德鲁克创造顾客 | 上游-创造顾客的理论化 | 德鲁克说"企业的唯一目的是创造顾客"——这是客户开发法的哲学基础；布兰克把"创造顾客"操作化为4步法——发现/验证/创造/建设；德鲁克定义"为什么"，布兰克展示"怎么做" |

## 适用场景

### 最适合

- 早期创业公司，假设未经检验，需要验证客户和需求
- B2B复杂销售，需要深度客户关系和可重复销售模型
- 大企业内部创新，新业务假设需要验证
- 非互联网行业，产品开发周期长，不能靠快速迭代试错
- 需要全局视角的创业者——从发现到建设的完整路径

### 不适合

- 已验证商业模式下的效率优化（假设已验证，不需要客户开发）
- 纯技术驱动的硬科技（客户需求明确但技术路径不确定）
- 强监管行业（合规要求可能限制"走出办公室"的验证方式）
- 极短周期的互联网产品（莱斯的Build-Measure-Learn更适合）
- 内部工具开发（用户已知，不需要发现）

## 实施检查清单

- [ ] 是否写下了明确的问题假设和客户假设
- [ ] 是否走出了办公室与真实客户对话（而非坐在办公室猜测）
- [ ] 客户访谈是否问行为而非态度（"你上次遇到这个问题是什么时候？"）
- [ ] 客户发现是否验证了问题存在和客户真实
- [ ] 客户验证是否找到了可重复可规模化的销售模型
- [ ] 验证失败后是否愿意回到客户发现重新开始
- [ ] 客户开发与产品开发是否并行而非先后
- [ ] 是否按4步顺序执行（发现→验证→创造→建设）
- [ ] 公司建设是否在客户创造成功后才开始
- [ ] 是否同时理解布兰克的全局视角和莱斯的执行工具

## 诚实边界

1. **4步法的线性假设**：布兰克强调4步必须按顺序执行，但真实的创业过程往往是非线性的——你可能在客户发现阶段就无意中完成了客户验证，或者在客户创造阶段发现需要回到客户发现。严格的线性顺序在理论上清晰但在实践中难以完全遵守。

2. **"走出办公室"的执行难度**：布兰克说"走出办公室"，但实际执行远比说起来困难：如何找到目标客户？如何让他们愿意跟你对话？如何避免访谈中的引导性提问？布兰克对执行细节的指导不够具体，需要补充其他方法论（如Mom Test访谈法）。

3. **客户验证的"可重复可规模化"标准模糊**：多少次成功销售才算"可重复"？获客成本在什么范围内算"可规模化"？布兰克没有给出明确标准，验证是否通过仍然依赖创业者的判断力。

4. **B2B偏见**：客户开发法最初是为B2B企业设计的（布兰克的8家创业公司大多是B2B），4步法对B2C消费者的适用性有限——B2C消费者更难访谈、更难验证付费意愿、更难建立可重复销售模型。

5. **客户开发与产品开发的并行协调**：布兰克说两条线必须并行，但并行协调在实践中非常困难——客户开发的节奏（访谈/验证）和产品开发的节奏（编码/测试）天然不同步，两条线的冲突管理需要大量沟通和妥协。

6. **对"办公室里没有真相"的过度解读**：走出办公室是必要的，但不是充分的——客户访谈也可能产生误导：客户可能不知道自己要什么（亨利·福特的"更快的马"），客户可能说一套做一套，小样本访谈可能不代表主流市场。布兰克对访谈数据的可靠性估计过于乐观。

7. **4步法的规模假设**：客户开发法假设创业公司有足够的时间和资源完成4步——但现实中很多创业公司在完成客户发现之前就耗尽了资金。4步法的完整执行需要最低资源门槛，低于这个门槛的创业公司可能无法完成。
