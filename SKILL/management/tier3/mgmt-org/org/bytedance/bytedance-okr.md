# 字节跳动 · OKR体系

> OKR是沟通工具，不是考核工具——先对齐再执行，全员透明让方向自涌现。

## 核心理念

字节OKR体系解决的核心问题是：**万人组织如何保持方向一致而不依赖层层下达指令？**

答案是：让目标本身成为信息载体。当每个人都能看到CEO的OKR，对齐就不再需要中间层转发。OKR的本质是沟通工具——它回答"我们在做什么"和"什么算做到"，而非"你做到了多少分"。

三个关键设计选择：
1. **全员透明**：任何员工可看任何人的OKR，包括CEO
2. **双月迭代**：节奏远快于年度KPI，适应快速变化
3. **挑战型目标**：鼓励设定有难度的目标，未完成不等于失败

## 框架结构

```
字节OKR体系
│
├── 目标设定层
│   ├── 全员透明（CEO→VP→总监→员工，上下左右可见）
│   ├── 挑战型目标（60-70%完成率即算优秀）
│   └── 自下而上提议 + 自上而下对齐
│
├── 迭代节奏层
│   ├── 双月周期（每2个月更新OKR）
│   ├── 双月会（全员同步方向+进度）
│   └── CEO面对面（每2个月公开给自己OKR逐项打分）
│
├── 评估反馈层
│   ├── 360度评估（上下左右多维反馈）
│   ├── OKR结果关联职级调薪（能上能下）
│   └── 评估重点：贡献度+协作度，非OKR完成率
│
└── 文化保障层
    ├── "少说我觉得，多说数据说"
    ├── 坦诚清晰的文化土壤
    └── 信息默认公开的协作习惯
```

## 关键模块

### 模块1：全员透明

- 定义：组织内任何人的OKR对任何其他人可见，包括目标、关键结果、完成进度和红标项
- 输入：个人/团队/公司的目标与关键结果
- 输出：方向自涌现，无需中间层转发
- 关键动作：
  - 新员工入职后即可浏览CEO的OKR及完成进度
  - OKR系统支持按人、按团队、按关键词搜索
  - 红标项（未达预期的KR）同样公开，不遮掩
- 常见误区：以为透明等于监督，实际上透明的目的是对齐而非考核；只公开目标不公开进度，导致对齐效果打折

### 模块2：双月迭代

- 定义：以2个月为周期更新OKR，节奏远快于传统年度KPI
- 输入：上一周期OKR完成情况+新周期业务变化
- 输出：快速修正方向，避免年度目标在变化中失效
- 关键动作：
  - 每个双月周期开始时设定新OKR
  - 双月全员会同步公司级方向调整
  - CEO面对面：张一鸣每2个月公开给自己OKR逐项打分，不遮掩短板
- 常见误区：双月迭代≠双月考核，迭代是为了快速对齐方向，不是为了更频繁地打分；把双月OKR当双月KPI用，目标越设越保守

### 模块3：360度评估

- 定义：OKR结果关联职级调薪，评估来自上下左右多个维度
- 输入：OKR完成情况+协作反馈+贡献度评价
- 输出：职级调整、薪酬调整依据
- 关键动作：
  - 评估维度：不仅看OKR完成率，更看贡献度和协作度
  - 能上能下：OKR结果直接影响职级，表现不佳可降级
  - 八级绩效体系（F/I/M-/M/M+/E/E+/O）与OKR结果关联
- 常见误区：把OKR完成率等同于绩效分数，实际上OKR是沟通工具，绩效评估是独立体系；360度评估变成人情分，需要坦诚清晰的文化来对冲

### 模块4：CEO面对面

- 定义：每2个月，CEO公开给自己OKR逐项打分，包括红标项
- 输入：CEO个人OKR及完成情况
- 输出：全员看到最高决策者的自我评价，建立坦诚文化
- 关键动作：
  - 逐项打分，不回避未完成项
  - 解释未完成原因，分享调整思路
  - 为全员树立"坦诚清晰"的榜样
- 常见误区：CEO面对面变成CEO表演，只讲成绩不讲问题；员工只听不问，缺乏双向互动

## 决策启发式

| 场景 | 判断规则 | 来源 |
|------|---------|------|
| 目标设定时犹豫"定高还是定低" | 定高——挑战型目标60-70%完成率即优秀，定低反而失去对齐价值 | 字节OKR设计哲学 |
| OKR与薪酬强关联 | 弱关联——OKR是沟通工具，强关联会导致目标保守化 | 与华为PBC对比 |
| 员工OKR与上级不一致 | 先对齐再执行——不一致说明Context供给不足 | CnC+OKR联动 |
| 双月周期内方向大变 | 及时调整OKR，双月迭代的意义就是快速修正 | 双月迭代设计 |
| 360度评估流于形式 | 检查是否缺少"坦诚清晰"的文化土壤 | 文化保障层 |
| OKR变成KPI | 回到本质——OKR回答"做什么"，KPI回答"做到了多少"，两者不可混同 | 字节OKR核心定义 |

## 适用场景

### 最适合

- 快速变化的业务环境，年度目标容易过时
- 知识型员工为主，需要自主对齐方向
- 组织规模大到层级传达失真，需要透明机制
- 文化土壤支持坦诚反馈、信息默认公开

### 不适合

- 强合规行业，目标必须100%承诺完成（用PBC更合适）
- 团队成员习惯"被分配任务"而非"自主对齐目标"
- 缺乏坦诚反馈文化，360度评估会流于形式
- 业务极其稳定可预测的环境（年度KPI足够）

## 实施检查清单

- [ ] OKR系统是否全员可见（包括CEO的OKR及红标项）
- [ ] 迭代周期是否短于季度（字节用双月）
- [ ] 目标设定是否鼓励挑战性（60-70%完成率即优秀）
- [ ] CEO/高管是否公开给自己OKR打分
- [ ] OKR与薪酬是否弱关联（避免目标保守化）
- [ ] 360度评估是否包含协作维度（非仅完成率）
- [ ] 是否有双月全员会同步方向
- [ ] 评估结果是否能上能下

## 诚实边界

1. **OKR≠绩效管理**：字节OKR是沟通工具，但公开资料中OKR与绩效的关联细节（如何弱关联、权重多少）未完全透明。
2. **360度评估的暗面**：多维反馈在"坦诚清晰"文化中有效，但在政治化组织中可能变成站队工具。
3. **双月节奏的代价**：频繁迭代意味着频繁调整，可能导致方向摇摆、团队疲劳。
4. **挑战型目标的悖论**：鼓励挑战意味着部分目标注定完不成，如何区分"合理挑战"和"目标虚高"需要成熟的管理判断。
5. **与华为PBC的对比需谨慎**：两种体系各有适用场景，不存在绝对优劣，取决于组织阶段和文化。
