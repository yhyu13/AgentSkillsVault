# 华为 · BLM 业务领先模型

> 将战略制定与执行打通的一体化框架，让"想明白"和"做到位"不再是两件事。

## 核心理念

BLM要解决的根本问题是：战略规划与执行落地之间的断裂。传统做法中，战略部门写完报告就交差，执行部门拿到目标就开干，中间缺乏共同语言和闭环机制。BLM的核心主张是——战略和执行必须用同一个框架思考，差距分析是起点，领导力和价值观是底座，战略四模块和执行四模块互为因果。

华为在IBM原版基础上做了关键改进：将产权与内部治理、企业宗旨纳入框架，形成HW-BLM七大要素，使其从纯商业战略工具升级为涵盖治理结构的完整企业领导力模型。

## 框架结构

```
                    ┌──────────┐
                    │  领导力  │  ← 顶层驱动
                    └────┬─────┘
                         │
              ┌──────────┼──────────┐
              ▼          ▼          ▼
        ┌──────────┐ ┌────────┐ ┌──────────┐
        │  价值观  │ │ 差距分析│ │  价值观  │
        └──────────┘ └───┬────┘ └──────────┘
                         │
          ┌──────────────┼──────────────┐
          ▼                             ▼
   ┌─────────────┐              ┌─────────────┐
   │  战略侧(4)  │              │  执行侧(4)  │
   ├─────────────┤              ├─────────────┤
   │ 市场洞察    │              │ 关键任务    │
   │ 战略意图    │  ────────▶   │ 正式组织    │
   │ 创新焦点    │  互为因果    │ 人才        │
   │ 业务设计    │              │ 氛围与文化  │
   └─────────────┘              └─────────────┘
```

HW-BLM在上述基础上增加两大要素：
- **产权与内部治理**：解决"谁拥有、谁决策、谁监督"的治理结构问题
- **企业宗旨**：回答"企业为什么存在"的终极命题

## 关键模块

### 模块1：差距分析

- 定义：BLM的起点，不是从愿景出发，而是从差距出发
- 输入：业绩差距（实际vs目标）+ 机会差距（现有vs可能）
- 输出：差距清单，驱动后续战略选择
- 关键动作：区分业绩差距（执行问题）和机会差距（战略问题），前者靠改进执行弥补，后者靠重新设计战略
- 常见误区：只看业绩差距不看机会差距；差距描述过于笼统，无法转化为行动

### 模块2：市场洞察（五看三定之前半）

- 定义：系统扫描外部环境，识别机会与威胁
- 输入：宏观数据、行业报告、客户反馈、竞争情报、内部能力盘点
- 输出：市场洞察报告 + 机会点清单
- 关键动作：
  - 看宏观/行业：政策、技术、经济周期
  - 看市场/客户：需求变化、客户细分、价值转移
  - 看竞争：对手策略、护城河、相对位势
  - 看自己：能力盘点、资源约束、核心优势
  - 看机会：交叉验证，筛选可切入的机会窗口
- 常见误区：五看变成五抄（堆砌数据不做判断）；只看外部不看自己；洞察与后续战略意图脱节

### 模块3：战略意图

- 定义：基于洞察，明确"我们要去哪里"的方向性承诺
- 输入：市场洞察报告 + 差距分析 + 价值观约束
- 输出：愿景描述 + 中长期目标 + 近期里程碑
- 关键动作：设定有挑战性但可分解的战略目标；区分"必须赢"和"可以选择"的战场
- 常见误区：战略意图变成口号堆砌；目标不可衡量或不可分解

### 模块4：创新焦点

- 定义：明确在哪些维度上做差异化投入
- 输入：战略意图 + 市场洞察中的机会窗口
- 输出：创新方向清单（业务模式创新/产品创新/运营创新）
- 关键动作：在资源有限条件下做取舍，聚焦3-5个创新焦点而非全面铺开
- 常见误区：把创新焦点等同于技术路线图；什么都想创新等于没有焦点

### 模块5：业务设计

- 定义：将战略意图和创新焦点转化为可操作的业务逻辑
- 输入：前四个模块的输出
- 输出：业务设计蓝图（客户选择+价值主张+盈利模式+范围+战略控制点）
- 关键动作：明确"服务谁、提供什么、怎么赚钱、护城河在哪"；这是战略侧最核心的输出
- 常见误区：业务设计只写客户和价值主张，缺少盈利模式和战略控制点；战略控制点模糊

### 模块6：关键任务

- 定义：将业务设计拆解为必须完成的少数关键事项
- 输入：业务设计蓝图
- 输出：5-8项关键任务 + 依赖关系 + 里程碑
- 关键动作：关键任务必须满足"如果这些任务没完成，战略就失败"的标准；识别跨部门依赖
- 常见误区：关键任务太多（超过8项就不关键了）；任务描述是活动而非成果

### 模块7：正式组织

- 定义：调整组织结构、流程、权限以支撑关键任务
- 输入：关键任务清单
- 输出：组织调整方案（架构/流程/权责/考核）
- 关键动作：组织跟着战略走，不是战略迁就组织；关键任务需要明确的组织归属
- 常见误区：组织调整停留在画架构图，不触碰流程和考核；新战略用旧组织执行

### 模块8：人才

- 定义：确保关键岗位有对的人
- 输入：关键任务 + 组织调整方案
- 输出：关键人才需求 + 获取/培养计划
- 关键动作：识别"哪些岗位的哪些人决定了战略成败"；差距大时先获取，差距小时先培养
- 常见误区：人才规划变成培训计划；只看数量不看关键岗位的胜任度

### 模块9：氛围与文化

- 定义：塑造支撑战略落地的行为规范和心理环境
- 输入：战略意图 + 关键任务对行为的要求
- 输出：需要强化的文化要素 + 需要改变的行为习惯
- 关键动作：文化不是贴标语，是考核导向和领导行为塑造的；战略转型往往需要文化转型
- 常见误区：把文化建设等同于团建活动；新战略需要新行为但考核还在奖励旧行为

### 模块10：五看三定（BLM市场洞察的标准操作法）

- 定义：将市场洞察从"看"推进到"定"的完整操作流程
- 输入：五看（宏观/行业→市场/客户→竞争→自己→机会）的原始素材
- 输出：战略控制点 + 目标 + 策略
- 关键动作：
  - 五看是输入过程，三定是决策输出
  - 定战略控制点：找到"对手难以复制、客户不可替代"的竞争壁垒
  - 定目标：将控制点转化为可衡量的中长期目标
  - 定策略：围绕控制点和目标，确定资源配置和行动路径
- 常见误区：五看和三定割裂，看了不定；战略控制点定得太泛（如"品牌"）而非具体（如"某技术专利壁垒+某客户关系锁定"）

### 模块11：DSTE流程（BLM的运行载体）

- 定义：BLM不是一次性工具，而是嵌入DSTE流程持续运转
- 输入：上一年度的战略复盘 + 外部环境变化
- 输出：SP报告 → BP → 执行监控 → 评估复盘
- 关键动作：
  - SP阶段（3-5年）：BLM全流程，输出中长期战略规划
  - BP阶段（年度）：基于SP做年度拆解，BEM接手战略解码
  - 执行监控：经营分析会跟踪KPI达成，偏差纠偏
  - 评估复盘：战略复盘驱动下一年SP调整
- 常见误区：SP做完就束之高阁；BP与SP脱节；复盘变成走过场

## 决策启发式

| 场景 | 判断规则 | 来源 |
|------|---------|------|
| 差距分析时 | 如果差距主要来自执行不力，先改执行；如果差距主要来自方向错误，先改战略 | BLM框架逻辑 |
| 市场洞察时 | 如果五看结论互相矛盾（如宏观利好但竞争恶化），优先看竞争和自己的相对位势 | 华为实践 |
| 设定战略意图时 | 如果目标无法分解为3年里程碑，说明意图还不够具体 | BLM操作规范 |
| 选择创新焦点时 | 如果创新焦点超过5个，说明没有真正聚焦 | 华为实践 |
| 业务设计时 | 如果无法用一句话说清盈利模式，说明业务设计还不成立 | BLM框架逻辑 |
| 拆解关键任务时 | 如果关键任务超过8项，说明还在列清单而非抓关键 | 华为实践 |
| 组织调整时 | 如果关键任务找不到明确的组织归属，说明组织还没跟上战略 | BLM框架逻辑 |
| 人才规划时 | 如果关键岗位的胜任度差距大且时间紧，先外部获取而非内部培养 | 华为实践 |
| 文化转型时 | 如果考核指标还在奖励旧行为，文化口号不会改变任何事 | 华为实践 |
| 五看三定时 | 如果战略控制点对手可以在1-2年内复制，那不是控制点只是优势 | 华为实践 |
| SP-BP衔接时 | 如果BP中的KPI无法追溯到SP中的战略意图，说明解码断裂 | DSTE流程逻辑 |

## 与其他方法论的关系

| 关联方法论 | 关系 | 接口 |
|-----------|------|------|
| DSTE | 母框架 | BLM是DSTE中SP制定阶段的核心工具；BLM输出SP报告，DSTE管理全流程闭环 |
| BEM | 下游 | BLM输出业务设计蓝图，BEM接收后进行战略解码，将战略转化为KPI和PBC |
| 五看三定 | 内嵌操作法 | 五看三定是BLM市场洞察模块的标准操作流程，不是独立方法论 |
| IPD | 并行 | BLM确定"做什么产品方向"，IPD解决"怎么开发产品"；BLM输出→IPD输入 |
| PBC | 间接下游 | BLM→BEM→PBC链条；BLM确定战略意图，经BEM解码后落实到个人PBC |
| VDBD | 前身 | 2002年美世VDBD→2006年IBM BLM，BLM是VDBD的升级替代 |
| BSC | 互补 | BSC提供战略地图的因果链可视化，BLM提供更完整的战略-执行一体化框架 |

## 适用场景

### 最适合

- 中大型企业制定3-5年战略规划（SP）
- 战略与执行长期脱节，需要统一语言和闭环机制的组织
- 业务转型期，需要系统思考"方向+路径+能力"的团队
- 高层团队战略对齐，需要结构化讨论框架的场景

### 不适合

- 初创企业（业务设计尚在探索，不适合做3-5年规划）
- 单一业务线的小团队（框架过重，成本收益不匹配）
- 纯执行层面的问题（执行问题用BEM或项目管理工具更直接）
- 短期战术决策（BLM是战略级工具，不适合月度/季度战术调整）

## 实施检查清单

- [ ] 差距分析已完成，区分了业绩差距和机会差距
- [ ] 五看已完成，每看都有明确结论而非数据堆砌
- [ ] 三定已完成，战略控制点具体且对手难以复制
- [ ] 战略意图可分解为3年里程碑
- [ ] 创新焦点不超过5个，且有明确取舍逻辑
- [ ] 业务设计包含完整的五要素（客户选择/价值主张/盈利模式/范围/战略控制点）
- [ ] 关键任务不超过8项，每项有明确成果和责任人
- [ ] 组织调整方案覆盖架构/流程/权责/考核四个维度
- [ ] 关键岗位人才盘点完成，获取/培养计划已制定
- [ ] 文化转型方向明确，考核指标已对齐新行为要求
- [ ] SP报告已输出，BP衔接机制已建立
- [ ] 战略复盘机制已嵌入DSTE流程

## 诚实边界

1. **框架不等于能力**：BLM提供了结构化思考框架，但不替代战略判断力。用BLM做出平庸战略是完全可能的。
2. **数据质量决定洞察质量**：五看三定的有效性取决于输入数据的质量和广度，垃圾进垃圾出。
3. **华为改进的适用性**：HW-BLM增加的产权与内部治理、企业宗旨两大要素，对治理结构复杂的集团型企业有价值，对治理简单的中小企业可能是过度设计。
4. **执行侧的深度有限**：BLM的执行四模块（关键任务/组织/人才/文化）是框架级指引，具体落地需要BEM等工具补充。
5. **文化依赖**：BLM的有效运转依赖"战略对齐"的组织文化，在政治博弈严重的组织中，BLM可能沦为形式主义工具。
6. **时间成本**：一次完整的BLM战略规划周期（SP）通常需要3-6个月，对资源有限的组织是显著投入。
