# Google · TGIF+Default Open

> 用每周全员问答和默认开放原则，让信息在组织中自由流动——信息不是权力的来源，价值只在共享时创造。

## 核心理念

TGIF+Default Open解决的核心问题是：**组织规模扩大后，信息自然向权力中心收缩，而信息收缩是决策质量下降的根源。**

Google从创业早期就面对一个悖论：公司越成功、人越多，信息流动越慢。管理者本能地囤积信息——知道别人不知道的事意味着权力、意味着控制。但Google的创始人认为这恰恰搞反了：在知识密集型组织中，信息只有被广泛共享才能创造价值，囤积信息只会让决策变差、让一线失去判断力。

他们的回答是两套互补机制：TGIF提供制度化的信息流动通道——每周五全员大会，创始人/CEO直面所有员工的无过滤提问；Default Open提供原则性的信息开放默认——除法律限制外，所有管理信息对员工公开。前者是仪式，后者是信念，两者缺一不可。

核心命题：**信息不是权力来源——权力来自决策质量，决策质量来自信息广度，信息广度来自制度化的透明。**

## 关键模块

### 模块1：TGIF全员大会

- 定义：每周五下午举行的全员大会，创始人/CEO直接回答员工提出的任何问题，无过滤、无预审
- 输入：员工通过Dory系统提交的问题+现场追问
- 输出：领导层真实意图的传递+信息不对称的消除+组织信任的积累
- 关键动作：
  - 创始人/CEO必须亲自出席并直接回答——不能派代表、不能让PR代笔、不能只回答预选问题
  - 问题完全由员工驱动——从产品战略到薪酬政策，从并购决策到管理失误，没有禁区
  - 现场追问机制——回答不满意时员工可以当场追问，不允许用"我们线下聊"回避
  - 每周一次的节奏不可中断——不是季度大会、不是年度信，而是高频的、持续的、不可取消的承诺
- 常见误区：把TGIF做成"领导讲话+员工鼓掌"的单向传达——TGIF的核心是问答而非宣讲，如果员工不能真正挑战领导层，它就退化为内部PR

### 模块2：Dory提问系统

- 定义：Google内部的问题收集和投票系统，员工提交问题、互相投票，得票最高的问题必须在TGIF上回答
- 输入：全员的问题提交+民主投票
- 输出：领导层无法回避的议程+员工关注点的真实信号
- 关键动作：
  - 投票机制确保最被关注的问题浮出水面——领导层不能挑选"安全"的问题回避尖锐问题
  - 匿名提交选项——降低提问的心理门槛，让最敏感的问题也能被提出
  - 得票排序公开透明——所有人都能看到哪些问题最受关注，防止暗箱操作
  - Dory是TGIF的"免疫系统"——没有Dory，TGIF就会退化为领导层自导自演的问答秀
- 常见误区：把Dory当作"意见箱"——意见箱是黑箱，投进去没人知道结果；Dory是公开投票，得票高的问题必须被回答

### 模块3：Default Open原则

- 定义：除法律限制（如未公开并购、个人隐私）外，所有公司信息默认对全体员工开放——需要理由才能保密，不需要理由才能公开
- 输入：公司内部的管理决策、战略文档、产品路线图、财务数据
- 输出：员工基于完整信息做出判断+信息囤积动机的消除
- 关键动作：
  - 反转保密逻辑——传统组织是"默认保密，需要理由才公开"；Google是"默认公开，需要理由才保密"
  - 保密需要主动论证——谁想保密，谁负责说明为什么必须保密，而非谁想公开谁负责论证
  - 内网信息全面开放——产品路线图、战略文档、代码库、内部研究，员工可自由访问
  - 法律限制是唯一合法的保密理由——"怕员工知道了不好管理"不是合法理由
- 常见误区：把Default Open等同于"什么都公开"——法律限制是真实约束，未公开的并购信息、员工个人数据等必须保密；Default Open改变的是默认值，不是取消所有边界

### 模块4：坏消息先行

- 定义：创造心理安全环境，让坏消息比好消息更快到达领导层——组织最大的风险不是坏消息本身，而是坏消息被层层过滤
- 输入：一线的真实问题、项目失败、客户投诉
- 输出：领导层基于真实状况决策+问题在早期被暴露
- 关键动作：
  - 领导者对坏消息的第一反应必须是感谢——"谢谢你告诉我"，而非"怎么会这样"或"谁的责任"
  - 区分"报坏消息的人"和"制造坏消息的人"——前者应该被奖励，后者才应该被追责
  - 坏消息的传播速度是组织健康度的指标——如果坏消息要经过多层过滤才能到达CEO，说明信息通道已经堵塞
  - 在TGIF上主动分享坏消息——领导层先公开自己的失误和挑战，给员工做示范
- 常见误区：把"坏消息先行"等同于"只报坏消息"——目的是加速坏消息的流动，不是制造悲观氛围；好消息同样需要被分享，只是坏消息更需要被加速

### 模块5：2002年取消管理者实验

- 定义：2002年Google曾尝试取消工程团队的管理者角色，让工程师完全自主管理，实验很快证明管理者不可或缺
- 输入：对"管理者是否必要"的极端测试
- 输出：管理者价值的实证澄清——管理者在职业指导、冲突解决、项目方向上不可替代
- 关键动作：
  - 实验揭示了管理者的真实价值——不是信息中转站（信息已经通过TGIF和Default Open流动了），而是人的管理者
  - 管理者的核心职能重新定义：职业发展指导、团队冲突调解、项目优先级决策——这些是信息透明无法替代的
  - 信息透明反而让管理者从"信息守门人"解放出来，专注于真正需要人的工作
  - 实验结论：信息透明消除了管理者作为信息瓶颈的必要性，但强化了管理者作为人的协调者的必要性
- 常见误区：用这个实验论证"管理者无用"——恰恰相反，实验证明管理者不可或缺，只是他们的价值不在信息控制而在人的协调

## 决策启发式

| 场景 | 判断规则 | 来源 |
|------|---------|------|
| 是否公开某信息 | 默认公开——只有法律限制才是保密的正当理由 | Default Open原则 |
| 员工不敢提问 | 检查领导层对尖锐问题的反应——如果回答时防御或回避，TGIF就会退化为表演 | TGIF机制 |
| 坏消息被延迟上报 | 如果坏消息到领导层需要经过3层以上过滤→信息通道堵塞，需要建立直通机制 | 坏消息先行 |
| 管理者囤积信息 | 如果管理者用信息不对称维持权威→说明信息透明机制失效，管理者退回了"信息守门人"角色 | 2002实验 |
| 全员大会变成单向传达 | 如果员工提问环节消失或被控制→TGIF已经名存实亡，需要恢复Dory机制 | TGIF+Dory |
| 是否需要保密 | 谁主张保密谁论证——如果论证理由不是法律限制，则不应保密 | Default Open |
| 组织规模扩大后信息流动变慢 | 增加信息流动的制度化通道（如TGIF），而非增加信息管控层级 | 规模与透明 |

## 与其他方法论的关系

| 关联方法论 | 关系 | 接口 |
|-----------|------|------|
| Netflix信息透明 | 对标-战略层vs全员层 | Netflix也极度透明但更偏战略层（Context, not Control让员工理解决策背景），Google透明覆盖更广（TGIF全员问答让每个员工都能直接挑战CEO） |
| 字节飞书透明 | 对标-工具驱动vs仪式驱动 | 字节用飞书文档实现信息透明（文档默认公开、评论即反馈），Google用TGIF+内网实现（每周仪式化问答+默认开放原则）——前者是异步的、工具嵌入的，后者是同步的、仪式强制的 |
| Google Project Aristotle | 下游效应 | TGIF+Default Open创造的信息透明环境，是心理安全的重要来源——当员工看到领导层公开回答尖锐问题，心理安全自然提升 |
| Amazon六页备忘录 | 对标-文档透明vs对话透明 | Amazon用六页备忘录实现信息对齐（阅读优先于口头汇报），Google用TGIF实现信息对齐（问答优先于文档传递）——前者是结构化的深度，后者是开放性的广度 |
| 华为"自我批判" | 对标-制度化反思vs制度化问答 | 华为自我批判是组织级反思（民主生活会），Google TGIF是组织级问答——前者是"我们哪里做错了"，后者是"你问我答" |

## 适用场景

### 最适合

- 知识密集型组织——决策质量高度依赖信息广度，一线员工需要完整上下文才能做出好判断
- 快速变化环境——信息过期快，周期性沟通不够，需要高频实时信息流动
- 创始人驱动的文化——创始人亲自参与TGIF，以身作则传递透明信号
- 人才密度高的组织——员工有能力处理复杂信息，不会因信息过载而瘫痪

### 不适合

- 上市公司面临严格信息披露合规要求的场景——法律限制是真实约束，不能为了透明违规
- 组织规模过大导致TGIF不可行——万人以上公司每周全员大会的边际效益递减
- 人才密度不足的组织——信息透明需要员工有判断力来处理信息，否则透明变成噪音
- 强层级军事化组织——"全员直接问CEO"与命令链根本冲突

## 实施检查清单

- [ ] 是否有制度化的全员问答机制——频率是否足够（每周而非每季度）
- [ ] 领导层是否亲自出席并直接回答——不能派代表、不能预审问题
- [ ] 是否有Dory类提问投票系统——员工能否驱动议程而非被动接受
- [ ] 信息是否默认公开——保密是否需要主动论证而非公开需要论证
- [ ] 坏消息是否能快速到达领导层——传播路径是否超过3层
- [ ] 领导层对坏消息的第一反应是否是感谢——而非追责或防御
- [ ] 管理者是否从"信息守门人"转型为"人的协调者"——信息透明后管理者的价值在哪里
- [ ] 全员大会是否保持问答本质——是否退化为单向传达

## 诚实边界

1. **规模的天花线**：TGIF在Google早期（几百到几千人）极其有效，但随着Google扩张到数万人，TGIF的效力明显下降——万人大会中个体提问的影响力被稀释，尖锐问题被大量温和问题淹没。规模是TGIF最大的敌人。

2. **法律约束的张力**：Default Open与上市公司信息披露规则之间存在天然张力。Google上市后，很多此前可以公开讨论的战略信息变成了"重大非公开信息"，TGIF的内容不得不收缩。这是制度透明的结构性限制。

3. **心理安全的隐性前提**：TGIF能运转，底层依赖的是心理安全。如果员工害怕提问会遭到报复（哪怕只是被记住"这个人爱找茬"），Dory的匿名选项也救不了——因为投票结果本身就是公开的。Google自身的心理安全来自Project Aristotle发现的那些因素，TGIF是结果而非原因。

4. **与Netflix透明的深度差异**：Netflix的信息透明更偏战略层——通过Context, not Control让员工理解决策背景后自主行动；Google的透明更偏全员层——通过TGIF让每个员工都能直接挑战CEO。前者服务于决策授权，后者服务于文化认同。目的不同，机制也不同。

5. **与字节飞书透明的载体差异**：字节用飞书文档实现信息透明，是异步的、工具嵌入日常工作的——员工随时可以翻阅任何公开文档。Google用TGIF+内网实现，是同步的、仪式化的——每周集中一次信息交换。异步透明更可持续但缺乏仪式感，同步透明更有冲击力但难以扩展。

6. **2002实验的语境限制**：取消管理者实验发生在Google早期工程团队，成员都是顶尖工程师、高度自驱。在人才密度不同的组织中，这个实验的结论不能直接套用——管理者在低自驱团队中的信息协调作用可能比Google实验中更大。

7. **知识盲区**：本文件基于公开资料整理，不包含Google内部TGIF的具体运营细节、Dory系统的投票算法、以及Default Open原则在上市后的具体调整措施。
