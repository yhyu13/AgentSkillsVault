# Google · OKR目标管理

> 用可量化的关键结果锚定模糊目标，用0.7分的理想区间倒逼挑战，用全员透明替代层层传达。

## 核心理念

Google OKR解决的核心问题是：**一家高速增长的公司，如何让每个人都在朝同一个方向用力，同时又不扼杀个体的判断力和进取心？**

答案藏在两个设计里：第一，把"我想做什么"拆成Objective（定性方向）和Key Results（定量验证），让模糊的雄心变得可检验；第二，把评分的甜蜜点设在0.6-0.7而非1.0，让"没做完"不等于"做砸了"，鼓励人敢于瞄准更远的地方。

三个底层信念：
1. **目标必须可量化验证**：没有Key Results的Objective只是口号
2. **完成70%比完成100%更有价值**：如果总是满分，说明目标定低了
3. **透明是最高效的对齐方式**：当每个人都能看到CEO的目标，中间层就不必充当信息转发站

## 框架结构

```
Google OKR目标管理体系
│
├── 目标设定层
│   ├── Objective（定性方向——"我们要去哪"）
│   ├── Key Results（定量验证——"怎么算到了"）
│   └── 三级结构：公司级 → 团队级 → 个人级
│
├── 季度节奏层
│   ├── 季度开始前4-6周：头脑风暴，收集方向
│   ├── 季度开始前2周：锁定公司级OKR
│   ├── 季度开始阶段：团队级OKR对齐
│   ├── 季度开始后1周：个人级OKR定稿
│   └── 季度中：周/双周进度check-in
│
├── 评分与透明层
│   ├── 0-1分制（0.6-0.7=理想区间，1.0=几乎不可能，0.3=保底线）
│   ├── 全员可查看任何人的OKR及评分
│   └── 自评+同事反馈+校准会议，三段式评估
│
└── 分离层
    ├── OKR评分 ≠ 绩效考评
    ├── OKR是方向对齐工具，绩效是回报分配工具
    └── 两者解耦：OKR不直接决定薪酬
```

## 关键模块

### 模块1：O+KR结构

- 定义：Objective是定性方向声明，Key Results是2-5条可量化的验证指标，两者成对出现
- 输入：战略意图、业务痛点、增长机会
- 输出：一组"方向+验证标准"的目标对
- 关键动作：
  - Objective用动词开头，描述方向而非数字（如"让Chrome成为最安全的浏览器"）
  - Key Results必须是可量化的，有明确数字和时间锚点（如"Q3末零日漏洞修复时间<24h"）
  - 每组OKR的KR数量控制在2-5条，超过5条说明目标不够聚焦
  - KR写法公式：从X到Y（基线→目标值），而非"提升XX%"
- 常见误区：把KR写成任务清单（"完成用户调研"是任务，"NPS从30提升到50"才是KR）；Objective写得太具体失去方向感，或太模糊失去指导性

### 模块2：季度周期

- 定义：以季度为节奏设定和刷新OKR，周期内包含设定、执行、评分三个阶段
- 输入：上一季度OKR评分、新季度业务变化、公司战略调整
- 输出：每季度一组新的OKR及上季度评分
- 关键动作：
  - 季度开始前4-6周：全员头脑风暴，收集方向性想法
  - 季度开始前2周：公司级OKR定稿，自上而下传递方向
  - 季度开始阶段：团队级OKR对齐，确保与公司级方向一致
  - 季度开始后1周内：个人级OKR定稿，完成三级对齐
  - 季度中：每周或双周check-in，更新KR进度，标记风险项
  - 季度末：评分，每条KR打0-1分，取平均值作为Objective得分
- 常见误区：把季度周期当成季度考核周期——OKR评分是自我诊断工具，不是绩效打分表；跳过头脑风暴阶段直接拍目标，导致OKR变成上级意志的传声筒

### 模块3：0-1分制与0.7理想区间

- 定义：OKR评分采用0-1连续分制，0.6-0.7分被视为理想完成区间
- 输入：每条KR的实际完成值与目标值之比
- 输出：0-1之间的评分
- 关键动作：
  - 每条KR独立评分：实际值/目标值，上限为1.0
  - Objective得分 = 所有KR评分的算术平均值
  - 0.6-0.7分 = 目标有挑战性且大部分达成，这是理想状态
  - 1.0分 = 目标太容易或过于保守，需要反思是否"放水"
  - 0.3分及以下 = 目标可能脱离现实，或执行出现重大问题
  - 评分后必须复盘：为什么是这个分数？下季度怎么调整？
- 常见误区：把0.7分等同于70分（不及格）——在OKR体系里0.7分是优秀；追求1.0分导致目标越来越保守，失去OKR的挑战价值

### 模块4：全员透明

- 定义：组织内任何人的OKR（含目标、关键结果、进度、评分）对任何其他人可见
- 输入：全员OKR数据
- 输出：方向自涌现，跨团队协作自发生
- 关键动作：
  - 新员工入职即可浏览CEO的OKR及历史评分
  - OKR系统支持按人、按团队、按关键词搜索
  - 评分同样公开，包括低分项——低分不是耻辱，是信息
  - 跨团队协作时先看对方OKR，判断是否方向一致再沟通
- 常见误区：只公开目标不公开评分——没有评分的OKR只是愿望清单；把透明当监控工具——透明的目的是对齐，不是盯人

### 模块5：自下而上+自上而下

- 定义：OKR设定采用双向模式——公司级自上而下定方向，团队级和个人级自下而上提议，再与上级对齐
- 输入：公司级OKR（方向）+ 个人/团队提议（具体目标）
- 输出：三级OKR完成对齐
- 关键动作：
  - 自上而下：公司级OKR传递战略方向，不是具体指令
  - 自下而上：个人和团队根据公司方向提出自己的OKR，体现对业务的判断
  - 对齐：上级审阅下级OKR，确保方向一致但不替代下级思考
  - 比例：约60%自下而上，40%自上而下——基层的判断力被信任和依赖
- 常见误区：自上而下变成"上级定目标、下级领任务"——如果个人OKR只是公司OKR的拆解副本，就失去了自下而上的信息优势；自下而上变成"各干各的"——如果缺少对齐环节，OKR就退化为个人计划表

### 模块6：绩效评估流程（与OKR分离）

- 定义：Google的绩效评估是一套独立于OKR评分的体系，包含自评、同事反馈、校准会议三段
- 输入：OKR评分（参考项之一）+ 同事反馈 + 管理层校准
- 输出：5级考评结果（5=变革性影响，4=超出预期，3=符合预期，2/1=需改进）
- 关键动作：
  - 员工自评：512字符限制，迫使提炼而非罗列
  - 同事反馈：3-8人提供评价，覆盖上下左右
  - 校准会议：5-10位经理共同讨论，消除单一管理者主观偏差
  - OKR评分是绩效评估的输入之一，但不是唯一输入，也不按固定权重折算
  - 5级考评体系：5=变革性影响（极少数），4=超出预期，3=符合预期（大多数），2=需改进，1=不合格
- 常见误区：把OKR评分直接换算成绩效分数——Google刻意将两者解耦，OKR评分高不等于绩效评级高；校准会议变成"分名额"——校准的目的是消除偏差，不是按比例分等

## 决策启发式

| 场景 | 判断规则 | 来源 |
|------|---------|------|
| 目标定高还是定低 | 定高——0.7分是理想区间，1.0分说明目标太保守 | 《Measure What Matters》 |
| OKR与薪酬是否挂钩 | 不直接挂钩——挂钩会导致目标保守化，OKR回归KPI | Google OKR设计哲学 |
| KR写成了任务怎么办 | 重写——任务描述"做了什么"，KR描述"做到了什么结果" | OKR实操拆解 |
| 自下而上的OKR与公司方向不一致 | 先对齐再执行——不一致说明信息传递有断裂 | 季度周期设计 |
| 评分低于0.3 | 复盘原因——可能是目标脱离现实，也可能是执行出现系统性障碍 | 0-1分制设计 |
| 透明导致焦虑 | 区分"对齐"和"考核"——透明的目的是让每个人知道方向，不是让每个人互相比较 | 全员透明设计 |
| 季度中方向大变 | 及时调整OKR——季度周期的好处就是可以快速修正，不必等到年底 | 季度节奏设计 |
| 校准会议流于形式 | 检查是否缺少坦诚反馈的文化土壤 | 绩效评估流程 |

## 适用场景

### 最适合

- 知识密集型组织，员工需要自主判断方向
- 业务环境季度级别变化，年度目标容易过时
- 组织规模大到层级传达失真，需要透明对齐机制
- 文化支持坦诚反馈和信息默认公开

### 不适合

- 强合规行业，目标必须100%承诺完成（用PBC更合适）
- 业务极其稳定可预测的环境（年度KPI足够）
- 缺乏坦诚反馈文化，全员透明会变成全员焦虑
- 团队成员习惯"被分配任务"而非"自主设定目标"
- 组织尚小（10人以下），季度OKR的管理成本高于收益

## 实施检查清单

- [ ] OKR是否采用O+KR成对结构（定性方向+定量验证）
- [ ] KR是否可量化（非任务清单）
- [ ] 迭代周期是否为季度（非年度）
- [ ] 季度开始前4-6周是否启动头脑风暴
- [ ] 公司级OKR是否在季度开始前2周定稿
- [ ] 评分是否采用0-1分制，0.6-0.7为理想区间
- [ ] OKR是否全员可见（含评分）
- [ ] 自下而上提议的比例是否达到约60%
- [ ] OKR评分是否与绩效考评解耦
- [ ] 绩效评估是否包含自评+同事反馈+校准会议三段
- [ ] 校准会议是否有5-10位经理参与（消除单一管理者偏差）

## 诚实边界

1. **OKR与绩效的"解耦"程度存疑**：Google官方说OKR不直接决定薪酬，但"不直接"不等于"不影响"——OKR评分作为绩效评估的输入之一，间接影响薪酬。完全解耦在现实中很难做到，员工仍会倾向在OKR中设定保守目标来保护绩效。

2. **0.7分理想区间的文化前提**：这一设计依赖"低分不等于失败"的文化共识。在许多组织中，0.7分会被直觉地理解为"70分不及格"，导致目标越来越保守。0.7分理想区间需要配套的叙事和文化建设才能落地。

3. **全员透明的心理成本**：公开资料多强调透明的好处，较少讨论透明的心理成本——在竞争性文化中，全员透明可能加剧内部比较和焦虑，反而降低对齐效果。

4. **校准会议的暗面**：5-10位经理校准的初衷是消除偏差，但经理之间的社交关系可能引入新的偏差（如"换票"——你给我的人高分，我给你的人高分）。公开资料未充分讨论这一风险。

5. **与字节OKR对比的简化**：Google季度+解耦 vs 字节双月+挂钩，是两种不同的组织选择。Google的解耦保住了挑战性但可能导致OKR"说一套做一套"，字节的挂钩保证了执行力但可能导致目标保守化。两种选择各有代价，不存在绝对优劣。

6. **季度节奏的局限**：对于需要长期投入的研究型项目（如DeepMind的基础研究），季度OKR可能过于短视，迫使研究者把长期问题拆成短期可交付物，损害研究质量。
