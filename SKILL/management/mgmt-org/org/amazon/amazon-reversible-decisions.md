# Amazon · 崇尚行动+可逆决策（Type 1/2 Decisions）

> 用决策分类决定决策深度——Type 1深思熟虑，Type 2先做再改，70%把握就行动

## 核心理念

Type 1/2决策框架解决的核心问题是：**组织越大，决策越慢，怎么破？**

贝索斯在2016年股东信中一针见血地指出：大多数组织把所有决策都当成不可逆的来处理，结果就是每件事都过度研究、层层审批、反复论证。这种"默认慎重"在大公司里是本能——没人因为"做了决定"被表扬，但很多人因为"做了错误决定"被惩罚。于是组织自然滑向决策瘫痪。

贝索斯的解法是给决策分类：把决策分成Type 1（不可逆）和Type 2（可逆），然后对号入座——Type 1用重流程深思熟虑，Type 2用轻流程快速行动。关键洞察是：**大多数决策是Type 2**。贝索斯原话："Many decisions and actions are reversible and do not need extensive study."当你意识到大部分决策可以撤回，决策的心理负担就大幅减轻。

70%法则是Type 2决策的行动阈值：有70%把握时就做决策，等90%就太晚了。这不是鼓励草率，而是承认信息永远不完美——在商业竞争中，速度本身就是价值。

核心公式：**决策速度 = 正确分类（Type 1 vs Type 2） × 适当信息量（70%法则）**

## 框架结构

```
可逆决策框架 = 用分类决定深度的决策操作系统
│
├── 分类层
│   ├── Type 1决策（单向门）
│   │   └── 不可逆、影响重大 → 深思熟虑
│   └── Type 2决策（双向门）
│       └── 可逆、影响有限 → 快速行动
│
├── 行动层
│   ├── 70%法则：70%把握就决策，等90%太晚
│   ├── 崇尚行动（Bias for Action）：速度是竞争优势
│   └── Disagree and Commit：反对是责任，承诺是纪律
│
├── 误判防护层
│   ├── Type 2误判为Type 1 → 过度研究，决策变慢
│   └── Type 1误判为Type 2 → 草率决策，不可挽回
│
└── 组织保障层
    ├── 单线程领导：独立团队减少协调成本
    ├── 两个披萨团队：小团队决策更快
    └── 6页纸备忘录：Type 1决策的深度思考工具
```

## 关键模块

### 模块1：Type 1决策——单向门

- 定义：不可逆或极难逆转的决策，一旦做出就无法或很难撤回，影响范围大且深远
- 输入：战略级信息、长期影响评估、多方利益分析
- 输出：经过深思熟虑的重大决策
- 关键动作：
  - 识别Type 1信号：退出一个主要市场、大规模并购、改变核心商业模式、品牌定位根本性调整
  - Type 1决策必须走重流程：充分收集信息、多角度论证、高层集体审议
  - 贝索斯的比喻：Type 1决策是"走进一扇单向门"——进去之后回不来
  - Amazon进入云计算（AWS）是Type 1决策——它改变了Amazon的商业本质，从零售商变成基础设施提供商
  - Type 1决策的判断标准不是"重要不重要"，而是"能不能撤回"——有些重要决策如果可逆，仍然应该快速做
- 常见误区：把"重要"等同于"不可逆"——很多重要决策其实是可逆的，重要性不等于不可逆性

### 模块2：Type 2决策——双向门

- 定义：可逆的、影响有限的决策，做错了可以撤回、调整、重来
- 输入：有限信息+快速判断
- 输出：快速决策+快速执行+必要时快速修正
- 关键动作：
  - 识别Type 2信号：功能迭代、定价调整、营销方案、工具选型、流程优化——大多数日常决策都属于此类
  - Type 2决策的核心原则：先做再改，而非先想再做。贝索斯原话："If you've made a Type 2 decision and you're wrong, you can undo it"
  - Type 2决策的真正成本不是做错，而是拖延——拖延的代价是时间、机会和士气
  - 大多数决策是Type 2——这是整个框架的基石假设。贝索斯估计组织中90%以上的决策属于Type 2
  - Type 2决策的加速器：授权给离现场最近的人做，不需要层层上报
- 常见误区：把Type 2当Type 1处理——这是大公司决策变慢的头号原因，贝索斯称之为"用重型机械处理轻量级问题"

### 模块3：70%法则——行动阈值

- 定义：当掌握的信息量达到理想状态的70%时就应该做决策，而非等到90%
- 输入：当前信息掌握度+决策可逆性+时间窗口
- 输出：决策时机判断
- 关键动作：
  - 70%不是精确数字，而是一个方向性指引——核心意思是"在信息不完美时行动"
  - 贝索斯原话："Most decisions should probably be made with somewhere around 70% of the information you wish you had. If you wait for 90%, in most cases, you're probably being slow"
  - 等到90%的代价：①竞争对手已经行动 ②市场窗口已经关闭 ③团队士气在等待中消耗
  - 70%法则的前提：决策必须是Type 2（可逆）——如果不可逆，70%把握远远不够
  - 信息从70%到90%的边际成本急剧上升，而边际价值急剧下降——这是70%法则的经济学基础
- 常见误区：把70%法则用于Type 1决策——70%法则只适用于可逆决策，不可逆决策需要更高把握度

### 模块4：崇尚行动（Bias for Action）

- 定义：Amazon 16条领导力原则之一，速度在商业中至关重要，很多决策可逆且不需要过度研究
- 输入：决策场景+可逆性判断
- 输出：快速决策+快速执行
- 关键动作：
  - Bias for Action是Type 1/2框架在领导力原则层面的表达——两者是同一思想在不同层面的体现
  - 速度本身就是竞争优势——在同等决策质量下，更快的组织赢
  - 崇尚行动不等于不思考——而是对Type 2决策不"过度思考"
  - 与Have Backbone Disagree and Commit配合：决策前充分反对，决策后全力执行——反对不拖延速度，承诺不稀释质量
  - 与Dive Deep的张力：深挖细节和快速行动在时间有限时必然冲突，需要根据决策类型选择侧重
- 常见误区：把Bias for Action等同于"不思考就行动"——崇尚行动的前提是正确分类决策类型，Type 1仍然需要深思熟虑

### 模块5：误判防护——分类错误的代价

- 定义：Type 1和Type 2的分类不是绝对清晰的，误判会产生不同方向的代价
- 输入：决策场景+分类判断
- 输出：分类校准+防护措施
- 关键动作：
  - Type 2误判为Type 1（过度慎重）：最常见的错误——把可逆决策当成不可逆来处理，导致决策变慢、团队等待、机会流失。这是大公司的通病
  - Type 1误判为Type 2（过度草率）：较少见但代价更大——把不可逆决策当可逆来处理，一旦做错无法挽回。Amazon Fire Phone就是典型案例——被当作Type 2决策快速推进，但实际影响深远
  - 防护策略：当分类不确定时，默认按Type 2处理（因为大多数决策确实是Type 2），但设置"撤回检查点"——如果执行过程中发现影响超出预期，立即升级为Type 1处理
  - 另一个防护：让做决策的人也承担决策后果——如果决策者不用为错误买单，就会倾向于把所有决策都当Type 1（反正不着急）
- 常见误区：认为分类必须100%清晰——现实是很多决策处于灰色地带，关键是建立"默认快速+异常升级"的机制

## 决策启发式

| 场景 | 判断规则 | 来源 |
|------|---------|------|
| 决策分类 | 如果做错了能撤回→Type 2，快速做；如果做错了无法撤回→Type 1，深思熟虑 | Type 1/2定义 |
| 信息把握度 | 如果≥70%且决策可逆→立即行动；如果<70%且不可逆→继续收集信息 | 70%法则 |
| 大公司决策变慢 | 如果发现可逆决策在走重流程→立即简化，授权给离现场最近的人 | Bias for Action |
| 分类不确定 | 如果不确定是Type 1还是Type 2→默认按Type 2处理，但设撤回检查点 | 误判防护 |
| 决策前有不同意见 | 如果决定前充分讨论→Disagree；如果决定后→Commit，全力执行 | Disagree and Commit |
| 发现决策做错了 | 如果是Type 2→快速撤回，不要因为沉没成本而坚持错误 | Type 2可逆性 |
| 团队等待决策 | 如果等待时间>决策本身执行时间→决策流程过重，检查是否把Type 2当Type 1处理 | Bias for Action |
| 信息从70%到90% | 如果边际信息获取成本>边际决策质量提升→停止收集，立即决策 | 70%法则经济学基础 |
| 决策者不承担后果 | 如果决策者不为错误买单→倾向于过度慎重，需要调整激励结构 | 误判防护 |
| 竞争对手已经行动 | 如果对手已行动而本方还在研究→大概率是Type 2被当Type 1处理了 | 速度即竞争优势 |

## 适用场景

### 最适合

- 快节奏市场中的决策加速——互联网、消费电子、SaaS等行业
- 大型组织出现决策变慢症状——会议多、审批长、等待久
- 创新驱动型团队——需要大量试错，Type 2决策占绝大多数
- 领导者希望建立"快速决策"文化——需要理论框架说服团队"不是所有决策都需要深思熟虑"
- 与单线程领导、两个披萨团队配合——组织独立+决策分类=极致速度

### 不适合

- 安全敏感行业——医疗、航空、核能等领域，"先做再改"的代价可能是生命
- 合规要求极高的场景——金融监管、数据隐私等领域，流程不可简化
- Type 1决策占多数的战略转型期——如果组织面临的大多数决策都是不可逆的，Type 1/2框架的加速价值有限
- 团队缺乏基本判断力——70%法则的前提是决策者有足够的商业直觉判断方向，否则70%把握也可能是错的
- 尚未建立撤回机制的组织——Type 2决策快速做的前提是做错了能快速改，没有撤回机制就是赌

## 实施检查清单

- [ ] 是否有明确的决策分类标准——团队是否能快速判断一个决策是Type 1还是Type 2？
- [ ] Type 2决策是否有授权机制——离现场最近的人是否能自主做Type 2决策，无需层层上报？
- [ ] 70%法则是否被实践——团队是否在信息不完美时敢于行动，还是在追求完美信息？
- [ ] 是否有撤回检查点——Type 2决策执行过程中，如果影响超出预期，是否有升级机制？
- [ ] Type 1决策是否走了重流程——重大决策是否有6页纸备忘录、多方论证、高层审议？
- [ ] 是否有分类误判的复盘——定期检查是否有Type 2被当Type 1处理（过度慎重）或Type 1被当Type 2处理（过度草率）？
- [ ] Disagree and Commit是否双向——决策前是否充分讨论，决策后是否全力执行？
- [ ] 决策速度是否被衡量——从提出问题到做出决策的平均时间是否被追踪？
- [ ] 决策者是否承担后果——做决策的人是否也为错误决策的后果负责？
- [ ] 与单线程领导是否配合——独立团队是否减少了Type 2决策的跨部门协调成本？

## 诚实边界

1. **Type 1和Type 2的边界模糊**：现实中很多决策处于灰色地带——看似可逆的决策可能产生不可逆的品牌损害（如Amazon Fire Phone），看似不可逆的决策可能通过巨大代价撤回。分类框架的清晰性在实践中经常被挑战，而框架本身没有给出"如何处理灰色地带"的精确方法。

2. **70%法则的量化困境**：70%不是一个可精确测量的数字——没有人能客观地说"我现在掌握了73%的信息"。70%法则更像是一种心理暗示（"别等了"），而非可操作的决策标准。在实践中，"70%"和"90%"的区分往往依赖直觉而非数据。

3. **"大多数决策是Type 2"的假设可能有偏差**：贝索斯说大多数决策是Type 2，但这个判断来自Amazon——一个拥有强大品牌、充沛现金流、市场主导地位的公司。对于资源有限、品牌脆弱的创业公司，一个错误的Type 2决策可能就是致命的。Amazon能"先做再改"是因为它改得起。

4. **Fire Phone的反例**：Amazon Fire Phone被当作Type 2决策快速推进，但实际造成了17亿美元的资产减记和严重的品牌损伤。这个案例说明：即使是Amazon自己，也会在Type 1/2分类上犯错。而且，Fire Phone的失败不是因为"做错了可以改"，而是"做错了改不了"——这恰恰是Type 1的特征。

5. **与华为ATI/ATB/ATC对比的简化**：华为的决策评审不是纯粹的"层层审批"——ATI/ATB/ATC每个决策点都有明确的通过/否决标准，评审效率可能比想象中高。将华为简化为"默认慎重"忽略了华为在流程中追求的效率。

6. **速度与质量的永恒张力**：框架假设"速度是竞争优势"，但速度和质量并非总是可兼得。在某些领域（如企业级SaaS、基础设施），决策质量比决策速度更重要。Type 1/2框架没有回答"什么时候速度不如质量重要"这个问题。
