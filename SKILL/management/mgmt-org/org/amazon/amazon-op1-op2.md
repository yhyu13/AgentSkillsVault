# Amazon · OP1/OP2年度计划 + ST目标

> 用自下而上的年度计划流程+薪酬长期绑定，让"原则-计划-流程-激励"四者一致，把战略意图压进每个人的日常决策。

## 核心理念

OP1/OP2解决的核心问题是：**如何让一家几十万人的公司，在年度目标设定上既保持战略一致性，又不丧失基层的主动判断力？**

Amazon的答案是双轮驱动：一轮是OP1/OP2的年度计划节奏——夏季制定、冬季校准，多轮上下对齐而非一次拍板；另一轮是ST目标机制——不是总部闭门定"10件大事"，而是从各业务单元的年度计划中筛选出公司级战略项目，自下而上涌现。

但流程本身不够。Amazon的深层设计是**四要素一致性**：原则（Leadership Principles）→计划（OP1/OP2）→流程（6页纸/PR/FAQ）→激励（薪酬结构）必须指向同一个方向。如果原则要求长期主义、但激励只看短期奖金，系统就会自相矛盾。因此Amazon的薪酬结构刻意偏向长期——层级越高，股票占比越高，现金占比越低。这让人在制定OP1目标时敢于设定偏高目标，因为个人回报不取决于当年是否100%达成。

目标设定故意偏高的逻辑：Amazon期望OP1目标的达成率在75%左右。如果某个团队年年100%完成，说明目标定低了；如果达成率太低，说明目标脱离现实。75%是"足够有野心但仍可执行"的甜蜜点。

## 框架结构

```
Amazon OP1/OP2年度计划体系
│
├── OP1层（Operation Plan 1）
│   ├── 时间：每年夏季，持续4-8周
│   ├── 流程：高层定年度目标 → 逐级分解 → 多轮上下对齐
│   ├── 特征：自下而上涌现 + 自上而下校准，反复数轮
│   └── 产出：各业务单元的年度计划 + 资源需求
│
├── OP2层（Operation Plan 2）
│   ├── 时间：次年1月
│   ├── 触发：结合Q4实际业绩 + 年末环境变化
│   ├── 规则：所有调整需最高决策层（S-Team）审批
│   └── 产出：修订后的年度执行计划
│
├── ST目标层（Strategic Targets）
│   ├── 来源：从各业务单元OP1中筛选公司级战略项目
│   ├── 机制：自下而上涌现，非自上而下指定
│   ├── 对比：传统"10件大事"是总部闭门定，ST目标是基层实践冒出来的
│   └── 产出：公司级ST目标清单，绑定专项资源
│
├── 激励一致性层
│   ├── 薪酬结构：层级越高 → 股票比例越高 → 现金比例越低
│   ├── 逻辑：长期激励让人敢于设定偏高目标
│   └── 与OP1的耦合：75%达成率预期 + 长期薪酬 = 不为短期达标牺牲长期价值
│
└── 四要素一致性
    ├── 原则（Leadership Principles）— 指明方向
    ├── 计划（OP1/OP2）— 配置资源
    ├── 流程（6页纸/PR/FAQ）— 约束决策方式
    └── 激励（薪酬结构）— 对齐个人动机
    → 四者必须指向同一方向，否则系统自相矛盾
```

## 关键模块

### 模块1：OP1年度计划制定

- 定义：每年夏季耗时4-8周的年度计划制定流程，是Amazon全年资源分配的核心环节
- 输入：上一年度执行结果、市场环境变化、各业务单元的战略意图
- 输出：各业务单元的年度计划（含目标、资源需求、关键里程碑）
- 关键动作：
  - 高层先提出年度方向性目标（非具体数字）
  - 各业务单元据此制定自己的年度计划，包含详细目标和资源需求
  - 计划逐级上报，高层审阅后反馈质疑和调整要求
  - 多轮上下对齐：不是一次拍板，而是反复数轮直到上下达成共识
  - 整个过程持续4-8周，时间投入本身就是对计划质量的保证
- 常见误区：把OP1当成"填表交差"——如果只有一轮上报没有多轮对齐，OP1就退化为形式主义的预算申报

### 模块2：OP2年度计划校准

- 定义：次年1月基于Q4实际业绩对OP1进行修订和校准
- 输入：Q4业绩数据、年末市场环境变化、OP1原始计划
- 输出：修订后的年度执行计划
- 关键动作：
  - 回顾Q4实际业绩，识别与OP1假设的偏差
  - 根据偏差调整当年执行计划（增减资源、调整优先级）
  - 所有调整必须经过最高决策层（S-Team）审批——不是自动生效
  - S-Team审批确保调整不会稀释战略重点
- 常见误区：把OP2当成"微调"走过场——如果OP2的调整不经S-Team实质性审批，就失去了校准的严肃性

### 模块3：ST目标（Strategic Targets）

- 定义：从各业务单元OP1中筛选出的公司级战略项目，是Amazon战略聚焦的核心机制
- 输入：各业务单元提交的OP1计划
- 输出：公司级ST目标清单（数量有限，绑定专项资源）
- 关键动作：
  - 各业务单元在OP1中提出自己认为最重要的战略项目
  - S-Team从所有业务单元的提案中筛选出公司级ST目标
  - ST目标获得专项资源保障，不受常规预算分配限制
  - 关键区别：传统"10件大事"是总部闭门拍板后向下传达，ST目标是基层在实战中识别的机会向上涌现
  - 自下而上的好处：一线更接近客户和市场，能更早识别战略性机会
- 常见误区：把ST目标等同于"总部重点任务"——如果ST目标全部由总部指定而非从基层提案中筛选，就失去了自下而上的信息优势

### 模块4：薪酬绑定长期

- 定义：薪酬结构随层级提升逐步偏向长期（股票），与OP1的偏高目标设定形成闭环
- 输入：职级体系、市场薪酬数据、公司长期价值预期
- 输出：各层级薪酬结构（现金+股票比例）
- 关键动作：
  - 层级越高，股票占总薪酬比例越高
  - 股票有归属期（vesting schedule），不是即时兑现
  - 长期薪酬让人在制定OP1目标时不会因为"完不成影响当年收入"而刻意压低目标
  - 与75%达成率预期配合：个人不需要100%完成目标才能获得好回报，因为股票价值取决于公司长期表现
- 常见误区：只改薪酬结构不改目标设定——如果薪酬绑定了长期但目标仍然保守，长期激励就变成了"躺赢"

### 模块5：四要素一致性

- 定义：原则、计划、流程、激励四个要素必须指向同一方向，否则系统会自相矛盾
- 输入：组织设计决策（原则定义、计划流程、决策流程、薪酬方案）
- 输出：自洽的组织运行系统
- 关键动作：
  - 原则（Leadership Principles）定义"我们信什么"——如Customer Obsession、Think Big
  - 计划（OP1/OP2）定义"我们做什么"——资源配置必须体现原则
  - 流程（6页纸/PR/FAQ）定义"我们怎么做决策"——决策方式必须与原则一致
  - 激励（薪酬结构）定义"我们奖励什么"——激励必须强化原则和计划
  - 四者不一致的典型症状：原则说"长期主义"，但激励全是短期现金奖金
- 常见误区：只改其中一个要素——比如引入6页纸流程但不改薪酬结构，结果流程变成了形式主义

## 决策启发式

| 场景 | 判断规则 | 来源 |
|------|---------|------|
| OP1目标定高还是定低 | 定高——期望75%达成率，100%完成说明目标太保守 | OP1设计哲学 |
| OP2是否需要调整 | 如果Q4实际与OP1假设有显著偏差→必须调整；如果偏差不大→保持OP1 | OP2校准逻辑 |
| ST目标从哪来 | 如果ST目标全部由总部指定→信息来源单一；如果从业务单元OP1中筛选→信息来源丰富 | ST目标机制 |
| 薪酬结构是否支持长期 | 如果高层现金占比过高→与"Think Big"原则矛盾；如果股票占比随层级递增→一致 | 四要素一致性 |
| OP1对齐轮次是否足够 | 如果只有一轮上报→对齐不足；如果经历多轮上下往返→对齐到位 | OP1流程设计 |
| 四要素是否一致 | 如果原则说长期但激励看短期→系统自相矛盾；如果四者指向同一方向→自洽 | 《Working Backwards》第1章 |
| 是否需要OP2审批 | 如果OP2调整不经S-Team审批→校准失去严肃性；如果经S-Team审批→校准有效 | OP2审批规则 |

## 与其他方法论的关系

| 关联方法论 | 关系 | 接口 |
|-----------|------|------|
| 华为DSTE | 对标 | DSTE是端到端战略管理流程（SP→BP→执行→复盘），OP1/OP2是年度计划节奏——DSTE覆盖更广（含3-5年SP），OP1/OP2更聚焦当年；DSTE的BP≈OP1，DSTE的经营分析会≈OP2的持续校准 |
| 华为BLM | 对标 | BLM管战略制定（市场洞察→业务设计），OP1不包含独立的战略制定模块——Amazon的战略思考嵌入在OP1多轮对齐中，不另设BLM式的结构化战略制定流程 |
| 华为BEM | 对标 | BEM管战略解码（SP→KPI→PBC），OP1的逐级分解≈BEM的垂直解码——但BEM有六步法结构化流程，OP1的分解更依赖领导力判断而非固定方法论 |
| 字节OKR | 对标 | 字节OKR双月迭代+弱薪酬关联+全员透明，Amazon OP1年度节奏+强长期薪酬绑定+层级对齐——字节靠频率换精度，Amazon靠深度换一致性 |
| Amazon 6页纸备忘录 | 上游 | OP1/OP2中的计划文档使用6页纸格式——叙述体写作约束计划质量 |
| Amazon 逆向工作法 | 并行 | OP1中的新产品提案可用PR/FAQ验证——PR/FAQ是OP1产品立项的"入场券" |
| Amazon Leadership Principles | 上游哲学 | 原则是四要素一致性的起点——OP1/OP2的运行依赖"Have Backbone"（敢于在多轮对齐中坚持）和"Think Big"（敢于设定偏高目标） |

## 适用场景

### 最适合

- 大型多业务单元公司，需要年度资源分配的系统性流程
- 战略方向相对稳定但执行细节需要每年校准的企业
- 希望用长期激励对冲短期主义倾向的组织
- 基层有较强市场感知力、适合自下而上涌现战略机会的公司

### 不适合

- 10人以下初创团队，4-8周的OP1流程成本远超收益
- 业务环境季度级别变化的公司，年度计划节奏太慢
- 缺乏长期激励工具（如股权/期权）的企业，无法实现薪酬绑定长期
- 基层缺乏战略判断力的组织，自下而上的ST目标机制无法有效运作
- 文化回避冲突的组织，OP1多轮对齐需要"Disagree and Commit"

## 实施检查清单

- [ ] OP1是否经历多轮上下对齐（而非一轮上报就定稿）
- [ ] OP1目标是否故意偏高（期望75%达成率，而非100%）
- [ ] OP2是否基于Q4实际业绩进行实质性校准
- [ ] OP2调整是否经过最高决策层审批（而非自动生效）
- [ ] ST目标是否从业务单元OP1中筛选（而非总部闭门指定）
- [ ] 薪酬结构是否随层级提升增加长期（股票）比例
- [ ] 原则-计划-流程-激励四要素是否指向同一方向
- [ ] 是否存在"原则说长期、激励看短期"的自相矛盾
- [ ] OP1计划文档是否使用叙述体格式（6页纸）而非PPT碎片
- [ ] 多轮对齐中是否有人敢于提出异议（Disagree and Commit文化）

## 诚实边界

1. **OP1/OP2内部细节不透明**：公开资料描述了OP1/OP2的框架和时间节奏，但多轮对齐的具体操作方式（如何轮、谁参与、争议如何裁决）属于Amazon内部信息，本文件基于公开资料推断。

2. **ST目标筛选标准未公开**：S-Team从业务单元OP1中筛选ST目标的标准和过程不透明，"自下而上涌现"是理念描述，实际操作中总部的影响力可能比公开资料暗示的更大。

3. **75%达成率的适用性**：这一期望值来自Amazon特定业务组合（高毛利零售+AWS），对低毛利或强合规行业可能不适用——有些行业必须承诺100%完成。

4. **薪酬绑定长期的局限**：股票激励依赖公司股价长期上涨。如果公司股价长期低迷，长期激励就失去吸引力，OP1偏高目标的设定逻辑也会动摇。

5. **与华为/字节对比的简化**：三种体系各有历史路径依赖——Amazon的OP1/OP2诞生于电商零售的年度节奏，华为DSTE诞生于B2B运营商业务的3-5年规划传统，字节OKR诞生于移动互联网的快速迭代需求。对比有助于理解差异，但不存在绝对优劣。

6. **四要素一致性的理想化**："原则+计划+流程+激励一致"是设计理想，现实中任何大型组织都存在局部不一致。Amazon自身也在持续调整中，并非完美自洽。
