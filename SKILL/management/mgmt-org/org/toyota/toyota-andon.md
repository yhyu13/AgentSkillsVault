# 丰田 · 安灯系统

> 不停线=没有问题=最大的问题——异常必须被看见、被停止、被解决

## 核心理念

安灯解决的问题是：为什么缺陷总是流到客户手中才发现？答案——因为生产线上的人发现了异常却不敢停线，或者根本没有机制让异常被看见。安灯系统用最直接的方式打破这个困境：任何人发现异常，拉绳停线，灯亮起来，所有人知道出了问题，问题必须就地解决才能恢复生产。安灯的核心不是灯，而是"停线的权力"——把质量控制的权力从管理者下放到一线操作者。不停线的生产线不是没有问题，而是问题被掩盖了。

## 关键模块

### 模块1：安灯信号机制

- 定义：用颜色和声音信号让异常在第一时间被所有人看见
- 输入：操作者的异常发现
- 输出：可视化的异常信号
- 关键动作：三色信号——绿（正常运行）、黄（需要帮助，不停线）、红（停线，必须解决）；蜂鸣器（听觉补充）；信号板位置——必须让所有人一眼看到
- 常见误区：安灯信号板放在角落，现场人员看不到

### 模块2：停线权力

- 定义：任何一线操作者都有权停线，无需请示上级
- 输入：操作者的判断（质量异常、安全隐患、设备故障）
- 输出：立即停止的生产线
- 关键动作：赋予操作者停线权力；管理者不得因停线惩罚操作者；停线是"发现问题的机会"而非"影响效率的麻烦"
- 常见误区：口头上说"可以停线"，实际上停线的人被批评或变相惩罚

### 模块3：快速响应

- 定义：停线后，支持人员必须在规定时间内赶到现场
- 输入：安灯信号
- 输出：赶到的支持人员（领班、工程师、维护人员）
- 关键动作：响应时间目标（通常30秒-2分钟）；支持人员听到信号立即赶往现场；现场诊断和临时修复
- 常见误区：响应时间太长，停线成本过高导致人们不敢停线

### 模块4：问题记录与根因消除

- 定义：每次安灯停线都是改善机会，必须记录并分析
- 输入：停线事件记录
- 输出：根因分析+永久对策
- 关键动作：记录每次停线的原因、时间、对策；用5Why分析根因；实施永久对策防止再发；跟踪停线频率趋势（停线减少=质量提升）
- 常见误区：只解决眼前问题恢复生产，不做根因分析和永久对策

## 决策启发式

| 场景 | 判断规则 | 来源 |
|------|---------|------|
| 发现异常但犹豫是否停线 | 停！宁可误停不可漏过 | 安灯原则 |
| 停线频率很高 | 停线多是好事=问题在被暴露，逐个消除 | 安灯哲学 |
| 停线频率为零 | 最大问题——问题被掩盖了 | 安灯哲学 |
| 想取消停线权力"提高效率" | 取消停线=允许缺陷流入下一工序 | 自働化原则 |
| 黄灯频繁亮 | 资源不足或技能不够，需要增加支持 | 安灯信号含义 |
| 停线后无人响应 | 检查响应机制和人员配置 | 快速响应原则 |

## 适用场景

### 最适合

- 流水线生产环境
- 质量缺陷代价极高的场景
- 需要建立"问题即机会"文化的组织
- 希望将质量控制权下放到一线的团队

### 不适合

- 非流程化的知识工作（需要适配为其他形式的异常上报）
- 对停线容忍度极低的场景（如医院手术室，需要分级响应）
- 管理层不真正授权停线的组织（安灯会变成装饰）

## 实施检查清单

- [ ] 安灯信号板是否在所有人可见的位置
- [ ] 三色信号（绿/黄/红）是否定义清晰
- [ ] 一线操作者是否真正有权停线（无惩罚）
- [ ] 停线后支持人员是否在规定时间内响应
- [ ] 每次停线是否有记录
- [ ] 是否用5Why/A3分析停线根因
- [ ] 是否跟踪停线频率趋势
- [ ] 管理层是否视停线为改善机会而非效率损失

## 诚实边界

1. 安灯的效力取决于"停线权力"的真实性——如果停线的人被变相惩罚，安灯形同虚设
2. 停线有成本，频繁停线说明系统问题多，需要管理层有耐心逐个消除
3. 安灯主要适用于物理生产线，知识工作需要重新设计异常上报机制
4. 安灯只能发现"被看到"的异常，隐性缺陷（如材料疲劳）需要其他检测手段
5. 过度依赖安灯可能导致"只有亮灯才行动"的被动心态，需要配合主动巡检
