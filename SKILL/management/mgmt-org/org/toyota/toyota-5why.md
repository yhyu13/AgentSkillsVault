# 丰田 · 5Why分析法

> 连问5个为什么，直到根因浮出水面——症状不是原因

## 核心理念

5Why解决的问题是：为什么问题总是反复发生？答案——因为大多数人只解决了症状，没有消除根因。大野耐一观察到，人们面对问题时习惯性地跳到对策，而对策往往只针对表面现象。5Why用最简单的规则——连续追问"为什么"——迫使思考深入到因果链的末端。它不需要统计工具，不需要复杂模型，只需要诚实和耐心。5Why的精髓不在"5"这个数字，而在"追问"这个动作——不满足于第一个答案，永远追问"为什么这个原因会发生"。

## 框架结构

```
5Why因果链模型
问题现象
  └→ 为什么1 → 直接原因
       └→ 为什么2 → 间接原因
            └→ 为什么3 → 系统原因
                 └→ 为什么4 → 管理原因
                      └→ 为什么5 → 根本原因
                           └→ 对策（针对根本原因）

经典示例（大野耐一）：
机器停了
 └→ 为什么？保险丝断了
      └→ 为什么？超负荷运转
           └→ 为什么？轴承润滑不够
                └→ 为什么？油泵吸不上油
                     └→ 为什么？油泵轴磨损
                          └→ 为什么？没装过滤器 ← 根因
                               └→ 对策：安装过滤器
```

## 关键模块

### 模块1：问题定义

- 定义：准确描述问题现象，区分事实与判断
- 输入：异常、偏差、客户投诉
- 输出：清晰、具体、可量化的问题陈述
- 关键动作：用数据描述问题（何时、何地、频率、影响程度）；避免在问题定义中混入原因假设；确保所有人理解一致
- 常见误区：问题定义模糊（"质量不好"而非"3月第2周次品率从2%升至8%"）

### 模块2：因果链追问

- 定义：从问题现象出发，逐层追问"为什么"，构建因果链
- 输入：问题陈述
- 输出：完整的因果链（至少5层）
- 关键动作：每层只问一个"为什么"；基于事实回答，不用猜测；如果因果链分叉，追踪每条分支；追问到可以采取具体对策的层级为止
- 常见误区：跳层（从现象直接跳到根因）；用"因为"代替"为什么"（把假设当事实）；因果链断裂（层与层之间没有直接因果）

### 模块3：根因验证

- 定义：确认找到的是根因而非中间原因
- 输入：因果链末端的原因
- 输出：经验证的根因
- 关键动作：逻辑检验——如果消除这个原因，问题是否不再发生？反向推演——从根因正向推导，是否能复现问题现象？现场验证——去现场确认因果链是否真实
- 常见误区：把"人为失误"当作根因（人为失误背后一定有系统原因）

### 模块4：对策设计

- 定义：针对根因设计对策，而非针对症状
- 输入：验证后的根因
- 输出：消除根因的具体对策
- 关键动作：对策必须直接针对根因；对策应防止问题再次发生（而非临时修补）；多个根因则多个对策；对策要可执行、可验证
- 常见误区：对策针对中间层原因而非根因；对策是"加强培训"或"加强检查"（治标不治本）

## 决策启发式

| 场景 | 判断规则 | 来源 |
|------|---------|------|
| 问题反复发生 | 上次对策只解决了症状，用5Why找根因 | 大野耐一 |
| 回答"人为失误" | 人为失误不是根因，继续追问为什么人会犯错 | 5Why原则 |
| 不确定追问几层 | 追问到可以采取具体对策的层级（通常5层左右） | 5Why实践 |
| 因果链分叉 | 每条分支都要追踪，可能有多条根因 | 5Why扩展 |
| 想跳过分析直接给对策 | 先完成5Why再给对策，否则对策一定治标 | 5Why纪律 |
| 找到的根因是"制度缺失" | 继续追问——为什么制度会缺失？ | 5Why深度 |

## 适用场景

### 最适合

- 反复发生的慢性问题
- 表面原因已找到但问题仍不断出现
- 需要跨团队共识的问题分析
- 培养深度思考习惯

### 不适合

- 紧急救火（先止血再分析）
- 高度复杂的系统性问题（可能需要统计工具配合）
- 根因涉及多个交互因素（5Why线性链可能不够，需要鱼骨图配合）
- 因果关系不确定的探索性场景

## 实施检查清单

- [ ] 问题定义是否清晰、具体、可量化
- [ ] 是否连续追问了至少5层"为什么"
- [ ] 每层回答是否基于事实而非猜测
- [ ] 因果链层与层之间是否有直接因果关系
- [ ] 是否避免了把"人为失误"当作根因
- [ ] 根因是否经过验证（消除后问题不再发生）
- [ ] 对策是否针对根因而非症状
- [ ] 对策是否是防止再发而非临时修补

## 诚实边界

1. 5Why是线性因果模型，现实中的问题往往有多因多果的网状结构，5层追问可能不够
2. "5"是经验值而非铁律——有时3层就够了，有时需要7层，关键是追到可对策的根因
3. 5Why的结果严重依赖追问者的经验和诚实度——不诚实的人可以引导出任何想要的"根因"
4. 把"人为失误"当根因是5Why最常见的失败模式——人犯错背后一定有系统原因
5. 5Why缺乏统计严谨性，对于变异型问题（需要区分普通原因和特殊原因），应配合SPC使用
