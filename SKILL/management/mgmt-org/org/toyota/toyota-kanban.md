# 丰田 · 看板管理

> 不被取走就不生产——用可视化信号卡实现拉动式生产

## 核心理念

看板解决的核心问题是：如何避免生产过剩？传统推式系统中，计划部门根据预测向前工序下达生产指令，结果要么生产过多（库存堆积），要么生产不足（缺料停线）。看板反其道而行——后工序根据自己的消耗，向前工序发出"请补充"的信号。没有信号卡，就不生产。看板把"该生产什么、生产多少、何时生产"的决策权从计划部门下放到现场，用物理卡片（或电子信号）替代中央调度，实现自组织式生产。

## 框架结构

```
看板系统运作模型
┌──────────┐    取货看板    ┌──────────┐
│  后工序   │ ─────────────→ │  前工序   │
│  (消耗)   │ ←───────────── │  (补充)   │
└──────────┘    生产看板    └──────────┘
     │                           │
     │ 取走零件                   │ 补充零件
     ↓                           ↓
┌──────────┐              ┌──────────┐
│ 零件存放处│              │ 零件存放处│
│ (看板箱)  │              │ (看板箱)  │
└──────────┘              └──────────┘

看板循环：
后工序取走零件 → 取货看板从零件箱取下 → 送到前工序
→ 前工序看到取货看板 → 开始生产 → 生产完成附上生产看板 → 放入存放处
```

## 关键模块

### 模块1：看板种类

- 定义：两种核心看板——取货看板和生产看板
- 输入：后工序的消耗信息
- 输出：前工序的生产指令
- 关键动作：取货看板（指示"去哪里取、取什么、取多少"）；生产看板（指示"生产什么、生产多少、用什么材料"）；信号看板（用于批量生产的场合，指示"当库存降到订货点时开始生产"）
- 常见误区：只有一种看板，混淆取货和生产指令

### 模块2：看板6条规则

- 定义：看板系统正确运行的6条铁律
- 输入：看板系统的运行约束
- 输出：自组织、无浪费的拉动式生产
- 关键动作：
  1. 不生产不合格品（不合格品不附看板，不送下一工序）
  2. 后工序来取（前工序不主动推送）
  3. 只生产后工序取走的量（看板数量=生产数量）
  4. 均衡化生产（看板必须与均衡化排程配合）
  5. 微调计划（看板数量是上限，可以减少不能增加）
  6. 持续改善（逐步减少看板数量，暴露问题，改善后继续减少）
- 常见误区：违反规则2（前工序主动推送），看板退化为推式排产

### 模块3：看板数量计算

- 定义：确定每种零件需要的看板数量
- 输入：每日需求量、补充周期、容器容量、安全系数
- 输出：看板数量（=上限库存量）
- 关键动作：公式 N = (D × T × (1+α)) / a，其中D=日均需求，T=补充周期，α=安全系数，a=容器容量；减少看板数量=降低库存=暴露问题
- 常见误区：看板数量一成不变，不通过减少看板来驱动改善

### 模块4：看板与均衡化

- 定义：看板系统需要均衡化排程才能平稳运行
- 输入：客户需求（品种和数量）
- 输出：均衡化的生产排程
- 关键动作：总量均衡（每天的总量基本稳定）；品种均衡（不同品种穿插生产，避免大批量）；看板按均衡化顺序排列
- 常见误区：只实施看板不均衡化排程，导致前工序负荷忽高忽低

## 决策启发式

| 场景 | 判断规则 | 来源 |
|------|---------|------|
| 前工序是否该生产 | 只在后工序取走后才生产 | 规则2-3 |
| 是否该增加看板数量 | 不增加，只减少（减少=改善机会） | 规则5-6 |
| 发现库存过多 | 减少看板数量，暴露问题 | 规则6 |
| 生产出现不合格品 | 不附看板，不送下一工序 | 规则1 |
| 前工序负荷不均 | 检查是否缺少均衡化排程 | 规则4 |
| 想用看板但需求极不稳定 | 先做需求均衡化，再看板化 | 看板前提条件 |

## 适用场景

### 最适合

- 重复性生产环境，需求相对稳定
- 工序间有物理物流连接的制造场景
- 希望从推式生产转向拉式生产的组织
- 需要可视化控制在制品数量的场景

### 不适合

- 需求极度不稳定（看板的前提是相对可预测的需求）
- 一次性项目（无重复性，看板无意义）
- 工序间无物理物流（纯知识工作需要适配）
- 生产周期极长的场景（看板信号反馈太慢）

## 实施检查清单

- [ ] 是否区分了取货看板和生产看板
- [ ] 是否遵守6条看板规则（尤其规则2：后工序来取）
- [ ] 是否计算了合理的看板数量
- [ ] 是否实施了均衡化排程
- [ ] 看板是否有固定存放位置（5S到位）
- [ ] 是否定期减少看板数量驱动改善
- [ ] 不合格品是否不附看板、不送下一工序
- [ ] 是否有电子看板替代物理卡片的计划（如适用）

## 诚实边界

1. 看板是JIT的工具，不是JIT本身——没有均衡化和连续流，看板只是好看的卡片
2. 看板数量减少会暴露问题，但暴露不等于解决——需要配套的改善能力
3. 软件行业的"看板"只继承了WIP限制思想，与丰田看板的物理拉动机制有本质区别
4. 看板对需求稳定性有要求，需求波动大的场景需要先做需求管理
5. 电子看板失去了物理卡片的触觉反馈和现场感，需要额外注意信息同步
