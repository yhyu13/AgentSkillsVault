# 麦肯锡 · 7S模型

> 用7个维度诊断组织——3个硬件S+4个软件S，任何变革必须7S联动否则必败

## 核心理念

7S模型解决的核心问题是：**为什么许多结构重组和组织变革失败了？**

1980年代，麦肯锡顾问汤姆·彼得斯和罗伯特·沃特曼在研究卓越企业时发现一个关键洞察：大多数组织变革只关注"硬件"要素（战略、结构、制度），而忽略了"软件"要素（风格、人员、技能、共同价值观）。硬件变革如果脱离软件支撑，必然失败。7S模型由此诞生——它将组织拆解为7个以S开头的维度，强调7个维度必须相互协调、联动变革。

7S模型的核心论点：**组织不是机器，而是有机体**。你可以快速调整战略和结构，但如果风格、技能、价值观没有同步变化，新的战略和结构会被旧的文化惯性拉回原状。

核心设计哲学：
- **硬件/软件二分**：3个硬件S（战略/结构/制度）可被直接设计和改变，4个软件S（风格/人员/技能/共同价值观）只能培育和引导
- **7S联动**：任何单一维度的变革必须伴随其他维度的适配调整
- **共同价值观为中心**：价值观是7S的枢纽，它影响其他6个S，也受其他6个S塑造

## 框架结构

```
7S模型 = 组织诊断的7维框架
│
├── 硬件S（可直接设计）
│   ├── Strategy（战略）：组织如何竞争和取胜
│   ├── Structure（结构）：组织如何分工和协调
│   └── Systems（制度）：组织如何运转和衡量
│
├── 软件S（只能培育）
│   ├── Style（风格）：领导者如何行为和示范
│   ├── Staff（人员）：组织如何选人和用人
│   ├── Skills（技能）：组织拥有什么核心能力
│   └── Shared Values（共同价值观）：组织信仰什么
│
└── 联动逻辑
    ├── 共同价值观是中心枢纽
    ├── 硬件S之间强耦合——战略决定结构，结构决定制度
    ├── 软件S之间强耦合——风格塑造人员，人员决定技能
    └── 硬件S与软件S必须对齐——战略与价值观对齐，结构与风格对齐
```

## 关键模块

### 模块1：Strategy（战略）

- 定义：组织为获得竞争优势而制定的资源配置和竞争方式选择
- 输入：外部环境分析+内部能力评估+价值主张
- 输出：战略意图+竞争定位+资源配置优先级
- 关键动作：
  1. 明确战略意图——组织要在什么市场、用什么方式、打败谁
  2. 识别战略控制点——哪些能力是竞争壁垒
  3. 配置资源优先级——战略不是什么都做，而是选择做什么和不做什么
  4. 检验战略与其他6S的对齐——战略是否与价值观一致？结构是否支撑战略？人员是否具备执行战略的技能？
- 常见误区：战略与价值观冲突——战略要求"快速试错"，价值观却是"零失误文化"，两者必然打架

### 模块2：Structure（结构）

- 定义：组织的分工方式、汇报关系和协调机制
- 输入：战略要求+业务特征+规模阶段
- 输出：组织架构图+权责划分+协调机制
- 关键动作：
  1. 职能型vs事业部型vs矩阵型——根据战略和业务复杂度选择
  2. 集权vs分权——根据战略对速度和一致性的要求选择
  3. 管理幅度——根据人员成熟度和制度完善度确定
  4. 检验结构与其他6S的对齐——结构是否支撑战略？制度是否匹配结构？风格是否适应结构？
- 常见误区：结构调整了但制度没跟上——新设事业部但没有配套的核算制度，事业部形同虚设

### 模块3：Systems（制度）

- 定义：组织的日常运转流程、衡量标准和激励机制
- 输入：战略目标+结构设计+人员特征
- 输出：流程体系+KPI体系+激励体系+信息系统
- 关键动作：
  1. 流程体系——核心业务流程（IPD/LTC/ITR等）支撑战略落地
  2. KPI体系——衡量标准必须与战略对齐，"衡量什么就得到什么"
  3. 激励体系——薪酬/晋升/荣誉必须强化战略期望的行为
  4. 信息系统——数据流转必须匹配组织结构，信息孤岛是制度失效的信号
- 常见误区：KPI与战略脱节——战略说"客户至上"，KPI却只考核收入不考核客户满意度

### 模块4：Style（风格）

- 定义：领导层的行为方式、决策风格和文化示范
- 输入：创始人的性格+行业特征+历史积淀
- 输出：组织的行为规范+决策模式+沟通方式
- 关键动作：
  1. 识别当前风格——是命令式还是参与式？是冒险型还是稳健型？
  2. 领导者行为审计——领导者"做什么"比"说什么"影响力大10倍
  3. 风格与战略的对齐——创新战略需要冒险型风格，成本领先战略需要严谨型风格
  4. 风格的可迁移性——领导者更替时风格是否可以延续？还是过度依赖个人？
- 常见误区：忽视风格的隐性影响力——领导者嘴上说"授权"，行为上事必躬亲，员工学到的是"不授权"

### 模块5：Staff（人员）

- 定义：组织如何吸引、选拔、培养和保留人才
- 输入：战略所需的人才画像+市场人才供给
- 输出：人才梯队+人才标准+人才发展体系
- 关键动作：
  1. 人才画像——战略需要什么样的人？现有人员与画像的差距？
  2. 选拔机制——选人标准是否与价值观对齐？只看能力不看文化契合？
  3. 培养体系——人才培养是否聚焦战略所需技能？
  4. 保留机制——关键人才的流失是否因为风格或制度问题？
- 常见误区：只招"聪明人"不看文化契合——能力与价值观不匹配的人，能力越强破坏力越大

### 模块6：Skills（技能）

- 定义：组织作为整体所拥有的核心能力和竞争优势
- 输入：战略要求+人员能力+历史积累
- 输出：核心能力清单+能力建设路径+能力差距分析
- 关键动作：
  1. 区分个人技能与组织技能——组织技能不是个人技能的简单加总，而是协同涌现
  2. 识别战略所需的核心能力——哪些能力是战略控制点？
  3. 能力差距分析——现有技能与战略要求的差距
  4. 能力建设路径——通过招聘、培训、并购、合作等方式补齐
- 常见误区：把技能等同于个人能力——个人能力强不代表组织能力强；关键人员离职后组织能力归零，说明这不是组织技能而是个人技能

### 模块7：Shared Values（共同价值观）

- 定义：组织成员共同信仰的核心信念和行为准则，是7S的中心枢纽
- 输入：创始理念+历史积淀+战略要求
- 输出：价值观陈述+行为准则+决策底线
- 关键动作：
  1. 价值观不是口号——必须转化为可观察、可衡量的行为准则
  2. 价值观与战略的双向检验——战略是否与价值观一致？价值观是否支撑战略？
  3. 价值观的传导机制——招聘筛选、晋升标准、荣誉体系、惩罚案例
  4. 价值观的演进——当战略转型时，价值观是否需要演进？如何演进？
- 常见误区：价值观墙上的字与实际行为不一致——"客户第一"但考核只看收入，员工学到的是"收入第一"

## 决策启发式

| 场景 | 判断规则 | 来源 |
|------|---------|------|
| 组织变革是否可行 | 如果只改了硬件S没改软件S→变革必败；7S必须联动 | 彼得斯&沃特曼 |
| 变革从哪个S开始 | 如果战略方向不清晰→从战略开始；如果战略清晰但执行不力→从制度或风格开始 | 麦肯锡组织诊断实践 |
| 7S是否对齐 | 如果任一S与其他S矛盾→对齐失败，矛盾点就是变革切入点 | 7S模型核心逻辑 |
| 价值观是否真实 | 如果价值观与KPI/激励矛盾→价值观是假的，KPI才是真价值观 | 麦肯锡组织诊断实践 |
| 结构调整是否有效 | 如果结构调整后制度未配套→结构调整无效 | 7S联动逻辑 |
| 人才策略是否正确 | 如果人才画像与战略要求不匹配→人才策略需调整 | 麦肯锡组织诊断实践 |
| 领导风格是否适配 | 如果领导风格与战略要求矛盾→要么换战略要么换风格 | 彼得斯&沃特曼 |

## 适用场景

### 最适合

- 组织变革前的全面诊断——识别7S中的对齐断裂点
- 并购后的整合规划——两个组织的7S差异是整合的起点
- 战略转型期的组织适配——新战略需要7S联动调整
- 文化建设的系统规划——文化不是孤立的，必须与其他6S对齐
- 领导层更替的风险评估——新领导的风格是否与现有7S兼容

### 不适合

- 紧急危机应对——7S诊断需要时间，危机需要快速决策
- 10人以下初创团队——7个维度过度拆解，小团队的问题通常集中在1-2个S
- 单一维度的深度优化——7S是广度框架，深度优化需要专项工具
- 日常运营管理——7S是诊断工具，不是运营工具
- 需要量化精度的场景——7S的软件S难以量化，定性判断为主

## 实施检查清单

- [ ] 战略是否清晰且与价值观对齐
- [ ] 结构是否支撑战略——权责划分是否匹配战略重点
- [ ] 制度是否匹配结构——KPI/流程/激励是否与结构设计一致
- [ ] 领导风格是否与战略要求一致——言行是否统一
- [ ] 人员画像是否与战略需求匹配——人才梯队是否有缺口
- [ ] 组织技能是否形成战略控制点——不依赖单一个人
- [ ] 价值观是否从口号转化为行为准则——与KPI/激励是否一致
- [ ] 7S之间是否存在矛盾——任一S与其他S冲突就是变革切入点
- [ ] 硬件S变革是否伴随软件S调整——只改硬件不改软件必败
- [ ] 是否识别了7S中的"锚定点"——哪个S最难以改变，它就是变革的约束条件

## 诚实边界

1. **7S是诊断框架而非行动方案**：7S告诉你"哪里不对"，但不告诉你"怎么改"。从诊断到行动之间需要大量补充工具——战略用BLM/DSTE，结构用组织设计方法论，制度用流程再造等。

2. **软件S难以量化**：风格、人员、技能、价值观都是定性维度，不同诊断者可能得出不同结论。7S诊断的主观性是它的固有局限，需要多人交叉验证。

3. **7S的静态性**：7S模型是一个快照式诊断工具，它描述的是某个时点的组织状态，不直接处理组织演化的动态过程。对于快速变化的环境，7S需要定期刷新。

4. **7S之间的因果关系不明确**：7S模型强调"联动"，但7个S之间的因果方向和强度在不同组织中差异巨大。7S模型没有提供因果分析的指导，容易沦为"7个维度都看看"的清单式诊断。

5. **文化差异的适用性**：7S模型诞生于1980年代的美国企业语境，"共同价值观"在美国企业文化中是核心驱动力，但在其他文化中可能不是。日本的"和"、中国的"关系"可能比"价值观"更重要。

6. **与华为基本法的互补盲区**：7S擅长诊断"哪里不对"，基本法擅长规定"应该怎样"，但两者都不擅长解决"如何从现状到目标"——这是变革管理方法论（如科特八步法）的领域。
