# 一张贴图的伪装

事实只来自 CG 加油站 BV1kXTL6qEYb 对 Neon Giant《上行战场》和 Tor Frick 2022 GDC 的转述。原片没说的数，标成演示假设。

## 先定镜头，再定贴图

这套只在镜头多数不够近时成立。原片把近看细节不够当成取舍，不是可以再修掉的缺陷。先问镜头会不会贴到表面。会，就不要进共享集。

## 五层，缺一就露馅

1. 模型 UV 裁到同一张 trim 的某一格，不平铺整张。
2. UV 的整数格选颜色或材质，小数部分才采样。不另做配色遮罩。原片限三种颜色、三种金属。
3. 脏迹三层分开：贴图自带的螺栓污渍、顶点色里的形状 AO、光照烘焙的场景 AO。
4. 第二套 UV 用同一招管贴花和发光。
5. 加权法线只改低模顶点法线。远看像高模，近看仍是低模。

## 采样时不要做的三件事

不要把一个面切成十几块再各自采样。块一多，trim 的螺栓和警示条会变成马赛克，三种算法就分不出来。一个面三到五块够用。

不要让「只共用 trim」和「完整伪装」裁不同的区域。对照要裁同一格，差别只来自颜色、脏迹和法线。否则观众分不清省下来的是纹理还是换了一张图。

不要把演示假设写进原片数字。24 件、BC7 兆字节、美术小时都是为了能算清而设的。原片只给了 80%、一张 4K、低于 100MB、8000+ 资产、50 MiB 换 10% 绘制调用、体积光 150 MiB 降到 40 MiB。

## 会露馅的四种情况

- 镜头贴到表面。
- 形状不同，却裁同一格。
- 三层脏用同一强度。
- 发光和污渍共用一个遮罩。

## 账要分两列

原片：约 80% 硬表面一套着色器；一张 4K；世界纹理低于 100MB；8000+ 资产；Xbox One 上光照图多约 50 MiB、绘制调用少 10%；体积光多一级 MIP，150 MiB 降到 40 MiB。

演示假设必须另标。光照图那 10% 的原因：虚幻要网格、材质、光照图三者相同才实例化，提高分辨率是把更多资产打进同一张光照图。

## 怎么用

做演示页之前先读 `references/source-ledger.md`。原片数字只从那张表抄。表外的数必须标成演示假设。四种露馅的判据在 `references/failure-cases.md`，演示页要能把至少两种做出来。

```powershell
python scripts/check_skill.py
```

这个检查只证明账和失败案例还在。它不证明画面好看。

## 演示页

单文件。三种并排：每件独享、只裁同一格、整数格加三层脏。旋钮改 UV、脏迹和镜头距离，账跟着变。贴图用程序生成或一张生成的 trim，嵌进文件，不引外链。近景必须能看见低模棱，否则这页只是在换颜色。

账分三列，颜色分开。原片数字用一种颜色，演示假设用另一种。不要把 127 MB 写成游戏实测。完整伪装的绘制调用可以按原片的 10% 来减，但要在格里写明这是演示假设。

```javascript
function cellOf(mode, index) {
  if (mode === "unique") return index % 16;
  if (mode === "trim") return 0;
  return index % 8;
}
```

独享用不同格。只裁 trim 时全部返回 0。完整伪装才允许换格。这个函数决定对照是否成立。

```javascript
function dirt(mask, edge, scene) {
  return Math.min(1, mask * 0.9 + edge * 0.8 + scene * 0.7);
}
```

三层各自有权重。把三个权重设成一样，夹角脏就会糊掉，对应失败案例里的第三种。
