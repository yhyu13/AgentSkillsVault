## 用途

用于构建系统化、可扩展、像素级精准的 UI 设计系统与组件库，将界面需求转化为可交互原型和可执行的设计规范。核心能力是「先建设计系统、再做页面设计」，用 Design Token 和组件库保证跨页面的一致性、可维护性和开发还原度。

不适用场景：品牌视觉识别系统（VI）、插画/纯艺术创作、后端逻辑设计、用户研究与需求决策。

## 核心原则

### 1\. 组件库先于页面设计（Design System First）

没有设计系统的页面设计是在沙子上盖楼。先定义好颜色、字体、间距、组件，再去排页面，效率和一致性才有保障。

- 任何界面设计工作，第一步都是建立或复用 Design Token 体系

- 每个视觉决策都要能回溯到设计系统中的规则，否则就是在制造技术债

- 页面只是组件的组合，组件才是设计系统的核心资产

### 2\. 无障碍不是事后补丁，是设计基因（Accessibility by Design）

从第一个像素开始就考虑对比度、焦点顺序、语义结构。等做完了再补无障碍，成本是十倍，效果是减半。

- 文本与背景对比度 ≥ 4\.5:1（WCAG AA），大文本 ≥ 3:1

- 所有交互元素必须有清晰的焦点状态（focus ring）

- 颜色不是传达信息的唯一手段，必须配合图标、文字或形状

- 语义化结构：标题层级正确、列表用列表组件、按钮是按钮

### 3\. 像素级不是强迫症，是对用户的尊重（Pixel\-Perfect）

1px 的错位用户感知不到，但 100 个 1px 的错位用户一定感知得到。细节的累积决定了产品的品质感。

- 所有间距、尺寸、圆角都是 8px 栅格的整数倍

- 文字基线对齐，图标垂直居中

- 边框 1px 不模糊，阴影不发灰

- 组件状态切换时，尺寸、位置、间距保持稳定，不跳动

### 4\. 好的设计系统让开发者做对比做错更容易（Dev\-Friendly）

Token 命名清晰、组件 API 直觉、文档示例充分——让正确的用法成为最省力的用法。

- Design Token 用语义化命名（如 `color-primary-500`），不用字面命名（如 `color-blue`）

- 组件的 props 数量克制，常用值设为默认

- 每个组件必须有完整的状态矩阵（default / hover / active / disabled / focus / error）

- 设计交付附带间距、字号、色值的标注规格，零损耗传达设计意图

## Design Token 体系

### 颜色系统

三级 Token 结构：基础色 → 语义色 → 组件色

- **基础色（Primitive）**：原始色板，如 gray\-50 \~ gray\-900、blue\-50 \~ blue\-900

    - 每个色系 10 个档位，50 最浅、900 最深

    - 相邻档位的色差均匀，确保视觉层级清晰

- **语义色（Semantic）**：有明确含义的颜色，如 primary、success、warning、danger、info

    - primary：主品牌色，用于主要按钮、选中态、重点强调

    - success：成功状态，如操作成功、数据增长

    - warning：警告状态，如待处理、中度风险

    - danger：危险/错误状态，如删除、报错、数据下降

    - info：信息状态，如提示、链接

- **组件色（Component）**：具体组件使用的颜色变量，如 button\-bg\-primary、input\-border\-focus

    - 组件色引用语义色，不直接引用基础色

    - 换主题时只改语义色，组件色自动跟随

### 字体系统

- **字体族（Font Family）**：

    - 中文：PingFang SC / 思源黑体 / 系统默认

    - 英文/数字：Inter / SF Pro / Roboto

    - 等宽：JetBrains Mono / SF Mono / Menlo

- **字号阶梯（Type Scale）**：基于 1\.2 或 1\.25 倍率的 6–8 档

    - 12px（辅助文字）、14px（正文）、16px（小标题）、18px（标题）、24px（大标题）、32px（超大标题）

- **字重（Font Weight）**：Regular \(400\)、Medium \(500\)、Semibold \(600\)、Bold \(700\)

- **行高（Line Height）**：正文 1\.5 \~ 1\.6，标题 1\.2 \~ 1\.3

### 间距系统

8px 栅格基准，常用间距值：

- 4px：元素内部微调（如图标与文字间距）

- 8px：紧凑间距（如列表项内边距）

- 12px：常规内边距

- 16px：标准间距（如卡片内边距、组件间距）

- 24px：区块间距（如模块之间）

- 32px：大区块间距（如章节之间）

- 48px：页面级间距

### 圆角与阴影

- **圆角（Border Radius）**：

    - 2px：小元素（如标签、徽章）

    - 4px：常规元素（如按钮、输入框）

    - 8px：卡片、弹窗

    - 12px \~ 16px：大卡片、面板

    - 999px：胶囊形（pill）

- **阴影（Box Shadow）**：

    - sm：轻微投影，用于悬浮态

    - md：中等投影，用于卡片、下拉菜单

    - lg：大投影，用于弹窗、抽屉

    - 阴影颜色用灰色半透明，不用纯黑（更自然）

## 组件库规范

### 组件分层

三级组件体系：原子组件 → 分子组件 → 页面模板

- **原子组件（Atoms）**：不可再分的基础元素

    - Button、Input、Checkbox、Radio、Switch、Badge、Tag、Icon、Avatar

    - 每个原子组件必须有完整的状态矩阵

- **分子组件（Molecules）**：由多个原子组件组成的功能单元

    - Form Item（Label \+ Input \+ Error Message）、Table Column、Card Header、Nav Item

    - 分子组件封装了常见组合模式，减少重复搭建

- **页面模板（Templates）**：完整页面布局骨架

    - Dashboard 布局、表单页、列表页、详情页、空状态页

    - 模板保证同类型页面的布局一致性

### 组件状态矩阵

每个组件必须定义并设计以下全部状态：

- **default**：默认状态

- **hover**：鼠标悬停（桌面端）

- **active / pressed**：按下/点击态

- **focus**：键盘焦点态（必须有清晰的 focus ring）

- **disabled**：禁用态（降低不透明度或变灰）

- **loading**：加载中（按钮内显示 spinner，禁用点击）

- **error / invalid**：错误态（红色边框 \+ 错误提示文字）

- **success / valid**：成功态（绿色边框 \+ 对勾图标）

### 组件 API 设计原则

- **Props 数量克制**：一个组件不超过 8 个核心 props

- **默认值合理**：最常用的状态设为默认值，减少调用方代码量

- **命名一致**：同一概念在所有组件中用同一个词（如都用 `disabled`，不要有的用 `disabled` 有的用 `readonly`）

- **支持扩展**：预留 `className` / `style` / `children` 等透传属性，应对特殊场景

- **类型安全**：枚举值明确，不接受任意字符串

## 界面设计流程

### 第一步：定义 Design Token

- 确定品牌主色，生成完整色板（10 档）

- 定义语义色映射（primary/success/warning/danger/info）

- 设定字体阶梯、间距系统、圆角和阴影规格

- 输出 Token 清单（JSON / CSS Variables 格式）

### 第二步：搭建原子组件库

- 按优先级从高到低实现：Button → Input → Checkbox/Radio/Switch → Badge/Tag → Icon → Avatar

- 每个组件完成全部状态矩阵的设计

- 组件命名和分类遵循统一规范

- 编写组件使用说明和最佳实践

### 第三步：构建分子组件

- 识别页面中重复出现的组件组合

- 封装成分子组件，定义 props 和状态

- 确保分子组件与原子组件的视觉语言一致

- 补充使用场景和示例

### 第四步：搭建页面模板

- 定义常见页面类型的布局骨架

- 设定栅格系统和断点（mobile / tablet / desktop）

- 模板中留出内容区域的占位

- 提供多种变体（如带侧边栏/不带侧边栏）

### 第五步：组装具体页面

- 从模板出发，用组件库搭建页面

- 不新增设计系统之外的颜色、字号、间距值

- 如发现组件库缺少元素，先回到组件库补充，再在页面中使用

- 确保页面在各断点下的响应式表现

### 第六步：设计 QA（像素级走查）

- 8px 栅格对齐检查：所有间距、尺寸都是 8 的整数倍

- 对比度检查：文本与背景对比度 ≥ 4\.5:1

- 组件状态一致性检查：同类型组件的间距、圆角、阴影一致

- 响应式检查：各断点下布局不崩、内容不溢出

- 无障碍检查：焦点顺序正确、语义标签完整

## 响应式设计规范

### 断点定义

- **Mobile**：\< 768px（手机竖屏）

- **Tablet**：768px \~ 1024px（平板 / 手机横屏）

- **Desktop**：1024px \~ 1440px（笔记本 / 桌面）

- **Wide**：\> 1440px（大屏显示器）

### 布局原则

- **移动优先（Mobile First）**：先设计移动端，再逐步增加大屏幕的内容和布局

- **流式布局（Fluid）**：容器宽度用百分比或 max\-width，不是固定像素

- **内容驱动断点**：断点由内容决定，不是设备尺寸——内容放不下了就加断点

- **触控友好**：移动端可点击区域 ≥ 44px × 44px

### 栅格系统

- Desktop：12 列，列间距 24px，外边距 48px

- Tablet：8 列，列间距 20px，外边距 32px

- Mobile：4 列，列间距 16px，外边距 16px

## 暗色模式设计规范

### 颜色映射原则

- 不是简单反色，需要重新调校每一档颜色的明度

- 背景色不用纯黑（\#000000），用深灰（如 \#121212 / \#1a1a1a），减少视觉疲劳

- 前景色不用纯白（\#ffffff），用浅灰（如 \#f0f0f0 / \#e0e0e0），降低对比度

- 品牌色在暗色模式下提高明度，确保在深色背景上清晰可见

### 层级表达

- 暗色模式下，层级通过「明度」表达：越靠上的元素，背景色越亮

    - 页面背景：最深（如 \#121212）

    - 卡片背景：中等（如 \#1e1e1e）

    - 弹窗/下拉菜单：最亮（如 \#2a2a2a）

- 阴影在暗色模式下效果减弱，可配合边框（1px 半透明白色）增强层级感

## 常见坑与避坑指南

### 设计系统类

- **Token 命名混乱**：用语义化命名，不用颜色名或数值名；换主题时改语义色就行

- **组件状态不全**：设计时只画 default 态，开发才发现缺 hover/disabled/error，临时补的风格不统一

- **间距值泛滥**：项目里出现 5px、7px、9px、11px 等各种非 8 倍数的间距，都是拍脑袋的结果

- **组件越做越多**：不抽象、不复用，每个页面都做新组件，最后组件库臃肿不堪

### 视觉类

- **文字不对齐**：中英文混排时基线不齐、图标和文字垂直方向不居中

- **边框发虚**：1px 边框在高清屏上模糊，因为用了半像素或颜色太深

- **阴影发灰**：阴影用纯黑半透明，看起来发灰发脏；应该用灰色系或带主色调的阴影

- **圆角不一致**：同一个页面里有的按钮 4px 圆角有的 6px，视觉上显得不精致

### 交付类

- **只给效果图不给规范**：开发只能凭眼睛量，还原度差；必须附带 Token 和组件规格

- **缺状态设计**：空状态、加载中、错误态、无数据态都没设计，开发自己瞎凑

- **响应式只做一版**：只做了桌面端，移动端完全没考虑，上线后手机上崩了

- **图标风格不统一**：有的线性有的面性、有的 2px 描边有的 1\.5px，看起来像来自不同产品

## 适用 / 不适用

- **适用**：Web 应用界面设计、移动端 App 设计、设计系统搭建、组件库建设、界面走查与还原度审查、可交互原型制作

- **不适用**：品牌 VI 设计、插画/海报设计、3D 建模、后端架构设计、用户研究与需求分析、营销文案写作
