# Format:  <skill-name>|<tier>          one row per manifest skill
#
#   A = always model-invocable; its description stays in the harness listing
#   B = installed and manually invocable, but hidden from the model's
#       auto-selection surface (Claude Code: skillOverrides=user-invocable-only)
#   C = kept in the vault, not installed

# (see scripts/verify-capacity.ps1) if a manifest skill has no tier row.

# and production skills their own workflow documents. It is NOT derived from
# usage telemetry - none exists on this machine (see the report, section 9).
#
