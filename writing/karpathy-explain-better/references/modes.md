# 四种输出形式的提示词模板与判断清单

每节包含:**适用场景 / 提示词模板 / 常见错误**。

---

## 1. 简化文字(ASD-STE100 风格)

**适用**

- 默认起点
- 用户说"看不懂""简单点"
- 概念本来不复杂,但被绕来绕去讲乱了

**提示词模板**

```
请用中文解释【主题】,借鉴 ASD-STE100 的清晰表达原则,但不要写成生硬的手册。

要求:
- 使用短句,一句话尽量只讲一个要点
- 同一个概念始终用同一个名称,必要术语首次出现时给出解释
- 先说核心结论,再用一个具体例子说明
- 保留关键前提和适用边界,不要为了简短删掉重要信息
```

**判断清单**

- ✅ 一段话能讲清的事,不要拆成五段
- ✅ 同一概念不要换两个名字("算法 A"不要来回切"方法/方案/模型")
- ❌ 不要为了"简短"删掉关键前提
- ❌ 不要硬塞航空术语风(fuselage / torque 之类)

---

## 2. 结构图

**适用**

- 模块之间谁调用谁、出错回哪里
- 流程有多分支(并行 / 串行 / 条件)
- "上一步的输出"是谁的输入——靠纯文字脑补不出来

**提示词模板**

```
请把下面的内容画成一张结构清晰的图,重点展示各部分之间的关系,而不是把原文塞进方框。

要求:
- 每个节点只保留一个核心概念
- 箭头注明关系或传递的信息(动词短句)
- 区分主流程和分支,标出输入与输出
- 原文没有交代的关系不要自行补全,不确定的地方单独标注
- 最后用三句话说明这张图应该怎么看

输出格式:优先 Mermaid 代码块;兜底 ASCII 图。
```

**判断清单**

- ✅ 节点不超过 12 个,否则再分层或分组
- ✅ 箭头写"做什么"(输入/触发/调用/校验),不写"是什么"
- ✅ 输出形态:主流程 vs 分支 / 实线 vs 虚线
- ❌ 不要把原文逐句塞进方框里
- ❌ 不要补全原文没说清的关系——不确定就标注

---

## 3. 可交互网页(单文件 HTML)

**适用**

- 算法演示:梯度下降、卷积/池化、决策树分裂、聚类迭代
- 机制可视化:注意力权重、卷积滤波器扫描、反向传播链
- 参数影响:学习率、正则化、阈值
- 流程可逐步展开,光看图看不出"下一步"

**没有真实数据怎么办**:在 canvas 里程序化绘制简化样本(粗笔画数字、简单几何、合成图),用 JS 实时绘制 + `getImageData` 读像素作为输入——不必等真实数据集下载完成。

**提示词模板**

```
请把【主题】做成一个能在浏览器直接打开的单文件 HTML 教学页面。

要求:
- 包含一句话结论、一张核心示意图、一个可以操作的小实验
- 操作后同步更新图示与解释,并提供重置按钮
- CSS 和 JavaScript 写在同一个文件里,不依赖外部资源,适配手机屏幕
- 先保证知识正确、交互可用,不需要复杂装饰
```

**判断清单**

- ✅ 单文件,内联 CSS/JS,断网也能看
- ✅ 控件数量 < 4 个(学习率 / 步数 / 数据 / 重置)
- ✅ 顶部一句话讲清"操作后会看到什么变化"
- ✅ 数值/边界正确——不能"交互酷但结果是错的"
- ❌ 不要花哨动画盖住内容
- ❌ 不要外链 CDN / 字体 / 图片

---

## 4. 讲解视频

**适用**

- 抽象概念需要视觉节奏(注意力机制、卷积过程)
- 用户只想听"那 3 分钟",不想从头学一门课
- 围绕**单一具体问题**,不是知识普及

**提示词模板**

```
帮我做一个 2 分钟的科普/教学视频,主题是【填写你的主题】。

要求:
- 使用 JS + Canvas(或 Remotion 框架)绘制
- 视觉风格为【手绘卡通 / 科技感微距 / 3Blue1Brown 数学动画】
- 画面必须包含平滑的动效
- 旁白配音使用【EdgeTTS 或 ElevenLabs】
- 请先在内部生成一份 STORYBOARD.md 分镜时间轴规范,
  确保角色设计、配色方案、镜头切换节奏整片统一
- 最后按帧导出代码
```

**判断清单**

- ✅ 围绕一个具体问题,不是"从头教 X"
- ✅ 分镜表先写(几秒 / 画面 / 旁白 / 动效)
- ✅ 旁白与画面同步(节奏不抢戏)
- ✅ 交付物可播放——不要只交一份"方案"
- ❌ 不要让模型自选 API key / 不要塞入付费资源
- ❌ 不要"看起来完整"——必须真能跑 / 真能播

## 选择哪种形式的决策树

```
看不懂 ──┐
         │
         ├─ 是表达不清 / 术语太绕?
         │      → 形式 1:简化文字
         │
         ├─ 是关系多 / 流程杂?
         │      → 形式 2:结构图
         │
         ├─ 是"试一下才知道"?
         │      → 形式 3:可交互网页
         │
         └─ 是节奏 / 动效才能讲清?
                → 形式 4:讲解视频
```

## 升级信号(从轻到重)

- 文字仍抽象 → 升图
- 图看懂了,但想"试一下" → 升网页
- 网页的每一步需要"被讲出来" → 升视频

## 降级 / 拒绝信号

- 视频需求其实一句结论就能解决 → 退回文字
- 用户只问"X 怎么用" → 别启动 skill,直接答
- 不确定用户是否愿意看视频 → 先问,不要默默交付
