# 让 Agent 盯住一个目标连跑几天，不要去改主循环

给 Agent 加「长期目标」，第一反应通常是改主循环：加一个 goal 分支、加一个计数器、再写一段「请继续完成目标」的提示词。

DeepSeek Harness 的 `packages/goal` 没这么做。`agent-loop` 一行没改。贯穿始终的一句话是：

**状态可以回放，权限必须重授。**

下面按一条脉络往下走。每一步先钉「是什么」，再钉「不是什么」。上一步如果走了「不是什么」，后面的实现再漂亮也会在同一处裂开。

---

## 脉络：加一个目标，不要改 loop

![需求 → 接缝 → 根 → 主干 → 切开四根分支。主线：状态可回放，权限必须重授](images/00-thread.png)

| 步 | 是什么 | 不是什么 |
|---|---|---|
| 需求 | 盯住一个目标，跨回合直到真正完成 | 改 loop、加计数器、把「请继续」写进提示词 |
| 接缝 | 一个服务持有状态；命令 / 工具 / 调度只消费 | 单体 feature；消费者各存一份 |
| 根 | 每次变更追加事件，当前态由日志 fold 出来 | 另存一张表；只活在内存的 steering |
| 主干 | 严格 fold + CAS：现在是什么版本、什么 phase | 后写覆盖；散落的布尔标志 |
| 切开 | phase 持久；能否续跑、谁能改、何时开下一轮只在运行时 | 把「能否自动续跑」写进日志，让恢复或 fork 自己跑起来 |

---

## 树：每层回答一个问题

目标功能不是一个开关，是从日志长出来的一棵树。红字是「不是什么」。树叶只实现所属分支，不另开主干。

![根 session log → 主干生命周期 → phase / activation / authority / round 四根正交分支](images/02-tree.png)

横切纪律——插件接缝、不透明 ID、非法配置加载即抛——约束整棵树，不是第五根分支。

---

## 接缝：一个服务，三个消费者

- `dsh-goal` 持有状态
- `dsh-command-goal`：人类 `/goal`
- `dsh-tool-goal`：模型 `get` / `create` / `update`，先过权限
- `dsh-goal-round-driver`：空闲时续跑

后三者都不拥有状态。新行为走接缝，不进循环。

![人与模型改目标，领域写日志，driver 在空闲时注入下一轮](images/01-architecture.png)

根是 session log。每次变更追加 `goal/change`，当前状态由 fold 推出，不另存表。进入模型请求的内容必须能从这份日志重建。Codex 的目标功能走「每个线程一行 SQLite」；这里走事件流。选一种真相，不要两套并存。

主干用比较并设置（CAS），不用加锁。每次变更带 `{ id, revision }`，过期直接拒绝。模型先读，再复制精确的 id / revision。后写覆盖在这里是 bug。

---

## 切开：phase 持久，activation 永不落盘

`phase` 是 `active` / `paused` / `blocked` / `complete`，写进日志，可以回放。

`activation` 是 `armed` / `disarmed`，只存在于当前进程。`session-start`、恢复、fork 一律 disarm。

![phase 写进日志；activation 永不落盘。合法组合：active + disarmed](images/03-two-dimensions.png)

所以会出现这种合法组合：phase 仍是 `active`，activation 却是 `disarmed`。它不会自动继续执行。必须等人明确 resume，才会重新 armed。执行授权绝不随状态一起回放。

---

## authority：活着的事实，不是提示词

改目标、停目标，不靠「请你不要乱改」，也不靠持久化的 root / fork 血缘：

1. 调用者必须是精确匹配的存活 agent，处在开放 turn
2. 改目标需要宿主签发的 `{ kind: 'user' }` 消息
3. `complete` / `blocked` 可以走当前 goal round 这条窄通道——只能报告终止，不能改目标

子代理、插件注入、过期回合，过不去。提示词只能引导「该不该」；执行期校验才决定「能不能」。

![三层执行期校验；血缘能说明来历，不能代替这一回合的签发](images/04-authority.png)

---

## round：一次一续，每轮重注入完整目标

四个条件同时成立才驱动下一轮：空闲、`active`、`armed`、轮次还有余量。每次空闲最多续一次。不是重试队列，不是定时器，不是循环计数器。

每一轮重新注入完整 objective。完成必须拿工作区 / 持久态当权威，先给证据。`blocked` 要连续 N 轮同一条件，加上具体理由。模型自己宣布完成，不算。

失败即停：持久化失败、队列失败、驱动异常，都是 disarm / block，不乐观重试。

![空闲检查 → 落盘 → 预留下一轮 → 注入完整目标 → 模型执行](images/05-round-loop.png)

---

## 能搬走的是判断

树叶会随仓库改名。根和主干如果对了，叶子换掉也还是同一棵树。根和主干如果错了——在 loop 里加分支、把 armed 写进日志、用提示词当权限——叶子写得再漂亮，恢复、fork、子代理、空闲续跑都会在同一处裂开。

产品契约可以和 Codex 相近（空闲自启动、反漂移、证据先行）。持久化与权限的切割可以完全不同。选哪一种，取决于你的 harness 已经把什么当作真相。
