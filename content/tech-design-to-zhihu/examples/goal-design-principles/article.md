# 让 Agent 盯住一个目标连跑几天，不要去改主循环

**TL;DR**

- 别把长期目标焊进主循环。发动机不动，旁边一本可以回放的账。
- 状态可回放，权限必须重授。进展能记住；自动续跑必须重新授权。
- 模型看见的必须能从日志翻出来。提示词里的「请继续」，不算。
- 「我做完了」不算完。听工作区。卡住要连续出现，才允许认输。
- 能抄走的是这套切割，不是某个仓库里的文件名。

给 Agent 加「长期目标」，第一反应通常是三件事：改主循环、加一个计数器、在提示词里写「请继续完成目标」。

这三条都快，也都会在同一处裂开：重启之后不知道当时叮嘱了什么；恢复出来的会话自己跑起来；模型把目标偷偷改小，好早点收工。

DeepSeek Harness 的 `packages/goal` 没改主循环。贯穿始终的一句话是：

**状态可以回放，权限必须重授。**

人话就是：目标这件事，要有一本翻得回来的账；每一次真正跑起来，都得重新拿到「准你自动续」的授权。下面按这个顺序讲。每一步先说它是什么，再说它不是什么。

---

## 第一反应是错路

别把长期目标焊进发动机。发动机还是原来的发动机；目标是旁边一本可以回放的账。

![错路是改 loop、加计数器、写请继续；正路是主循环不动，旁边接一个目标服务](images/09-wrong-loop.png)

是：主循环一行不改，一个服务专门记目标。人的命令、模型的工具、空闲时的调度，都只消费这个服务，谁也不私藏一份。

不是：在 loop 里加 goal 分支，也不是靠提示词让模型「记得继续」。

---

## 脉络：加一个目标，不要改 loop

判断按这条链往下走。上一步如果走了「不是什么」，后面的实现再漂亮也会裂。

![需求 → 接缝 → 树根 → 主干 → 切开。主线：状态可回放，权限必须重授](images/00-thread.png)

| 步 | 是什么 | 不是什么 |
|---|---|---|
| 需求 | 盯住一个目标，跨回合直到真正完成 | 改 loop、加计数器、把「请继续」写进提示词 |
| 接缝 | 一个服务持有状态；命令 / 工具 / 调度只消费 | 单体功能；消费者各存一份 |
| 树根 | 每次变更追加事件，当前态由日志折出来 | 另存一张表；只活在内存的叮嘱 |
| 主干 | 折一遍流水账 + 核对版本：现在是第几版、走到哪 | 谁后写谁赢；满地布尔开关 |
| 切开 | 「走到哪」可以持久；「这一进程还准不准自动续」只活在当前进程 | 把「能否自动续跑」写进日志，让恢复或 fork 自己跑起来 |

---

## 树：每层回答一个问题

目标功能不是一个开关。它是从日志长出来的一棵树。红字是「不是什么」。树叶只实现所属那根枝，不另开主干。

![树根是会话日志，主干是可回放的生命周期，四根枝分别回答进展、能否续、谁能改、何时开下一轮](images/02-tree.png)

横切的三条纪律——接缝、不透明 ID、非法配置加载就报错——约束整棵树，不是第五根枝。

---

## 接缝：一个服务，三个消费者

人改目标、模型改目标，都进同一个服务。服务往日志里追加一条变更。空闲调度看到变更，才决定要不要开下一轮。

![人与模型改目标，领域写日志，空闲时才注入下一轮](images/01-architecture.png)

是：状态只在一处。不是：命令、工具、调度各存一份，对不上再猜。

---

## 树根：模型看见的，必须能翻出来

你不能一边让模型按某句话做事，一边让这句话只活在某次运行的内存里。否则「它当时到底被叮嘱了什么」，无法回放，也无法在恢复后对齐。

![会进模型请求的内容都必须能在会话日志里找到；内存叮嘱不算目标功能](images/07-logged.png)

是：目标状态、续跑时重新念的那段完整目标，都先落账。

不是：系统提示词里随口加一句「请继续」，进程一死就没了。

---

## 两种记账法，选一本当真相

Codex 那条路：每个线程一行表，读这一行就知道现在的目标。重启后如果还是进行中，就重新武装。

DeepSeek Harness 这条路：不另开抽屉。每次变更往会话日志追加一条，把流水账折一遍，得到现在。重启强制解除武装——账可以回放，自动续跑的授权必须人再给一次。

![一行表或一串事件，二选一；两套都写就是两套真相](images/08-two-stores.png)

产品契约可以相近：空闲续跑、防漂移、拿证据再完成。记账法和「重启后能不能自己跑起来」，可以完全不同。选你的系统已经认哪本账。两边都做，就是两套真相。

---

## 主干：同时改一份账，过期的丢掉

像两个人同时改同一份文档。后保存的那份不该默默覆盖先保存的那份。

改之前记下「我看到的是第 3 版」。提交时如果已经是第 4 版，这份改动作废，重新读再改。

![甲按第 3 版改成第 4 版收下；乙还拿着第 3 版来改，直接拒绝](images/06-cas.png)

是：先读到第几版，改的时候核对还是这一版。

不是：谁后写谁赢，也不是加一把大锁让全世界排队。模型被要求：先读，再把读到的编号和版本原样抄回去。

---

## 切开：走到哪可以记住，准不准自动续必须重授

「走到哪」写成 `active` / `paused` / `blocked` / `complete`，写进日志，可以回放。

「这一进程还准不准自动续」写成 `armed` / `disarmed`，只存在于当前进程。启动、恢复、fork，一律先解除武装。

![左边是可回放的进展；右边是永不落盘的武装。合法组合：还在进行中，但这一进程不准自动续](images/03-two-dimensions.png)

所以会出现这种合法组合：账上还是「进行中」，这一进程却不准自动续。它不会自己跑起来。必须等人明确说继续，才会重新武装。

人话：你可以记住作业做到哪一页；但不能因为书还夹着书签，电脑一开机就自己写下去。

---

## 谁能改：看这一回合还活着，不看提示词，不看血缘

改目标、停目标，不靠「请你不要乱改」，也不靠「你是从哪个会话 fork 出来的」。

看的是这一回合还活着的事实：调用者还在、轮次还开着、改目标这件事上有没有宿主签发的人类消息。报完成、报卡住，可以走当前这一轮的窄通道——只能报终止，不能改题目。

子代理、插件塞进来的话、已经结束的回合，过不去。

![三层执行期校验；提示词只引导该不该，校验才决定能不能](images/04-authority.png)

血缘能说明来历，不能代替这一回合的签发。

---

## 续跑：空了才续一次；题目每一轮重新念一遍

四个条件同时成立，才开下一轮：闲着、还在进行中、这一进程已武装、轮次还没用完。每次空闲最多续一次。不是重试队列，不是定时器，不是循环计数器。

![空闲检查 → 先落盘 → 预留下一轮 → 注入完整目标 → 模型执行](images/05-round-loop.png)

长期目标最常见的死法，不是跑不动，是模型偷偷改题。所以每一轮把完整目标再注入一次。收工不听口头，听工作区。卡住也要同一条件连续出现，才允许认输——避免一轮运气不好就放弃。

![「我做完了」不算完；工作区对得上完整目标才算。卡住要连续出现](images/10-evidence.png)

失败即停。写账失败、排队失败、调度异常，都解除武装或标成卡住，不乐观重试。

---

## 收获和结论

树叶会改名，函数会搬家。能抄走的是下面七句。

![七条可搬走的判断：别焊进 loop；状态可回放权限必须重授；模型看见的必须能翻出来；过期写入丢掉；听工作区；一本账；树根错了叶子会一起裂](images/11-takeaway.png)

**收获**

1. **别把目标焊进主循环。** 发动机不动；旁边一本可以回放的账。不是在 loop 里加分支。
2. **状态可回放，权限必须重授。** 进展写进日志；自动续跑授权只活在这一进程。不是恢复后自己接着跑。
3. **模型看见的，必须能翻出来。** 内存叮嘱、口头「请继续」，不算目标功能。
4. **同时改一份账，过期的丢掉。** 先读版本再改。谁后写谁赢是 bug。
5. **「我做完了」不算完。** 听工作区。卡住要连续出现，才允许认输。
6. **记账法可以不同，真相只能一本。** 一行表或一串事件，二选一。产品契约可以相近。
7. **树根和主干错了，叶子再漂亮也会在同一处裂开。** 改 loop、把武装写进日志、用提示词当权限——恢复、fork、子代理、空闲续跑会一起爆。

**结论**

给 Agent 加长期目标，不是让它「记得继续」，而是让世界有一本可回放的账，并且每一次真正跑起来，都重新拿到执行授权。能抄走的是这套切割，不是某个仓库里的文件名。

**PS.** 如果你只带走一句：状态可回放，权限必须重授。恢复出来的会话可以记得作业做到哪一页，但不能因为夹着书签，电脑一开机就自己写下去。

**PPS.** 这和「把模型训得更听话」不是一回事。提示词只能引导该不该；执行期校验才决定能不能。血缘、fork、子代理，都代替不了这一回合的签发。

**PPPS.** 文里的插件名、函数名都会过时。如果你在自己的系统里只改 loop、把「准不准续跑」写进日志、用提示词当权限——恢复、fork、空闲续跑，会在同一处裂开。那才是这篇要拦的事。
