# 俞航工程笔记文风

## 用途

写技术规划、排查笔记、进展周报、使用手册、测试说明时，按俞航本人的工程笔记习惯写。

不用于对外公众号文章、营销稿、散文、正式公文，那些另走对应文风。

## 文风样本（本人写的）

- 火炬iOS ips dysm文件 查看堆栈
- 火炬本地打包Cook加速（必看）
- S15火炬prereview首包全平台出包情况汇总
- 2024 全年

AI 代写的稿子不算样本。市场与技术路线调研、FDE 工作方案、V3.0 设计方案那种核心判断、壁垒、飞轮密集加粗的咨询报告体，要避开。

## 规则

### 1. 标题写主题或目标

写 ASTC压缩加速、Shader编译加速，不写 如何提升打包效率 这类问句，不写口号。

### 2. 对象：判断开头，自然语言收尾

每条先写对象、再下判断，比如：国际服 ok、重打中、Speed 和 Size 设置成 0。

判断之后别停在标签上，接着用自然口语把原因和结论讲完。先给结论，再补条件，不铺垫、不寒暄。

### 3. 数字、命令、路径原样放

8m01s -> 2m29s、M3 Ultra 256GB、CL 5879332 pending，不换算、不四舍五入、不换说法。

命令和配置贴代码块，给真实文件名和路径，不写 某配置文件 这种指代。千分位带逗号（85,093），大数用万（40 万、1.5 万）。

### 4. 原因到结论，逻辑词显式带出来

每条按原因到结论的顺序写，显式用因为、所以、原因是、因此、但、就差这类词，因果关系直接读出来，不靠读者自己拼。

机制能简则简，不层层铺垫，但逻辑词不能省。

### 5. 没定论留 TODO

原因 TODO、待 p4 提交、基线数据还没有。没做完直接标状态，不包装成已完成，也不编。

### 6. 按主题分组，不套计数框架

用 现状、卡点、接下来 这种功能分组。不写 两个问题、三条纪律、五大抓手 这种标签框架。

菜单路径、流程顺序用 ->：jira面板 -> 列表 -> 时间筛选。

### 7. 加粗和下划线的用法（排版重点）

- 加粗只给关键数字，不给概念词。概念词加粗像咨询报告，确定性规则链、模板注册表这种直接写。
- 下划线只给写全原因到结论的整句，比如：基线数据没打出来，所以没有量化结论。
- 标签碎片不下划线，先跑三件事、先让录入生效这种不是结论。
- 路径和命令不要放在下划线标签里，markdown 渲染会丢行；放下划线外面。

## 禁止

- 连接词：首先、其次、此外、值得注意的是、综上所述
- 模板腔：统一开头、排比、段尾总结、强行升华
- 口语抒情：说白了、摆在这里、钱花得不明不白、未来可期
- AI 爱用的符号少用：×（倍数写成 倍）、~（约数写成 约）、直角引号（概念直接写）、破折号解释、密集加粗
- 编数据、编案例、编对话

## AI 爱用的词（替换表）

| AI 爱用 | 换成 | 例子 |
|---|---|---|
| 轴 | 维度；分组直接写主题 | 去重轴 -> 去重；砍轴 -> 砍维度 |
| 门禁 | 闸门、关口 | 成本门禁 -> 成本闸门 |
| 键、key | 直接说是什么 | 不改 key -> 不动去重规则 |
| 说清 | 讲明白 | 说清再立项 -> 讲明白再立项 |
| 没定 | 没有敲定 | 输入输出没定 -> 输入输出没有敲定 |
| 扩不扩 | 扩不扩展 | 规则扩不扩 -> 规则扩不扩展 |
| 不收 | 不收录 | 不收或写明状态 -> 不收录或写明状态不良 |
| 沉淀 | 存回、记下来 | 经验沉淀回知识库 -> 经验存回知识库 |
| 闭环 | 接通、打通 | 读写闭环 -> 读写接通 |
| 赋能、抓手、飞轮、壁垒、护城河、心智、打法、颗粒度 | 不用，换成大白话 | 颗粒度细 -> 分得细 |
| 聚焦、收敛 | 先做、定下来 | 聚焦三件事 -> 先做三件事 |

对齐、链路、打通、落地、卡点、基线、口径、盘点是本人常用词，不算 AI 味。

## 适用 / 不适用

- 适用：技术规划、排查笔记、进展周报、使用手册、测试说明
- 不适用：对外文章、营销稿、散文、正式公文

## 完整范例（KR2 段落，2026-10-09 定稿）

KR2 现状（recook 耗时缩到 50%，@彭天成）：

**去重（省 job 条数）：**

- 产物层共享：不用管。UE 本来就按内容身份去重，**85,093 条**引用只对应 **10,495 份**产物，去重因子 **8.11 倍**，说明这部分没有重复编译。
- 变体膨胀：真正白花的编译。<u>三个维度乘开、维度多编译多，所以砍维度、不动去重规则</u>。
- 结果层重复：<u>同一份字节跨质量档重复拷贝（GLSL 39.71%、Vulkan 51.92%），因此这些行直接跳过</u>。
- 补锁修复：<u>FindId 和 Register 之间窄竞态的修复已落源码、编译通过，就差 p4 提交</u>。

**吞吐（省单 job 时间）：**

- 集群利用率：<u>batchgroup 默认只有 128、派发线程被卡住，所以 900 核没跑满</u>。
- 安卓积压：**40 万**待返回 Shader 任务，PC 只有 **1.5 万**，差 **26 倍**；<u>安卓多花约 5 小时、但现有耗时差异解释不了，因此继续归因</u>。
- P0 实验：先跑三件事，batchgroup 从 128 调到 **256/512**，看集群能不能跑满；安卓纹理压缩改成 **DXT**、对齐 PC，打 MUMU 包验证；ShaderCompileWorker 换 **release**、替掉 develop，看版本能省多少。

**降非必要 recook：**

- INI 白名单：<u>基线数据没打出来，所以没有量化结论</u>。
