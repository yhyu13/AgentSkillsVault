## 🟢 第二章 · 快速原型 MVP

### 黄金法则
- **快速原型 = 决策快 ≠ 代码快**
- **两周能交付的，不要做两个月**
- **客户的第一个 yes 比完美设计重要 100 倍**
- **假数据也能证明价值**
- **帮客户砍需求也是 FDE 的核心价值**

### 需求五问法（客户第一句话后必问）
1. **现状**：现在怎么做的？每天多少量？哪步最花时间？
2. **痛点**：哪个环节最让你头疼？量化（多少时间/多少钱）？
3. **期望**：理想状态长啥样？成功的标准是什么？
4. **约束**：有什么不能动的（数据/系统/合规）？
5. **优先级**：A/B/C 三件事哪个先做？验收标准是什么？

### MVP 三条铁律
1. **先让客户说 yes** —— 第一个版本让客户想用第二个版本
2. **每行代码要回答问题** —— 回答不出来就不要写
3. **假数据比没数据好** —— 先搭 Demo，客户会自己去整理数据

### 技术栈速选
| 场景 | 最快栈 | 预计时长 |
|------|--------|----------|
| 内部 demo | Streamlit / Gradio + Pandas | 1-2 天 |
| 客户演示 | FastAPI + React 模板 | 1 周 |
| 正式上线 | Docker + PostgreSQL + CI/CD | 2 周 |
| K8s 部署 | 只在客户已用 K8s 时才上 | 2-4 周 |

### 早会三问（每周一）
1. 上周客户用了什么？
2. 本周要交付什么？
3. **上周做的东西里能砍掉哪些？** ← 第三问最重要

## 🟡 第三章 · 最后一公里部署

### 4 种客户环境
| 类型 | 难度 | 提前必确认 |
|------|------|------------|
| 公有云 | ★★ | VPC / 权限 / 白名单 |
| 私有云 | ★★★ | K8s 版本 / 网络 / 镜像仓库 |
| 物理机房 | ★★★★ | 谁开门 / 账号 / 有无 sudo |
| 断网环境 | ★★★★★ | 离线包 / 备用笔记本 |

**第一课**：永远不信"环境准备好了"——带好 Plan B

### 部署三板斧
1. **Docker**（保命符）—— 不管啥环境，先打包
2. **IaC**（基础设施即代码）—— 别手敲，80% 用 Docker Compose
3. **上线清单** —— 没有清单的部署 = 俄罗斯轮盘

### Dockerfile 模板（背诵）
```dockerfile
FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
ENV TZ=Asia/Shanghai
HEALTHCHECK --interval=30s --timeout=10s \
  CMD curl -f http://localhost:8000/health || exit 1
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
```

### 部署前 8 问
- [ ] 配置用环境变量了？数据库迁移准备好？
- [ ] `/health` 接口 + `HEALTHCHECK` 配好？
- [ ] 日志输出到 stdout？告警配好？
- [ ] 回滚方案？第三方服务地址对？端口不冲突？资源够？

### 必监控 5 指标
| 指标 | 阈值 |
|------|------|
| CPU | >80% 告警 |
| 内存 | >85% 告警 |
| 磁盘 | >85% 告警 |
| P99 延迟 | >3s 告警 |
| 5xx 错误率 | >1% 告警 |

### 现场诊断 6 步（10 分钟/步）
1. 复现（截图/录屏）
2. 看日志（`tail -100`）
3. 查监控（CPU/内存/磁盘）
4. 查数据库（`pg_stat_activity`）
5. 定位根因（A→B→C 画流程图）
6. 修 + 验 + 善后

### 数据集成三步
1. **抓样本**（100 条脱敏数据）
2. **建映射**（`FIELD_MAP = {...}`）
3. **渐进接入**（1 天 → 1 周 → 3 年）

### FDE 的 CI/CD 原则
- 每个环境一个配置（不要"通用配置"）
- 部署 = 一次命令（不能 10 步手动）
- 回滚必须快（部署可以慢）
- 部署要有通知（钉钉/微信群）

## 🔴 第四章 · 与客户并肩作战

### 90/10 法则
**客户评价你 = 90% 体验 + 10% 技术**

### 商业语言三板斧
| 关键词 | 老板听到 | 翻译公式 |
|--------|----------|----------|
| **降本** | 省钱！ | 自动化 / 流程优化 / 错误减少 |
| **增收** | 赚钱！ | 数据驱动 / 体验提升 / 交叉销售 |
| **风控** | 不出事！ | 异常检测 / 合规 / 实时告警 |

### 三要三不要
- ✅ 要：用比喻 / 先给结论 / 给选项
- ❌ 不要：用术语 / 先讲原理 / 只给一个方案

### 第一次见客户 · 黄金 30 分钟
- **0-10 min**：聊业务别聊技术（让客户先说）
- **10-20 min**：展示"懂行"（"我刚看了你们数据，发现 X"）
- **20-30 min**：约定合作方式（每日对进度 / 随时 @ / 共享文档）

**万能开场白**（背诵）：
> "张总你好，今天我们就是来听你说问题的。你不用理解技术细节，你只需要告诉我现状、痛点、期望，我来负责翻译成方案。今天结束时，我会给你清晰判断——哪些马上能做、哪些需要时间、哪些还不适合做。你看行不行？"

### 期望管理公式
**满意度 = 实际体验 - 期望值**
（杠杆不在做得更好，在管理好期望）

### 4 场景应答模板

| 场景 | 一句话模板 |
|------|------------|
| 客户说"简单，一天搞定" | "你说得对，如果是基本功能 2-3 天。我建议先做最小版本给你看效果，明天发 Demo，先看方向对不对" |
| 客户加需求 | "这个我记下了。你希望：① 砍掉 C 来做 D / ② 顺延到 A 后 / ③ 另起项目？你看哪个合适？" |
| 进度延期 | 当天就预警——问题+影响+方案，三段式，让客户做选择 |
| 客户说"不好" | 接情绪（不解释）→ 找根因 → 给方案 → 复盘 |

### 现场诊断速查命令
```bash
tail -100 /var/log/myapp/app.log    # 日志
top -bn1 | head -20                  # 资源
df -h                                # 磁盘
netstat -tlnp                        # 端口
dmesg | grep -i oom                  # OOM
docker logs --tail 100 myapp         # Docker 日志
SELECT * FROM pg_stat_activity WHERE state != 'idle';  # 慢查询
```

### 三份必交文档
1. **系统操作手册**（给运营）：登录/使用/巡检
2. **故障排查手册**（给运维）：常见问题/排查/联系人
3. **维护说明**（给下一任 FDE）：架构图/配置/注意事项/遗留

### 撤退检查清单
- [ ] 三份文档交付
- [ ] 核心功能稳定运行 ≥ 2 周
- [ ] 客户运营独立操作 ≥ 3 次
- [ ] 毕业复盘做完
- [ ] 半年联系窗口留好

## 🎯 一页纸心法（FDE 终极三句话）

> **第二章**：快速原型 = 决策快。让客户说 yes 的能力，比你的代码重要 100 倍。
>
> **第三章**：能部署的 FDE = 凤毛麟角。Docker + 清单 + 监控 = 你的护城河。
>
> **第四章**：客户买的是"省钱"和"赚钱"，不是"大模型"。技术好 ≠ 客户说好。
